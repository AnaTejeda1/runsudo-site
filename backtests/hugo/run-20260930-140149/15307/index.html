The issue

View on GitHub

Hugo's built-in js.Build function currently doesnt support and/or list es2025 as available target parameter.
As far as i understood js.Build relies on evanw/esbuild for bundling, transforming and minifying javascript ressources.

According to hugo's own release notes esbuild was just bumped to 0.28.2.
According to esbuild's release notes, support for es2025 as target parameter exists since 0.27.5.
Hugo should therefore support es2025 as target parameter.

However when doing something like this:

{{- $buildParams := dict
    "minify" true
    "sourceMap" "none"
    "target" "es2025"
}}
{{- with . | js.Build $buildParams }}
    <script>{{ .Content | safeJS }}</script>
{{- end }}

results in the following error message:
`
... JSBUILD: failed to transform "/ts/test.ts" (text/typescript): unsupported target: [es2025] ...
`

What version of Hugo are you using (hugo version)?

hugo v0.165.0

Does this issue reproduce with the latest release?

Yes

What the agent reported

js.Build now accepts "target" "es2025". The new tests fail without the fix and pass with it, but I had to run them with go test directly because ./bt-test couldn't build anything in its container.

What was wrong: Hugo checks the target name against a fixed list in internal/js/esbuild/options.go. That list stopped at es2024, so es2025 produced unsupported target: [es2025] before esbuild was ever called. The esbuild version Hugo uses (v0.28.2) already supports ES2025.

What I changed:

  • internal/js/esbuild/options.go: added "es2025": api.ES2025, to the list of accepted targets.
  • docs/content/en/_common/functions/js/options.md: added es2025 to the documented target list.
  • internal/js/esbuild/options_test.go: added es2024 and es2025 cases to TestToBuildOptionsTarget.
  • resources/resource_transformers/js/js_integration_test.go: added TestBuildTargetES2025. It runs your exact template (minify true, sourceMap "none", target "es2025", output via <script>{{ .Content | safeJS }}</script>) on a TypeScript file. It checks that the page contains the minified script: <script>(()=>{var o="Hello ES2025";console.log(o);})();

Test evidence:

  • ./bt-test couldn't run: its container has no network and its Go module cache is empty, so every run stopped at [setup failed] while trying to download modules from proxy.golang.org. That's an environment problem, not a test result.
  • What I ran instead: go test with GOMODCACHE=/bt/cache/go-mod GOPROXY=off, which uses the local copy of the same pinned modules.
  • Before the fix: TestToBuildOptionsTarget/es2025 failed with unsupported target: [es2025]. TestBuildTargetES2025 failed with the error from your report: JSBUILD: failed to transform "/ts/test.ts" (text/typescript): unsupported target: [es2025].
  • After the fix: all tests in both packages (internal/js/esbuild and resources/resource_transformers/js) pass, including the two new ones.
  • Check that the test catches the bug: with only the fix temporarily removed, the integration test failed again with the same error.
  • Assertion fix: the first version of the integration test checked for the wrong text. I corrected it to match the real minified output before the final runs.
  • Possible fragility: the integration test expects esbuild's exact minified output. That output is stable while esbuild stays at v0.28.2, but a future esbuild upgrade could change it (for example, by renaming the variable).

Requirements:

  1. Accept es2025 as a js.Build target: done, proven by the unit test and the integration test.
  2. Your template no longer errors: done; TestBuildTargetES2025 reproduces it end to end.
  3. List es2025 as an available target: done in the docs. I checked that esbuild v0.28.2 actually provides ES2025 before adding it.

Nothing is committed. AGENTS.md and CLAUDE.md show as deleted in the working tree, but they were already deleted before this session and I left them alone.
