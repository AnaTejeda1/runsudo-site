Add build.cleanDestinationDir config option

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Patch A is the better fix: it is correct, adds the requested option without risk, and is better tested.

**Patch A**
- Adds `build.cleanDestinationDir.keep`, a list of glob patterns relative to the publish directory. This is what the issue asks for.
- Adds `.git` to the files that are always kept. This directly fixes the worktree/submodule `.git` file being deleted.
- Keeps all existing protections: `.gitignore`, `.gitattributes` and dot-directories are still preserved. User patterns only add to that list.
- Its testscript covers the issue's exact scenario: `.git` file, `.domains`, `_redirects` and `foo/bar/.mysecretfile`. It runs both with and without a `static/` directory, and also checks a kept directory with nested content, `**` patterns and a submodule `.git` file in a subdirectory.
- A unit test covers pattern matching, leading-slash normalization, case sensitivity and invalid-glob errors.
- Docs are updated.
- The change is small and limited to the cleanup logic.

**Patch B**
- Moves `cleanDestinationDir` from the root config to `build.cleanDestinationDir.enable`. It deletes the RootConfig field, remaps the CLI flag and adds a deprecation path. This is a broader redesign than the issue requires.
- The built-in protections are only default values for `KeepFiles` and `KeepDirs`, so any user setting replaces them. Its own Scenario 4 shows this: setting `keepFiles = ['.domains', '_redirects']` and `keepDirs = ['keep-me']` deletes `.gitignore` and the `.hidden/` directory.
- In the issue's own setup, a user who adds `.domains` to `keepFiles` would lose protection of the worktree `.git` file. Setting any `keepDirs` would also allow real `.git` directories to be deleted.
- That is a data-loss footgun, and it undermines the core use case.
- Removing the root field adds the risk of missing other references to it.
- Negation support is extra scope that does nothing for the reported problem.

On correctness, safety and test coverage, Patch A is clearly better.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Usecase

I'm using Codeberg Pages to host my website, you can find the repostitory at https://codeberg.org/ilovelinux/pages

I have two branches:

  • main: hugo project
  • pages: hugo build (output of public/)

Since I'm using Codeberg Pages with a custom domain, I also need a .domains file[^codebergDomains] to be pushed in the pages branch.

When I

  • Have files in the static/ directory.
  • Switch to main branch.
  • Create the public/ folder using a git worktree of the pages branch.
  • Run hugo build --cleanDestinationDir.

I need

  • To remove outdated content
  • To retain:
  • .git file created by git worktree[^gitWorktreeFile].
  • .domains file used by Codeberg Pages in order to allow custom domains[^codebergDomains].
  • _redirects file for redirects (however I'm not using it yet)[^codebergRedirects].

Instead

  • The files I need to be retained are deleted.

Proposal

Add a configuration field to list relative file paths to public/ that should be retained when using --cleanDestinationDir.

Example

 filesToRetain:
  - .git
  - .domains
  - _redirects
  - foo/bar/.mysecretfile

Files retained:

  • public/.git
  • public/.domains
  • public/_redirects
  • public/foo/bar/.mysecretfile

[!NOTE]
I'm not suggesting to use filesToRetain as configuration field, but I couldn't think of a better name.

Notes

[!IMPORTANT]
--cleanDestinationDir does nothing when when the static/ directory doesn't exist since its value is used inside the copyStaticTo function.
https://github.com/gohugoio/hugo/blob/c4bbc2805c7092deafabae01e71ff2dda37bd877/commands/hugobuilder.go#L481

Workaround

[!WARNING]
This approach is error-prone.

I implemented a workaround in my Makefile that:

  • Repairs the worktree folder, as suggested in https://github.com/gohugoio/hugo/pull/6261#issuecomment-1692321365.
  • Restores the .domains file.

Related issues & PR

  • https://github.com/gohugoio/hugo/issues/3202 was about .git folder being deleted. Fixed thanks to:
  • https://github.com/spf13/fsync/pull/10
  • https://github.com/gohugoio/hugo/pull/3210.
  • https://github.com/gohugoio/hugo/issues/4546 was about .git file of a submodule[^gitSubmoduleFile] being deleted. Closed because it was considered a discussion.
  • https://github.com/gohugoio/hugo/pull/6261 was introducing a fix for the .git file in order to work correctly with git worktrees and submodules. Closed because of the Stale bot but it looks like it was still kept into consideration since @bep kept moving it among milestones after that. However this wouldn't solve my issue since .domains and _redirects files would still be deleted.
