Walrus expression duplicate evaluation failures with rewrite

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches remove the stale cross-assert `variables_overwrite`/scope state and both make the independent reproducers pass. The difference is in how fully they fix the root cause and in scope. Root cause: `visit_NamedExpr` returned the NamedExpr node itself, which was then reused as a result, as a BoolOp condition, and inside `display()` for the explanation, so the walrus ran again on each reuse. Patch B fixes this at the source: `visit_NamedExpr` assigns the walrus to a temporary once at its position in the statement sequence and the explanation reads the temporary, and `visit_Name` snapshots any load of a name that a walrus rebinds anywhere in the same assert. That gives correct single evaluation, correct left-to-right ordering, and correct explanation values uniformly across Compare, Call, BinOp, BoolOp, UnaryOp and generic paths with no per-visitor special cases. Patch A keeps returning the raw NamedExpr and instead patches each consumer (assign in Compare, snapshot of bare NamedExpr/Name operands in BoolOp, a new `visit_operand` lookahead for Compare/Call/BinOp). Its explanation for a walrus is `display(Name(target))`, a load of the variable evaluated later in the failure block, so a walrus nested inside a Compare operand of a BoolOp whose name is rebound by a later operand (e.g. `assert (a := 1) == 2 or (a := 3) == 4`) still reports the post-rebind value; B's temporaries avoid this. A's lookahead-based design is also considerably harder to reason about and does not cover container literals, IfExp or other generic_visit paths the same way. On tests, A deletes the whole existing `TestAssertionRewriteWalrusOperator` class (181 lines, including the `PYTEST_DONT_REWRITE` and several explanation checks) and reconstitutes only some of them in the coverage file, which is unrelated churn and loses coverage; B keeps the existing suite intact and adds focused regression tests for the issue, a call/boolop reuse case, failure-explanation single evaluation, and the `enable_assertion_pass_hook` path. B is the more correct, simpler and better-scoped fix.

The issue

View on GitHub

When we upgraded pytest from 7.2.0 -> 9.0.3, test failures appeared due to our use of walrus operators (:=) within assert statements. I have narrowed and reproduced this in test_walrus.py below. These two failing tests will _pass_ if we add PYTEST_DONT_REWRITE to the docstring, or run pytest --assert=plain test_walrus.py.

"""
Minimal reproducer: pytest 9.0.3 assertion rewriting evaluates walrus operator (:=) twice.
    pytest /tmp/test_walrus.py          # FAILS
    pytest /tmp/test_walrus.py --assert=plain  # PASSES
"""

class Counter:
    def __init__(self):
        self.value = 0

    def increment(self):
        self.value += 1


def test_walrus_in_assertion_basic():
    """Walrus captures wrong value: rewriter evaluates := twice."""
    c = Counter()
    assert (before := c.value) == 0
    c.increment()
    assert before != (after := c.value)


def test_walrus_running_counter():
    """Cumulative walrus increments fire twice each → count doubles."""
    count = 0
    items = []
    items.append("a")
    assert (count := count + 1) == len(items)  # count becomes 2, not 1
    items.append("b")
    assert (count := count + 1) == len(items)  # count becomes 4, not 2
    items.append("c")
    assert (count := count + 1) == len(items)  # count becomes 6, not 3
    assert count == 3  # fails: count is 6
