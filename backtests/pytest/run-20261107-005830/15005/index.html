In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause identically: the infinity guard in ApproxScalar.__repr__ and __eq__ called math.isinf(abs(self.expected)), which converts Decimal('1e400') to float and overflows to inf. Both replace it with a helper that uses Decimal.is_infinite() for Decimals and math.isinf otherwise, and all independent tests pass on both. Patch B stops there: a 10-line production change plus a test that exercises the issue's exact reproducer (rel and abs tolerance), negation, both operand orders, out-of-tolerance inequality, list and mapping containers, and real Decimal infinities, plus a repr check for the out-of-range value. That test fails on base and passes after. Patch A bundles the same fix with a large unrelated redesign: it adds a new public warning class PytestApproxDecimalToleranceWarning exported from pytest and documented in the reference, emits warnings at approx() call time for float tolerances on Decimal comparisons (which would newly break any user suite running with filterwarnings=error), deletes ApproxDecimal.__repr__ so existing repr output changes (the patch rewrites an existing test's expectation from '2.60 ± 1.0e-2' to '2.60 ± 2.6e-2' and wraps existing tests in pytest.warns), rewrites the running-max logic in all three _repr_compare methods, adds numpy object-dtype unboxing, changes 0.0 literals to 0, reorders NaN/negative tolerance checks, and ships five changelog entries for a different issue number. Under the stated criteria, that extra work earns no credit and counts against A because it adds risk (new default warnings, changed repr, modified existing tests) and obscures the fix. The issue

View on GitHub

pytest.approx returns False for two finite Decimal values even though their exact difference is below the requested Decimal tolerance.

Reproducer

from decimal import Decimal

import pytest

expected = Decimal("1e400")
actual = Decimal("1.0000001e400")
rel = Decimal("0.000001")
difference = abs(actual - expected)
tolerance = rel * abs(expected)

print("difference:", difference)
print("tolerance:", tolerance)
print("both finite:", expected.is_finite() and actual.is_finite())
print("in tolerance:", difference < tolerance)
print("relative comparison:", actual == pytest.approx(expected, rel=rel))
print("absolute comparison:", actual == pytest.approx(expected, abs=tolerance))

Output on pytest 9.1.1:

difference: 1E+393
tolerance: 1E+394
both finite: True
in tolerance: True
relative comparison: False
absolute comparison: False

Both comparisons should be True. The same result occurs on current main at 3fd8675d6d798507c06cf9c60753be6d9d7b0e17.

This appears to happen because the infinity guard calls math.isinf(abs(self.expected)), which treats finite Decimal("1e400") as binary-float infinity before the exact Decimal tolerance is used.

Environment: CPython 3.12.3, Ubuntu 24.04.4 LTS, Linux 6.8.0-100-generic x86-64. Reproduced on pytest 9.1.1 and the current main commit above.
