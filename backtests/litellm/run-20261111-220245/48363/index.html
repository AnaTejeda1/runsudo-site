[Bug]: Admin UI Router Settings renders no input for String-typed general_settings fields (spend-log retention, cleanup run budget/timeout)

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

The independent tests give no signal: every run on base, A and B failed with the same FileNotFoundError for the node binary, so the verdict rests on the diffs. Both patches fix the root cause the same way, by adding a `String` branch to SettingValueEditor that renders an Input with aria-label, shows the stored value, and feeds onChange so Update submits the typed value; both add integration tests that would fail before and pass after. The difference is at the edges. Patch A mirrors the existing List handling: it trims input, maps an emptied field to null, and extends the update handler so an emptied String field triggers handleResetField (delete) rather than an update, and its key on stored_in_db makes the uncontrolled input reset after a delete, matching the List branch's visible convention. Patch B passes the raw string through, so clearing the box and clicking Update sends an empty string to updateConfigFieldSetting and stores "" in the DB for duration-style settings like retention periods, which is an untested and likely harmful state the existing code deliberately avoids for Select/List. B's controlled input is fine but offers no equivalent safeguard. B's test does usefully exercise the trash-icon reset path, and A's tests cover display, update with trimming, and clear-on-empty; test quality is comparable. On correctness at the issue's edges and consistency with surrounding conventions, A is the better fix.

Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The issue

Description

On the Admin UI page /ui/router-settings/ (General Settings card), every general_settings field whose field_type is "String" renders an empty value cell — no input control at all. The row shows only the description, the status badge ("Not Set" / "In DB") and the Update/reset buttons. Clicking "Update" submits nothing (field_value is undefined), so these settings cannot be viewed or edited from the UI.

Integer-typed fields on the same page (maximum_spend_logs_cleanup_batch_size, maximum_spend_logs_cleanup_max_batches) render a normal number input — only String fields are affected.

Affected fields (all declared "String" by the backend):

field_namefield_type
maximum_spend_logs_retention_periodString
maximum_health_check_retention_periodString
maximum_daily_tag_spend_retention_periodString
maximum_spend_logs_cleanup_run_budgetString
maximum_spend_logs_cleanup_batch_timeoutString

Once a value is set via the API, it is not displayed either (the cell stays empty), so operators can't see the current value in the UI — the row's trash/reset button still works.
