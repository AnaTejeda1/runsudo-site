The component changes in both patches are functionally identical: both switch `headers` from `ref` to `computed` so titles react to locale changes, and both replace the hardcoded header titles and Active/Inactive labels with `i18n.baseText` lookups against new keys added to en.json. Either resolves the root cause. The independent tests crashed on every tree (exit 9), so they provide no signal. The differentiators are tests and craft. Neither patch adds unrelated churn. B wins on tests and marginally on craft.

Bug Description

When you uninstall or update a community node package that is used in workflows, the modal shows a table of those workflows. All the text in that table is written in English straight into the code, so it does not get translated:

  • The column headers "Workflow", "Owner" and "Status"
  • The "Active" and "Inactive" labels in the status column

https://github.com/n8n-io/n8n/blob/fa52841130f3576b50da09a55a9d1e61ae9ad5f8/packages/frontend/editor-ui/src/features/settings/communityNodes/components/NodesInWorkflowTable.vue#L30-L40
https://github.com/n8n-io/n8n/blob/fa52841130f3576b50da09a55a9d1e61ae9ad5f8/packages/frontend/editor-ui/src/features/settings/communityNodes/components/NodesInWorkflowTable.vue#L95-L96

The rest of the modal is already translated. For example, the title uses settings.communityNodes.confirmModal.uninstall.title.

To Reproduce

  1. Set the UI to a language other than English.
  2. Go to Settings > Community nodes and install any package.
  3. Add one of its nodes to a workflow and save the workflow.
  4. Go back to Community nodes, open the package menu and click Uninstall package.
  5. The table of workflows is still in English.

Expected behavior

The table headers and the status labels show in the selected language.

Debug Info

I found this while reading the code on master (2.46.0). The text is written into the code, so it happens on every setup.

Environment

  • Operating System: macOS (platform independent)
  • n8n Version: 2.46.0 (master)
  • Node.js Version: 24.x
  • Database: n/a
  • Execution mode: n/a
