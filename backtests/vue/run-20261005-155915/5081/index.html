Throw an error on createVNode with using innerHTML and children at the same time

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The issue asks for render functions to accept `innerHTML` and children together without crashing: use `innerHTML` when it is provided, otherwise render the children.

The crash comes from the renderer itself. It mounts children into an element whose content `innerHTML`/`textContent` then replaces. On the next patch, those vnode children point to DOM nodes that no longer exist (or are no longer in the element). The patch fails or corrupts the DOM, which matches the `__asyncLoader` TypeError in the report.

**Patch A** changes no runtime behavior. It only adds a dev-mode warning when a non-nullish `innerHTML`/`textContent` is combined with non-empty children.
- It does not fix the stale-children patching problem, and it does not toggle content dynamically as the reporter wants.
- In the issue's exact repro (`innerHTML: undefined`), Patch A deliberately emits no warning and changes nothing.
- Its tests only check that warnings fire. None of them would catch the crash or the toggle behavior, so they show nothing about the reported bug.

**Patch B** fixes the root cause in the renderer:
- `mountElement` skips children when a content override is present.
- `patchElement` handles every transition: override→children mounts fresh, children→override unmounts the rendered children (lifecycle hooks fire), and override→override leaves the children untouched. It also clears the TEXT patch flag.
- `unmount` skips children that were never rendered.
- It uses `!= null` consistently, so empty strings and `0` count as overrides. The same rule is applied in hydration and in the SSR renderer, keeping client and server consistent.
- It handles a subtle optimized-mode case: compiled non-block elements whose dynamic descendants are tracked by the parent block keep their children mounted. A dedicated test covers this.

Patch B's tests exercise exactly the reporter's scenario (toggling `innerHTML` between undefined and a value while children change). They cover text and array children, component mount/unmount hooks, keyed reordering while overridden, hydration, and SSR edge values. These tests would fail on the old code.

Patch B is larger and touches core renderer paths, which adds some risk. Even so, it is the only patch that actually resolves the reported behavior, so B is clearly better.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
