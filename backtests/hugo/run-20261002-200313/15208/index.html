Both patches have the same core fix. Each adds a `Namespace.Publish` method that type-asserts to `resource.Source`, calls `Publish()` and returns the original resource. Each registers it through `AddMethodMapping`. So both resolve the issue equally at the root, and `{{ ... | resources.Publish }}` works in both.

B is slightly more robust: it adds an explicit nil check, matching the "must provide a Resource object" convention used elsewhere in that namespace. Its doc comment explains the pipe use case.

On tests, A covers only a single happy path (minify, then publish, file exists). B tests several resource kinds (plain text, a minified transformation, an image, a copied resource, and an unpublished control) and checks the published file content. It also checks that a copied resource is published at its new path and not the original, and that unpublished resources are not written. B adds a negative test showing a non-Source (a Page) fails with the expected error.

B's test has some risk: the copied-resource `Name` assertion and the base64 PNG fixture depend on test-builder behavior. Even so, its coverage is much broader and more meaningful.

B also adds user-facing docs for the new function. This is neutral to slightly positive and adds no risk.

Overall the correctness is equivalent, and B wins on tests and edge-case handling.
