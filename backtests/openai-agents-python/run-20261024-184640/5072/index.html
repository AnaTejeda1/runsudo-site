Realtime: agent_end names the post-handoff agent instead of the agent whose turn ended

Tie

The judges split evenly between our patch and the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches make the identical core fix: in the turn_ended branch they capture `self._active_output_response_agent or self._current_agent` before the guardrail state is cleared and pass it to RealtimeAgentEndEvent. This is exactly the root cause the issue identifies (the snapshot taken at turn_started is the agent that produced the turn, and it was being cleared one line before the end event was built). All five independent tests fail on base and pass on both patches, so on the issue's core scenarios they are equivalent.

The differences are in tests and in one adjacent change. Patch A adds a single test that mirrors the repro (start A, handoff A->B, end A, and asserts `_current_agent` is B). Patch B adds two tests: one that also drives the follow-up turn and asserts the full paired sequence (start A, handoff, end A, start B, end B), which directly exercises the per-agent pairing the issue says consumers depend on, and one for a late turn_started arriving after output and a handoff for the same response. Patch B's second source change makes agent_start use the same snapshot when turn_started arrives after the response was already activated by earlier output; in that ordering base would name B as the starter of A's response, the same misattribution class the issue describes, so the change is consistent with the fix and the guardrail precedent rather than unrelated churn, and it is covered by a test. It is low risk because a fresh response re-assigns the snapshot in the same branch.

Craft is a minor wash: A's test sits in test_session.py with top-level imports, while B uses function-local imports in a handoff test file, which is slightly less tidy. Overall B wins on test strength (verifies the next-turn pairing the issue motivates) with equal correctness on the reported bug and a coherent, low-risk adjacent consistency fix.

Describe the bug

When a Realtime response contains a handoff tool call, the handoff completes before the model's turn_ended event and moves _current_agent to the target agent. The turn_ended branch in RealtimeSession then emits RealtimeAgentEndEvent(agent=self._current_agent), so the caller sees:

agent_start(A)  →  handoff(A → B)  →  agent_end(B)  →  agent_start(B)  →  agent_end(B)

RealtimeAgentEndEvent.agent is documented as "The agent that ended", but A never ends and B ends without having started. Any consumer that pairs agent_start / agent_end per agent (turn markers in a UI, per-agent timing, per-agent usage attribution read on agent_end) attributes A's turn to B.

The session already knows which agent produced the turn: _active_output_response_agent is captured at turn_started and is what the output guardrails use for the same reason. It is cleared one line before the agent_end event is built.

Repro steps

Self-contained, no network.

import asyncio

from agents.realtime.agent import RealtimeAgent
from agents.realtime.events import RealtimeAgentEndEvent, RealtimeAgentStartEvent, RealtimeHandoffEvent
from agents.realtime.model_events import (
    RealtimeModelToolCallEvent,
    RealtimeModelTurnEndedEvent,
    RealtimeModelTurnStartedEvent,
)
from agents.realtime.session import RealtimeSession
from agents.realtime.testing import ScriptedRealtimeModel


async def main():
    agent_b = RealtimeAgent(name="b")
    agent_a = RealtimeAgent(name="a", handoffs=[agent_b])
    model = ScriptedRealtimeModel(strict=False)
    session = RealtimeSession(model, agent_a, None, run_config={"async_tool_calls": False})
    await session.enter()

    await model.emit(RealtimeModelTurnStartedEvent(response_id="response_1"))
    await model.emit(RealtimeModelToolCallEvent(name="transfer_to_b", call_id="call_1", arguments="{}"))
    await model.emit(RealtimeModelTurnEndedEvent(response_id="response_1"))

    while not session._event_queue.empty():
        event = session._event_queue.get_nowait()
        if isinstance(event, RealtimeAgentStartEvent):
            print("agent_start", event.agent.name)
        elif isinstance(event, RealtimeHandoffEvent):
            print("handoff", event.from_agent.name, "->", event.to_agent.name)
        elif isinstance(event, RealtimeAgentEndEvent):
            print("agent_end", event.agent.name)
    await session.close()


asyncio.run(main())

Output on main:

agent_start a
handoff a -> b
agent_end b

Expected behavior

agent_start a
handoff a -> b
agent_end a

The turn that ended was produced by A; the handoff only decides who speaks next. I have a one-line fix with a regression test ready and will open a PR referencing this issue.
