Description

When declaring a RootModel and adding a Field annotation to the root property that includes examples, those examples are not part of the generated JSON schema. This also applies to the deprecated attribute. The title attribute is also not applied or it is overwritten by the class name of the root model class.

Most other attributes, such as pattern or description are exposed as expected. Furthermore, placing examples in json_schema_extra also works as expected.

Example Code

from typing import Annotated
from pydantic import RootModel, Field

class Foo(RootModel):
    root: Annotated[str, Field(examples=["foo", "bar"], deprecated=True)]

print(Foo.model_json_schema())  # does not include examples or deprecated.

Summary

What was wrong: For a RootModel, the root field's JSON-schema metadata (title, examples, deprecated) was silently dropped from model_json_schema(). In pydantic/_internal/_generate_schema.py, the RootModel branch of _model_schema discarded the second element of _common_field_schema(...) — the core_metadata carrying pydantic_js_updates (marked with a # FIXME). Regular model fields attach that metadata to their field core schema so json_schema.py's generate_inner merges it in; RootModel never did. pattern/description/json_schema_extra survived only because each has a separate code path.

What I changed (pydantic/_internal/_generate_schema.py, RootModel branch): stopped discarding the field metadata and merged its pydantic_js_updates onto the inner schema so generate_inner applies them. description is explicitly excluded from the merge because it is already handled by the dedicated RootModel branch in _update_class_schema, and routing it through js_updates would break the existing docstring-over-field-description precedence. pydantic_js_extra (json_schema_extra) is deliberately not merged, since it too is handled separately — avoiding double application.

Test evidence:

  • Added tests/test_root_model.py::test_model_with_field_examples_deprecated_and_title — the exact scenario from the report. Confirmed it FAILS without the fix (title overwritten with 'AModel', examples/deprecated missing) and PASSES with it.
  • Blast-radius gate on tests/test_root_model.py + tests/test_json_schema.py: the first run surfaced a real regression in test_model_with_both_docstring_and_field_description (description precedence); after the one-time repair (excluding description), the re-run is fully green: 609 passed, 3 skipped, 1 xfailed.
  • Reviewer verdict: PASS.

Requirements disposition:

  • examples lost in RootModel schema → fixed, covered by regression test.
  • deprecated lost → fixed, covered by the same test.
  • title not applied / overwritten by class name → fixed, covered by the same test (field title 'My Title' now wins; class name still used as fallback when no field title).
  • pattern/description continue to work → preserved (verified: description precedence test and existing test_model_with_field_description still pass).
  • json_schema_extra continues to work → preserved (not double-applied; existing tests pass).

All changes are left uncommitted in the working tree.
