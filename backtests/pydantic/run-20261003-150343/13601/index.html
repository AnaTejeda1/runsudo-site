model_dump(exclude=...) is silently ignored in python mode when a wrap model_serializer is gated with when_used="json"

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause the same way. In the function serializer's `to_python`, `json_key` and `serde_serialize`, the old code always scoped include/exclude to empty after `self.call`. That is wrong when the function was not called (`Ok((false, v))`, the `when_used` gate fails), because no filtering has happened and the fallback serializer needs the caller's include/exclude. Both patches keep the empty scope for the `Ok((true, v))` branch and pass the original state through on the fallback branch, so they are functionally equivalent on correctness.

Patch A adds a new `include_exclude()` accessor on `SerializationState`. That accessor clones the `IncludeExclude` (Bound refcount bumps) only to re-scope it into the same values, which is a small widening of the API for no real benefit. Patch B restructures each match so the fallback branch uses `state` directly. It touches only `function.rs`, avoids the clone, and its comment explains why the fallback keeps filtering.

The tests separate the two more clearly. Patch A tests plain and wrap model serializers with `when_used='json'` only. Its wrap serializer ignores the handler and returns `{'ser': True}`, which does not mirror the issue's `handler(self)` pattern. Patch B parametrizes over both `'json'` and `'json-unless-none'`, which the issue names explicitly, and over wrap and plain. It uses the issue's exact `handler(self)` shape and checks python mode, json mode and `model_dump_json`. It also covers nested include/exclude through an outer model, which exercises the scoped propagation. Finally, it adds field_serializer cases with index-level include/exclude on lists, which hit the same code path and would fail before the fix. Patch B's tests are the more thorough regression coverage of the reported scenario and its neighbours, and its implementation is slightly leaner.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

When a model declares @model_serializer(mode="wrap") with when_used="json" (or "json-unless-none"), the runtime exclude argument passed to model_dump() is silently ignored in python mode. The same call in JSON mode behaves correctly.

Expected: model_dump(exclude={"b"}) omits b regardless of when_used, since the gate concerns which serializer runs and not which fields the caller asked to drop.

Actual: b is present in python mode.

Example Code

from pydantic import BaseModel, SerializerFunctionWrapHandler, model_serializer


class Gated(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap", when_used="json")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


class Always(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


  # Gated to JSON: python mode ignores exclude.
  print(Gated(a=1, b=2).model_dump(exclude={"b"}))               # {'a': 1, 'b': 2}  <-- expected {'a': 1}
  print(Gated(a=1, b=2).model_dump(mode="json", exclude={"b"}))  # {'a': 1}          <-- correct

  # Identical model without the gate: python mode honours exclude.
  print(Always(a=1, b=2).model_dump(exclude={"b"}))              # {'a': 1}

  Output:

  gated  python: {'a': 1, 'b': 2}
  gated  json  : {'a': 1}
  always python: {'a': 1}
