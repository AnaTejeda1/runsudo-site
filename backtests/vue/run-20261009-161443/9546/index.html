Issue #9546 Merged fix PR #15523 Run 9 Oct 2026 · run-20261009-161443 vuejs/core

defineProps options object loses properties when using generics

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the same root cause the same way. They replace the conditional `PropMethod<T>` with an unconditional function-like constructor type. That stops `PropType<T>` from becoming a deferred conditional when `T` is a type parameter, and that deferral is what caused `RequiredKeys`/`OptionalKeys` to drop non-required props. The difference is in `InferPropType`.

Patch A keeps the `unknown extends V ? keyof V extends never ? ...` chain. It only swaps the inner `D` for `unknown extends D ? V : D`. When `V` is a generic `T`, `unknown extends V` stays deferred, so the result is still an unresolved conditional type. Patch A relies on TypeScript treating that deferred conditional as assignable to `T` when both branches are. That probably passes `expectType`, but users still get an opaque conditional type rather than `T`, and it is a less direct fix.

Patch B adds an earlier check: `[T] extends [PropType<any> | { type: PropType<any> }]`. For an explicit runtime type it returns `V` directly. Because the prop-options object type is not itself a generic object type, this resolves eagerly to a clean `T`. That is the more robust result.

There is a modest risk that B's short-circuit changes behaviour for explicit-type props where `V` is `unknown` and a default supplies `D`. That is an edge case, and the existing suites would likely catch it.

On tests, B is clearly stronger. It covers exactly the issue's three shapes (bare `PropType<T>`, `{type}`, `{type, required}`) plus defaults, arrays, union constructors, function props with generic args, Boolean/String alongside generics, readonly-ness and unknown-key errors. It covers both `defineProps` and `defineComponent` (`setup` and `this`), and it also checks `ExtractPropTypes`, `ExtractPublicPropTypes` and `ExtractDefaultPropTypes`. A's test is narrower: it constrains `T extends Record<string, any>` and checks only a few cases plus assignability.

Scope is comparable. Overall B gives a cleaner inferred type and much broader regression coverage.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
