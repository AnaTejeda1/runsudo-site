Support slug in section, taxonomy, and term pages

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Patch A does not address the issue at all. It renames an interface parameter and swaps HasAnyVector for HasVector in MatchSiteVector. That is unrelated churn, and possibly a semantic change, with no connection to slug support for sections, taxonomies or terms. It adds no tests.

Patch B targets the slug feature directly. The repository apparently already has base slug support, since the existing test in page_permalink_test.go expects /es/ayuda/ paths. Patch B fixes what is still missing for live rebuilds. It tracks a per-branch slug signature tree, compares that tree against the previous build, and forces affected descendants to be rebuilt from source and their identities marked changed. It also fixes two latent bugs that the rebuild path exposes: contentNodesMap unpacking of page meta sources, and aliasing of the term sitesMatrixBase map (fixed with maps.Clone).

Patch B adds several meaningful rebuild tests covering:
- section slug edits that propagate to descendants, resources and terms
- taxonomy slug edits
- cascade terms without a content file
- a slug edit combined with adding a new language
- a slug edit combined with a cascade edit

It also adjusts one existing assertion to the absolute RSS link. That adjustment is slightly suspicious, but it is plausible for an index.xml <link> to carry the baseURL.

Patch B is clearly the better fix.

The issue

<!-- Describe this new feature. Think about if it really belongs in the Hugo core module; you may want to discuss it on https://discourse.gohugo.io/ first. -->

Currently with multilanguage sites you can localize the URL for pages by setting slug in the frontmatter.

However there is no slug support for sections. This means the only way to localize a section URL is to use url together with [[cascade]]. This is annoying since you have to "redo from scratch" the entire URL format, with : tokens, duplicating names for parent sections, etc.

Proposal: add support for slug in section pages. It would behave the obvious way, basically being equivalent to changing the directory name for the section. It would affect the URL for the section and all descendant pages.

Example:

help/
    _index.en.md    # contains no slug
    _index.es.md    # contains slug="ayuda"
    how-to-frob/
       index.en.md    # contains no slug
       index.es.md    # contains slug="como-frobear"

would result in the following paths:

help/
help/how-to-frob/
es/ayuda/
es/ayuda/como-frobear/
