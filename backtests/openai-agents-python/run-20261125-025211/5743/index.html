The issue

View on GitHub

Describe the bug

#5567 / #5634 fixed run_input_guardrails so that a sibling input guardrail that had already completed when the tripping result was consumed is still reported. run_output_guardrails in src/agents/run_internal/guardrails.py has the same asyncio.as_completed loop and was not changed, so OutputGuardrailTripwireTriggered.run_data.output_guardrail_results (and RunResultStreaming.output_guardrail_results in streamed runs) still omits a passed sibling output guardrail whenever the tripping guardrail is registered first. The docs say output tripwires "provide the equivalent accumulated results through exception.run_data.output_guardrail_results" (docs/guardrails.md), which is only true for one registration order.

Debug information

  • Agents SDK version: 0.24.0 (also main at d6896165, 2026-11-10, which includes #5634)
  • Python version: 3.12.10
  • Operating system: Windows 11
  • Model and model provider: not involved; agents.testing.ScriptedModel
  • Does the issue reproduce with the latest Agents SDK release? Yes
  • Does the issue occur consistently or intermittently? Consistently (both guardrails are synchronous, so the order is deterministic)

Repro steps

No API key needed.

import asyncio

from openai.types.responses import ResponseOutputMessage, ResponseOutputText

from agents import Agent, GuardrailFunctionOutput, OutputGuardrail, OutputGuardrailTripwireTriggered, Runner
from agents.testing import ScriptedModel


def model() -> ScriptedModel:
    message = ResponseOutputMessage(
        id="msg_1", type="message", role="assistant", status="completed",
        content=[ResponseOutputText(type="output_text", text="hello", annotations=[])],
    )
    return ScriptedModel([{"output": [message]}])


def verdict(name: str, trips: bool) -> OutputGuardrail:
    def guardrail(context, agent, agent_output):
        return GuardrailFunctionOutput(output_info=name, tripwire_triggered=trips)

    return OutputGuardrail(guardrail_function=guardrail, name=name)


def names(results) -> list[str]:
    return [r.guardrail.get_name() for r in results]


async def main() -> None:
    for order in (["trips", "passes"], ["passes", "trips"]):
        guardrails = [verdict(n, n == "trips") for n in order]
        try:
            await Runner.run(Agent(name="a", model=model(), output_guardrails=guardrails), "hi")
        except OutputGuardrailTripwireTriggered as exc:
            print(f"run          {order} -> {names(exc.run_data.output_guardrail_results)}")

        result = Runner.run_streamed(Agent(name="a", model=model(), output_guardrails=guardrails), "hi")
        try:
            async for _ in result.stream_events():
                pass
        except OutputGuardrailTripwireTriggered as exc:
            print(
                f"run_streamed {order} -> {names(exc.run_data.output_guardrail_results)}"
                f" (result.output_guardrail_results {names(result.output_guardrail_results)})"
            )


asyncio.run(main())

Expected behavior

Every output guardrail that has already completed successfully when the runner consumes the tripping result is included exactly once in exception.run_data.output_guardrail_results (and in RunResultStreaming.output_guardrail_results), regardless of registration order, the same contract #5634 established for input guardrails. Results that only complete during cancellation cleanup stay excluded, as on the input side.

Root cause

src/agents/run_internal/guardrails.py at d6896165: run_output_guardrails (line 196) iterates asyncio.as_completed(guardrail_tasks) (line 225) and, on a tripping result (line 227), records only that result, cancels the siblings and raises (lines 228-238). A sibling task that is already done() but whose completion as_completed has not yielded yet is never recorded. The input paths got _unreported_input_guardrail_results (lines 55-66) for exactly this case in #5634; run_output_guardrails does not call it. All four callers (run.py lines 1352 and 2099, run_internal/run_loop.py lines 522 and 861) pass a sink list that becomes run_data.output_guardrail_results, so the omission reaches Runner.run, Runner.run_streamed and the terminal-tool path alike.

Proposed fix

Generalise the helper over both result types and call it from the output loop before cancelling, mirroring the input fix:

TGuardrailResult = TypeVar("TGuardrailResult", InputGuardrailResult, OutputGuardrailResult)

def _unreported_guardrail_results(tasks: list[asyncio.Task[TGuardrailResult]], recorded: list[TGuardrailResult]) -> list[TGuardrailResult]: ...

# run_output_guardrails, on tripwire:
record(result)
for sibling in _unreported_guardrail_results(guardrail_tasks, guardrail_results):
    record(sibling)

Branch with the fix and a regression test (tests/test_guardrails.py::test_output_guardrail_tripwire_snapshot[False|True], a mirror of test_input_guardrail_tripwire_snapshot from #5634; it fails on main and passes with the change, the whole file passes, ruff and mypy are clean): https://github.com/reeve25/openai-agents-python/tree/fix/output-guardrail-sibling-results

This report and the fix branch were prepared with Claude Code (claude-fable-5-1); I reviewed the repro, the diff and the test output. Not run: the full test suite or a live model call.
