Description

Actual: With a valid legacy auth.json already present, fresh V2 database bootstrap does not import its OpenAI OAuth credential. A native regression test reads undefined for the credential row. Restarting does not import it either.

Expected: The credential is imported during first initialization and appears among saved accounts. The synthetic test credentials are not expected to authenticate.

Cause: Fresh bootstrap runs schema.up(tx) and records all migration IDs without calling their up functions. Thus the existing legacy credential importer is skipped and then marked complete. A minimal fix is to run that importer's up(tx) immediately after schema.up(tx) in the fresh-bootstrap transaction, before recording migration IDs. The attached candidate patch additionally makes malformed, non-object legacy files non-fatal and includes regression coverage.

On native source commit c1c9a139934a707636e59278e18ef3ec4ac763b9, the tests-only patch reproduced the failure (missing row, exit 1); the full candidate passed all 20 migration tests and bun typecheck in packages/core. The fix was also checked against pinned 2.0.6 source (b084acc55ea2cdb50e9c2ec49a8d9ab3608d43ad): 21 focused migration tests and packages/core typecheck passed. These are local database tests, not a verified live OAuth login, provider request, or token refresh.

This fix helps only databases initialized after the legacy file is in place. Already-initialized databases need a separate safe recovery path; resetting an existing database risks user data. Related discussion: #40920 (closed, unmerged).
