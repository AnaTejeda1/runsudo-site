The issue

View on GitHub

I've seen a lot of user questions about CrawlSpider, most of them caused by its limitations. I'm biased but when asked I awlays reply "please consider not using it". In my experience and opinion, the control flow in a CrawlSpider spider is both confusing by itself and too different from one in a normal spider that it should be only recommended for very basic spiders with no extensibility requirements.

We currently have this text from 2009 in the CrawlSpider doc:

This is the most commonly used spider for crawling regular websites, as it provides a convenient mechanism for following links by defining a set of rules. It may not be the best suited for your particular web sites or project, but it’s generic enough for several cases, so you can start from it and override it as needed for more custom functionality, or just implement your own spider.

As a minimally needed change, I think the first half shouldn't say anything like "the most commonly used" and the second half should more prominently say that you don't need to use CrawlSpider and you should switch to Spider if you run into limitations of CrawlSpider.

I will also agree with any of the more controversial suggestions, from adding "this isn't recommended to use for new code" and up to extracting it into a separate project or even deprecating and removing.
