[Bug]: per-turn-control-2026-07-01 filtered for azure_ai, but Azure AI Foundry supports it — Claude Code fails with "messages.1.output_config: Extra inputs are not permitted"

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches make the identical one-line config change, flipping per-turn-control-2026-07-01 from null to forwarded for azure_ai, and both remove azure_ai from the 'dropped' parametrization. Correctness and scope are therefore equal; the difference is entirely in test coverage. Patch B adds a minimal direct check that update_headers_with_filtered_beta keeps the beta for provider='azure_ai'. It would fail before and pass after, but it only exercises the lookup table. Patch A adds a test that goes through AzureAnthropicMessagesConfig end to end: validate_anthropic_messages_environment, the provider filter, and transform_anthropic_messages_request, with a Claude Code-shaped request body (output_config on a mid-conversation system message). It is parametrized over both the case where the client sends the beta and the case where LiteLLM must add it from the per-message output_config, and it asserts both that the final header set is exactly {per-turn-control, effort} and that the system message's output_config survives in the outgoing body. That directly mirrors reproduction step B in the issue and would catch regressions in the add-beta path or the body transformation that Patch B's test cannot see. A's test relies on an existing _claude_code_turn helper and the Azure config's signatures, which I cannot verify here, so there is some fragility risk, but given the surrounding file already tests output_config-driven beta injection for other providers the helper is very likely present. On the tests criterion A is meaningfully stronger, with no downside on correctness, scope, or craft.

Description

What happened?

Claude Code (v2.1.281) sets per-turn effort by putting output_config on a mid-conversation
role: system message, which requires the per-turn-control-2026-07-01 beta.

#41189 added this beta to the allowlist for anthropic only. For azure_ai it is set to null
in anthropic_beta_headers_config.json (the PR caveat notes azure_ai drops it on purpose).
As a result, every Claude Code turn with effort control fails through the proxy on Azure AI Foundry:

litellm.BadRequestError: Azure_aiException - {"type":"error","error":{"type":"invalid_request_error",
"message":"messages.1.output_config: Extra inputs are not permitted"}}

This breaks effort levels (xhigh / ultracode) for Claude Opus 5.5 on Azure AI Foundry.

Azure AI Foundry does support this beta

Direct call to the Foundry Anthropic endpoint, bypassing LiteLLM, same body
(output_config on a role: system message):

  • WITHOUT anthropic-beta: per-turn-control-2026-07-01 → 400 messages.1.output_config: Extra inputs are not permitted
  • WITH anthropic-beta: per-turn-control-2026-07-01,effort-2025-11-24 → 200, normal assistant message

curl https://<resource>.services.ai.azure.com/anthropic/v1/messages \
-H "x-api-key: ***" -H "anthropic-version: 2023-06-01" -H "Content-Type: application/json" \
-H "anthropic-beta: per-turn-control-2026-07-01,effort-2025-11-24" \
-d '{"model":"claude-opus-5-5","max_tokens":50,"output_config":{"effort":"xhigh"},
"messages":[{"role":"user","content":[{"type":"text","text":"Reply OK"}]},
{"role":"system","content":[{"type":"text","text":"# Environment"}],"output_config":{"effort":"low"}}]}'

Proposed fix

In litellm/anthropic_beta_headers_config.json, section azure_ai:

"per-turn-control-2026-07-01": "per-turn-control-2026-07-01"

and update the provider-filtering test added in #41189 accordingly.

Environment

  • LiteLLM proxy 1.101.0 (Docker), beta headers config fetched from main (no LITELLM_LOCAL_ANTHROPIC_BETA_HEADERS)
  • Model: azure_ai/claude-opus-5-5, api_base on *.services.ai.azure.com
  • Client: Claude Code 2.1.281 (/v1/messages?beta=true)

Workaround

Local copy of the config with the value above, LITELLM_LOCAL_ANTHROPIC_BETA_HEADERS=True.

Config

# Models are managed in the DB via the Admin UI (STORE_MODEL_IN_DB=True).
# Equivalent definition of the affected model:
model_list:
  - model_name: claude-opus-5-5
    litellm_params:
      model: azure_ai/claude-opus-5-5
      api_base: https://<resource>.services.ai.azure.com
      api_key: os.environ/AZURE_AI_API_KEY
      custom_llm_provider: azure_ai

litellm_settings:
  drop_params: true
  success_callback: ["prometheus"]
  failure_callback: ["prometheus"]

  num_retries: 3

  master_key: os.environ/LITELLM_MASTER_KEY
  database_url: os.environ/DATABASE_URL

LiteLLM Version

v1.101.0

Steps to Repro

Steps to Reproduce

A. With Claude Code

  1. Start LiteLLM proxy 1.101.0 with the config above (default beta headers config, fetched from main).
  2. Point Claude Code 2.1.281 at the proxy: ANTHROPIC_BASE_URL=https://<litellm-proxy> ANTHROPIC_AUTH_TOKEN=sk-... claude --model claude-opus-5-5
  3. Set an effort level: /effort xhigh (or ultracode).
  4. Send any prompt, e.g. hello.
  5. Result: API Error: 400 — the proxy log shows Azure_aiException - messages.1.output_config: Extra inputs are not permitted. With CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1 the same prompt succeeds (effort control disabled).

B. With curl, through the proxy (Claude Code-shaped request)

curl -s https://<litellm-proxy>/v1/messages \
-H "Authorization: Bearer sk-..." -H "anthropic-version: 2023-06-01" -H "Content-Type: application/json" \
-H "anthropic-beta: per-turn-control-2026-07-01,effort-2025-11-24" \
-d '{"model":"claude-opus-5-5","max_tokens":50,"output_config":{"effort":"xhigh"},
"messages":[{"role":"user","content":[{"type":"text","text":"Reply OK"}]},
{"role":"system","content":[{"type":"text","text":"# Environment"}],"output_config":{"effort":"low"}}]}'

→ 400 messages.1.output_config: Extra inputs are not permitted
(the proxy drops per-turn-control-2026-07-01 because it is null for azure_ai).

C. Same body, directly to Azure AI Foundry (bypassing LiteLLM)

Same curl against https://<resource>.services.ai.azure.com/anthropic/v1/messages
with x-api-key instead of Authorization:

  • with anthropic-beta: per-turn-control-2026-07-01,effort-2025-11-24 → 200
  • without that header → 400 (same error as B)

Expected

B should return 200, like C with the beta header: LiteLLM should forward
per-turn-control-2026-07-01 for azure_ai.

Actual

LiteLLM filters the beta for azure_ai, so every Claude Code turn with effort control fails.
