Update select parsing to the current HTML Standard

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The production changes in the two patches are nearly identical. Both:
- remove the InSelect and InSelectInTable modes, SelectScopeMember and inSelectScope;
- drop the select case from resetInsertionMode;
- add a select-fragment-context check;
- make input and nested select close an open select in scope;
- make hr generate implied end tags when a select is in scope;
- split option and optgroup handling to follow the current spec;
- add select to InBodyEndClosers.

There are two small code differences:
- For an option or optgroup outside a select, B pops the current option directly with `tb.pop()`. This matches the spec text ("pop the current node") more literally. A routes through `processEndTag("option")`, which behaves the same here.
- For a nested select, A uses `break` and B uses `return false`. Both ignore the token after popping, so the result is equivalent.

Correctness is effectively equal, so tests decide it. A adds three small tests: select content retained, hr closing option and optgroup, and input closing select.

B adds a dedicated SelectParsingTest with broad coverage:
- customizable select content, including button and selectedcontent, with zero errors;
- formatting-element reconstruction;
- textarea and keygen staying inside the select;
- nested select;
- input inside a table within a select not closing the select, since the table is a scope boundary;
- optgroup and option implied-end behaviour;
- options outside a select;
- stray `</select>`;
- select inside table cells and fostered out of a table;
- the select fragment context, both via parseFragment and via `Element.html()`.

B's coverage exercises the edge cases of the scope-based rules and the fragment paths. It also updates the namespace-aware option test rather than just deleting its assertions, and its changelog entry is more informative. On tests and thoroughness, B is the stronger patch.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

jsoup has the former InSelect and InSelectInTable insertion modes.

The current HTML parsing rules handle select content through the in-body insertion mode, including customizable select content.

We should update the tree builder to follow the current rules and retire the obsolete select insertion modes.
