Description

Description
curl -fsSL https://opencode.ai/v2/install | bash fails on a machine where curl is the snap build. The installer creates the staging dir in the host shell (install L309: local tmp_dir="${TMPDIR:-/tmp}/opencode_install_$$"), then hands that path to curl. Confined snaps get a private /tmp bind-mounted over the host one, so curl has no such path, fails with exit 23, and the message added in #59312 tells me to check free space. Nothing was full — this is a mount-namespace mismatch between the process that creates the directory (bash) and the process that writes into it (curl).

Setting TMPDIR=$HOME/tmp makes the same command succeed, so I'd suggest making that the fallback instead of /tmp. #59312 itself documents TMPDIR=~/tmp as the fix, and #55006 / #64031 show /tmp is already a problem area for you — this is the same directory causing a different failure mode.
