The issue

Initial Checks

  • I confirm that I'm using Pydantic V2

Description

ValidateCallWrapper.__call__ is declared as def __call__(self, *args, **kwargs), so the instance is bound to the name self. A decorated function with a keyword parameter literally named self can then never be called with it: f(self=1) raises TypeError: ValidateCallWrapper.__call__() got multiple values for argument 'self' before validation runs. The wrapped function itself is fine with that name; it is only the wrapper's signature that collides. Same in 2.12.5, 2.13.5 and pydantic/_internal/_validate_call.py on main.

Making self positional-only in __call__ (def __call__(self, /, *args, **kwargs)) removes the collision without changing anything else. Can send the PR.

Example Code

import pydantic.version
from pydantic import validate_call


@validate_call
def f(*, self: int) -> int:
    return self


try:
    print("f(self=1) ->", f(self=1))
except TypeError as e:
    print("f(self=1) -> TypeError:", e)
print(pydantic.version.version_info())

The review confirms the fix is correct, minimal, and complete. Done.

Summary

What was wrong: In pydantic/_internal/_validate_call.py, ValidateCallWrapper.__call__ was declared def __call__(self, *args, **kwargs). The instance binds to the name self, so any @validate_call-decorated function with a keyword parameter literally named self could never be called with it — f(self=1) raised TypeError: ValidateCallWrapper.__call__() got multiple values for argument 'self' before validation ever ran.

What I changed:

  • pydantic/_internal/_validate_call.py:133 — made self positional-only: def __call__(self, /, *args, **kwargs). Now a user-supplied self=... flows into **kwargs instead of colliding with the bound instance. Single-character change, exactly as the report proposed.
  • tests/test_validate_call.py — added test_self_keyword_argument (issue #13773) asserting f(self=1) == 1, coercion f(self='2') == 2, and ValidationError on a non-coercible value.

Test evidence:

  • Reproduced the exact reported TypeError before the fix (via .venv/bin/python).
  • The new regression test failed before the production change with the exact reported TypeError, and passes after.
  • Gate: ./bt-test tests/test_validate_call.py → 65 passed (exit 0), including the new test; no previously passing test regressed.
  • Reviewer confirmed the diff matches the report, __call__ is the only affected collision site (the module-level wrapper functions have no self/cls param and just forward kwargs), and nothing unrelated changed.

Requirements disposition:

  1. Fix validate_call so a function with a keyword param named self is callable — implemented, with a regression test seen failing before and passing after.
  2. Report's proposed approach (def __call__(self, /, *args, **kwargs)) — implemented exactly; verified no other collision sites in the file require the same change (evidence: reviewer's read of update_wrapper_attributes and all other methods).

All changes are left uncommitted in the working tree.
