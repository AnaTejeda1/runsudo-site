Daytona extra allows daytona 2.0, which removes the 0.x API DaytonaSandboxClient uses

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches make the identical one-line change to pyproject.toml, capping the extra at `daytona>=0.226.1,<1`, which is exactly the fix the issue requests and addresses the root cause (the extra resolving to the 2.x SDK whose root package no longer exposes the 0.x symbols the client imports). Lockfile changes were stripped from both diffs, so neither can be judged on uv.lock. On correctness and scope they are equal.

The difference is tests. Patch B adds none. Patch A adds two: one parses pyproject.toml, extracts the daytona specifier, and asserts that 0.226.1 satisfies it while 1.0.0 and 2.0.0 do not. This test would fail on the pre-patch specifier (`>=0.226.1` admits 2.0.0) and pass after, so it is a genuine regression guard against someone dropping the cap. The second test asserts the uv.lock requires-dist entry matches the pyproject specifier, guarding against the pyproject/lock drift the issue implicitly cares about.

Craft caveats on A: it hand-rolls a PEP 440-ish comparator (~40 lines) instead of using `packaging.specifiers.SpecifierSet`, relies on `tomli` on Python <3.11 and on `Path`, `Any`, and `sys` already being imported in the test module (no import changes appear in the diff), and the uv.lock test is somewhat coupled to uv's lock format. These are mild risks and some over-engineering, but they do not negate the value of having a test that actually fails before and passes after. Since the fixes are otherwise identical, the presence of a meaningful regression test tips it to A.

Describe the bug

The daytona extra requires daytona>=0.226.1 with no upper bound. Daytona SDK 2.0 keeps only the clients, DaytonaConfig and the errors at the daytona package root and moves the 0.x API to daytona.v0. agents/extensions/sandbox/daytona/sandbox.py imports CreateSandboxFromImageParams, CreateSandboxFromSnapshotParams, SandboxState, Resources, SessionExecuteRequest and daytona.common.pty from the root. On 2.x, DaytonaSandboxClient() raises the "requires the optional daytona dependency" error even though the extra is installed, and reinstalling the extra gets 2.x again.

2.0.0 was briefly the default install on 2026-11-13. Daytona pulled it back (yanked on PyPI) and plans to make it the default again next week. After that, a fresh pip install "openai-agents[daytona]" gets 2.0.0.

Expected behavior
