The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Patch A fixes the root cause; Patch B only masks the two visible symptoms. The reported issue has three intertwined manifestations of one underlying problem: model_rebuild() is not thread-safe — it mutates class attributes (delattr/setattr of __pydantic_core_schema__/__pydantic_validator__/__pydantic_serializer__) while other threads read those same attributes and iterate vars(cls) during annotation evaluation. This yields (1) 'dictionary changed size during iteration', (2) the intermittent 'no attribute __pydantic_core_schema__' AttributeError, and (3) the noted data-corruption risk of a parent's validator being reused. Patch A introduces a global reentrant lock serializing all rebuilds, so no thread mutates the class __dict__ while another rebuild reads/iterates it — closing all three at their source. The reentrancy (nested rebuild during generic parametrization in __class_getitem__) and global-not-per-class rationale (to avoid deadlock) are correctly reasoned, and the double-checked-locking with an unlocked fast-path plus in-lock recheck is careful and correct. It also adds MockCoreSchema to the mock check and mirrors the guard in dataclasses.py for consistency. Patch B (a) snapshots vars(typ).copy() to dodge the iteration error and (b) wraps delattr in try/except AttributeError — but leaves the fundamental non-thread-safety intact: two threads can still run complete_model_class concurrently, racing on setattr of the validator/serializer, so an instantiating thread can still observe a half-built or parent validator. It patches symptoms 1 and 2 while symptom 3 (which the existing in-code comment already flags) persists. On tests, A's are decisively stronger: a deterministic event-coordinated two-thread test that proves the lock serializes and that the waiting thread returns None without re-firing the on_complete hook, plus a reentrancy regression test — versus B's stochastic 15-second hammer loop whose passing is probabilistic and weakly diagnostic. A's method re-indentation adds churn, but it is inherent to wrapping the body in a `with` block and is justified. Correctness, tests, and craft all favor A.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

NOTE: Repro script generated with Claude Fable

Repro: concurrent lazy `model_rebuild()` raises
`RuntimeError: dictionary changed size during iteration`.

Setup: a module using `from __future__ import annotations` defines models whose
field types are only defined *later* in the same module. Building such a model's
schema fails during class creation, so pydantic leaves it incomplete (mock
validator) and defers the build to the first instantiation via
`model_rebuild(raise_errors=False)`.

If the first instantiations happen concurrently (e.g. FastAPI's threadpool
serving the first requests after process start), multiple threads enter
`model_rebuild()` for the same class simultaneously. `model_rebuild()` mutates
the class `__dict__` (delattr/setattr of `__pydantic_core_schema__`,
`__pydantic_validator__`, `__pydantic_serializer__`), while
`NsResolver.types_namespace` includes the live `vars(cls)` of that class in the
`LazyLocalNamespace` another thread is iterating during annotation evaluation
(`LazyLocalNamespace.data`). Result:

    RuntimeError: dictionary changed size during iteration

The same race also intermittently produces
    AttributeError: type object 'Box0' has no attribute '__pydantic_core_schema__'
from the delattr block at the top of `model_rebuild()`.

Each round executes the module source into a fresh module (fresh, incomplete
classes -- like a freshly started process) and races threads instantiating the
models. Typically fires within a few dozen rounds (< 1 min).

Run: python pydantic_rebuild_race_repro.py
"""

import sys
import threading
import time
import traceback
import types

import pydantic

print(f"python {sys.version}")
print(f"pydantic {pydantic.VERSION}")

sys.setswitchinterval(1e-5)  # more frequent thread preemption; widens the race window

N_LEAVES = 16  # leaf models, defined at the end of the module so everything before stays incomplete
N_MODELS = 4  # top-level models, the ones instantiated by the racing threads
N_METHODS = 60  # dummy methods to enlarge each class __dict__ (the dict iterated during annotation eval)
N_THREADS = 32
ROUNDS = 200
RACE_WINDOW_S = 0.5


def make_module_source() -> str:
    boxes = " | ".join(f"Box{g}[Leaf{l}]" for g in range(N_GENERICS) for l in range(N_LEAVES))

    # so their schema build is deferred until first instantiation.

    for l in range(N_LEAVES):
        lines += [f"class Leaf{l}(BaseModel):", "    x: int = 0", ""]
    return "\n".join(lines)


MODULE_SOURCE = make_module_source()

errors: list[str] = []
errors_lock = threading.Lock()


def worker(barrier: threading.Barrier, model: type) -> None:
    barrier.wait()
    end = time.monotonic() + RACE_WINDOW_S
    while time.monotonic() < end:
        try:
            model()  # first call hits the mock validator -> lazy model_rebuild()
        except Exception:
            with errors_lock:
                errors.append(traceback.format_exc())

    mod = types.ModuleType(f"repro_generated_{rnd}")

    for t in threads:
        t.start()
    for t in threads:
        t.join()

    hits = [tb for tb in errors if "changed size during iteration" in tb]
    if hits:
        print(hits[0], file=sys.stderr)
        print(f"REPRODUCED in round {rnd}: RuntimeError: dictionary changed size during iteration")
        sys.exit(1)

        first_line = errors[0].strip().splitlines()[-1]

Concurrent lazy model_rebuild() of the same incomplete model raced against itself:

  1. NsResolver.types_namespace (pydantic/_internal/_namespace_utils.py:276) stored the live vars(typ) mappingproxy in LazyLocalNamespace. LazyLocalNamespace.data iterates it lazily via ns.items(), while another thread's model_rebuild() mutated the same class __dict__ (delattr/setattr of __pydantic_*__) → RuntimeError: dictionary changed size during iteration.
  2. The report's secondary symptom: model_rebuild at pydantic/main.py:696 did delattr(cls, attr) after an attr in cls.__dict__ check; a concurrent rebuild removing the attribute in between raised AttributeError: ... has no attribute '__pydantic_core_schema__'.

What I changed

  • pydantic/_internal/_namespace_utils.py: append vars(typ).copy() instead of the live mappingproxy. mappingproxy.copy() delegates to dict.copy — a single GIL-held C operation — so it yields an atomic, stable snapshot. Only pydantic-internal attributes are mutated during rebuild, none needed for annotation evaluation, so snapshotting is semantically safe.
  • pydantic/main.py: wrapped the guarded delattr(cls, attr) in try/except AttributeError: pass to tolerate a concurrent rebuild having already removed the attribute. The pre-existing if attr in cls.__dict__ guard means the only path to that AttributeError is the race, so no legitimate error is swallowed.
  • tests/test_edge_cases.py: added test_concurrent_lazy_model_rebuild_no_dict_mutation_error, a threaded regression test modeled on the report's reproducer (fresh incomplete models exec'd per round, 24 threads on a barrier, setswitchinterval(1e-5)), asserting no "changed size during iteration" RuntimeError and no spurious __pydantic_core_schema__ AttributeError.

Test evidence
