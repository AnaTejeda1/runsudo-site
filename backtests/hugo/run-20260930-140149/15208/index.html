What the agent reported

I added resources.Publish, so {{ resources.Get "main.js" | js.Build | resources.Publish }} now works and returns the same resource it was given. The new test passes, but ./bt-test could not build the package in this container: it tries to download Go modules and the container has no DNS (lookup proxy.golang.org ... server misbehaving, "setup failed"). All results below come from go test run against the offline module cache at /bt/cache/go-mod instead.

What was wrong: the resources template namespace had no Publish function. The only way to publish a resource was to call its .Publish method, which can't go at the end of a pipe.

What I changed:

  • tpl/resources/resources.go: new Namespace.Publish(r resource.Resource) (resource.Resource, error). It calls the resource's own Publish() and returns the resource unchanged. It works for plain assets, images and transformed resources (js.Build, minify, and so on). Anything that can't be published, including nil (for example when resources.Get finds nothing), gets an error saying so.
  • tpl/resources/init.go: registers ctx.Publish, with no alias, so a bare publish isn't confused with the method.
  • docs/content/en/functions/resources/Publish.md: a new docs page in the same format as Minify.md. I did not edit docs/data/docs.yaml, because it is generated from the Go source by hugo gen docshelper.
  • tpl/resources/resources_integration_test.go: new TestPublish. Each case publishes a resource without ever using its permalink, then checks both the rendered output and which files land in public/:
  • the exact case from the report, resources.Get "js/built.js" | js.Build | resources.Publish, which should write public/js/built.js;
  • a plain asset;
  • a resources.FromString resource;
  • a minify pipeline, which should write other.min.js and not other.js;
  • a resource that is fetched but never published, which must not appear in public/.

Test evidence:

  • Before the change: TestPublish fails with can't evaluate field Publish in type interface {}. I checked this by stashing the two production files and rerunning.
  • After the change: TestPublish passes, and the whole ./tpl/resources/ package passes, including TestCopy and TestCopyPageShouldFail. ./tpl/internal/... passes, and go vet and gofmt are clean.
  • ./tpl/tplimpl/: only TestVimeoShortcode fails, and it fails the same way with and without my change, so it is unrelated.
  • Test fix: the test-writer's first draft expected resource names without a leading slash. Hugo renders them as /js/main.js, so I corrected those strings in the new test before it passed. No existing test was changed.

Requirements:

  1. Pipeable resources.Publish: done, and tested with the report's exact js.Build pipeline.
  2. Returns the input resource: done. The test checks the returned value's Name, MediaType and Content.
  3. It actually publishes, with no .RelPermalink or .Publish call: done. The test checks the files in public/ and confirms an unpublished resource is not written.

A reviewer checked the final diff against the report and found nothing blocking and no unrelated changes. AGENTS.md and CLAUDE.md were already deleted before I started, and I left them alone. Everything is uncommitted in the working tree.
