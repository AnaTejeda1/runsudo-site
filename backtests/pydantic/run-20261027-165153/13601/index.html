model_dump(exclude=...) is silently ignored in python mode when a wrap model_serializer is gated with when_used="json"

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the same root cause in the same place: when the serializer function is gated off (when_used='json' in python mode), the fallback serializer was wrapped in a scoped empty IncludeExclude, so caller include/exclude was discarded. Both now forward the caller's include/exclude to the fallback path and only clear it when the function actually ran; independent tests pass equally for both across json and json-unless-none, include and exclude, nested and ungated comparisons. The difference is in tests and craft. Patch B's tests are considerably more thorough: it adds a parametrized pydantic-core test (plain and wrap, json and json-unless-none) at the layer where the fix lives, plus pydantic-level tests for wrap, plain, and nested Annotated serializers with nested include/exclude, and checks model_dump_json too. Patch A adds a single test covering plain and wrap with when_used='json' only, with no nested or json-unless-none coverage and nothing in pydantic-core's own suite. On craft, A adds a new public accessor that clones the IncludeExclude on every fallback call and rebuilds a scoped state unnecessarily; B passes the existing state straight through to the fallback and scopes only in the function-used branch, which is clearer about intent and avoids the needless clone, at the cost of some verbosity. Neither patch adds unrelated churn. B is the better fix on tests and marginally on craft.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

When a model declares @model_serializer(mode="wrap") with when_used="json" (or "json-unless-none"), the runtime exclude argument passed to model_dump() is silently ignored in python mode. The same call in JSON mode behaves correctly.

Expected: model_dump(exclude={"b"}) omits b regardless of when_used, since the gate concerns which serializer runs and not which fields the caller asked to drop.

Actual: b is present in python mode.

Example Code

from pydantic import BaseModel, SerializerFunctionWrapHandler, model_serializer


class Gated(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap", when_used="json")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


class Always(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


  # Gated to JSON: python mode ignores exclude.
  print(Gated(a=1, b=2).model_dump(exclude={"b"}))               # {'a': 1, 'b': 2}  <-- expected {'a': 1}
  print(Gated(a=1, b=2).model_dump(mode="json", exclude={"b"}))  # {'a': 1}          <-- correct

  # Identical model without the gate: python mode honours exclude.
  print(Always(a=1, b=2).model_dump(exclude={"b"}))              # {'a': 1}

  Output:

  gated  python: {'a': 1, 'b': 2}
  gated  json  : {'a': 1}
  always python: {'a': 1}
