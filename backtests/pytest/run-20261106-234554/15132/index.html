B's incidental doc change to `minversion = "3.0"` is unrelated churn, though harmless and arguably a correction. A's AUTHORS edit is neutral. Overall B delivers the same fix with meaningfully stronger regression coverage and kept documentation consistent, so B is the better patch.

The issue

View on GitHub

Summary

faulthandler_timeout rejects native numeric values in TOML configuration, even though the option is documented as a float and the TOML examples use a number.

Reproduction

On pytest main at f5240bef4, with Python 3.12 on Windows:

[pytest]
faulthandler_timeout = 5

Running a test produces:

ERROR: pytest.toml: config option 'faulthandler_timeout' expects a string, got int: 5

The same option works when configured through INI-style configuration or as a quoted TOML string.

Expected behavior

Native TOML integers and floats should be accepted for this float-valued option, consistent with the documentation and the other typed TOML options.

I have a small local fix and regression test ready for review.
