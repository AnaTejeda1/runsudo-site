Describe the enhancement you want to request

Expose Claude Agent plan usage to plugins.

Claude Code sends a rate_limit_event SDK message with utilization and reset times for the 5-hour and weekly windows. The Claude Agent provider only uses it to word limit errors in claude-agent-error.ts, and plugins never see it.

Today a plugin that shows Claude subscription usage has to poll api.anthropic.com/api/oauth/usage, which is rate limited, and read Claude Code's OAuth token to do it. The provider's design says OpenCode never reads those tokens. ChatGPT sign-ins don't have this problem: the backend streams a codex.rate_limits frame with each response, which plugins can read through the experimental.ws.receive hook.

Proposal: attach the latest rate_limit_info to the step's finish provider metadata, so it shows up as native.rateLimit on session.step.ended. That uses the existing event and needs no new API. I have a small PR ready.
