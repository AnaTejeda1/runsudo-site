Defer formatting discarded errors during nested union serialization

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches stop the eager formatting: all four independent repr-count tests go from FAIL-ASSERT on base to PASS on both, and the final warning/error text is unchanged for both. The decisive difference is the observable exception protocol the issue explicitly calls out. Patch A builds the aggregate as a lazy PyErr whose args materialize to the same (message, None, None, None) tuple as the eager path, so a wrap serializer that catches it sees an identical exception; the independent test for this passes on A. Patch B constructs the exception via Bound::new, which bypasses BaseException.__init__ and leaves .args == (), exactly the regression the issue warned about, and the independent test confirms FAIL-ASSERT on B. B tries to paper over this with a custom __reduce__ for pickling, but that does not restore .args for user code, and it adds a new message enum, Python::attach inside to_py_err, and __traverse__ complexity to the exception type. A's approach keeps the child errors only in Rust until normalization, so no GC traversal changes are needed, and A's tests cover the repr count, warnings-disabled path, and the wrap-serializer args/repr invariants directly. A's one risk is the early Ok(None) return in TaggedUnionSerializer when warnings are disabled, which could skip whatever the non-UnexpectedValue else branch does, but that is narrower than B's confirmed args regression. A better satisfies correctness as the issue defines it, has stronger tests, and is the smaller, less invasive change.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

This issue was posted by Codex Desktop using gpt-6.1-sol on behalf of David.

Serializing a valid dataclass subclass through str | list[str | Content] calls its __repr__ twice, although serialization succeeds without warnings. This becomes expensive when the representation includes large byte payloads.

Reproduced on Pydantic 2.13.5 / pydantic-core 2.46.5 and current Pydantic main 37dc34b4f001191b4f3db707cc52bac95baf17f0 (2.15.0a0+dev / core 2.50.0).

<details>
<summary>Minimal reproduction</summary>

from pydantic import TypeAdapter
from pydantic.dataclasses import dataclass

calls = []

@dataclass
class Content:
    data: bytes

@dataclass
class Image(Content):
    def __repr__(self):
        calls.append(1)
        return f'Image(data={self.data!r})'

value = [Image(data=b'abc')]
adapter = TypeAdapter(str | list[str | Content])
print(adapter.dump_json(value, warnings='error'))
print(len(calls))
# b'[{"data":"abc"}]'
# 2

The same case calls repr zero times when the annotation is list[str | Content], without the outer union. dump_python also reproduces the eager calls.

</details>

The nested union fails its strict pass because the value is a subclass. UnionChoices::serialize calls union_serialization_unexpected_value, which immediately joins the child exceptions with ToString::to_string. The outer union then succeeds during its lax pass and discards those formatted errors.

Affected source: union.rs at the tested commit.

pydantic-core #1652 deferred formatting individual unexpected values, but the nested aggregate still formats eagerly. pydantic-core #1649 describes the earlier case.

A local prototype retaining child exceptions until __str__ removes the unnecessary calls without changing strict/lax branch selection. It also removes five repr calls in the downstream Pydantic AI #11138 example. Output, final warning/error text, filtering, and metadata serializer counts match the unmodified upstream build in the executed probes.

The prototype is not ready for a PR: a wrap serializer can catch an intermediate aggregate, so its exception protocol needs care. Constructing that aggregate directly currently changes .args from (message, None, None, None) to (). Retained exceptions also need correct GC traversal. The intended fix is lazy formatting while preserving those observable details.
