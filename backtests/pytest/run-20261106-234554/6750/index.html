compat::getfuncargnames removes self from instance method twice by mistake

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches make the same root-cause change: skip stripping the first argument name when `inspect.ismethod(function)` is true, since a bound method's signature has already dropped self/cls. Placement differs (A checks it first, B inside the `cls and ...` branch) but they are behaviourally equivalent, and the independent tests confirm both fix every issue scenario. The differences are in tests and craft. Patch A adds a direct unit test of `getfuncargnames` with bound instance methods, a bound classmethod, and an unbound function with `cls` given, which exercises exactly the claim in the issue (the function strips self twice), plus a pytester integration test that covers both the `callobj` and no-`callobj` paths through a custom collector. Patch B adds a single pytester integration test that covers more method kinds (positional-only receiver, keyword-only fixture, classmethod, staticmethod), which is good coverage, but it does not test `getfuncargnames` itself. Patch A also explains the new condition with an inline comment in the style of the surrounding code. Patch B's changelog and AUTHORS entries follow pytest's PR conventions and are a genuine plus, but they do not outweigh A's more targeted unit test and clearer code comment. Neither has unrelated churn. A is modestly better.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.
