Cannot create defauldict field with dict value type

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause the same way: they add `dict: dict` (and `frozenset: frozenset`) to the allowed default-factory mapping, so `defaultdict[str, dict]` now infers `dict` as its factory.

Patch B does only that. Its tests cover the issue directly:
- A parametrized test over bare and parametrized `dict` and `frozenset`. It checks that `default_factory` is the expected type, that missing keys return the empty container, and that values are coerced to the right type.
- A test that reproduces the issue's exact `BaseModel` with `prop: defaultdict[str, dict] = defaultdict(dict)`, including mutation of a missing key.

These tests fail before the change and pass after it.

Patch A makes the same core fix but adds churn and risk:
- It moves the table to module level.
- It adds a Python ≥3.15 branch that remaps `collections.abc.Mapping` from `dict` to `frozendict`. This is a silent behavior change for existing `defaultdict[..., Mapping]` users on 3.15, unrelated to the issue. It also refers to a bare `frozendict` name with `noqa: F821`.
- It changes the error message wording from "keys" to "values". This is a reasonable correction but out of scope.
- It rewrites the existing infer-default test into a parametrized one. That test is adequate but does not exercise the issue's model scenario or parametrized `dict[str, X]`.

On correctness both resolve the issue. B's tests are more targeted, and A's extra Mapping→frozendict remap adds regression risk without being asked for. B is the cleaner, safer fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

For now it's impossible to create a model with defaultdict(dict) value.
It's possible to create with Mapping and MutableMapping types, then why not add the basic simple type dict? Other basic types are allowed too.

The corresponding code is located here.

Example Code

from collections import defaultdict
from pydantic import BaseModel

class Test(BaseModel):
    prop: defaultdict[str, dict] = defaultdict(dict)
# ...
# pydantic.errors.PydanticSchemaGenerationError: Unable to infer a default factory for keys of type <class 'dict'>. Only float, frozenset, int, dict, str, set, list, tuple, bool are supported, other types require an explicit default factory set using `DefaultDict[..., Annotated[..., Field(default_factory=...)]]`
