Initial Checks

  • I confirm that I'm using Pydantic V2

Description

Validating a ZoneInfo field with certain invalid strings raises a raw OSError subclass instead of a ValidationError:

  • A tz database directory name such as 'America', 'Europe' or 'Etc' raises IsADirectoryError on Python 3.10–3.12 when the tzdata package is installed (tzdata is a pydantic dependency on Windows and is also pulled in by e.g. pandas). CPython only started converting this case to ZoneInfoNotFoundError in 3.13 (gh-85702).
  • An over-long key (e.g. 300 characters) raises OSError: [Errno 63] File name too long (reproduced on Python 3.12 with tzdata, and on Python 3.13 on macOS without it).

validate_str_is_valid_iana_tz in pydantic/_internal/_validators.py only catches (ZoneInfoNotFoundError, ValueError, TypeError), so these errors propagate unchanged. Expected: a zoneinfo_str validation error, the same as for 'Not/AZone'. For example, in a web API that validates a user-supplied timezone, these inputs currently produce an unhandled exception instead of a validation error.

Suggested fix: add OSError to the caught exceptions. I have a small patch with a regression test ready if this is welcome.

Example Code

from zoneinfo import ZoneInfo
from pydantic import BaseModel

class Model(BaseModel):
    tz: ZoneInfo

Model(tz='Not/AZone')  # ValidationError (expected)
Model(tz='America')    # IsADirectoryError: [Errno 21] Is a directory: '.../site-packages/tzdata/zoneinfo/America'
Model(tz='a' * 300)    # OSError: [Errno 63] File name too long: '...'
