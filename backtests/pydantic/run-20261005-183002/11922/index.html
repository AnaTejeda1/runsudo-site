Some Field attributes lost in JSON schema when using RootModel

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the core issue the same way: they copy `examples` (made JSON-able) and `deprecated` from the RootModel's `root` FieldInfo into the model-level schema. They also both keep `model_config['title']` ahead of the field title. The deciding difference is title handling. Patch A falls back to `cls.__pydantic_fields__['root'].title` whenever no title has been set, but `FieldInfo.title` can be filled in by a `field_title_generator`, either from config or on the Field. With such a generator, Patch A would rename the model schema to the generated field title (e.g. 'ROOT') instead of the class name, which is a regression for users who set `field_title_generator`. Patch B guards against this by only using an explicitly set title (`_attributes_set.get('title')`), and it adds a test for exactly this case covering both config-level and field-level generators. Patch B also places the explicit root title ahead of `model_title_generator`, which fits the issue's complaint that the field title is overwritten. Patch B also handles `deprecated=''` (an empty message), consolidates the RootModel detection into a single `root_field` variable reused for description, examples, deprecated and `json_schema_extra`, and avoids repeated `issubclass` checks. Its tests are broader and would fail before the change: a deprecation message, serialization mode, a generic `RootModel[Annotated[...]]`, a nested RootModel in `$defs`, config precedence, and the title-generator case. Patch A's tests cover the basic cases but miss the title-generator interaction its own change breaks. B is more correct and better tested.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

When declaring a RootModel and adding a Field annotation to the root property that includes examples, those examples are not part of the generated JSON schema. This also applies to the deprecated attribute. The title attribute is also not applied or it is overwritten by the class name of the root model class.

Most other attributes, such as pattern or description are exposed as expected. Furthermore, placing examples in json_schema_extra also works as expected.

Example Code

from typing import Annotated
from pydantic import RootModel, Field

class Foo(RootModel):
    root: Annotated[str, Field(examples=["foo", "bar"], deprecated=True)]

print(Foo.model_json_schema())  # does not include examples or deprecated.
