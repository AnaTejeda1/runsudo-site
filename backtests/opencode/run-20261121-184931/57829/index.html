[FEATURE]: regression test for agent files created after startup

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches add the requested 'agent file created after startup' case to config/agent.test.ts, and both exercise the real plugin reload path (write file, emit change, wait for reload, assert the agent is loaded), so neither is tautological. Patch A covers the harder and more realistic shape: the source directory itself does not exist at startup, parametrized over all four agent source directories (agent/agents/mode/modes) with the mode-directory default asserted. It also delivers the issue's explicit suggestion of symmetry by adding the same case to command.test.ts, and adds a live-watcher integration test in reload.test.ts for both existing and newly created .opencode directories, which is closest to the end-to-end regression the issue references. Its helpers (host, agentHost, advance, directoryEntry, tmpdir, fs, path) are the ones already used by the surrounding tests, and the reload-counter wrapper is a straightforward way to synchronize. Patch B is narrower: one test, directory pre-created before startup, so it only covers the easier 'file appears in a watched directory' case. It also introduces Bus.Service, Stream, and Fiber usage without adding imports; if those are not already imported in agent.test.ts the test would not compile, and the Fiber.join after advance(() => updated >= 1) is redundant. Patch B's Stream.take(1) subscription is also slightly fragile if an unrelated Agent.Event.Updated fires first. The extra scope in A is exactly what the issue asked to consider, and it does not obscure the core test, so it is not held against it. A is the better regression guard.

Describe the enhancement you want to request

Every config plugin has a regression test for "a source file appears (or changes) after startup, and the plugin rebuilds" — command.test.ts has "rebuilds commands when a source file is created/updated/renamed", reload.test.ts has "loads skills when {root} appears after startup", and policy.test.ts, model.test.ts, shell.test.ts, image.test.ts, compaction.test.ts, snapshot.test.ts, websearch.test.ts and tool-output.test.ts all have a reload case.

config/agent.test.ts has none. The agent plugin's only reload case is "ignores updates outside agent source directories", where the file already exists on disk before the change is emitted. Nothing covers the case where the agent file is created after the plugin has loaded — which is exactly the shape of #57138.

The behaviour itself looks correct: I added loads an agent file created after startup to packages/core/test/config/agent.test.ts and it passes. So this is a guard against the regression, not a bug report — and it would have caught #57138 at the plugin layer if that layer were the one at fault.

Suggested change: keep the new case in config/agent.test.ts, and consider adding the same "created" case to the other config plugins for symmetry.
