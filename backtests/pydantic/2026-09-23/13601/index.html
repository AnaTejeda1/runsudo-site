Both patches identify the same root cause correctly: the function serializer unconditionally scoped include/exclude to empty before delegating, which is only valid when the serializer *function actually ran* (and did the filtering itself). Both fixes distinguish the ran/not-ran branches and let the fallback see include/exclude, so correctness is a tie — both resolve the issue at root and hold under the described scenarios (python vs json mode, exclude and include). Patch B instead splits every one of the three serializer methods into duplicated if/else branches where the else arm repeats the entire serializer call verbatim (including the multi-line json_key map chain). That duplication, repeated three times, is noticeably harder to read and maintain and offers no functional advantage over A (A's scope-to-current-value is equivalent to B's pass-through). A's approach is the smaller, cleaner correct fix, so A wins.

Description

When a model declares @model_serializer(mode="wrap") with when_used="json" (or "json-unless-none"), the runtime exclude argument passed to model_dump() is silently ignored in python mode. The same call in JSON mode behaves correctly.

Expected: model_dump(exclude={"b"}) omits b regardless of when_used, since the gate concerns which serializer runs and not which fields the caller asked to drop.

Actual: b is present in python mode.

Example Code

from pydantic import BaseModel, SerializerFunctionWrapHandler, model_serializer


class Gated(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap", when_used="json")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


class Always(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


  # Gated to JSON: python mode ignores exclude.
  print(Gated(a=1, b=2).model_dump(exclude={"b"}))               # {'a': 1, 'b': 2}  <-- expected {'a': 1}
  print(Gated(a=1, b=2).model_dump(mode="json", exclude={"b"}))  # {'a': 1}          <-- correct

  # Identical model without the gate: python mode honours exclude.
  print(Always(a=1, b=2).model_dump(exclude={"b"}))              # {'a': 1}

  Output:

  gated  python: {'a': 1, 'b': 2}
  gated  json  : {'a': 1}
  always python: {'a': 1}

What the agent reported

The fix is complete and verified. Here's my final report.

Summary

What was wrong: In pydantic-core's function_type_serializer! macro (pydantic-core/src/serializers/type_serializers/function.rs), all three serialization methods (to_python, json_key, serde_serialize) unconditionally cleared the runtime include/exclude via scoped_include_exclude(IncludeExclude::empty()) before delegating to the chosen serializer. That is only correct when the user's serializer function actually ran (the gate-on branch), because it already applied filtering (a wrap serializer via its handler). When a @model_serializer(mode="wrap", when_used="json"/"json-unless-none") runs in python mode, the gate is off, so call() returns the original, unfiltered value and delegates to the fallback (inner model) serializer — but the caller's exclude= had already been wiped, so it was silently dropped. JSON mode worked because the gate is on there.

What I changed: Threaded a used boolean out of the self.call(...) match in each of the three methods. Only the gate-on branch (used == true) clears include/exclude; the gate-off/fallback branch passes the original state through unchanged so the fallback serializer honors the runtime exclude. Minimal, applied identically across all three methods. Only function.rs (fix) and tests/test_serialize.py (tests) changed.

Test evidence:

  • Two regression tests added after test_model_serializer_wrap_info: test_model_serializer_wrap_when_used_json_exclude and test_model_serializer_wrap_when_used_json_unless_none_exclude.
  • Before the fix: both failed on model_dump(exclude={'b'}) == {'a': 1} (got {'a': 1, 'b': 2}).
  • After the fix (fresh container, full file): 92 passed, 1 skipped for tests/test_serialize.py, including the two new tests and the existing test_model_serializer_wrap / _wrap_info.

Build note: ./bt-test runs uv run --no-sync, which does not rebuild the Rust extension. The fix takes effect via maturin develop into the workspace-mounted .venv (the built .so lives at pydantic-core/python/pydantic_core/*.so, inside the mount), so it persists across fresh --rm containers — confirmed by my final full-file gate run passing in a new container.

Blast radius: The macro is shared by plain and wrap, field- and model-level function serializers gated by when_used. The gate-off branch always carries the unfiltered original value (user function never ran), so filtering is now applied exactly once — no double-filtering. This also fixes the same latent bug for gated field serializers with nested include/exclude. Gate-on behavior is unchanged. Full test_serialize.py (93 tests) passes.
