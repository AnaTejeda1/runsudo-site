Consider bumping mainImageVersionNumber

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches invalidate cached outputs of `.Filter` by changing how the filter cache key is computed. Previously `confMain.Key = hashing.HashString(gfilters)` ignored every version number, so even bumping `mainImageVersionNumber` would not have invalidated filtered images. Both patches close that gap, which is the root cause of the issue's concern.

**Patch B**
- Adds a dedicated `filterVersionNumber = 1` with a comment citing the two fixes.
- Adds a small `FilterKey` helper that hashes the filters together with `mainImageVersionNumber` and `filterVersionNumber`.
- This invalidates exactly the outputs affected by the cited fixes, which are filter behavior on transparent colors and paletted images and palette preservation for filter chains.
- Adds a meaningful unit test, `TestFilterKeyVersionNumbers`. It checks that the key is stable, that different filters give different keys, and that bumping either version number changes keys, including for option-less filters like Grayscale.
- Updated test hashes are limited to filter-related outputs.

**Patch A**
- Exports `mainImageVersionNumber` and `formatVersionNumbers`, an unnecessary public API change.
- Adds `PNG: 1` to the format versions. That invalidates every PNG output, including plain resizes unrelated to filters, which is a blunter tool than needed.
- Folds the target format version into the filter key, so png and webp filter outputs now get different hashes for no stated reason.
- Carries a large amount of unrelated formatting churn: reflowed `AssertFileContent` calls in several test files. This obscures the real change.
- Adds no new test. It only updates expected hashes, which would pass whatever the key composition is.

**Verdict:** B is the more targeted, cleaner and better-tested fix that follows existing conventions (a finer-grained version counter, like `smartCropVersionNumber` and the format version numbers).

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
