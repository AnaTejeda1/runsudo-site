Initial Checks

  • I confirm that I'm using Pydantic V2

Description

ValidateCallWrapper.__call__ is declared as def __call__(self, *args, **kwargs), so the instance is bound to the name self. A decorated function with a keyword parameter literally named self can then never be called with it: f(self=1) raises TypeError: ValidateCallWrapper.__call__() got multiple values for argument 'self' before validation runs. The wrapped function itself is fine with that name; it is only the wrapper's signature that collides. Same in 2.12.5, 2.13.5 and pydantic/_internal/_validate_call.py on main.

Making self positional-only in __call__ (def __call__(self, /, *args, **kwargs)) removes the collision without changing anything else. Can send the PR.

Example Code

import pydantic.version
from pydantic import validate_call


@validate_call
def f(*, self: int) -> int:
    return self


try:
    print("f(self=1) ->", f(self=1))
except TypeError as e:
    print("f(self=1) -> TypeError:", e)
print(pydantic.version.version_info())

What the agent reported

The fix is complete and verified.

Summary

What was wrong: ValidateCallWrapper.__call__ was declared as def __call__(self, *args, **kwargs), binding the wrapper instance to the name self. A @validate_call-decorated function with a keyword-only parameter literally named self could never be called with it — f(self=1) raised TypeError: ValidateCallWrapper.__call__() got multiple values for argument 'self' before validation ever ran. The wrapped function itself is fine with that name; only the wrapper's signature collided.

What I changed:

  • pydantic/_internal/_validate_call.py (line 133): made self positional-only — def __call__(self, /, *args: Any, **kwargs: Any) -> Any:. Now self=... flows through **kwargs to the wrapped function instead of colliding. The second wrapping layer (wrapper_function) already used only *args, **kwargs, so no other change was needed.
  • tests/test_validate_call.py: added regression test test_kwarg_named_self decorating def f(*, self: int) and asserting f(self=1) == 1 plus f(self='1') == 1 (coercion).

Test evidence:

  • Before the fix, the new test failed with the exact reported TypeError at _validate_call.py:40.
  • After the fix, the full tests/test_validate_call.py suite passed: 65 passed (including the new test; all previously-passing tests still green).
  • Reviewer confirmed the diff is minimal and scoped to exactly the reported problem, with no unrelated or scratch-file changes.

Requirements disposition:

  1. Fix validate_call so a keyword parameter named self is callable (report's proposed self, / approach) — implemented, with passing regression test and full-suite gate.
