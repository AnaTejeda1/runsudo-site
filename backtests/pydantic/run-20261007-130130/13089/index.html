Decimal JSON schema pattern rejects pydantic's own scientific notation serialization output (v2.12 regression)

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches stop pydantic's own serialized `Decimal` output (e.g. `'1E-7'`) from being rejected by the generated schema. They differ in how.

**Patch B** keeps the existing feature (a pattern is always emitted) and fixes it where it breaks, as the issue itself suggests.
- The unconstrained pattern gains an optional exponent group, and its lookahead is adjusted so strings like `'e5'` or `'.e5'` are still rejected.
- When `max_digits` or `decimal_places` is set, it adds scientific-notation alternatives. Each exponent is enumerated within the bounds the constraints allow, and the digit counting holds up when checked: e.g. `1.2E-7` with `decimal_places=8`, and positive exponents bounded by the number of whole digits.
- It also fixes a latent anchoring bug: the first alternative previously lacked a `$`, so `re.search` would accept too many integer digits.
- Its tests are end to end: they serialize real `Decimal` values through `model_dump_json()` and check the result against both the serialization and validation patterns. They also cover acceptance and rejection under constraints, and these tests would fail before the change.

**Patch A** takes a broader redesign.
- By default it drops the pattern entirely. That restores the v2.11 output but silently removes constraint information from every user's `Decimal` JSON schema, which is a public behavior change.
- The precise patterns move behind an opt-in `get_decimal_pattern`/`build_decimal_pattern` override, with new validation and serialization pattern builders that are much more exact, including `allow_inf_nan`.
- That work is well engineered and well tested. However, the main fix for the reported issue is "emit no pattern", and most of the new pattern code is unreachable unless users subclass `GenerateJsonSchema`.
- The docs carry two `version-changed` blocks that read contradictorily ("includes a pattern" vs "no longer includes a pattern").
- Many existing test expectations were rewritten simply to drop the pattern.

Under the scope criterion, Patch A's redesign adds risk: it removes existing schema behavior and obscures the fix. Patch B resolves the root cause within the current design with focused, meaningful tests.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

model_json_schema(mode="serialization") pattern for Decimal breaks on scientific notation

The serialization schema for Decimal fields generates a regex that rejects values that model_dump_json() itself produces.

Specifically: pydantic-core's serializer calls str() on Decimal objects, which outputs scientific notation for small/large values. E.g. Decimal('0.0000001') becomes "1E-7". But the pattern added in #11987 (^(?!^[-+.]*$)[+-]?0*\d*\.?\d*$) has no [eE] component, so it'll never match those strings.

As a result, any downstream consumer validating model_dump_json() output against model_json_schema(), such as OpenAPI validators and codegen + validation tools like Orval + Zod, will intermittently reject perfectly valid serialized values. Intermittent because only certain Decimal values trigger scientific notation.

v2.11:

{"anyOf": [{"type": "string"}, {"type": "null"}]}

v2.12:

{"anyOf": [{"pattern": "^(?!^[-+.]*$)[+-]?0*\\d*\\.?\\d*$", "type": "string"}, {"type": "null"}]}

Two possible fixes:

  • Append (?:[eE][+-]?\d+)? to the pattern in serialization mode
  • Normalize Decimal to fixed-point during serialization before it ever hits the schema

Example Code

import json
import re
from decimal import Decimal
from pydantic import BaseModel

class MyModel(BaseModel):
    value: Decimal | None

schema = MyModel.model_json_schema(mode="serialization")
pattern = next(
    v for v in schema["properties"]["value"]["anyOf"] if v.get("type") == "string"
)["pattern"]
regex = re.compile(pattern)

# pydantic serializes this as "1E-7" which fails its own schema's pattern
m = MyModel(value=Decimal("0.0000001"))
serialized = json.loads(m.model_dump_json())["value"]

print(f"Pattern: {pattern}")
print(f"Serialized: {serialized!r}")
print(f"Matches: {bool(regex.match(serialized))}")
# Pattern: ^(?!^[-+.]*$)[+-]?0*\d*\.?\d*$
# Serialized: '1E-7'
# Matches: False
