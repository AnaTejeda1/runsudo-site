What the agent reported

TypeAdapter.json_schema() now uses the adapter's config, so TypeAdapter(bytes, config={'ser_json_bytes': 'base64'}).json_schema() returns {'type': 'string', 'format': 'base64url'}. That matches what BaseModel produces. The new regression test failed before the fix and passes after it. The changes are uncommitted in the working tree.

What was wrong: the JSON schema generator picks the bytes format from its current config (pydantic/json_schema.py:817). That config starts out empty. Models, dataclasses and TypedDicts apply their own config while their schema is generated, but TypeAdapter.json_schema() never passed its config in. So the generator always used the default, 'binary'.

What I changed (pydantic/type_adapter.py:739): the adapter's config is now applied around the generate(...) call. When no config is given, nothing changes. An adapter can't have a config if the type already carries one (the constructor raises), so models keep using their own config.

Tests:

  • New test: tests/test_type_adapter.py::test_ta_config_applied_to_json_schema checks that the default stays 'binary' and that ser_json_bytes='base64' gives 'base64url'. Before the fix it failed with {'format': 'binary'} != {'format': 'base64url'}.
  • Nearby files: ./bt-test tests/test_type_adapter.py tests/test_json_schema.py gave 775 passed, 3 skipped, 2 xfailed, 0 failed.
  • Full suite: ./bt-test tests/ gave 11344 passed and 1 failed. The failure is tests/test_validators.py:1995, which compares file paths (/work/... vs /workspace/...). It fails the same way with my changes stashed, so it comes from the test environment.

Effect on existing users: any setting the schema generator reads from config now takes effect for a TypeAdapter, not just ser_json_bytes. That includes ser_json_temporal, ser_json_timedelta, json_schema_mode_override and json_schema_serialization_defaults_required. This is consistent with how models behave, and all existing tests pass. Anyone who was relying on those settings being ignored will see different schema output, so it deserves a changelog note.

Requirements:

  1. Adapter config applies in TypeAdapter.json_schema(): fixed, with the regression test above.
  2. The model and adapter give the same bytes format: the new test asserts 'base64url', which is what the report shows for the model. Existing model tests (test_model_default_bytes and similar) still pass.
  3. Default adapters still give 'binary': asserted in the same test.

Not fixed: the static TypeAdapter.json_schemas([...]) method still ignores each adapter's config. It builds all the adapters' schemas in one call to generate_definitions, which has no way to take a config per input. Fixing it would mean changing that function's interface, which is beyond this report's example and beyond a minimal fix. I didn't add a test for it; it's a reasonable follow-up.
