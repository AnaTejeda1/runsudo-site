common/hugo: Include aom, dav1d, and libavif in commands/env output

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Patch A does what the issue asks. It adds libavif v1.4.1, aom v3.14.1 and dav1d 1.5.3 next to libwebp in GetDependencyListNonGo, and notes that these versions must stay in sync with the genwebp and genavif Makefiles. Its unit test reads the version variables from those Makefiles and asserts each formatted dependency appears in the output. That test fails before the change and also catches later drift, which is a real check rather than a tautology. Its testscript checks the exact version strings in `hugo env` output. Patch B routes the versions through a new warpc.GetWASMDeps(), which makes common/hugo import internal/warpc. That is a new cross-package dependency from a low-level common package into an internal subsystem, with some risk of import cycles or heavier coupling. It also adds a KaTeX entry the issue did not ask for, with a hardcoded version that nothing checks against js/package.json. It reformats unrelated code in warpc.go (dispatcher closures, WithImportResolver), which obscures the fix. Its constants are still hand-maintained with only 'keep in sync' comments, and its testscript checks only module paths, not versions, so it would not catch wrong versions. A is narrower, lower-risk, and better tested.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
