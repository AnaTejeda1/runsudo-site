Support slug in section, taxonomy, and term pages

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The independent tests show the base commit already produces the issue's static paths (all non-rebuild tests PASS on base), so the remaining gap is slug changes during a running build: adding, changing, or removing a branch slug must relocate the section and all descendants. Patch A does not touch that at all. It renames a parameter in the VectorProvider interface and switches MatchSiteVector from HasAnyVector to HasVector, which is unrelated to slug handling, adds no tests, and leaves all three rebuild scenarios failing exactly as on base. Patch B directly addresses the root cause: it records the slug of every section, taxonomy and term page per site vector during assembly, compares against the previous build's slugs on rebuild, marks the whole subtree below a changed slug stale, forces re-unpacking of page meta sources, and registers the affected page identities as assemble changes so dependents (home page listings, term pages) are rebuilt. It also clones the seenTerms vectors before mutation to avoid corrupting shared state, with a dedicated regression test for the taxonomy cascade case. Its new tests (TestSlugInBranchPagesRebuild, TestSlugInBranchPagesResourcesAndPagination, TestRebuildEditTaxonomyCascadeKeepsTerms) exercise slug add/change/remove on nested sections, taxonomies, resources and pagination, and would fail before the change. All three independent rebuild tests flip from FAIL-ASSERT to PASS under B. The one existing-test edit (expecting an absolute RSS link) is a minor assertion tweak, not a weakening. Scope is appropriate and the code follows surrounding conventions (ConcurrentMap/ConcurrentSet, previous* fields on HugoSites). B is the clear winner.

The issue

<!-- Describe this new feature. Think about if it really belongs in the Hugo core module; you may want to discuss it on https://discourse.gohugo.io/ first. -->

Currently with multilanguage sites you can localize the URL for pages by setting slug in the frontmatter.

However there is no slug support for sections. This means the only way to localize a section URL is to use url together with [[cascade]]. This is annoying since you have to "redo from scratch" the entire URL format, with : tokens, duplicating names for parent sections, etc.

Proposal: add support for slug in section pages. It would behave the obvious way, basically being equivalent to changing the directory name for the section. It would affect the URL for the section and all descendant pages.

Example:

help/
    _index.en.md    # contains no slug
    _index.es.md    # contains slug="ayuda"
    how-to-frob/
       index.en.md    # contains no slug
       index.es.md    # contains slug="como-frobear"

would result in the following paths:

help/
help/how-to-frob/
es/ayuda/
es/ayuda/como-frobear/
