Description

model_json_schema(mode="serialization") pattern for Decimal breaks on scientific notation

The serialization schema for Decimal fields generates a regex that rejects values that model_dump_json() itself produces.

Specifically: pydantic-core's serializer calls str() on Decimal objects, which outputs scientific notation for small/large values. E.g. Decimal('0.0000001') becomes "1E-7". But the pattern added in #11987 (^(?!^[-+.]*$)[+-]?0*\d*\.?\d*$) has no [eE] component, so it'll never match those strings.

As a result, any downstream consumer validating model_dump_json() output against model_json_schema(), such as OpenAPI validators and codegen + validation tools like Orval + Zod, will intermittently reject perfectly valid serialized values. Intermittent because only certain Decimal values trigger scientific notation.

v2.11:

{"anyOf": [{"type": "string"}, {"type": "null"}]}

v2.12:

{"anyOf": [{"pattern": "^(?!^[-+.]*$)[+-]?0*\\d*\\.?\\d*$", "type": "string"}, {"type": "null"}]}

Two possible fixes:

  • Append (?:[eE][+-]?\d+)? to the pattern in serialization mode
  • Normalize Decimal to fixed-point during serialization before it ever hits the schema

Example Code

import json
import re
from decimal import Decimal
from pydantic import BaseModel

class MyModel(BaseModel):
    value: Decimal | None

schema = MyModel.model_json_schema(mode="serialization")
pattern = next(
    v for v in schema["properties"]["value"]["anyOf"] if v.get("type") == "string"
)["pattern"]
regex = re.compile(pattern)

# pydantic serializes this as "1E-7" which fails its own schema's pattern
m = MyModel(value=Decimal("0.0000001"))
serialized = json.loads(m.model_dump_json())["value"]

print(f"Pattern: {pattern}")
print(f"Serialized: {serialized!r}")
print(f"Matches: {bool(regex.match(serialized))}")
# Pattern: ^(?!^[-+.]*$)[+-]?0*\d*\.?\d*$
# Serialized: '1E-7'
# Matches: False

What the agent reported

The change is complete and verified. Final report below.

What was wrong

GenerateJsonSchema.decimal_schema in pydantic/json_schema.py generates a string pattern for Decimal fields. For unconstrained decimals (and decimal-places-only decimals) the pattern was ^(?!^[-+.]*$)[+-]?0*\d*\.?\d*$ — with no exponent component. But pydantic-core's serializer calls str() on Decimal, which emits scientific notation for small/large values (Decimal('0.0000001') → "1E-7"). So model_dump_json() output was rejected by the model's own model_json_schema(), breaking OpenAPI/codegen validators intermittently (v2.12 regression from PR #11987).

What I changed

  • pydantic/json_schema.py — in get_decimal_pattern, appended an optional scientific-notation group (?:[eE][+-]?\d+)? before the terminal $ in the two $-anchored cases that actually rejected such strings:
  • Case 3 (decimal_places only): …0*(?:[eE][+-]?\d+)?$
  • Case 4 (no constraints): \d*\.?\d*(?:[eE][+-]?\d+)?$
  • Cases 1 & 2 (max_digits) were left unchanged — their unanchored first alternative already matches scientific notation, so they never rejected it.
  • tests/test_json_schema.py — added regression test test_decimal_serialization_schema_matches_scientific_notation (reproduces the exact report: Decimal('0.0000001') → "1E-7" must match the schema's own pattern), and updated all existing hardcoded pattern assertions to the corrected pattern.
  • docs/concepts/json_schema.md — updated the two printed-output examples (validation + serialization) to the new pattern (these are executed as doc tests).

I chose the regex approach over pydantic-core normalization because the latter lives in a separate crate not editable here; correcting the schema pattern fully resolves the reported mismatch and is also correct for validation mode, since Decimal accepts scientific-notation string input.

Test evidence

  • Regression test fails before the fix: assert pattern.match('1E-7') is not None → AssertionError: assert None is not None against pattern …\d*\.?\d*$.
  • After the fix: ./bt-test on the regression test + test_decimal_json_schema + test_special_decimal_types → 5 passed.
  • Full tests/test_json_schema.py → 559 passed, 3 skipped, 1 xfailed.
  • Docs examples ./bt-test tests/test_docs.py -k json_schema → 25 passed (includes the changed json_schema.md:263-309 block).
  • Reviewer confirmed the regex is well-formed, accepts "1E-7"/"1E+20"/"-2.5E-10", still rejects empty/"++"/"1.2.3", and nothing unrelated changed.

Requirements disposition

  1. Fix option A — append (?:[eE][+-]?\d+)? to the pattern → Implemented (Cases 3 & 4). Test evidence above.
  2. Fix option B — normalize Decimal to fixed-point during serialization → Skipped (mutually exclusive alternative). Evidence: this would require changes in pydantic-core (str(Decimal) behavior lives in the pydantic-core Rust crate, not in this repo's pydantic/ Python source), which is out of scope for a pydantic/json_schema.py fix; option A resolves the report entirely.
  3. Reported scenario: serialized output must match its own schema → Implemented + covered by the regression test asserting the exact model_dump_json → pattern round-trip.
