Remove -embedded from the default exec.allow

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The issue asks only to remove '-embedded' from the default exec.allow. Patch B does exactly that: it changes the sass regex to '^(dart-)?sass$' and updates the TOML test. It also adds explicit assertions that 'sass' and 'dart-sass' are accepted and 'dart-sass-embedded' and 'sass-embedded' are rejected; the rejection checks would fail before the change and pass after it. B also updates the docs (Babel.md example and docs.yaml) to match the new default. Patch A makes the same sass change but also removes '^tailwindcss$' from the default allow list. That is an unrequested behavior change: every TailwindCSS user would need to add tailwindcss to security.exec.allow, which is a breaking change outside the issue's scope. A has to patch three integration tests with custom security.exec.allow settings just to keep them passing, which shows the regression it introduces. A also leaves the node permissions defaults referencing tailwindcss, which is now inconsistent with its own allow list. A adds no meaningful new test of the -embedded removal beyond the TOML string update. B is correct, narrowly scoped, better tested, and keeps the docs consistent.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
