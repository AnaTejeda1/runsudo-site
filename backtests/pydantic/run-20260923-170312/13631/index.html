Description

When a discriminated union uses a bool discriminator (Literal[True] / Literal[False]), the generated JSON schema's discriminator.mapping uses the Python string representations "True" and "False" as keys:

"discriminator": {
    "mapping": {"False": "#/$defs/Disabled", "True": "#/$defs/Enabled"},
    "propertyName": "enabled"
}

Per the OpenAPI discriminator specification, mapping keys must match the serialized payload value of the discriminator property. For a boolean property, that value serializes to JSON true/false, so the keys should be "true" and "false". Tooling that resolves the mapping against the payload (code generators, validators such as openapi-generator or Redocly) fails to match either variant.

Expected:

"mapping": {"false": "#/$defs/Disabled", "true": "#/$defs/Enabled"}

Note that Enum discriminator keys are already normalized to their value (k.value) before stringification in GenerateJsonSchema.tagged_union_schema; bool keys just fall through to str(k).

Example Code

from typing import Literal

from pydantic import BaseModel, Field


class Enabled(BaseModel):
    enabled: Literal[True]
    config: str


class Disabled(BaseModel):
    enabled: Literal[False]


class Model(BaseModel):
    setting: Enabled | Disabled = Field(discriminator='enabled')


print(Model.model_json_schema()['properties']['setting']['discriminator'])
# {'propertyName': 'enabled', 'mapping': {'True': '#/$defs/Enabled', 'False': '#/$defs/Disabled'}}

What the agent reported

The fix is complete and verified. Here is my final report.

What was wrong

In GenerateJsonSchema.tagged_union_schema (pydantic/json_schema.py), discriminator mapping keys are stringified via str(k). Enum keys were normalized to k.value first, but bool keys fell straight through to str(k), producing the Python reprs "True"/"False". Per the OpenAPI discriminator spec, mapping keys must match the serialized JSON payload value, and a JSON boolean serializes to true/false — so tooling (openapi-generator, Redocly, etc.) could not resolve the mapping.

What I changed

pydantic/json_schema.py — added a bool-normalization branch after the existing Enum branch:

if isinstance(k, Enum):
    k = k.value
if isinstance(k, bool):
    k = 'true' if k else 'false'

Placed as a separate if after the Enum branch so an Enum whose .value is a bool is also normalized. isinstance(k, bool) does not catch plain ints (Literal[1] still renders '1'), so only booleans are affected.

tests/test_json_schema.py — added test_discriminated_union_bool_discriminator, asserting:

Model.model_json_schema()['properties']['setting']['discriminator'] == {
    'propertyName': 'enabled',
    'mapping': {'true': '#/$defs/Enabled', 'false': '#/$defs/Disabled'},
}
