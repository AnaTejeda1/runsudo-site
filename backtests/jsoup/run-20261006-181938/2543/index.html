Correct offsite link detection in Cleaner

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches replace the string-prefix check with a case-insensitive hostname comparison, so both fix the two core symptoms: a prefixed host like example.com.test being treated as local, and same-host links outside the base path being treated as external.

Patch B also covers the issue's other two requirements.

- **Relative links stay local.** Patch B detects a relative href directly: it resolves the raw href against two different placeholder hosts and checks whether it takes the placeholder's host both times. This keeps relative links local even when the base URI has no host, such as `file:///home/x/`. Patch A instead requires a non-empty base host, so a relative link under a `file:` base gets `rel=nofollow`. That contradicts "relative links should remain local."
- **Absolute links are external with no base URI.** Patch B handles the case where the base is only the internal `DummyUri` placeholder, so an absolute link to the placeholder host itself is still external. Under Patch A, an absolute link to the dummy host would match the placeholder base and be treated as local. This is an edge case, but it is part of the issue's stated semantics.

On tests, Patch B's are much more thorough. They cover:
- a lookalike host, including userinfo (`example.com@evil.com`);
- a base with a path, both with and without `preserveRelativeLinks`;
- case-insensitive hosts;
- the no-base case, including the placeholder host and protocol-relative links;
- a base with no host (`file:`).

Patch A's single test covers only the two headline cases.

On craft, Patch B's two-placeholder trick is somewhat clever and adds complexity. It is well documented, though, and moved into named helpers. Patch A is simpler but misses stated requirements. Overall, Patch B is the more correct and better-tested fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

The Cleaner uses a string-prefix comparison to determine whether a link points to the same site as the document base URI.

This can incorrectly treat a prefixed hostname as local when the base URI has no trailing slash, and can treat local links as external when the base URI contains a path.

Parse and compare the resolved link and base URI hostnames instead.

Relative links should remain local, while absolute links should be considered external when no base URI is available.
