The "failed to extract" error refers to outer shortcode instead of inner shortcode

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The bug: an unclosed nested shortcode (`img`) swallows content until it reaches the outer `{{< /figure >}}` closing tag. That tag gets treated as `img`'s closing, which leaves `figure` apparently unclosed, so the error names the wrong shortcode.

Patch B fixes this at the root. When the closing tag's name doesn't match the shortcode being extracted, it raises an error naming the inner shortcode ("shortcode \"img\" must be closed or self-closed"). It also gives a specific message for a stray closing tag on a shortcode that doesn't use `.Inner`. Its tests reproduce the exact scenario from the issue (figure/img/figcaption) and assert the error names `img` and not `figure`. They also cover the top-level unclosed case, the stray closing tag case, and a positive case with valid nesting. These tests would fail before the change and pass after.

Patch A only re-wraps errors from nested extraction with the nested shortcode's position. It does not change how a mismatched closing tag is matched, so the issue's scenario would still report `unclosed shortcode \"figure\"`. Its test covers a different situation (inner template not found) and never exercises the unclosed-nested case from the issue. Patch A therefore does not resolve the reported problem.

Patch B is correct and well tested; Patch A misses the root cause.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
