Spurious comma in parametrize causes obfuscated crash

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root crash in ParameterSet._for_parametrize by detecting a non-sized value before calling len() and reporting a clean collection error that names the offending test; A does it via try/except TypeError, B via an isinstance(Sized) check, and either works for the None/int cases in the issue (independent tests 1 and 2 pass on both). The issue has a second explicit ask: when the value is a string, show it as the unpacked character list (['f','o','o']) so the user can see it was treated as a sequence. Patch B implements this and tests it; Patch A ignores it entirely, and the independent test for it fails on A. B's tests are also stronger: a parametrized case covering None/int with both the '"x,"' and tuple-argnames forms, a no_fnmatch_line('*TypeError*') guard, and assert_outcomes(errors=1), versus A's single None case. B's error message keeps the existing names/count framing, which is consistent with the adjacent mismatch message, and it updates the stale TODO comment accurately. Scope and craft are comparable otherwise (A touches AUTHORS, neutral). B is the more complete fix of the reported issue.
