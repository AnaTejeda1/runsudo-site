In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches make the identical two-line change at the root cause in `_get_items` (adding `by_alias=True` to both `model_dump` calls), and both pass all five independent tests, so on the core fix they are equal. The difference is in how completely each handles the scenarios the issue itself describes. The issue explicitly names `rewind_session_items` as broken by the alias mismatch and `_restore_popped_session_items` as sending `async_` through `add_items()`. Patch B's single test is well constructed, exercising the real AsyncOpenAI client over an httpx MockTransport and asserting on the posted request body, which is a more realistic round-trip than A's mock-based test, and its minimal scope is a genuine virtue. The issue

View on GitHub

Describe the bug

OpenAIConversationsSession.get_items() and pop_item() convert Conversations API items with model_dump(exclude_unset=True) but without by_alias=True. A function call the API returned with "async": true therefore comes back keyed by the SDK attribute async_ instead of the wire field async, which is not a valid key of ResponseFunctionToolCallParam. Re-adding or replaying that history sends an unknown parameter to the API. This is the same alias loss fixed for output-to-input replay in #5477 / #5638 and for RunState in #5352 / #5358, on the session read path.

Debug information

  • Agents SDK version: 0.24.0 (also main at 1fc77bbc, 2026-11-09)
  • Related library versions: openai 3.29.0
  • Python version: 3.12.10
  • Operating system: Windows 11
  • Model and model provider: not involved; the Conversations API client is mocked below
  • Does the issue reproduce with the latest Agents SDK release? Yes
  • Does the issue occur consistently or intermittently? Consistently

Repro steps

No API key needed. The mock yields exactly what client.conversations.items.list() returns for a function call made with the async flag.

import asyncio
from unittest.mock import AsyncMock, MagicMock

from openai.types.responses.response_function_tool_call_item import ResponseFunctionToolCallItem

from agents.memory.openai_conversations_session import OpenAIConversationsSession


async def main() -> None:
    item = ResponseFunctionToolCallItem.model_validate(
        {"id": "fc_1", "type": "function_call", "call_id": "call_1", "name": "lookup",
         "arguments": "{}", "status": "completed", "async": True}
    )

    async def conversation_items(**kwargs):
        yield item

    client = MagicMock()
    client.conversations.items.list = MagicMock(side_effect=conversation_items)
    client.conversations.items.delete = AsyncMock()
    session = OpenAIConversationsSession(conversation_id="conv_1", openai_client=client)

    items = await session.get_items()
    print("get_items():", {k: v for k, v in items[0].items() if k.startswith("async")})
    popped = await session.pop_item()
    print("pop_item():", {k: v for k, v in popped.items() if k.startswith("async")})


asyncio.run(main())

Observed:

get_items(): {'async_': True}
pop_item(): {'async_': True}

Expected:

get_items(): {'async': True}
pop_item(): {'async': True}

Expected behavior

Items returned by the session keep the API field names, so get_items() and pop_item() return {"type": "function_call", ..., "async": True}, the same shape ToolCallItem.to_input_item() produces since #5638, and they can be passed to add_items() on another session, to Runner.run(input=...), or re-added by the runner without an unknown-parameter error.

Root cause

src/agents/memory/openai_conversations_session.py lines 107 and 115 (_get_items, both branches) call item.model_dump(exclude_unset=True). ResponseFunctionToolCallItem (in the ConversationItem union) declares async_: Optional[bool] = FieldInfo(alias="async"), so without by_alias=True the dump emits the attribute name. pop_item() returns self._get_items(limit=1)[0], so it has the same shape.

By inspection only: rewind_session_items in src/agents/run_internal/session_persistence.py compares runner-side items (carrying async since #5638) with the session tail from get_items() (carrying async_), so the suffix never matches and the rewind is skipped; _restore_popped_session_items feeds popped items back to add_items(), which would send async_ to conversations.items.create. I did not send a replayed item to the live API, so the exact error text is not captured.

Proposed fix

Dump with wire aliases at both sites, mirroring #5638:

all_items.append(item.model_dump(exclude_unset=True, by_alias=True))

Branch with the two-line fix and a regression test (tests/memory/test_openai_conversations_session.py::TestOpenAIConversationsSessionBasicOperations::test_get_items_and_pop_item_preserve_wire_aliases, which fails on main and passes with the change; the whole file passes, ruff and mypy are clean): https://github.com/reeve25/openai-agents-python/tree/fix/conversations-session-wire-aliases

The same model_dump(exclude_unset=True) pattern without by_alias also appears in openai_responses_compaction_session.py (_normalize_compaction_output_items), run_internal/items.py (_coerce_to_dict), run_internal/session_persistence.py (_session_item_key) and run_internal/turn_resolution.py (_dump_output_item); I have not confirmed that aliased fields reach those paths, so this report covers the session read path only.

This report and the fix branch were prepared with Claude Code (claude-fable-5-1); I reviewed the repro, the diff and the test output. Not run: a live Conversations API call to capture the server's exact error.
