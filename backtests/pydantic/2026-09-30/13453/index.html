RootModel.model_dump() typing signature rejects supported serialization arguments

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the core bug the same way. They widen `context` to `Any | None` and add `fallback: Callable[[Any], Any] | None` and `polymorphic_serialization: bool | None` in the same positions as `BaseModel.model_dump`. Both keep the `Any` return type. On correctness they are essentially equal. B also narrows `include`/`exclude` to `IncEx | None`, which is closer to the base but was not asked for.

Tests decide it for A. A adds the issue's exact example calls to `tests/typechecking/root_model.py`. That is the suite that runs mypy, pyright and pyrefly, so it directly catches this regression and fails before the fix. A also adds a runtime test that the calls work, and an AST-based sync test comparing parameter names, annotations and defaults against `BaseModel`. The sync test skips the `include`/`exclude` annotations, but it is still a useful drift guard. B adds no type-checker cases at all. B's only test sets the global `typing.TYPE_CHECKING = True` and re-executes `root_model.py` as a new module. That leaks process-global state during the run, imports TYPE_CHECKING-only symbols, and builds a duplicate `RootModel` class. It is fragile and could interfere with other tests.

Scope and craft also favour A. B replaces RootModel's explanatory docstring with a copy of BaseModel's, and its test asserts the two docstrings are identical. The copied text says 'Returns: A dictionary representation of the model', which is wrong for RootModel. That is exactly the case the original docstring explained. B also locks the two docstrings together for no real benefit. A's change is minimal and focused.

The issue

View on GitHub

Initial Checks

  • I confirm that I'm using Pydantic V2

Description

RootModel inherits the runtime implementation of BaseModel.model_dump(), but defines a separate declaration under TYPE_CHECKING to preserve its more precise return type.

That declaration has diverged from the base method:

  • context is restricted to dict[str, Any] | None instead of Any | None.
  • fallback is missing.
  • polymorphic_serialization is missing.

As a result, Mypy, Pyright, and Pyrefly reject valid calls that succeed at runtime.

All three calls in the example below succeed at runtime.

Mypy currently reports errors equivalent to:

Argument "context" to "model_dump" of "RootModel" has incompatible type "str"
Unexpected keyword argument "fallback" for "model_dump" of "RootModel"
Unexpected keyword argument "polymorphic_serialization" for "model_dump" of "RootModel"

Pyright and Pyrefly report the same signature incompatibilities.

Expected behavior

The type-checking-only RootModel.model_dump() declaration should accept the same parameters, annotations, defaults, and ordering as BaseModel.model_dump(), while preserving the more precise RootModel return annotation.

Cause

The declaration appears to have drifted as the base method evolved:

  • Serialization context originally updated both signatures.
  • BaseModel.context was later widened to Any.
  • fallback was subsequently added to BaseModel.model_dump().
  • polymorphic_serialization was later added to BaseModel.model_dump().

Those later changes were not propagated to the manually maintained RootModel declaration.

Proposed fix

Update only the static RootModel.model_dump() signature and add focused regression cases to tests/typechecking/root_model.py.

No runtime serialization behavior needs to change.

I have prepared and locally validated a focused two-file fix. The following checks pass:

  • Mypy type-checking suite
  • Pyright type-checking suite
  • Pyrefly type-checking suite
  • Focused RootModel serialization tests
  • Ruff lint and formatting checks
  • git diff --check

I would be happy to submit the PR after the issue is reviewed and assigned.

What the agent reported

I fixed the RootModel.model_dump() signature so type checkers accept the three calls from the report. I couldn't run Mypy, Pyright or Pyrefly: none are installed and there's no network access to install them. The evidence is a new pytest test that compares the two signatures. It failed before the fix and passes after.

What was wrong: RootModel declares its own model_dump() signature (only visible to type checkers) so it can return Any. That copy had fallen behind BaseModel.model_dump() in pydantic/main.py:

  • context only accepted a dict[str, Any] | None, not Any | None.
  • fallback was missing.
  • polymorphic_serialization was missing.

The calls already worked at runtime; only type checking rejected them.

What I changed:

  • Fix, in pydantic/root_model.py: context is now Any | None. I added fallback: Callable[[Any], Any] | None = None between warnings and serialize_as_any, and polymorphic_serialization: bool | None = None last. Callable comes from collections.abc, which Ruff requires. The return type stays -> Any, and runtime behaviour is unchanged.
  • Not changed: include/exclude stay annotated Any, where the base method uses IncEx | None. The report asks for identical annotations, but narrowing these would make type checkers reject calls they accept today, and the report didn't raise them. They are the only remaining difference besides the return type.
  • Tests, in tests/typechecking/root_model.py: the report's three example calls. These are only checked by the type-checker suites, so they haven't been run as type checks here.
  • Tests, in tests/test_root_model.py:
  • test_root_model_model_dump_signature_matches_base_model reads both source files and checks that the two model_dump signatures have the same parameter names, order, annotations and defaults (ignoring the return type and the include/exclude annotations). It will also catch any future drift.
  • test_root_model_model_dump_accepts_base_model_arguments runs the three example calls and checks their results: 'prefix:value', 'fallback' and [{'x': 1, 'y': 2}].

Test evidence:

  • Before the fix: the signature test failed on the context annotation ('dict[str, Any] | None' != 'Any | None'), and the other list had 2 extra parameters.
  • After the fix: ./bt-test tests/test_root_model.py tests/test_serialize.py gives 168 passed, 1 skipped.
  • Lint: ruff check, ruff format --check and git diff --check are clean.
  • Review: a read-only review found nothing blocking and no unrelated edits.
