model_dump(exclude=...) is silently ignored in python mode when a wrap model_serializer is gated with when_used="json"

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause the same way. Before, the function serializer always cleared include/exclude before calling the next serializer, even when `when_used` meant the user function never ran and the fallback serializer was used. Both now clear include/exclude only when the function actually ran (`Ok((true, v))`) and keep the caller's include/exclude on the fallback path. Both apply this to `to_python`, `json_key` and `serde_serialize`, so they behave the same.

Patch A restructures each match arm and passes the original `state` straight to the fallback serializer. Patch B keeps the original shape and adds an `include_exclude()` accessor on `SerializationState` that clones the value, which is then re-scoped. B's diff is slightly smaller, but it adds a public accessor and an extra clone. Neither is risky.

The difference is in the tests. Patch A covers:
- the issue's exact scenario (wrap `model_serializer` whose function calls the handler) for both `when_used='json'` and `'json-unless-none'`, checking python mode, json mode and `model_dump_json`;
- plain `model_serializer`;
- nested include/exclude through `field_serializer` in plain and wrap modes;
- the gated fallback path directly at the pydantic-core `SchemaSerializer` level.

Patch B has a single test, covering only `when_used='json'`. Its wrap function never calls the handler, so it does not reproduce the issue's `handler(self)` case, although it does exercise the fallback path. Both test sets would fail before the fix and pass after. Patch A's are broader and closer to the reported scenario, so A wins on testing with correctness equal.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

When a model declares @model_serializer(mode="wrap") with when_used="json" (or "json-unless-none"), the runtime exclude argument passed to model_dump() is silently ignored in python mode. The same call in JSON mode behaves correctly.

Expected: model_dump(exclude={"b"}) omits b regardless of when_used, since the gate concerns which serializer runs and not which fields the caller asked to drop.

Actual: b is present in python mode.

Example Code

from pydantic import BaseModel, SerializerFunctionWrapHandler, model_serializer


class Gated(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap", when_used="json")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


class Always(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


  # Gated to JSON: python mode ignores exclude.
  print(Gated(a=1, b=2).model_dump(exclude={"b"}))               # {'a': 1, 'b': 2}  <-- expected {'a': 1}
  print(Gated(a=1, b=2).model_dump(mode="json", exclude={"b"}))  # {'a': 1}          <-- correct

  # Identical model without the gate: python mode honours exclude.
  print(Always(a=1, b=2).model_dump(exclude={"b"}))              # {'a': 1}

  Output:

  gated  python: {'a': 1, 'b': 2}
  gated  json  : {'a': 1}
  always python: {'a': 1}
