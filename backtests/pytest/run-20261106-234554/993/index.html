ImportError raised by plugins make pytest return EXIT_TESTSFAILED

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The issue's title and body complain that ImportErrors raised by plugins at startup escape as a raw traceback and yield exit code 1. The root cause is that `import_plugin` re-raises ImportError and nothing in `_main` catches it, regardless of whether the plugin was requested via `-p`, `pytest_plugins`, `PYTEST_PLUGINS`, or an entry point.

Patch A fixes that root cause: it classifies plugin load failures (not found -> UsageError/4, found but raised -> PluginImportFailure/3), catches the new exception in `_main`, prints a filtered traceback consistent with the existing conftest-error path, handles entry-point loading and UsageError passthrough, and fixes the `e.args[0]` IndexError on a bare `raise ImportError`. It updates every existing test that relied on ImportError, adds broad acceptance tests covering all four load paths, and documents the exit codes and the behaviour change. Its choice of 3 for a broken plugin vs 4 for a broken conftest is deliberate, documented, and matches the issue's own suggestion that the code should be 3; the issue's two asks ('same code' and 'should be 3') are in tension, so failing the independent 'same exit code' test is a defensible design choice rather than a defect.

Patch B only wraps `consider_conftest` so a `pytest_plugins` failure becomes a ConftestImportFailure. That fixes example 2 and the IndexError, but a plugin that fails under `-p` (the independent test shows exit code 1 still), under `PYTEST_PLUGINS`, or as a pytest11 entry point still crashes out with code 1, which is exactly the title's complaint. B's tests are reasonable for the path it covers but it leaves the general problem unresolved.

A is larger and breaking in exception types, but the extra scope directly serves the issue rather than being unrelated churn. A wins on correctness and test coverage.

The issue

View on GitHub

Currently there's some inconsistency on which exit code is returned by pytest when import errors happen during startup.

example 1

# contents of conftest.py
raise ImportError

# contents of test_foo.py
def test_foo():
    pass

Running py.test in this directory produces error code 4 - EXIT_USAGEERROR.

example 2

# contents of conftest.py
pytest_plugins = 'plugin'

# contents of plugin.py
raise ImportError

# contents of test_foo.py
def test_foo():
    pass

Here py.test produces error code 1 - EXIT_TESTSFAILED.

Shouldn't they all return the same error code? Furthermore, shouldn't the error code be 3 - EXIT_INTERNALERROR instead?
