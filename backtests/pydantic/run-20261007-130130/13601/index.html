model_dump(exclude=...) is silently ignored in python mode when a wrap model_serializer is gated with when_used="json"

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the same root cause the same way. In `function.rs`, when `self.call` returns `Ok((false, v))` (the function was gated out by `when_used`), the fallback serializer now receives the caller's include/exclude instead of `IncludeExclude::empty()`. The `Ok((true, v))` path still clears include/exclude, since the user function is responsible for filtering. The behaviour of the two patches is the same across `to_python`, `json_key` and `serde_serialize`.

The implementations differ only slightly. Patch A adds a new public `include_exclude()` accessor on `SerializationState` that clones the struct, then re-scopes the state with that clone. This is a redundant clone and re-scope that adds API surface. Patch B passes the existing `state` straight to the fallback serializer and needs no new accessor, which is simpler and more direct.

Tests are where the patches differ most. Patch A's wrap test never calls `handler`, so it does not reproduce the issue's scenario of a wrap serializer that delegates. It covers neither `json-unless-none` nor field-level serializers, and its docstring is a leftover `"""<link>"""` placeholder. Patch B reproduces the issue exactly: a wrap serializer calling `handler(self)`, parametrized over both `json` and `json-unless-none`. It checks python and JSON modes, including `model_dump_json`, and adds a plain-mode test. It also adds a test for field-level Plain/WrapSerializer with nested include/exclude on lists and dicts, which exercises the same changed code path for non-model serializers. These tests would fail before the fix and pass after it, and they cover more of the affected behaviour.

With correctness equal, Patch B wins on test quality and on slightly cleaner craft.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

When a model declares @model_serializer(mode="wrap") with when_used="json" (or "json-unless-none"), the runtime exclude argument passed to model_dump() is silently ignored in python mode. The same call in JSON mode behaves correctly.

Expected: model_dump(exclude={"b"}) omits b regardless of when_used, since the gate concerns which serializer runs and not which fields the caller asked to drop.

Actual: b is present in python mode.

Example Code

from pydantic import BaseModel, SerializerFunctionWrapHandler, model_serializer


class Gated(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap", when_used="json")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


class Always(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


  # Gated to JSON: python mode ignores exclude.
  print(Gated(a=1, b=2).model_dump(exclude={"b"}))               # {'a': 1, 'b': 2}  <-- expected {'a': 1}
  print(Gated(a=1, b=2).model_dump(mode="json", exclude={"b"}))  # {'a': 1}          <-- correct

  # Identical model without the gate: python mode honours exclude.
  print(Always(a=1, b=2).model_dump(exclude={"b"}))              # {'a': 1}

  Output:

  gated  python: {'a': 1, 'b': 2}
  gated  json  : {'a': 1}
  always python: {'a': 1}
