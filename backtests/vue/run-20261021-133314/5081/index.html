Throw an error on createVNode with using innerHTML and children at the same time

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The issue asks for no error and for the element to show innerHTML when provided, otherwise the children, with both changing dynamically. On the base tree the original crash no longer reproduces (the mount test passes on base), so the live defect is the dynamic case: when innerHTML/textContent goes from a value back to nullish while children are unchanged, the element stays empty because the old child vnodes are still considered mounted but their DOM was replaced. Patch B addresses exactly that in patchElement: it broadens the reset condition from truthy to `!= null` (so an empty-string innerHTML also unsets correctly) and, after clearing the element, puts the still-mounted old children's DOM back (text via hostSetElementText, arrays via move) so the subsequent diff operates on real content. Its tests cover text children, array children with component reuse (no remount), empty-string toggles, textContent, and a compiled block with PROPS patch flags, plus SSR nullish cases; the independent toggle tests go from FAIL on base to PASS with B. Patch A does not change runtime behaviour at all; it only adds a dev warning telling users not to combine innerHTML/textContent with children, which runs contrary to the issue's stated expectation and leaves all three independent toggle scenarios failing exactly as on base. Its tests pass only because they assert the new warning text, not any fix. B's approach carries some risk (moving vnodes whose DOM was detached by innerHTML), but it is targeted, commented, and well exercised, including the block-tree path. B is the better fix.
