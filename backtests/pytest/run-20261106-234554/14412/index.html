Incorrect timing info when using subtests and console_output_style='times'

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

The issue's reproducer is a unittest.TestCase using self.subTest, and the reported symptom is that subtest lines show 0.000us. Patch B only fixes the terminal reporter: it returns the SubtestReport's duration in verbose mode and excludes subtest reports from the per-module accounting. But for unittest subtests, _pytest/unittest.py builds the CallInfo with duration=0, so B still prints 0.000us for every unittest SUBPASSED line. The independent test test_unittest_subtest_lines_show_subtest_duration confirms this: it fails on B with 'SUBPASSED(i=0) 0.000us', while A passes. Patch A fixes both halves: it threads the current report into _get_progress_information_message (cleaner than B's instance-level _current_logreport side channel), shows the subtest's own duration on subtest lines, excludes subtests from the module sum so their time is not double-counted, and wraps TestCase.subTest to measure start/stop so addSubTest produces a real duration, with cleanup of the wrapper and timing dict after the test. A's tests cover the unittest case (passing and failing), the subtests fixture case, and the once-counted module time including line wrap, with actual lower-bound duration assertions. B's tests only use the subtests fixture, assert merely that '0.000us' does not appear, include an xdist test that skips when xdist is absent, and add an unrelated slow-teardown test and AUTHORS churn. A resolves the issue at its root cause; B masks only the fixture path and leaves the issue's exact scenario broken.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.

pytest does not seem to report accurate timing info when using subtests and console_output_style = 'times':

pyproject.toml

[tool.pytest]
addopts = [
    '--capture=tee-sys',
    '-v'
]
console_output_style = 'times'

test_subtests.py

import time
import unittest

class Test(unittest.TestCase):
    def test_subtests(self):
        for i in range(3):
            with self.subTest(i=i):
                time.sleep(1)
