model_dump(exclude=...) is silently ignored in python mode when a wrap model_serializer is gated with when_used="json"

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause the same way. In `function_type_serializer`, when `self.call` returns `Ok((false, v))` (the function was skipped by the `when_used` gate), the fallback serializer now receives the caller's original include/exclude instead of `IncludeExclude::empty()`. The empty filter is correct only when the user function actually ran, since the function (or its handler) is then responsible for filtering. Both apply this to `to_python`, `json_key` and `serde_serialize`, so correctness is effectively equal.

Patch A returns early from the `false` branch with the unchanged `state`. This avoids scoping and cloning altogether, keeps the existing structure and adds no new API surface. It also clarifies the comments.

Patch B threads a third tuple element through the match. It adds a new public `include_exclude()` accessor on `SerializationState` that clones the include/exclude, then re-scopes the state with that clone. This is functionally equivalent but slightly more machinery, including a new public method, for the same effect.

On tests, both would fail before the fix and pass after.
- Patch A parametrizes over both `json` and `json-unless-none`, which are the two gating values named in the issue. It checks include and exclude in python and json mode with a handler-calling wrap serializer, mirroring the issue's reproduction exactly.
- Patch B also covers `plain` mode, a nice extra, and asserts that the json-mode path still runs the function. However, it only tests `when_used='json'`, and it leaves a stray `"""<link>"""` placeholder docstring.

Overall the fixes are equivalent. Patch A is more minimal, adds no API, and its test matches the issue's scenarios, including `json-unless-none`, so it edges out Patch B.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

When a model declares @model_serializer(mode="wrap") with when_used="json" (or "json-unless-none"), the runtime exclude argument passed to model_dump() is silently ignored in python mode. The same call in JSON mode behaves correctly.

Expected: model_dump(exclude={"b"}) omits b regardless of when_used, since the gate concerns which serializer runs and not which fields the caller asked to drop.

Actual: b is present in python mode.

Example Code

from pydantic import BaseModel, SerializerFunctionWrapHandler, model_serializer


class Gated(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap", when_used="json")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


class Always(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


  # Gated to JSON: python mode ignores exclude.
  print(Gated(a=1, b=2).model_dump(exclude={"b"}))               # {'a': 1, 'b': 2}  <-- expected {'a': 1}
  print(Gated(a=1, b=2).model_dump(mode="json", exclude={"b"}))  # {'a': 1}          <-- correct

  # Identical model without the gate: python mode honours exclude.
  print(Always(a=1, b=2).model_dump(exclude={"b"}))              # {'a': 1}

  Output:

  gated  python: {'a': 1, 'b': 2}
  gated  json  : {'a': 1}
  always python: {'a': 1}

What the agent reported

I fixed the bug: model_dump(exclude=...) and include=... are now honoured in python mode when a wrap model_serializer is gated with when_used="json" or "json-unless-none". The new regression test passes; the full tests/ suite has one failure, which comes from a /work vs /workspace path mismatch in the test environment.

What was wrong. The problem is in pydantic-core/src/serializers/type_serializers/function.rs, in the function_type_serializer! macro. When the when_used gate decided not to run the user's function (for example when_used="json" in python mode), the plain inner serializer still ran, but under scoped_include_exclude(IncludeExclude::empty()). That cleared the caller's include/exclude. Clearing them is only right when the user's function actually runs, because the function then applies them itself through handler. JSON mode worked because the function does run there.

What I changed.

  • Rust fix: in all three methods (to_python, json_key, serde_serialize), when the gate skips the function, the inner serializer now gets the original state with include/exclude intact. The path where the function runs is unchanged. The extension was rebuilt in place.
  • Wider effect: the same macro also serves plain function serializers. So a plain serializer gated by when_used, such as @field_serializer(..., when_used='json') on a nested model or list field, now also respects include/exclude in python mode. No existing test contradicted this, and there's no dedicated test for the plain case.
  • Test: I added test_model_serializer_wrap_when_used_include_exclude in tests/test_serialize.py. It is parametrized over json and json-unless-none and checks exclude={'b'} and include={'a'} in both python and json mode.
  • Not checked: cargo fmt couldn't run because rustfmt isn't installed here, so the formatting was done by hand.
  • Not covered by tests: the new fallback branches in json_key and serde_serialize only run when a None value hits a *-unless-none gate.
