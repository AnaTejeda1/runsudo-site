In this judgment, Patch A = our agent, Patch B = the merged fix.

The lint fires because the source root equal to `dir` produces the bare entry `"*"`. Without `baseUrl`, TypeScript and VS Code require `paths` entries to be relative.

Correctness: Patch A fixes the entry itself by prefixing `./` when the path isn't already relative. The mapping becomes `"./*"`, which is valid without `baseUrl` and keeps the original meaning. Non-relative imports like `js/foo` still resolve against the assets directory in the editor. Entries for other roots already start with `../` and are left unchanged. Patch B silences the lint by dropping the current root from `paths` entirely. That removes a mapping that was doing useful work. When other roots exist, bare imports no longer fall back to the site's own assets directory. When the site's assets dir is the only root, `Build` returns nil and no jsconfig is produced at all. B masks the symptom by removing functionality, while A corrects the malformed value.

Tests: Both add tests that would fail before their change. A's test checks the exact output: `./*` for the self root and `../../c/assets/*` for another root, using `filepath.FromSlash` so it works across platforms. It fails on the old code, which emitted `*`. B's test only asserts nil for a single self root, which tests the new skip behavior rather than validity of the output.

Scope and craft: Both are small and focused. A's prefix check is simple and consistent with the existing `filepath` usage. B's comment is clear, but the behavioral regression outweighs that.

Overall, A is the more faithful root-cause fix.

The issue

View on GitHub

When building a site that calls js.Build, the assets/jsconfig.json file looks like this:

{
 "compilerOptions": {
  "paths": {
   "*": [
    "*"
   ]
  }
 }
}

VS Code lints line 5 as follows:

Non-relative paths are not allowed when 'baseUrl' is not set. Did you forget a leading './'?

What the agent reported

The generated assets/jsconfig.json no longer triggers the VS Code notice. The regression test fails before the fix and passes after, but only when run directly with go test. ./bt-test never got as far as running tests.

What was wrong: An earlier commit (ff2903a93) removed the deprecated baseUrl setting from the generated file. Without baseUrl, TypeScript and VS Code require every entry under compilerOptions.paths to start with ./ or ../. When the source root is the folder holding jsconfig.json (the normal case, the project's own assets folder), Build in resources/jsconfig/jsconfig.go wrote a bare "*". That is the entry VS Code flagged on line 5.

What changed:

  • resources/jsconfig/jsconfig.go: Build now adds a ./ prefix to any path that doesn't already start with ./ or ../, so "*" becomes "./*". Paths that already start with ../ are unchanged. It uses the same separator style as the rest of the code, and TypeScript accepts either slash.
  • resources/jsconfig/jsconfig_test.go: I added a case to TestJsConfigBuilder with source roots /a/b and /c/assets and Build("/a/b"). It expects ["../../c/assets/*", "./*"]. The existing checks are unchanged.

Test evidence:

  • ./bt-test did not produce a result. It exited 1 three times (once with the test only, twice after the fix) because the setup step couldn't download github.com/bep/helpers@v0.12.0: there is no network, and it doesn't use the local module cache at /bt/cache/go-mod. No tests ran, so these runs say nothing either way.
  • Direct runs against that cache, offline:
  • Before the fix, the new check failed with got []string{"*", "../../c/assets/*"}, want []string{"../../c/assets/*", "./*"}.
  • After the fix, ./resources/jsconfig/ passes, and the neighbouring ./internal/js/esbuild tests also pass.

Blast radius: Build is only called from hugolib/hugo_sites_build.go:665, where the file is written, and no other tests check these paths. A read-only reviewer found the fix correct, including folder names that start with dots and Windows separators.

Requirements:

  1. Remove the VS Code notice "Non-relative paths are not allowed when 'baseUrl' is not set": done. The generated path is now ./*, shown by the new check failing before the fix and passing after.
  2. Don't bring back baseUrl: kept. The existing check that the output has no baseUrl still passes.
