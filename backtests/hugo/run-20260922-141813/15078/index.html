Summary

What was wrong

hugo new content posts/drafts/trip-to-puebla/index.md failed with a false no page found for "…"; the target path conflicts with existing content error and left only a "Content Placeholder" file — but only when the target sat under a section whose branch-bundle _index.md had cascade: {draft: true}.

hugo new content writes a temporary placeholder content file, runs an internal non-draft build to resolve the page object (so the archetype can be applied), then overwrites the placeholder with the rendered archetype. The parent section's cascade: {draft: true} was marking the placeholder page as a draft; the non-draft build dropped it (content_map_page_assembler.go → site.shouldBuild), so HugoSites.GetContentPage returned nil and create/content.go reported the false conflict. Paths not under a draft cascade (e.g. posts/2026/07/foo/index.md) were unaffected — matching the report exactly.

What I changed

  • hugolib/content_factory.go — added a single draft: false line to the placeholder front matter in CreateContentPlaceHolder. A page's own front-matter value takes precedence over an inherited cascade value (verified in hugolib/page__meta.go: front matter fills pageConfig.Params first; cascade only fills keys not already present), so the transient placeholder is no longer treated as a draft and survives the internal build. The placeholder is immediately overwritten by the applied archetype, so draft: false never persists to the user's file.
  • testscripts/commands/new_content.txt — added an "Issue 15078" regression scenario (+ a -- drafts-index.md -- block) that creates a section with cascade: draft:true, runs hugo new content under it, and asserts the real archetype output (Trip to Puebla) is present and Content Placeholder is not.

I intentionally did not enable a global BuildDrafts for this build (my first attempt did, and it broke the existing Issue 12786 scenario, which relies on a real draft leaf-bundle being dropped to detect a resource conflict). The surgical placeholder change preserves that behavior.

Test evidence

  • Regression test failed before the fix with the exact reported error (no page found … the target path conflicts with existing content).
  • After the fix: TestCommands/new_content passes (all scenarios: 12599, 12602, 12786, 14112, 15078, archetypedir), and the full create package (TestNewContentFromFile/*, TestNewContentFromDirSiteFunction) passes — confirming no regression in the shared placeholder path.
  • Reviewer confirmed the diff is minimal, matches the report, and cannot persist draft: false to user content.

Requirements checklist

  1. Fix the false "target path conflicts" error under a draft: true cascade — implemented + tested (regression test fails before / passes after).
  2. Behavior identical whether target is trip-to-puebla/index.md or trip-to-puebla — same code path (buildFile); the fix targets the shared placeholder, so both forms are covered. Not separately scripted, but the mechanism is path-form-independent.
  3. Non-drafts case (posts/2026/07/foo/index.md) must keep working — preserved; no cascade means no draft, and create tests + other new_content scenarios pass.
  4. Don't break existing conflict detection (12602 dir conflict, 12786 leaf-bundle resource conflict, 14112 case collision) — verified; all pass, and I explicitly avoided the global-BuildDrafts approach that broke 12786.
