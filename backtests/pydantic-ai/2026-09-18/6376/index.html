What the agent reported

The fix is complete and verified. Here is my final report.

What was wrong

ToolOutput.__init__ in pydantic_ai_slim/pydantic_ai/output.py accepted max_retries and stored it directly with no validation. Negative values would silently produce undefined retry behavior — inconsistent with Tool.max_retries, which was fixed in #6375 to reject negatives with a UserError.

What I changed

pydantic_ai_slim/pydantic_ai/output.py — added a 2-line guard at the top of ToolOutput.__init__, before any attribute assignment:

if max_retries is not None and max_retries < 0:
    raise exceptions.UserError(f'max_retries must be >= 0, got {max_retries}')

This mirrors #6375 exactly (same condition, same message string). It uses exceptions.UserError because that file already references UserError via the exceptions module rather than a bare import — keeping the change minimal and localized. None is still accepted (preserves the "use agent-level default" behavior).

tests/test_agent_output_schemas.py — added UserError to the existing from pydantic_ai import (...) block and appended a "ToolOutput parameter validation" region with three tests mirroring the #6375 test set: test_tool_output_rejects_negative_max_retries (the reported scenario → UserError), plus zero and None boundary cases.

Test evidence

  • Before the fix: test_tool_output_rejects_negative_max_retries failed with DID NOT RAISE UserError; the zero/none tests passed.
  • After the fix: all three new tests pass.
  • No regressions: the full tests/test_agent_output_schemas.py file — 18 passed.
  • Reviewer confirmed the diff matches the #6375 convention, asserts the user-visible outcome, and changes nothing unrelated.

Working tree contains only my two edits (the three pre-existing file deletions from the session-start snapshot are unrelated and untouched by me). No commits made.
