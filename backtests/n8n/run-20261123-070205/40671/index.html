Agent with AWS Bedrock - lite llm via the open ai creds

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

The issue is that an agent using OpenAI credentials with a custom base URL (LiteLLM in front of Bedrock) fails because the runtime now injects the OpenAI-only `prompt_cache_key` field, which the proxy rejects, and this used to work. Patch A fixes this at the root: it adds `usesOfficialOpenAiApi` (reusing the same custom-endpoint rule the OpenAI builder already uses, covering both `baseURL` and the `url` alias) and makes `buildCallPromptCacheOptions` stop generating `prompt_cache_key`/`prompt_cache_retention` for non-official endpoints, while still honoring explicitly configured values. It threads the flag through the call-site provider options, skills cache TTL, and memory orchestrator, and adjusts retention defaulting accordingly. The user's existing configuration starts working again with no action. Tests are solid: unit tests for the new helper and for the suppression/explicit-passthrough behavior, plus an end-to-end test with a fake `/responses` endpoint that returns the LiteLLM 400 whenever the cache fields are present, exercised in both generate and stream modes and asserting the request body lacks the fields. Patch B does not fix the reported failure. With the product's default (force-on) caching, it still sends the fields to the custom endpoint; its own test explicitly asserts that `prompt_cache_key` and `prompt_cache_retention: '24h'` are sent to the custom endpoint when caching is on. Instead it maps the rejection to a friendlier error telling the user to turn off prompt caching, and builds the plumbing (shared resolver, builder write-path, builder prompt, Vue toggle, i18n, SSE stringification, docs) to let users opt out. That is a symptom-level workaround requiring manual user intervention, so the issue's scenario ('this was possible before') remains broken by default. The error detection is also heuristic (regex over message text across several payload shapes), and the change is far broader in scope and risk than the ask. B's opt-out toggle is a reasonable adjacent feature, but it earns no credit as a fix. The independent tests crashed on all trees, so they provide no signal either way; judged on the diffs, A resolves the root cause with targeted, well-tested changes.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.
