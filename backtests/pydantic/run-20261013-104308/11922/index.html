Some Field attributes lost in JSON schema when using RootModel

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the issue in the same place, `GenerateJsonSchema._update_class_schema`. Each one reads the RootModel's `root` FieldInfo and emits `examples` (via `to_jsonable_python`), `deprecated: True`, and the root field's title. Both let an explicit `config['title']` take precedence over the field title.

Correctness differences are minor:
- **Title precedence:** Patch A puts the root field title ahead of `model_title_generator`. Patch B applies it only when neither config title nor generator set one. An explicit field title is arguably more specific than a generic generator, so A's ordering is reasonable, but neither choice is clearly wrong.
- **Examples:** Patch A overwrites `examples`, while Patch B uses `setdefault`. The inner schema rarely has its own examples here, so this is roughly equivalent.
- **Deprecated:** Patch A checks `is not None and is not False`, which handles deprecation-message strings and `deprecated` instances. Patch B uses truthiness, which is equivalent except for an empty-string message.
- **Description:** Patch A also refactors the existing description branch to reuse the cached `root_field_info`. This is a small clarity improvement with no added risk.

Tests are the main differentiator. Both cover examples, deprecated, title, and config-title override. Patch A goes further:
- It checks that a non-JSON-native example (a `date`) is serialized to `'2020-01-02'`, exercising the `to_jsonable_python` path.
- It checks that a string deprecation message yields `deprecated: True`.
- It checks the nested-in-model case, where the RootModel appears under `$defs` with the title and examples intact. This is the realistic usage scenario.

Patch B's tests are narrower and miss these paths. Overall the fixes are equivalent in substance, and A has stronger test coverage and slightly cleaner code.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

When declaring a RootModel and adding a Field annotation to the root property that includes examples, those examples are not part of the generated JSON schema. This also applies to the deprecated attribute. The title attribute is also not applied or it is overwritten by the class name of the root model class.

Most other attributes, such as pattern or description are exposed as expected. Furthermore, placing examples in json_schema_extra also works as expected.

Example Code

from typing import Annotated
from pydantic import RootModel, Field

class Foo(RootModel):
    root: Annotated[str, Field(examples=["foo", "bar"], deprecated=True)]

print(Foo.model_json_schema())  # does not include examples or deprecated.
