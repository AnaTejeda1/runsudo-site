Exceptions without a traceback print multiple times if chained

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches stop the duplication for the issue's exact example (independent tests for the plain chain pass on both). Patch B does so by passing chain=False to format_exception in the no-traceback fallback only. That leaves the same root cause in the exception-group branch, which also calls format_exception with chaining enabled and even formats the outer excinfo.value instead of the current chain element `e`, so a traceback-less exception group in a chain still gets its chain printed twice; the independent test test_exception_group_without_traceback_in_chain fails on B and passes on A. B's chain=False would also drop the __cause__/__context__ of exception-group members if a group ever hit the fallback. Patch A addresses the root cause in both call sites with a helper that nulls only the top-level cause/context on a TracebackException, preserving member chains, and fixes the excinfo/excinfo_ mix-up. Its tests cover the issue example, group chain non-duplication, and member chains still shown; the adjustment to the existing exceptiongroup test expectation (matching the E-prefixed SyntaxError line) follows from no longer natively rendering the chain and is consistent. B's changelog and AUTHORS entries are good convention, but they do not outweigh an incomplete fix. A wins on correctness and test coverage.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.

Minimal example:

def test_errors():
    ex1 = ValueError("abcd")
    ex2 = IndexError("efgh")
    ex3 = KeyError("ijkl")
    ex4 = RuntimeError("mnop")
    ex1.__cause__ = ex2
    ex2.__context__ = ex3
    ex3.__cause__ = ex4
    raise ex1

What's happening is a little clearer when running with colourful output, the first, third and sixth "the above exception" lines are highlighted, but the rest are plain. Seems at each step of the chain, the full traceback for that exception is output, which includes that of any that happened higher in the chain. This only happens if __traceback__ is None, in practice I found this by messing with it on caught exceptions.
