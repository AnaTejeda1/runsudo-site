The issue

View on GitHub

Hugo's built-in js.Build function currently doesnt support and/or list es2025 as available target parameter.
As far as i understood js.Build relies on evanw/esbuild for bundling, transforming and minifying javascript ressources.

According to hugo's own release notes esbuild was just bumped to 0.28.2.
According to esbuild's release notes, support for es2025 as target parameter exists since 0.27.5.
Hugo should therefore support es2025 as target parameter.

However when doing something like this:

{{- $buildParams := dict
    "minify" true
    "sourceMap" "none"
    "target" "es2025"
}}
{{- with . | js.Build $buildParams }}
    <script>{{ .Content | safeJS }}</script>
{{- end }}

results in the following error message:
`
... JSBUILD: failed to transform "/ts/test.ts" (text/typescript): unsupported target: [es2025] ...
`

What the agent reported

The fix is complete and verified. Final report:

What was wrong

Hugo's js.Build maps a target string (e.g. "es2020") to an esbuild target enum via the nameTarget map in internal/js/esbuild/options.go. That map stopped at "es2024". When "es2025" was requested, the lookup in compile() found nothing, target stayed 0, and the guard if target == 0 && len(engines) == 0 && len(opts.Target) > 0 fired, producing the reported error unsupported target: [es2025]. The evanw/esbuild dependency (v0.28.2, which includes ES2025 support since 0.27.5) already exposed the api.ES2025 constant — Hugo simply never mapped it.

What I changed

Two files, one line each:

  • internal/js/esbuild/options.go — added "es2025": api.ES2025, to the nameTarget map, right after the es2024 entry.
  • internal/js/esbuild/options_test.go — added {"es2024", api.ES2024} and {"es2025", api.ES2025} table entries to the existing TestToBuildOptionsTarget (which previously only covered up to es2023).

I left the stale Target doc comment (which already omits es2021–es2024) untouched to keep the change minimal — it's pre-existing and out of scope.

Verification

  • I confirmed api.ES2025 exists in the esbuild v0.28.2 module cache inside the build container.
  • Gate run: ./bt-test -run 'TestToBuildOptions|TestDecodeExternalOptions' ./internal/js/esbuild/ — all esbuild option tests pass, including the new TestToBuildOptionsTarget/es2024 and TestToBuildOptionsTarget/es2025 subtests, with no failures anywhere in the report. The regression test is genuine: without the map entry, es2025 would error (unsupported target) rather than mapping to api.ES2025.
  • The reviewer confirmed the fix targets exactly the reported code path, the regression test is real, no existing test was weakened, and the diff is limited to these two files (plus the pre-existing AGENTS.md/CLAUDE.md deletions from the initial working-tree state).

All changes are left uncommitted in the working tree.
