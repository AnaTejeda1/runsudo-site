Scoped slot transforms array argument if rendered conditionally

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the core v-if case the same way. When a `<slot>` gets a compiler-injected key, the key goes to a new 6th `renderSlot()` argument instead of being merged into the slot props, and the runtime gives a user-provided `props.key` precedence. For `<slot v-if v-bind="arr">`, both now emit `_renderSlot($slots, "default", _normalizeProps(_guardReactiveProps(arr)), undefined, undefined, 0)`, so the array reaches the slot unchanged.

Patch A is more thorough on correctness. It also stops `pushRefVForMarker()` from adding `ref_for: true` to a slot's v-bind object. Without that, `<slot v-for ... v-bind="g">` and keyed `<template v-for><slot v-bind="g.items"/></template>` would still become `mergeProps({ref_for: true}, g)` and turn the array into an object. That is the same class of bug the issue reports (behaviour changing depending on surrounding directives). Patch B does not touch `buildProps`, so in v-for contexts the array is still converted, and its key-only injection there does not help.

Patch A's change is also narrower. It only reroutes the key for the single-v-bind-expression case and leaves the existing `{ key: 0 }` object-literal output intact, which is harmless because that is already an object. Patch B reroutes every slot key injection, changes existing snapshots, and widens the `RenderSlotCall` AST types. That is more churn and more risk.

On tests, Patch A adds compiler tests for v-if/v-else, v-for and keyed template v-for, runtime `renderSlot` tests, and full compile-plus-runtime integration tests. These include `Array.isArray` checks and a keyed reorder. Patch B's tests cover v-if and the runtime, including custom-element mode. However, it also writes a vFor snapshot entry into `transformElement.spec.ts.snap`, which is sloppy and points to a test-harness mistake.

Overall, Patch A fixes the root cause across the related scenarios with cleaner scope and stronger tests.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Steps to reproduce

  1. Create a component with a scoped slot that is rendered conditionally
  2. Pass an array as the sole argument to the slot

What is expected?

Array is rendered normally.
If you render items of that array in v-for loop, you only see items inside that array

What is actually happening?

Array is transformed into object. Items and their indexes are staying the same, key field is added
