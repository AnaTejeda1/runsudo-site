Issue #12569 Merged fix PR # Run 9 Oct 2026 · run-20261009-161443 vuejs/core

Custom directive's unmounted event is not triggered on v-for element

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Root cause: in a stable v-for (constant source), the child is first forced into a block, either by a dynamic `:key` or by a before-update hook / custom directive with children. Because it is a block, buildProps skips NEED_PATCH. transformFor then demotes it to a plain vnode, so it is missing from the parent's dynamicChildren and its directive/ref/vnode-hook unmount is skipped.

Both patches restore NEED_PATCH on demotion, so both fix the reported `:key` + directive case.

Patch A carries the decision from buildProps itself. It adds `needsPatch` and `isBlockRequired` on the VNodeCall, so the vFor transform reuses the same analysis instead of duplicating it. A also sees the deeper problem. When an element was made a block so that before-update hooks run before its children update, demoting it to a plain vnode breaks that ordering. Nested dynamic children get collected into the fragment's dynamicChildren ahead of the parent and are patched before the parent's beforeUpdate. A keeps such elements as blocks (`isBlockRequired`). It also handles the camelized `vue:beforeUpdate` spelling. Its runtime tests check this ordering, and they check unmount of directive hooks, vnode hooks, static ref arrays and setup-const function refs.

Patch B re-scans the AST props in vFor with a hand-written mirror of buildProps' condition. That copy is fragile and partly odd: it checks `on` args starting with `vnode`, and only static args. B also demotes before-update/directive-with-children blocks, which keeps the hook-ordering regression. Its compiler test even asserts that `<p v-for v-foo>hi</p>` becomes a non-block vnode. B's integration tests are good for the reported scenario but never exercise ordering with nested dynamic children.

Overall, A fixes the root cause more robustly and preserves the block semantics. It has broader, meaningful tests and only a modest increase in scope.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
