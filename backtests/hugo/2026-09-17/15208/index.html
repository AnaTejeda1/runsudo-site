Summary

What was requested: A new template function resources.Publish so a resource can be published inline within a pipeline —

{{ resources.Get "main.js" | js.Build | resources.Publish }}

— instead of the awkward {{ (resources.Get "main.js" | js.Build ).Publish }}. It should return the Resource it receives as input so the pipeline keeps flowing.

What I changed (3 files, all uncommitted):

  1. tpl/resources/resources.go — Added a Publish method on *Namespace, placed next to the existing Copy method: go func (ns *Namespace) Publish(r resource.Resource) (resource.Resource, error) { dst, ok := r.(resource.Source) if !ok { return nil, fmt.Errorf("resource %T does not implement resource.Source", r) } if err := dst.Publish(); err != nil { return nil, err } return r, nil } The Publish() error method lives on the internal resource.Source interface (not resource.Resource), so the input is type-asserted before calling it. On success it returns the same resource r, enabling pipeline chaining.
  1. tpl/resources/init.go — Registered ctx.Publish via AddMethodMapping, following the existing pattern.
  1. tpl/resources/resources_integration_test.go — Added TestResourcesPublish, which runs {{ $r := resources.Get "main.js" | resources.Publish }} through the real template pipeline, asserts the file lands at public/main.js, and asserts $r.RelPermalink renders — proving the return value is the usable resource.

Test evidence (./bt-test, results from test-report.json):

  • TestResourcesPublish — PASS
  • TestGet, TestCopy, TestCopyPageShouldFail, TestGlobalResourcesNotPublishedRegressionIssue12190, TestGlobalResourcesNotPublishedRegressionIssue12214 — all PASS
  • 0 failures across the entire suite.
