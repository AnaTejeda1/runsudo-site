The Playground's TS version is set to 7 by default.

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause the same way: they pass an explicit `typescriptVersion` ref to `useStore`, so the playground stops defaulting to `latest` (TS 7).

Patch B pins the exact version '6.0.3'. That is simple and safe, but it will go stale as 6.x patch releases ship. It also gives users no hint that TS 7 is unsupported, which the issue explicitly asked for ('It is helpful to tell that').

Patch A defaults to the bare major '6'. jsDelivr resolves that to the newest 6.x release, so the default keeps up with patch releases. Patch A also:
- Marks TS 7+ entries (and `latest`) in the version dropdown as '(unsupported)' with an explanatory tooltip, which covers the issue's secondary ask.
- Fixes the active-item highlighting so the bare-major default highlights the release it resolves to.
- Moves the logic into a small, testable module.

Patch A's tests exercise real behavior (the default is major 6, support detection, active-version resolution). Some assertions are close to tautological, but the `isActiveVersion` tests are meaningful. Patch B adds no tests.

The main risk in A is relying on a bare major tag being accepted wherever @vue/repl uses the version. This is plausible given jsDelivr semantics, but it is less certain than B's exact pin. On balance, A covers more of the issue, is more robust over time, and is tested.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
