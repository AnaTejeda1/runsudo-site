Summary

What was wrong: TypeAdapter.json_schema() never threaded the adapter's config into JSON Schema generation. It created a GenerateJsonSchema instance whose config-wrapper stack held only an empty default ConfigWrapper({}). For a bare type like bytes, nothing ever pushed the adapter's config onto that stack (only the model/dataclass/typeddict handlers push config, which is why BaseModel worked). So bytes_schema read the default ser_json_bytes='utf8' and emitted format: 'binary' instead of 'base64url'.

What I changed (pydantic/type_adapter.py, json_schema()): wrapped the generate() call in with schema_generator_instance._config_wrapper_stack.push(self._config):, so the adapter's config becomes the stack tail during generation. ConfigWrapperStack.push is a no-op when passed None, so the class-based case (where self._config is always None — a config for a BaseModel/dataclass/TypedDict raises at construction) is unaffected.

Test evidence:

  • Added test_type_adapter_config_bytes in tests/test_json_schema.py, mirroring the existing test_*_default_bytes idiom, parametrized base64 → base64url (the reported bug) and utf8 → binary.
  • Confirmed it failed before the fix (assert {'format': 'binary'} == {'format': 'base64url'}) and passes after.
  • Gate: ./bt-test tests/test_json_schema.py tests/test_type_adapter.py → 776 passed, 3 skipped, 2 xfailed (skips/xfails pre-existing). No previously passing test regressed — the blast radius (all TypeAdapter.json_schema callers) is covered by these suites.
  • Reviewer confirmed correctness, minimality, no unrelated changes, no scratch files.
