The Rust changes are functionally identical. Both add `by_alias`/`by_name` fields to `InternalValidator`, capture them from `Extra` in `new`, and forward them in both `validate` and `validate_assignment`. The only difference is where the struct fields sit. That fixes the root cause: the wrap handler (and generator item validation) was rebuilding `Extra` with `by_alias: None, by_name: None`. Correctness is therefore a wash, and the decision rests on the tests. Patch A's tests follow the issue closely. They reproduce the alias_generator + `validate_by_name=True` setup and go through `TypeAdapter.validate_python`, `validate_json` and `model_validate`. They are parametrized over a plain model and a wrapped model, so the plain model acts as a control. They also cover a WrapValidator on a field and the generator/Iterable path, which is the other user of `InternalValidator` in `generator.rs`. All of these fail before the fix. Patch B's first test also checks by_alias/by_name for a wrap model validator and a wrap field validator, so it is valid regression coverage, though it omits the JSON path and the generator path. Its second test checks strict, extra, from_attributes and context forwarding. Those settings were already forwarded before the patch, so that test would pass on the old code and adds little evidence about this fix. Patch A's tests cover the fix more fully, including the generator code path the change also touches, so A is slightly better.

Description

The handler passed to a wrap-mode model validator appears to silently drop the passed-in by_name/by_alias arguments from the top-level validate_python methods.

Example Code

from typing import Self
from pydantic import BaseModel, TypeAdapter, ValidatorFunctionWrapHandler, model_validator

CFG = {"alias_generator": lambda s: s.replace("_", "-"), "validate_by_name": True}

class Plain(BaseModel):
    model_config = CFG
    build_depends: list[str] = []

class Wrapped(BaseModel):
    model_config = CFG
    build_depends: list[str] = []

    @model_validator(mode="wrap")
    @classmethod
    def _noop(cls, data, handler: ValidatorFunctionWrapHandler) -> Self:
        return handler(data)

data = {"build_depends": ["x"]}  # field name, not the alias
print(TypeAdapter(Plain).validate_python(data, by_alias=True, by_name=False))    # build_depends=[]    correct
print(TypeAdapter(Wrapped).validate_python(data, by_alias=True, by_name=False))  # build_depends=['x'] wrong
