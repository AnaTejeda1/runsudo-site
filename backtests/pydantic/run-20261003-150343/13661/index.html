Runtime by_name/by_alias arguments dropped by model_validator(mode="wrap")

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches make the same core fix in `pydantic-core/src/validators/generator.rs`. Each adds `by_alias`/`by_name` fields to `InternalValidator`, captures them from `Extra` in `new`, and forwards them in both `validate` and `validate_assignment` instead of hard-coding `None`. This fixes the root cause: the wrap-validator handler and the generator both go through `InternalValidator`. The Rust changes are functionally identical. The only difference is where the struct field is placed; B's spot next to `context` is marginally tidier, but this is cosmetic.

Tests are the deciding difference. Patch A's parametrized test covers four alias/name combinations across several paths:
- `model_validate`, `TypeAdapter.validate_python` and `model_validate_json`, for both a plain model and a model with a wrap `model_validator`.
- A nested field-level wrap validator, for both Python and JSON input.
- Lazy generator validation via `Iterable[...]`, which also uses `InternalValidator` and so is a second regression site fixed by the same change.

Patch B's first test covers the model-wrap and nested field-wrap cases for Python input only. It does not exercise the JSON path or the generator path. B's second test checks context, strict, extra and from_attributes forwarding. Those settings were already propagated before this change, so that test is regression hardening rather than a check that would fail before the fix. It is neutral under the scope criterion.

With the fixes equivalent, A's broader coverage of the affected code paths, including the generator and JSON validation, makes it the somewhat stronger patch.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

The handler passed to a wrap-mode model validator appears to silently drop the passed-in by_name/by_alias arguments from the top-level validate_python methods.

Example Code

from typing import Self
from pydantic import BaseModel, TypeAdapter, ValidatorFunctionWrapHandler, model_validator

CFG = {"alias_generator": lambda s: s.replace("_", "-"), "validate_by_name": True}

class Plain(BaseModel):
    model_config = CFG
    build_depends: list[str] = []

class Wrapped(BaseModel):
    model_config = CFG
    build_depends: list[str] = []

    @model_validator(mode="wrap")
    @classmethod
    def _noop(cls, data, handler: ValidatorFunctionWrapHandler) -> Self:
        return handler(data)

data = {"build_depends": ["x"]}  # field name, not the alias
print(TypeAdapter(Plain).validate_python(data, by_alias=True, by_name=False))    # build_depends=[]    correct
print(TypeAdapter(Wrapped).validate_python(data, by_alias=True, by_name=False))  # build_depends=['x'] wrong
