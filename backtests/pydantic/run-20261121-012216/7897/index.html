Performance issues with parsed datetime comparisons pydantic_core.TzInfo

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Patch A fixes the root cause: it emits stdlib `datetime.timezone` objects (`timezone.utc` for zero offset, cached per-offset instances otherwise), so CPython's identity fast path applies to every parsed datetime with the same offset, not just UTC. Patch B only interns the zero-offset `TzInfo`; every non-UTC offset still gets a fresh `TzInfo` instance, so comparisons between datetimes with the same non-UTC offset still go through `utcoffset()` calls. The independent tests confirm this split: A passes all five, while B fails the same-non-UTC-offset sorting test with essentially base-level slowness (64.5x). The issue's stated expectation is that Pydantic 'use a performant tzinfo when parsing datetime objects' and it explicitly contrasts with v1's `datetime.timezone.utc`, which A restores. A also updates the existing repr/type tests, adds identity and sort tests for both datetime and time validators, and fixes the docs to match the new output. A's downside is a visible behavioral change (tzinfo type and `tzname` format change from `TzInfo(...)` to stdlib timezone), which is a compatibility risk and a broader scope than strictly needed, and it adds an LRU cache with a mutex. But that change is exactly what the issue requests, the caching is bounded and race-safe (get_or_insert, lock released while calling into Python), and the Rust is clear. B is minimal and low-risk but leaves a clearly implied part of the problem unsolved. Correctness and test coverage favor A decisively.

Initial Checks

  • I confirm that I'm using Pydantic V2

Description

Compared to Pydantic v1, v2 performs much more slowly when doing comparisons between parsed datetime objects with time zone information. This is likely caused by the time zone information being parsed into a pydantic_core.TzInfo object rather than the vanilla datetime.timezone object.

Example of the parsed datetime difference between the two versions:

v1: datetime.datetime(2023, 5, 24, 4, 0, tzinfo=datetime.timezone.utc)
v2: datetime.datetime(2023, 5, 24, 4, 0, tzinfo=TzInfo(UTC))

This performance degradation can be seen clearly when sorting a large number of parsed datetime objects. I suspect this is due to adjustments that need to be made for daylight savings time and UTC offsets, but when working in UTC those shouldn't come into play. In my example you can see that using my local time zone (EDT) has similar performance issues using datetime.timezone, although pydantic_core.TzInfo still has worse performance in UTC.

For now a simple fix is to set the time zone to a pytz time zone as there is no performance degradation there (like in the example code), but I would expect that Pydantic would use a performant tzinfo when parsing datetime objects.

For reference, here is the output of the example code when running on my machine:

10.41208 - pydantic_core.TzInfo
6.05901 - datetime.astimezone()
0.45409 - datetime.astimezone(timezone.utc)
0.47059 - datetime.astimezone(pytz.utc)
0.47961 - datetime.astimezone(pytz.timezone('US/Eastern'))

Example Code

import random
import time
from datetime import datetime, timedelta, timezone

import pydantic_core
import pytz

n = 1000000
now = datetime.today()

offsets = [timedelta(hours=random.random() * 72) for _ in range(n)]

dates_pydantic = [(now - offset).replace(tzinfo=pydantic_core.TzInfo(0)) for offset in offsets]
dates_dt = [d.astimezone() for d in dates_pydantic]
dates_dt_utc = [d.astimezone(timezone.utc) for d in dates_pydantic]
dates_pytz = [d.astimezone(pytz.utc) for d in dates_pydantic]
dates_pytz_est = [d.astimezone(pytz.timezone('US/Eastern')) for d in dates_pydantic]

start = time.time()
sorted(dates_pydantic)
print(f"{time.time() - start:0.5f} - pydantic_core.TzInfo")

start = time.time()
sorted(dates_dt)
print(f"{time.time() - start:0.5f} - datetime.astimezone()")

start = time.time()
sorted(dates_dt_utc)
print(f"{time.time() - start:0.5f} - datetime.astimezone(timezone.utc)")

start = time.time()
sorted(dates_pytz)
print(f"{time.time() - start:0.5f} - datetime.astimezone(pytz.utc)")

start = time.time()
sorted(dates_pytz_est)
print(f"{time.time() - start:0.5f} - datetime.astimezone(pytz.timezone('US/Eastern'))")
