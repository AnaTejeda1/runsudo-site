The "failed to extract" error refers to outer shortcode instead of inner shortcode

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The issue's case is an inner shortcode (`img`) whose template uses `.Inner` but which is never closed. The parser lets `img` consume `{{< /figure >}}` as its own closing tag, so the error is then reported as an unclosed `figure`. Patch B fixes this at the root: when a closing tag's name does not match the current shortcode's name, it reports that the current (inner) shortcode "must be closed or self-closed". Patch B also wraps errors from nested shortcodes with the nested shortcode's position, so the reported line and column point at the inner shortcode. Its tests reproduce the issue's figure/img/figcaption structure, cover the unclosed case at one and two nesting levels plus a template-not-found case, and include a positive case confirming that properly closed and self-closed nesting still renders. Patch A only adds position wrapping for errors from nested extraction, and its test covers only a missing inner template. It does nothing about the closing-tag mismatch, so the issue's exact scenario would still produce `unclosed shortcode "figure"`. Patch A therefore addresses only an adjacent symptom, not the reported bug.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
