Summary

What was wrong

Deleting or renaming a directory inside static/ while hugo server was running caused a panic:

panic: unknown component: "static" in processPartialFileEvents (hugolib/hugo_sites_build.go:1084)

In hugolib/hugo_sites_build.go, the processPartialFileEvents function processes filesystem events for partial rebuilds. When a static/ directory is removed, the event resolves to a *paths.Path whose Component() is "static" (the extensionless-directory removal path appends /_index.md to the path string but keeps the static component). That path is fed into the handleChange closure's switch pathInfo.Component(), which only had cases for content/layouts/assets/data/i18n/archetypes — so "static" fell through to default: panic(...).

What I changed

  • hugolib/hugo_sites_build.go (production fix): Added a case files.ComponentFolderStatic: before the default panic. Static files are synced to the output separately (by the static syncer in server mode) and aren't part of the page/resource dependency graph, so the case only logs — it adds no identity changes, doesn't set needsPagesAssemble, and doesn't trigger a coarse rebuild. Minimal, 7-line change.
  • hugolib/rebuild_test.go (regression test): Added TestRebuildRenameDirectoryStatic, which seeds static/mydir/file.txt, runs in watch/running mode, then renames the static directory and rebuilds — exactly the reported scenario.

Test evidence

  • The test-writer confirmed fail-before/pass-after: with the fix temporarily reverted, the test fails with panic: unknown component: "static" at hugo_sites_build.go:1084; with the fix restored it passes.
  • My authoritative gate — ./bt-test -run TestRebuild ./hugolib/ — passed: 59 rebuild tests passed, 0 failed, including the new TestRebuildRenameDirectoryStatic.

All changes are left uncommitted in the working tree. (Note: the pre-existing AGENTS.md/CLAUDE.md deletions shown in git status predate this task and are unrelated to the fix.)
