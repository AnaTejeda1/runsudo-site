Description

At commit cd1d8be820a8036818d6e82603a3ab07e0f855b5, make help describes test-examples as “Run only the tests from the documentation”, but make test-examples exits successfully without evaluating documentation examples on Linux.

The recipe searches docs/examples for *.py. All eight files currently in that directory are Markdown, so the search has no matches. Contributors using this target to check an edited example receive no test results and can miss errors.

The existing tests/test_docs.py suite discovers Markdown and docstring examples and handles their skip, Python-version, grouping and expected-failure settings. Could this target delegate to that suite? Normal pytest already covers these examples; the problem is the dedicated Makefile command.

Source references:

  • Makefile recipe
  • Current documentation runner
  • Contributor instructions for example testing

Example Code

With the development testing dependencies available, run these commands from that checkout:

find docs/examples -type f -name '*.py'
make test-examples

The search produces no output. The target prints the uv version and running examples, then exits 0.

For a failure control, temporarily add this assertion after pydantic_model = MyModel.model_validate(sql_model) in the Python code block in docs/examples/orms.md:

assert pydantic_model.model_dump() == {'metadata': {'key': 'wrong'}}

The original target still exits 0. Replacing its recipe with uv run pytest tests/test_docs.py detects the assertion ('val' != 'wrong'): 730 collected, 625 passed, 104 skipped, 1 failed; make exits 2. Removing the temporary assertion gives 626 passed and 104 skipped with make exiting 0.
