Description

pydantic_core.to_json (and to_jsonable_python) documents timedelta_mode and temporal_mode as independent parameters governing disjoint type sets:

  • timedelta_mode: How to serialize timedelta objects, either 'iso8601' or 'float'.
  • temporal_mode: How to serialize datetime-like objects (datetime, date, time), either 'iso8601', 'seconds', or 'milliseconds'.

(This is what both the API docs and the shipped _pydantic_core.pyi type stub say.)

Given that contract, to_json(..., timedelta_mode="float", temporal_mode="iso8601") should serialize datetime/date/time as ISO 8601 strings and timedelta as a float. Instead, datetime/date/time are also coerced to unix-timestamp floats, timedelta_mode="float" silently overrides temporal_mode="iso8601" for all temporal types.

There is no combination of the two parameters that yields ISO datetimes with float-second timedeltas, even though the documented parameters imply there should be.

Root cause / regression. This regressed in #1743. Before that PR, SerializationConfig had a dedicated timedelta_mode: TimedeltaMode field and to_json had no temporal_mode parameter, so timedelta_mode was genuinely independent. #1743 replaced the dedicated field with a single unified temporal_mode and retrofitted timedelta_mode as a legacy alias that maps into it.

Either the docs/.pyi should be corrected to state that timedelta_mode is a deprecated alias that affects all temporal types, or (preferably) timedelta should retain an independent setting so the documented behavior holds. Personally I have a requirement to be able to set the timedelta format independent of the other datetime types.

Example Code

import datetime
import pydantic_core

payload = {
    "dt": datetime.datetime(2026, 7, 9, 12, 0, 0),
    "d": datetime.date(2026, 7, 9),
    "t": datetime.time(12, 0, 0),
    "td": datetime.timedelta(hours=1, minutes=30),
}

# Per the docs: temporal_mode governs dt/d/t; timedelta_mode governs td.
actual = pydantic_core.to_json(
    payload, timedelta_mode="float", temporal_mode="iso8601"
).decode()

expected = '{"dt":"2026-07-09T12:00:00","d":"2026-07-09","t":"12:00:00","td":5400.0}'

print("actual  :", actual)
print("expected:", expected)
assert actual == expected, "timedelta_mode='float' wrongly coerced datetime/date/time to floats"
# AssertionError: actual == {"dt":1783598400.0,"d":1783555200.0,"t":43200.0,"td":5400.0}

Summary

What was wrong. pydantic_core.to_json/to_jsonable_python document timedelta_mode (iso8601/float, governs timedelta) and temporal_mode (iso8601/seconds/milliseconds, governs datetime/date/time) as independent parameters over disjoint type sets. Since PR #1743 unified them, SerializationConfig held a single temporal_mode, and from_args derived that one mode from timedelta_mode whenever temporal_mode was the default "iso8601" — then applied it to all temporal types. So to_json(..., timedelta_mode="float", temporal_mode="iso8601") wrongly coerced datetime/date/time to unix-timestamp floats, and no argument combination could produce ISO datetimes with float-second timedeltas.

What I changed (implementing the report's preferred option — an independent timedelta setting):

  • src/serializers/config.rs: added a separate timedelta_mode: TemporalMode field to SerializationConfig, resolved independently in both from_args and from_config. Datetime-likes are governed solely by temporal_mode; timedelta follows timedelta_mode when temporal_mode is the default iso8601, and follows an explicit temporal_mode/ser_json_temporal of seconds/milliseconds when set (preserving prior behavior and matching the existing test_config_timedelta_timedelta_ser_flag_prioritised priority test).
  • src/serializers/infer.rs: the three timedelta dispatch sites (to_json, serde_serialize, json_key) now read state.config.timedelta_mode; datetime/date/time still read temporal_mode.
  • tests/serializers/test_any.py: added test_timedelta_mode_independent_of_temporal_mode, asserting the exact reported scenario for both to_json and to_jsonable_python.

Test evidence.

  • Before the fix, the new test failed: to_json(payload, timedelta_mode='float', temporal_mode='iso8601') emitted {"dt":17835...} (a float) instead of the ISO string.
  • After building (make build-dev) and re-running, the new test passes, and the full serializers suite is green: 805 passed, 5 skipped, 1 xfailed (./bt-test pydantic-core/tests/serializers/ pydantic-core/tests/test_garbage_collection.py), including the pre-existing test_config_timedelta_timedelta_ser_flag_prioritised.
