ExceptionGroups do not respect __tracebackhide__

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches pass every independent test, but the structural differences favor A on correctness.

Patch A builds the group's native traceback from the already-pruned `traceback` (via `_build_raw_traceback`), so the cut performed by `Function._traceback_filter` (dropping pytest runner/pluggy frames above the test function) is preserved, exactly as the old `traceback[0]._rawentry` approach did. Patch B instead calls `TracebackException.from_exception(excinfo.value)`, which starts from the raw `__traceback__` of the exception, and then filters it against a fresh `ExceptionInfo.from_exception(e)` whose traceback is also un-cut and only `__tracebackhide__`-filtered. The computed `traceback` variable is used only for `extraline`. That means the group's own stack in B will include pytest-internal frames (runner `from_call`, pluggy callers, `pytest_pyfunc_call`) that the expected output in the issue does not show; the independent tests only assert absence of f1/f2/f3/g1 and presence of the test frame, so they would not catch this regression. B also keeps using `excinfo` rather than the per-chain `excinfo_`, so when a group is the cause of another exception it renders the outer exception again (A explicitly fixes that and tests it), and B's `zip(..., strict=True)` plus `(filename, lineno)` string matching are more fragile (e.g. `Code.path` normalization on Windows could drop frames entirely, while A matches by position with a length guard for `sys.tracebacklimit`).

On tests, A is stronger: it parametrizes over long/short/auto/full-trace, asserts the exact native layout consecutively, checks that --full-trace still shows everything, and adds a chain/duplication test. B has a single --tb=short test with loose fnmatch checks.

Scope and craft: A's extra chain fix is tightly related to the same code path and documented in the changelog; its cycle-safe traversal with a visited set and the tracebacklimit guard show care at the edges. B is more compact but its redesign of how the group stack is obtained introduces the internal-frame regression. A wins.

This is as much a feature request as it is a bug - the logic has simply not been implemented given that exception groups always fall back to displaying using tbstyle "native". See #9159

Designing the output of exception groups to be as pretty as the other "tbstyle"s would require a lot of design decisions, but a minimal implementation could keep the look of "native" except add features such as traceback filtering.
