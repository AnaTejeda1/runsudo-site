Tool approval is not honored on resume when Runner.run is given a context

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches locate the same root cause: `resolve_resumed_context` built a brand-new `RunContextWrapper` whenever `context=` was supplied, discarding the `_approvals` recorded on the state's wrapper by `state.approve()`, so the resumed run re-interrupted. Both fix the plain-context case identically (mutate the restored wrapper's `.context` in place, keep approvals/usage), and the independent tests pass for both across dict, dataclass, wrapper, streamed and in-memory scenarios.

They diverge on the wrapper-override path and on scope. Patch B keeps the caller's `RunContextWrapper` as the run's wrapper, merges the state's approvals into it (state decisions win) and carries usage over, explicitly mirroring the existing `RunState.from_json(context_override=wrapper)` convention. Patch A silently discards a caller-supplied wrapper and only lifts its `.context` value, a behaviour change that could break any caller or existing test relying on `result.context_wrapper is override`. Patch A also goes well beyond the issue: it changes `agent.py` so nested `Agent.as_tool()` resumes now pass the parent application context instead of `None`, and aliases the restored nested wrapper's `usage` to the parent `ToolContext.usage`. That is an adjacent redesign of the nested-resume contract with its own correctness surface (shared Usage object, parent context overwriting the deserialized nested context) and is not needed to fix the reported bug; it adds risk rather than credit.

On tests, B's parametrized test covers exactly the issue matrix (run vs run_streamed × dict/dataclass/wrapper × approve/reject = 12 cases, with JSON round-trip and `context_deserializer` as in the repro) plus usage-preservation tests for both override kinds, all of which would fail on base. A's tests are also meaningful (in-place unit test, run and streamed JSON resume, nested as_tool), but a chunk of them exercise A's own extra nested/usage behaviour rather than the issue. B is the tighter, lower-risk fix with the more directly issue-aligned tests.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Describe the bug

A tool with needs_approval=True correctly pauses the run and produces an approval interruption. After serializing the RunState, reconstructing it, calling state.approve(item) and resuming through Runner.run, the tool executes only if no context= was passed to Runner.run.

If any context object is supplied — a plain dict or a dataclass — the resumed run re-interrupts and the tool body is never invoked, despite the approval having been recorded on the reconstructed state.

This is not a context-serialization problem. A plain dict context requires no restoration at all and still fails, and none of context_override=, context_deserializer=, or strict_context=True on RunState.from_json changes the outcome. The RunState context was serialized from a dataclass... warning appears in the dataclass case but is a separate concern — silencing it does not fix the resume.

What I ruled out:

  • Not tool identity. With context=None the resumed callback receives the same call_id and byte-identical arguments as the interruption carried, so the round-trip preserves them. In the failing cases the interruption reloaded from JSON still reports the correct raw_item.call_id and raw_item.arguments — the data survives; the approval is not applied.
  • Not a wrapper or third-party interference. The repro uses a bare FunctionTool with an inline on_invoke_tool. Originally found through a tool-wrapping library; reproduces identically without it.
  • Not agent reuse. Fresh Agent instances are constructed for the resumed run in every case.

Not investigated: whether Runner.run_streamed is affected, and the internal approval-key derivation — which seems the likeliest place for a context-dependent mismatch, but I did not want to speculate about internals.

Impact: for integrations that carry identity or authorization through the run context, the only configuration in which approval resume currently works is the one that omits the information required to identify the acting user.

import asyncio
import json
from dataclasses import dataclass

import agents
from agents import Agent, FunctionTool, Runner
from agents.items import ModelResponse
from agents.models.interface import Model
from agents.run_state import RunState
from agents.usage import Usage
from openai.types.responses import (
    ResponseFunctionToolCall,
    ResponseOutputMessage,
    ResponseOutputText,
)

agents.set_tracing_disabled(True)


def scripted(turns):
    class Scripted(Model):
        def __init__(self):
            self._turns = list(turns)
            self.n = 0

        async def get_response(self, system_instructions, input,
                               model_settings, tools, output_schema, handoffs,
                               tracing, *, previous_response_id=None,
                               conversation_id=None, prompt=None):
            self.n += 1
            turn = self._turns.pop(0) if self._turns else "done"
            if isinstance(turn, str):
                out = [ResponseOutputMessage(
                    id=f"m{self.n}", role="assistant", status="completed",
                    type="message",
                    content=[ResponseOutputText(type="output_text", text=turn,
                                                annotations=[])])]
            else:
                out = [ResponseFunctionToolCall(
                    type="function_call", name=n, arguments=a, call_id=c,
                    id=f"f{self.n}") for (n, a, c) in turn]
            return ModelResponse(output=out, usage=Usage(), response_id=None)

        def stream_response(self, *a, **k):
            raise NotImplementedError

    return Scripted()


@dataclass
class Ctx:
    principal: str


async def attempt(label, context, **from_json_kwargs):
    """pause on approval -> serialize -> reconstruct -> approve -> resume."""
    invoked = []

    async def on_invoke(ctx, input_str):
        invoked.append(ctx.tool_call_id)
        return "tool-ran"

    def tool():
        return FunctionTool(
            name="w", description="d",
            params_json_schema={"type": "object", "properties": {},
                                "additionalProperties": False},
            on_invoke_tool=on_invoke, strict_json_schema=False,
            needs_approval=True)

    run_kwargs = {} if context is None else {"context": context}

    first = Agent(name="a", instructions="i", tools=[tool()],
                  model=scripted([[("w", "{}", "cA")], "unused"]))
    paused = await Runner.run(first, "go", **run_kwargs)
    assert paused.interruptions, "expected an approval interruption"

    blob = json.dumps(paused.to_state().to_json())

    second = Agent(name="a", instructions="i", tools=[tool()],
                   model=scripted(["done"]))
    state = await RunState.from_json(second, json.loads(blob),
                                     **from_json_kwargs)
    state.approve(state.get_interruptions()[0])

    resumed = await Runner.run(second, state, **run_kwargs)
    status = "OK" if invoked else "BROKEN"
    print(
        f"{label:36s} "
        f"final={resumed.final_output!r:8s} "
        f"invoked={invoked!s:9s} "
        f"interrupts={len(resumed.interruptions)}  "
        f"{status}"
    )


async def main():
    print(f"openai-agents {getattr(agents, '__version__', '?')}")
    dict_ctx = {"principal": "ella"}
    obj_ctx = Ctx("ella")

    def restore_obj(data):
        return Ctx(**data) if isinstance(data, dict) else data

    await attempt("no context (control)", None)
    await attempt("dict", dict_ctx)
    await attempt("dict + context_override", dict_ctx,
                  context_override=dict_ctx)
    await attempt("dict + context_override + strict", dict_ctx,
                  context_override=dict_ctx, strict_context=True)
    await attempt("dataclass + context_deserializer", obj_ctx,
                  context_deserializer=restore_obj)
    await attempt("dataclass + deserializer + strict", obj_ctx,
                  context_deserializer=restore_obj, strict_context=True)


if __name__ == "__main__":
    asyncio.run(main())
