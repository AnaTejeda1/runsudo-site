Add command line option for doing POSTs

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches add an option to fetch, view (via fetch), shell and parse, but Patch A delivers what the issue asks for: a `--data` option that behaves like `curl -d` (POST by default, body set, `Content-Type: application/x-www-form-urlencoded`), plus `-X/--method` to override the method. The independent tests confirm it: A passes all five scenarios, while B fails the form-encoding check because `Request.from_curl` does not add the Content-Type header that real `curl -d` sends, so servers expecting form data may not parse B's POST body. B's `--curl COMMAND` design is a reasonable, more general alternative, but it forces users to embed a whole curl command string rather than offering the simple data flag the issue requests, and its parse-command test does not exercise a POST at all. A's tests cover each command (fetch, parse, shell, view, including the reactorless shell path and the method/data interaction and empty-method validation); the view test is skipped only on Windows, which is a reasonable constraint for a fake-browser script and still runs on the platforms the issue implies. On craft, A adds a news entry and consistent docs for every command; B imports `SequenceExclude` from `scrapy.utils.datatypes` while the neighbouring fetch command uses `scrapy.utils._datatypes`, suggesting a deprecated import path, and changes the `set_spidercls` signature of the parse command. B's usage-error handling and URL/curl exclusivity checks are fine but do not outweigh the functional gap. A is the better fix.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.
