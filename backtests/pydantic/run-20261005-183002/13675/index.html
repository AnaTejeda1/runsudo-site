TypeAdapter config not used for JSON Schema generation

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the reported case the same way: `TypeAdapter.json_schema()` now pushes `self._config` onto the generator's config stack. `TypeAdapter(bytes, config={'ser_json_bytes': 'base64'}).json_schema()` will therefore yield `format: base64url` under either patch.

Patch A stops there. It leaves the sibling API `TypeAdapter.json_schemas()` broken: adapters passed to it still have their config ignored. That is the same root cause, reached through the other public entry point for adapter JSON schema generation.

Patch B also fixes `json_schemas()`. It records a per-input config and pushes it around both `generate_inner` passes in `generate_definitions`. Setting a private `_inputs_configs` attribute after construction is a little awkward, but it is contained and defaults to no-op behavior.

B also fixes a closely related inconsistency. Stdlib dataclasses and TypedDicts without their own config used to push `{}`, which reset to default config. They now push `None`, so they inherit the parent config. This matches how core schema generation treats them. Without it, `TypeAdapter(list[SomeTypedDict], config=...)` would still emit the wrong schema for nested fields, so the config fix would not hold for those types. B is careful here: it keeps `{}` for the `_update_class_schema` / extra-behavior uses, so only the config-stack semantics change.

Tests: A has one test (`list[bytes]`), which would fail before the fix. B tests more:
- the exact issue case and the default case;
- `ser_json_temporal`;
- `json_schema_mode_override`;
- `json_schemas` with mixed configs, which checks that config does not leak between inputs;
- nested dataclass/TypedDict inheritance, for both TypeAdapter and BaseModel.

These are meaningful regression tests. B's extra changes stay within the issue's theme (config honored in JSON schema) and add little risk. B is the more complete and better-tested fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
