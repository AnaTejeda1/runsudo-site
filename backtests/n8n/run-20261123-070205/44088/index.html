Better

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the four hardcoded strings the issue names in exactly the same way: an en.json key for Insights, three keys for the header button aria-labels, and `i18n.baseText(...)` lookups in MainSidebar.vue and MainSidebarHeader.vue. On correctness for the reported issue they are equivalent; the key naming differs only cosmetically (A reuses the existing `mainSidebar.state.*` namespace for the toggle label, B introduces a `mainSidebar.header.*` namespace), and both are consistent with surrounding conventions. The independent tests crashed on every tree, so they provide no signal either way. The deciding criterion is tests: Patch A adds tests in MainSidebar.test.ts and MainSidebarHeader.test.ts that register a synthetic locale with translated messages, switch the i18n instance to it, and assert the rendered Insights label and the three button accessible names show the translated text and not the English fallback. These tests would fail on the base commit (where the strings are hardcoded) and pass after the change, so they are genuine regression tests rather than tautologies. Patch B adds no tests at all. Patch A also localizes the Insights command title in useGenericCommands.ts and adds a matching test; this is beyond the issue's ask and earns no credit on its own, but it is low risk (keeps the 'insights' keyword and adds the lowercased translation) and does not obscure the fix. With correctness, scope, and craft roughly even, A's meaningful test coverage makes it the better fix.

Bug Description

Some labels in the main sidebar are written in English straight into the code, so they do not get translated:

  • The Insights item at the bottom of the sidebar.
  • The screen reader labels of the three buttons at the top of the sidebar: "Add new item" (the + button), "Open command palette" (the search button) and "Toggle sidebar".

https://github.com/n8n-io/n8n/blob/5ee5c2bf152c1a5c6eb0c1183a8d4c9b202ed4bf/packages/frontend/editor-ui/src/app/components/MainSidebar.vue#L125

https://github.com/n8n-io/n8n/blob/5ee5c2bf152c1a5c6eb0c1183a8d4c9b202ed4bf/packages/frontend/editor-ui/src/app/components/MainSidebarHeader.vue#L163

https://github.com/n8n-io/n8n/blob/5ee5c2bf152c1a5c6eb0c1183a8d4c9b202ed4bf/packages/frontend/editor-ui/src/app/components/MainSidebarHeader.vue#L254

https://github.com/n8n-io/n8n/blob/5ee5c2bf152c1a5c6eb0c1183a8d4c9b202ed4bf/packages/frontend/editor-ui/src/app/components/MainSidebarHeader.vue#L275

The other items in the same list, such as Templates, already use i18n keys.

To Reproduce

  1. Set the UI to a language other than English.
  2. Look at the bottom of the main sidebar. The Insights item is still in English.
  3. Use a screen reader, or inspect the +, search and sidebar buttons at the top of the sidebar. Their labels are still in English.

Expected behavior

The Insights item and the button labels show in the selected language, like the rest of the sidebar.

Debug Info

I found this while reading the code on master (2.48.0). The text is written into the code, so it happens on every setup.
