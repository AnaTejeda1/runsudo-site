Decimal JSON schema pattern uses lookahead regex unsupported by pydantic-core

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Patch A fixes the root cause directly. It rewrites the Decimal pattern generator so it never emits look-around assertions. It keeps the existing semantics: leading zeros in the integer part and trailing zeros in the fraction are not counted, and empty or sign/dot-only strings are rejected. It also switches to `[0-9]` so the compiled regex stays small. The pattern stays in the default schema, so existing JSON Schema consumers get the same constraints, now in a form pydantic-core can compile.

A's tests target the issue's scenario well:
- An exact reproduction of the round-trip through `StringConstraints`, including a rejection of `'-.'`.
- A parametrized cross-check that pydantic-core and Python `re` agree across many `max_digits`/`decimal_places` combinations, in both modes.
- An exhaustive check of the hardest case (only `max_digits` set) against a reference digit-counting function.
- A large-constraint test to guard against regex size limits.
These would all fail before the change.

Patch B avoids the bug by removing the pattern from the default schema. It moves pattern generation behind an opt-in `get_decimal_pattern` override and adds a much larger `build_decimal_pattern`, which also handles exponents, inf/nan and a separate serialization-mode grammar. This is a breaking behavior change and a broad redesign beyond the issue's ask. Users relying on `max_digits`/`decimal_places` appearing in the schema silently lose them. The new opt-in patterns are only checked with Python `re`, never compiled by pydantic-core, so the original concern (round-tripping through pydantic) is not verified for the code B adds. B also deletes many existing assertions in favor of plain `{'type': 'string'}`. The extra complexity (`_int_range_pattern`, serialization-specific exponent enumeration) adds risk without addressing the reported problem any better.

A is narrower, preserves behavior, and is verified against pydantic-core.

Description

Pydantic v2 emits a JSON schema for Decimal fields that includes a regex pattern with a negative lookahead ((?!...)). This pattern cannot be compiled by pydantic-core's Rust regex crate, which does not support look-around assertions.

This means the JSON schema pydantic produces for Decimal cannot be round-tripped back through pydantic's own validation e.g. constructing a TypeAdapter with StringConstraints(pattern=...) using the emitted pattern fails with a SchemaError.

This is a practical problem for any tooling that reconstructs pydantic types from emitted JSON schemas (e.g. MCP structured content parsing via FastMCP).

Example Code

"""Minimal reproduction: Decimal JSON schema pattern uses lookahead unsupported by pydantic-core.

Pydantic generates a JSON schema for Decimal fields with a regex pattern that uses
a negative lookahead (?!...). When that schema is round-tripped back through pydantic
(e.g. via TypeAdapter with StringConstraints), pydantic-core's Rust regex engine
rejects it because it does not support look-around assertions.
"""

from decimal import Decimal
from typing import Annotated

from pydantic import BaseModel, StringConstraints, TypeAdapter


class MyModel(BaseModel):
    amount: Decimal


def test_decimal_json_schema_pattern_roundtrips_through_pydantic_core():
    schema = MyModel.model_json_schema()

    # Decimal emits an anyOf with a string variant carrying the pattern
    string_variant = next(v for v in schema['properties']['amount']['anyOf'] if v.get('type') == 'string')
    pattern = string_variant['pattern']

    # The emitted pattern contains a negative lookahead:
    assert '(?!' in pattern

    # Feeding it back into StringConstraints fails with:
    #   SchemaError: regex parse error: look-around ... is not supported
    ConstrainedStr = Annotated[str, StringConstraints(pattern=pattern)]
    TypeAdapter(ConstrainedStr)


if __name__ == '__main__':
    test_decimal_json_schema_pattern_roundtrips_through_pydantic_core()
