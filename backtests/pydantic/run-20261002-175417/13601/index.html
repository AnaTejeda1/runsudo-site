model_dump(exclude=...) is silently ignored in python mode when a wrap model_serializer is gated with when_used="json"

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches find the same root cause. In function.rs, the shared tail of to_python/json_key/serde_serialize always wrapped the state in `scoped_include_exclude(IncludeExclude::empty())`. That was true even when `call` returned `(false, v)`, meaning the function was skipped because of `when_used` and the fallback serializer should run instead. As a result the fallback model serializer never saw the caller's include/exclude in python mode. Both patches fix this the same way: they clear include/exclude only when the function actually ran, and pass it through unchanged to the fallback otherwise. Patch A does this by splitting the match arms and passing `state` directly to the fallback. Patch B keeps the original shape and re-scopes with a cloned copy via a new `SerializationState::include_exclude()` accessor. The two are semantically equivalent across all three methods. B's diff is a bit smaller and stays closer to the existing structure, at the cost of a new accessor and a redundant clone and re-scope. A's restructure is still clear and well commented. On correctness and scope they are effectively tied.

The difference is in the tests. Patch A parametrizes over both `json` and `json-unless-none` (the issue names both). It uses the issue's exact wrap pattern (`return handler(self)`), checks both include and exclude in python mode, checks JSON mode, and checks `model_dump_json`. It also adds a plain `when_used='json'` model-serializer test and a nested field_serializer test (plain and wrap) with nested include/exclude. That last test exercises the same function-serializer code path in a different context, and would fail before the fix. Patch B's test covers plain and wrap in python mode for `when_used='json'` only. Its wrap serializer returns a constant instead of calling the handler, so it does not mirror the reported scenario. It also skips `json-unless-none` and the field-serializer path. Both sets of tests would fail before the fix and pass after, but A's are broader and closer to the issue's scenarios, so A wins on the tests criterion.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

When a model declares @model_serializer(mode="wrap") with when_used="json" (or "json-unless-none"), the runtime exclude argument passed to model_dump() is silently ignored in python mode. The same call in JSON mode behaves correctly.

Expected: model_dump(exclude={"b"}) omits b regardless of when_used, since the gate concerns which serializer runs and not which fields the caller asked to drop.

Actual: b is present in python mode.

Example Code

from pydantic import BaseModel, SerializerFunctionWrapHandler, model_serializer


class Gated(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap", when_used="json")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


class Always(BaseModel):
    a: int
    b: int

    @model_serializer(mode="wrap")
    def _serialize(self, handler: SerializerFunctionWrapHandler) -> object:
        return handler(self)


  # Gated to JSON: python mode ignores exclude.
  print(Gated(a=1, b=2).model_dump(exclude={"b"}))               # {'a': 1, 'b': 2}  <-- expected {'a': 1}
  print(Gated(a=1, b=2).model_dump(mode="json", exclude={"b"}))  # {'a': 1}          <-- correct

  # Identical model without the gate: python mode honours exclude.
  print(Always(a=1, b=2).model_dump(exclude={"b"}))              # {'a': 1}

  Output:

  gated  python: {'a': 1, 'b': 2}
  gated  json  : {'a': 1}
  always python: {'a': 1}
