metrics: --templateMetrics duration columns have inconsistent formatting

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause the same way. They replace `time.Duration.String()` with a fixed two-decimal formatter whose unit suffix has a constant width, so decimal points line up in the right-aligned columns. Patch A's suffix is 3 runes (`"  s"`, `" ms"`, `" µs"`); Patch B's is 2 (`"s "`, `"ms"`, etc. via `%-2s`). Go's fmt pads by rune, so `µs` is handled correctly in both.

Correctness: both resolve the issue. Patch B also handles rounding carry-over, so 999.996ms prints as `1.00s ` instead of `1000.00 ms`. Patch A's output still aligns in that case, but the value reads oddly, so B is a little more polished.

Tests: this is where B clearly wins. Patch A only unit-tests `formatDuration` on four values. It also had to loosen the partials integration test regex (`\s*` between number and unit) because its new space-separated format would otherwise break that test. Patch B unit-tests the formatter, including zero and the rounding-carry boundaries. It also adds an end-to-end `WriteMetrics` test, run with and without hints, that checks decimal-point positions across rows of different magnitudes. That test directly checks the issue's stated goal (aligned decimal points) and would fail on the old code. B's compact format (`1.23ms`) matches the existing integration-test regex, so no test had to be weakened.

Scope and craft: both changes are focused. B's formatter is cleaner, with a doc comment and no duplicated `Sprintf` per branch. A's double-space `"%.2f  s"` with an inline comment is slightly awkward.

Overall, B has stronger, issue-targeted tests and handles the rounding edge case.

The issue

View on GitHub

The --templateMetrics output table prints duration values (sum/avg/max) using time.Duration.String(), which varies both units and decimal places depending on the magnitude. This makes the table hard to scan when rows have durations of different magnitudes.

Proposed fix: Use a fixed-decimal formatter (two decimal places, unit suffix padded to consistent width) so decimal points align across all rows in the table.
