Transition should sniff for teleport in custom components

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause the same way. When a component nested in <Transition> renders a Teleport as its root, they forward the transition hooks past the Teleport to its first non-comment child. Both handle the initial render path (renderComponentRoot) and the update path (setTransitionHooks recursing into component.subTree). Patch A does this by special-casing Teleport at both call sites with `isTeleport(...) ? getInnerChild(x) || x : x`. Patch B adds a Teleport branch inside setTransitionHooks itself, so every caller gets the behavior and the hooks are never left on the Teleport vnode. Patch B's comment notes that leaving them there would fire afterLeave too early. Patch B is also more robust at the edges. It guards with `isVNode(child)` before recursing, so un-normalized primitive children (e.g. a raw string passed via h()) are skipped. Patch A would call setTransitionHooks on a raw string and assign `.transition` to a primitive, which throws in strict-mode ESM. Patch B's dev warning uses a dedicated isTransitionableRoot helper built on the existing filterSingleRoot, and still warns correctly for non-element teleported content. On tests, Patch B is clearly stronger. Its unit tests cover the full enter/leave lifecycle with element assertions, appear hooks, out-in mode between two teleporting components, absence of the warning, and the still-warn case for text content. Patch A's unit tests are thinner: a KeepAlive test unrelated to the issue, an empty-Teleport test, and one hook-update test. Both add an essentially identical e2e test. Overall the fixes are comparable in correctness, but B is more centralized, safer at edge cases, and much better tested.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

This is a follow up from

  • #5836

My Intention in #5836 was, that a user should be able to do this:

<Transition>
  <CustomComp />
</Transition>

<!-- Custom Comp -->
<Teleport>
  <div></div>
</Teleport>

However, the fix for #5836 only allows:

<Transition>
  <Teleport>
    <div></div>
  </Teleport>
</Transition>

For me as a user those 2 should feel equivalent.
The way it is now is not really useful. If you are not gonna use a custom component inside transition, you could just easily swap teleport and transition around (which already worked before the fix):

<teleport>
  <transition>
    <div></div>
  </transition>
</teleport>

But the whole point of #5836 was to allow to transition any component that teleports internally.
And since nesting a custom component into a transition works already, teleport should just be transparent in this case

Usecase:

  • modals <transition><Modal /></transition>
  • popovers
  • ...
