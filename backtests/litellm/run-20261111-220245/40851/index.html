What happened?

session_id in the spend logs table never reflects a caller's litellm_session_id — it's silently overwritten by a per-call correlation id that's different on almost every request. This makes it impossible to group or filter spend logs by session for anyone relying on litellm_session_id, even though that's exactly what the field is documented to carry.

I also found a related-but-distinct prior report, #23157 ("Sessions are no longer correctly grouped together in the Spend Logs UI") and its associated PR #23245 (closed, unmerged) — but that one was about a UI-side grouping/counting bug in the read path (session_total_count on the logs-list endpoint). In my repro below, the session_id value itself is already wrong at write time, before any UI grouping logic even runs — so I don't believe this is a duplicate.

Expected: every spend log row for requests that shared the same litellm_session_id should have that same value in session_id.

Actual: each row gets a different value — unrelated to what was sent.

User Flow

Before a (hypothetical) fix: an operator building a per-session cost dashboard from spend logs can't group requests that belong to the same conversation, because the stored session id is different on every request even when the client sent an identical one.

  1. They send three separate POST https://litellm-domain/v1/chat/completions calls, each with the same "litellm_session_id": "convo-42" in the request body (simulating three turns of one conversation).
  2. They query their spend-logs store (or GET https://litellm-domain/spend/logs) for those three requests and see three different session_id values in the results — none of them "convo-42".
  3. Their dashboard, which groups cost by session_id, shows three separate single-request "sessions" instead of one three-request session — the per-session cost total is wrong for every conversation with more than one turn.

After a (hypothetical) fix: the same three calls all land under one session.

  1. They send the same three POST https://litellm-domain/v1/chat/completions calls with "litellm_session_id": "convo-42".
  2. Querying spend logs for those three requests now shows session_id: "convo-42" on all three rows.
  3. Their dashboard correctly groups all three requests into one session with the right total cost.
