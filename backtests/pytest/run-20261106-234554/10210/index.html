pytest.approx does not raise in mixed data type nested structures

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause the same way: they replace the `isinstance(x, type(expected))` check with a generic 'is this a non-string Collection' predicate in both ApproxMapping and ApproxSequenceLike, and every independent test passes on both. The differences are in craft and tests. Patch B distinguishes, inside a mapping, a nested Mapping (keeps the 'nested dictionaries' message) from other nested containers (uses the 'nested data structures' message), so `approx({"k": [1]})` reports accurately. Patch A routes every nested value in a dict through the 'nested dictionaries' message, so a list inside a dict is reported as a nested dictionary, which is misleading, and A's tests codify that inaccurate wording. Patch B's parametrized construction test is also broader (list/tuple/dict parents each paired with list/tuple/set/dict children) and its comparison test mirrors the issue's exact reproductions including the equal-values case. Patch A has one small advantage: it excludes bytearray as well as str/bytes, and adds tests for bytes leaves, whereas B would now raise for a bytearray element, an obscure edge the issue does not mention. B's extra `or _is_sequence_like(x)` is redundant but harmless. On balance B's more accurate error reporting and more thorough tests outweigh A's bytearray handling.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.

description

when using pytest.approx on nested data structures I'd expect it to raise an exception also for mixed data type containers like a tuple in a list. So far it only works for the same data types e.g. lists in lists, tuples in tuples.
For mixed data structures it incorrectly returns False, even though they should match which is a little misleading (also see below).
