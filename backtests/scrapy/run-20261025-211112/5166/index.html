HTTP cache should be for project but spider

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause the same way: an opt-in setting that drops the spider-name partition from both built-in storages, and both pass every independent test. The difference is scope and test coverage. Patch A adds a single boolean HTTPCACHE_SHARED, touches exactly the two path/db-name computations, and its new tests live in the shared StorageTestMixin and DummyPolicyTestMixin, so they run against both FilesystemCacheStorage and DbmCacheStorage, cover the per-spider default, the shared case, isolation between shared and non-shared caches, and an end-to-end middleware hit with the 'cached' flag and httpcache/hit stat. Its only extra change is a harmless mkdir(exist_ok=True) cleanup. Patch B introduces a string enum HTTPCACHE_SCOPE and, beyond the issue's ask, a whole new 'domain' partitioning mode (hostname quoting, filesystem-only, with an IPv6 case that is skipped under a w3lib condition), plus an unrelated removal of the 'If empty, the HTTP cache will be disabled' sentence from HTTPCACHE_DIR docs. The value validation with a clear ValueError is a nice craft touch, and the enum is extensible, but the extra mode adds surface area and risk that the issue did not request, and B's tests stop at the storage layer with no middleware-level check. On correctness they are equal; on tests A is somewhat broader for the behaviour actually asked for; on scope A is clearly tighter. A is the better fix.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.
