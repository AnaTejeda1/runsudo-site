The issue

Description

The desktop app's file-diff view crashes on any partial (truncated) diff with:

Error: FileDiff: loadDiffFiles is required to load full files for a partial diff
    at gv.loadFilesIfNecessary (oc://renderer/assets/file-CsiGC-aR.js:307:50061)
    at gv.render (oc://renderer/assets/file-CsiGC-aR.js:307:54462)
    at Object.draw (oc://renderer/assets/file-CsiGC-aR.js:767:5250)

Large diffs are served truncated (isPartial: true), and the view's loadFilesIfNecessary() hard-throws when options.loadDiffFiles is missing. In the shipped 2.0.20 renderer bundle (file-CsiGC-aR.js), the string loadDiffFiles appears exactly once — this consume site — so no caller ever provides it and every partial diff throws on render. The hydration path it feeds (loadFilesForDiff → handleFilesLoaded) exists but is never wired to a loader. Small diffs render fine, so the crash looks intermittent.

This started with the 2.0.20 auto-update; 2.0.19 did not have it. Differs from #44918 (that one is a renderer hang from a synchronous line-diff on v1; this is a throw from a missing option on v2).

Steps to reproduce

  1. Open a repo with a working-tree change large enough to be truncated server-side
  2. Open the file diff view for it
  3. View throws instead of rendering

Suggested fix

Pass a loadDiffFiles callback when constructing the view — it receives the partial FileDiff and should fetch the full diffs (e.g. via the VCS diff API) for handleFilesLoaded to merge. As a fallback, rendering the truncated diff with a "truncated" notice beats throwing from render().

Local workaround that confirmed the diagnosis: patching the shipped app.asar to replace the throw with a console.warn + early return makes partial diffs render truncated instead of crashing.
