What the agent reported

hugo new content posts/drafts/trip-to-puebla/index.md now works under a section with cascade: draft: true: it writes the real archetype content instead of stopping with the "conflicts with existing content" error. The official ./bt-test gate never actually ran the tests, so all results below come from running go test directly.

What was wrong: Before building the page, hugo new content writes a temporary placeholder file (the "Content Placeholder" page you saw) and then looks that page up. That file said nothing about drafts, so your cascade: draft: true made it a draft. hugo new doesn't build drafts, so the placeholder was left out and the lookup found nothing. The error text calls that a path conflict, though no conflict existed, and the placeholder was left on disk.

What I changed:

  • hugolib/content_factory.go: the placeholder front matter now includes draft: false. A value the page sets itself overrides a cascaded one. The placeholder is always replaced by the archetype output, so this never shows up in your file; the final draft setting still comes from your archetype.
  • I first tried building drafts during hugo new instead. That broke an existing test (Issue 12786), where creating p1/p2.md next to an existing p1/index.md must be rejected. That check only works because the existing page is a draft and gets left out, so I dropped that approach.

Test evidence:

  • New test: I added a case to testscripts/commands/new_content.txt using your exact _index.md front matter. It runs hugo new content posts/drafts/trip-to-puebla/index.md and hugo new content posts/drafts/another-post.md, then checks that each file exists, no longer says "Content Placeholder", and has the archetype title.
  • Before the fix it failed with no page found for ".../trip-to-puebla/index.md"; the target path conflicts with existing content.
  • After the fix it passes, along with the rest of the new test scripts, including the existing conflict cases.
  • Why not ./bt-test: ./bt-test . -run TestCommands/new_content stopped during setup because it couldn't download Go modules (proxy.golang.org is unreachable here). I ran the tests with go test against the local module cache at /bt/cache/go-mod instead.
  • Other tests: ./create/... passes. TestCommands and ./hugolib/ each have failures, but it's the same module and git-info tests that need network access, with and without my change (checked by stashing it).
  • Review: an independent review found no blocking issues.
