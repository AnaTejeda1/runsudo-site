Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the reported path: terminal usage is attached to the ModelBehaviorError in `_response_terminal.py`, recorded on the response span in `OpenAIResponsesModel` for both HTTP and websocket, added to `context_wrapper.usage` via a context manager around `get_response_with_retry` for non-streamed runs and directly in `run_single_turn_streamed` for streamed runs, and the error still propagates. All independent tests pass on both. The differences are in risk and completeness. Patch A rewrites `apply_retry_attempt_usage` and `get_response_with_retry`, replacing the `failed_policy_attempts + compatibility_retries_taken` count with `request_attempt - 1` and threading a `reported_usage` map through the retry loop. That lets a retried incomplete attempt keep its billed usage, which is a reasonable extension, but it silently changes how conversation-locked and compatibility retries are counted (any path that bumps `request_attempt` without a policy failure now produces a zero-usage request entry), a behavior change the issue did not ask for and that cannot be verified from the diff. Patch B keeps the core change contained: it stores the terminal Response on the error through small helpers, adds a once-only `consume_terminal_failure_usage` guard against double counting, and also restores `span_data.response`/`input` when tracing includes data, which directly answers the issue's complaint that the errored span has 'no model, input or usage'. B also applies the same span handling to `AnyLLMModel`, which shares the terminal helper, so the fix is consistent across the Responses-shaped models. On tests, both add meaningful before/after tests; A covers the no-usage case and its retry accounting, B covers HTTP, websocket, any-llm and hosted multi-agent in streamed and non-streamed modes plus the trace_include_sensitive_data=False case. Net: B resolves the issue as fully with less collateral risk; A's retry refactor is the main thing counting against it.

The issue

Describe the bug

#4901 reported that a terminal response.incomplete or response.failed raises ModelBehaviorError before its usage is recorded. It was closed while waiting for a real api.openai.com example. Here is one. 0.24.0 still does this: _fetch_response raises on status in {"failed", "incomplete"} before get_response sets span_data.usage or span_data.response. The response's usage is lost to RunContextWrapper.usage and to the response span.

A gpt-5.4-mini agent with ModelSettings(max_tokens=6000, reasoning=Reasoning(effort="medium")) on a multi-turn tool task hit response.incomplete (incomplete_details.reason = "max_output_tokens") in 2 runs: the reasoning used up the output budget. The run raised ModelBehaviorError. The response span is exported with error status and nothing else, so no model, input or usage. Any cost total built from either source misses that call. A call cut off at its output limit used all of its max_output_tokens, so it is often the most expensive call in the run.

OpenAI returns usage on such a response. A direct call on api.openai.com, client.responses.create(model="gpt-5.4-mini", input="Explain how HTTP caching works.", max_output_tokens=16, reasoning={"effort": "medium"}) (openai 3.51.0, 2026-11-15), returned HTTP 200. Here are its fields, without the output:

{
  "model": "gpt-5.4-mini-2026-03-17",
  "status": "incomplete",
  "incomplete_details": {"reason": "max_output_tokens"},
  "output_item_types": ["reasoning"],
  "usage": {
    "input_tokens": 12,
    "input_tokens_details": {"cache_write_tokens": 0, "cached_tokens": 0,
      "cache_write_tokens_details": {"ttl_12h_tokens": 0, "ttl_30m_tokens": 0}},
    "output_tokens": 16,
    "output_tokens_details": {"reasoning_tokens": 16},
    "total_tokens": 28
  }
}

Through the SDK, this response raises ModelBehaviorError in _fetch_response, and those 28 tokens are counted nowhere.

Expected behavior

When the terminal response carries usage, add it to the run's usage and to the span before raising. The error stays an error.

Debug information

  • Agents SDK 0.24.0 (latest), openai 3.51.0, Python 3.14.2, macOS
  • Model: gpt-5.4-mini via OpenAIResponsesModel, non-streaming (Runner.run)
