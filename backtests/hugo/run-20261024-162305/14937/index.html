Add build.cleanDestinationDir config option

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches add build.cleanDestinationDir with an enable switch plus keep patterns, and both pass all four independent tests, so the decision rests on design risk, docs, and craft. Patch A is additive: the existing hardcoded rules (.gitignore/.gitattributes, dot-directories) stay, the new `keep` globs are checked first against the slash-normalized path relative to publishDir, the root cleanDestinationDir key and flag keep working via isCleanDestinationDir, and a bool shorthand is decoded. It ships unit tests for decoding/glob matching/clone isolation/invalid-glob errors, a testscript covering bool shorthand, keep with and without static/, and keep combined with the flag, and it updates the configuration docs and docs.yaml. Patch B goes further than the issue asks: it deletes RootConfig.CleanDestinationDir, remaps the CLI flag to build.cleanDestinationDir.enable, adds a deprecation, and turns the built-in keep rules into default globs with negation support. Some of that is nice (keeping `.git` files by default covers the worktree case), but it introduces a real footgun that its own test exposes: setting keepFiles = ['.domains','_redirects'] replaces the defaults, so .gitignore/.gitattributes and dot-directories are suddenly deleted (scenario 4 output drops .gitignore and .hidden/). A user following the issue's use case would lose files Hugo previously always preserved. B also adds no documentation for the new keys or the deprecation, and the broader refactor (removing a root config field, changing flag mapping) adds migration risk with no benefit to the reported problem. A resolves the issue with less risk, better tests, and complete docs.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.

The issue

Usecase

I'm using Codeberg Pages to host my website, you can find the repostitory at https://codeberg.org/ilovelinux/pages

I have two branches:

  • main: hugo project
  • pages: hugo build (output of public/)

Since I'm using Codeberg Pages with a custom domain, I also need a .domains file[^codebergDomains] to be pushed in the pages branch.

When I

  • Have files in the static/ directory.
  • Switch to main branch.
  • Create the public/ folder using a git worktree of the pages branch.
  • Run hugo build --cleanDestinationDir.

I need

  • To remove outdated content
  • To retain:
  • .git file created by git worktree[^gitWorktreeFile].
  • .domains file used by Codeberg Pages in order to allow custom domains[^codebergDomains].
  • _redirects file for redirects (however I'm not using it yet)[^codebergRedirects].

Instead

  • The files I need to be retained are deleted.

Proposal

Add a configuration field to list relative file paths to public/ that should be retained when using --cleanDestinationDir.

Example

 filesToRetain:
  - .git
  - .domains
  - _redirects
  - foo/bar/.mysecretfile

Files retained:

  • public/.git
  • public/.domains
  • public/_redirects
  • public/foo/bar/.mysecretfile

[!NOTE]
I'm not suggesting to use filesToRetain as configuration field, but I couldn't think of a better name.

Notes

[!IMPORTANT]
--cleanDestinationDir does nothing when when the static/ directory doesn't exist since its value is used inside the copyStaticTo function.
https://github.com/gohugoio/hugo/blob/c4bbc2805c7092deafabae01e71ff2dda37bd877/commands/hugobuilder.go#L481

Workaround

[!WARNING]
This approach is error-prone.

I implemented a workaround in my Makefile that:

  • Repairs the worktree folder, as suggested in https://github.com/gohugoio/hugo/pull/6261#issuecomment-1692321365.
  • Restores the .domains file.

Related issues & PR

  • https://github.com/gohugoio/hugo/issues/3202 was about .git folder being deleted. Fixed thanks to:
  • https://github.com/spf13/fsync/pull/10
  • https://github.com/gohugoio/hugo/pull/3210.
  • https://github.com/gohugoio/hugo/issues/4546 was about .git file of a submodule[^gitSubmoduleFile] being deleted. Closed because it was considered a discussion.
  • https://github.com/gohugoio/hugo/pull/6261 was introducing a fix for the .git file in order to work correctly with git worktrees and submodules. Closed because of the Stale bot but it looks like it was still kept into consideration since @bep kept moving it among milestones after that. However this wouldn't solve my issue since .domains and _redirects files would still be deleted.
