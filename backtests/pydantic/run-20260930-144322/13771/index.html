The issue

Initial Checks

  • I confirm that I'm using Pydantic V2

Description

ValidateCallWrapper.__call__ is declared as def __call__(self, *args, **kwargs), so the instance is bound to the name self. A decorated function with a keyword parameter literally named self can then never be called with it: f(self=1) raises TypeError: ValidateCallWrapper.__call__() got multiple values for argument 'self' before validation runs. The wrapped function itself is fine with that name; it is only the wrapper's signature that collides. Same in 2.12.5, 2.13.5 and pydantic/_internal/_validate_call.py on main.

Making self positional-only in __call__ (def __call__(self, /, *args, **kwargs)) removes the collision without changing anything else. Can send the PR.

Example Code

import pydantic.version
from pydantic import validate_call


@validate_call
def f(*, self: int) -> int:
    return self


try:
    print("f(self=1) ->", f(self=1))
except TypeError as e:
    print("f(self=1) -> TypeError:", e)
print(pydantic.version.version_info())
f(self=1) -> TypeError: ValidateCallWrapper.__call__() got multiple values for argument 'self'

What the agent reported

Fixed: a @validate_call function with a keyword parameter named self can now be called with it. The regression test failed before the change, and it and the rest of tests/test_validate_call.py and tests/test_decorators.py pass after it (96 passed).

Cause: ValidateCallWrapper.__call__ in pydantic/_internal/_validate_call.py was declared as def __call__(self, *args, **kwargs). The decorator returns the bound method, so a call like f(self=1) gave the method a second value for its own self. Python raised TypeError: ... got multiple values for argument 'self' before validation ever ran.

Change (pydantic/_internal/_validate_call.py:133): made self positional-only, as the report suggested:

def __call__(self, /, *args: Any, **kwargs: Any) -> Any:

A keyword self=... now ends up in **kwargs and gets validated like any other argument. Nothing else in the method changed.

Test: I added test_keyword_parameter_named_self to tests/test_validate_call.py, right after test_positional_and_keyword_with_same_name. It uses the report's function (def f(*, self: int)) and checks three things:

  • f(self=1) == 1
  • f(self='2') == 2, so the value is still being validated and converted
  • f(self='x') raises ValidationError

Test evidence:

  • Before the fix: the new test failed with TypeError: ValidateCallWrapper.__call__() got multiple values for argument 'self', which reproduces the report.
  • After the fix: ./bt-test tests/test_validate_call.py tests/test_decorators.py gave 96 passed, including the new test.

Blast radius: the only difference is that self can no longer be passed to __call__ by keyword. Only pydantic calls __call__, and binding the method always supplies self by position, so nothing that worked before is affected. The / syntax needs Python 3.8 or later, which pydantic already requires. The reviewer also checked the other wrappers in the call path: wrapper_function (sync and async) takes only *args, **kwargs, so it has no similar name clash.

Requirements:

  1. f(self=1) should work instead of raising TypeError: done; the new test covers it.
  2. Use the suggested fix, def __call__(self, /, *args, **kwargs): done exactly as written. The change is one line and only two files changed (checked with git status).
  3. "Without changing anything else": existing tests pass unchanged, and the reviewer found no other wrapper with the same problem.
  4. "Same on main": confirmed; main had the same signature before this edit.

The changes are uncommitted in the working tree, and I left no scratch files.
