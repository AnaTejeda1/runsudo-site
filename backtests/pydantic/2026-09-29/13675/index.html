Both patches identify the same root cause—the TypeAdapter's config is not carried into the JSON Schema generator's config-wrapper stack—and both fix it in the right place. The decisive difference is craft and correctness of the mechanism. Patch B uses the generator's intended API, the `_config_wrapper_stack.push(...)` context manager, scoped narrowly around the single `generate` call so the config is pushed and popped cleanly, leaving the generator's stack invariant intact. Patch A instead wholesale reassigns `schema_generator_instance._config_wrapper_stack` to a freshly constructed `ConfigWrapperStack`, discarding whatever initial state the generator set up in its constructor and never restoring/unwinding it; this reaches deeper into private internals and is more fragile against the generator's own lifecycle assumptions. On tests, Patch B's case (nested `list[bytes]`, default mode, asserting `base64url` propagates through container items) is a slightly stronger regression guard than Patch A's flat `bytes` case, since it also exercises propagation into subschemas. Scope and size are comparable and minimal for both. Patch B is the cleaner, more idiomatic, root-cause fix.

Summary

What was wrong

TypeAdapter.json_schema() ignored the adapter's config when generating a JSON schema. Config-dependent format handlers in GenerateJsonSchema (e.g. bytes_schema) read config from self._config_wrapper_stack.tail, but that stack is initialized with an empty ConfigWrapper({}) and only gets real config pushed onto it by the model/dataclass/TypedDict handlers. For a bare TypeAdapter(bytes, config=...), the core schema is a plain bytes node with no enclosing model, so nothing ever supplied the adapter's config — and ser_json_bytes='base64' fell back to the default, emitting 'binary' instead of 'base64url'.

What I changed

  • pydantic/type_adapter.py (one line in TypeAdapter.json_schema): after constructing the schema generator, seed its base config wrapper stack from the adapter's own config: python schema_generator_instance._config_wrapper_stack = _config.ConfigWrapperStack(_config.ConfigWrapper(self._config)) This makes the adapter's config the base the format handlers consult. When the adapter wraps a model/dataclass/TypedDict, those handlers still push their own config on top (and Pydantic disallows passing config for such types, so the base stays empty) — so existing behavior is unchanged.
  • tests/test_json_schema.py: added test_type_adapter_bytes, a parametrized regression test mirroring the neighboring test_model_default_bytes/test_dataclass_default_bytes style.

Test evidence

  • Regression test failed before the fix (base64 case: 'binary' != 'base64url'), passes after.
  • ./bt-test tests/test_json_schema.py tests/test_type_adapter.py: 776 passed, 3 skipped, 2 xfailed — no regressions.
  • Verified the report's exact call TypeAdapter(bytes, config={'ser_json_bytes': 'base64'}).json_schema() now returns {'format': 'base64url', 'type': 'string'}.
