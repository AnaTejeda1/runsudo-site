Summary

What was wrong
Commit ec52e638c upgraded KaTeX from 0.16.21 to 0.18.4, which produces different rendered math output. Hugo's transform.ToMath caches its rendered output on disk (the MiscCache file cache), keyed by "tomath/" + fileCacheEntryVersion + .... Because that version constant was never bumped, sites with a pre-existing cache (e.g. the docs site's chem example) would keep serving the old KaTeX 0.16.21 output from the stale cache instead of the new output. The constant's own comment states it must be incremented on incompatible changes.

What I changed
A single-line, minimal edit in tpl/transform/transform.go:296:

-	const fileCacheEntryVersion = "v1" // Increment on incompatible changes.
+	const fileCacheEntryVersion = "v2" // Increment on incompatible changes.

This changes the cache key prefix, orphaning all stale tomath/v1/... entries so the new KaTeX output is regenerated and cached under tomath/v2/....

Test evidence

  • Gate: ./bt-test -run 'TestToMath' ./tpl/transform/ — all ToMath tests pass, and the github.com/gohugoio/hugo/tpl/transform package passes (TestToMath, TestToMathError + 4 subtests, TestToMathBigAndManyExpressions + 2 subtests, TestToMathRenderHookPosition, TestToMathMacros, TestToMathStrictMode).
  • Reviewer: PASS — confirmed the diff is exactly the one-line "v1"→"v2" change with the comment intact, and no unrelated source files were touched (the AGENTS.md/CLAUDE.md deletions shown in git diff --stat were pre-existing in the working tree before this task).

Note on regression testing
I deliberately did not add a regression test. This is a cache-invalidation version bump with no test-observable behavior: the existing ToMath tests assert on output substrings (<span class="katex"><math, etc.) that pass regardless of the constant's value, and there is no golden-output or KaTeX-version test in the repo. The only "test" one could write would assert the literal constant equals "v2", which is a change-detector that adds no real coverage. The verification here is that all existing ToMath tests continue to pass with the bumped version.

All changes are left uncommitted in the working tree.
