Throw an error on createVNode with using innerHTML and children at the same time

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

The issue is a runtime crash (`Cannot read properties of undefined (reading '__asyncLoader')`). It happens when an element's `innerHTML` and its children change dynamically. Once `innerHTML` has overwritten the DOM, the renderer tries to diff or unmount stale child DOM nodes. The user expects no error, with `innerHTML` taking precedence when set and the children rendering otherwise.

Patch A changes `patchElement` in the renderer. When the old vnode had `innerHTML`/`textContent`, it does not try to diff the old children against DOM that no longer exists. Instead it unmounts the old vnode children so component unmount hooks still run. It then mounts the new children fresh and re-applies the content prop when it is unchanged, since the props patch would otherwise skip it. It also stops the optimized `PatchFlags.TEXT` path from clobbering `innerHTML`/`textContent`. This addresses the root cause. Its tests exercise the reported toggle scenarios:
- text children
- array children with keyed reordering and a child component's `unmounted` hook
- `textContent`
- a compiled-style block with `TEXT | PROPS` flags

These tests would fail or crash before the change.

Patch B only adds a dev-mode warning in `createBaseVNode` when `innerHTML`/`textContent` is non-null and children are present. It explicitly does not warn when the prop is nullish, which is exactly the issue's repro (`innerHTML: undefined`). It makes no change to the renderer, so the crash still happens when the values toggle at runtime. Its tests only check that warnings are emitted. Patch B therefore does not fix the reported bug.

Patch A is more complex and adds some risk in the patch path, but it is the only one that is correct.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
