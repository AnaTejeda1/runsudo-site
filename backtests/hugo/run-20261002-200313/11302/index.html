The "failed to extract" error refers to outer shortcode instead of inner shortcode

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

The issue's root cause is in extractShortcode. When a nested shortcode that uses .Inner (`img`) is left unclosed, its parse loop treats the outer `{{< /figure >}}` close tag as its own. It sets closed=true and consumes that tag. The outer `figure` then reaches EOF and reports "unclosed shortcode figure", which is the misleading error in the report.

Patch A fixes this directly. In the IsShortcodeClose branch it peeks at the closing name. If that name differs from the current shortcode's name, it returns "shortcode \"img\" must be closed or self-closed" instead of swallowing the outer close. It keeps the existing "does not evaluate .Inner" error for a closing tag on a non-inner nested shortcode, so that check still happens before the mismatch error. It also wraps nested non-FileErrors with the nested shortcode's position, so the error points at line 6:1 (the `img` line) rather than at the outer shortcode.

Patch A's tests cover:
- the exact issue scenario, asserting the inner name and position and that "figure" is absent;
- an unclosed inner shortcode just before the outer close;
- a closing tag on a non-inner nested shortcode;
- a positive case where a non-inner `img` mixed with closed `figcaption` still renders correctly.

Patch B only adds position wrapping for errors that already come back from nested extraction. It does nothing about the close-tag swallowing. In the issue's scenario the error is produced by the outer shortcode at EOF, not by the nested call, so B would still report "unclosed shortcode figure". B's test uses a different scenario (inner template not found) and does not exercise the reported bug. Patch A resolves the issue; Patch B does not.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
