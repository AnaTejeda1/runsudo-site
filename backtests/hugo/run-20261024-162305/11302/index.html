The "failed to extract" error refers to outer shortcode instead of inner shortcode

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

The issue's actual scenario is an unclosed nested shortcode (img, which evaluates .Inner) inside figure: the parser consumes `{{< /figure >}}` as img's closing tag, then reports figure as unclosed. Patch A addresses this root cause in extractShortcode: when a closing tag's name does not match the current shortcode, it reports that the inner shortcode must be closed (or, if the named shortcode takes no inner, reports the stray closing tag at its position), and it additionally wraps nested errors with the nested shortcode's position. Patch B only does the latter: it re-positions errors that bubble up from nested extraction (e.g. missing template) but does nothing for the mismatched-close case, so the user's exact content still yields `unclosed shortcode "figure"` at the outer position. The independent tests confirm this: both tests built from the issue's own content and error line (naming the inner shortcode, and reporting its line) pass on A and still fail on B, while B only fixes the missing-template-position case that A also fixes. Tests: A adds a build test for the valid nested case plus five error-case assertions covering message and position at multiple nesting depths and delimiter styles; B adds one test for the missing-template position only, which does not exercise the issue's reported scenario. Scope/craft: A's change is larger but targeted and uses the existing error prefix, herrors.NewFileErrorFromPos and posFromInput conventions; the extra inner/no-inner distinction on the close tag is justified by the ambiguity in the issue. B is clean but incomplete.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours.
