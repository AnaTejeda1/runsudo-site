Issue #9546 Merged fix PR #15523 Run 5 Oct 2026 · run-20261005-155915 vuejs/core

defineProps options object loses properties when using generics

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches find the same root cause. `PropMethod` was a conditional type on `T`, so `PropType<T>` stayed deferred whenever `T` was a type parameter. That in turn deferred `RequiredKeys`/`OptionalKeys`, which dropped the optional props `a` and `b`. Both make `PropMethod` non-conditional, so both fix the exact scenario in the issue.

Patch A goes further, and the extra work hardens the same generic-PropType path rather than adding unrelated churn:
- **Generic defaults.** It replaces the assignability check `T[K] extends { default: undefined | (() => undefined) }` with an identity-based `IsUndefinedDefault`. The old check would itself defer for a default like `() => T`, and A's tests cover that case (`d`).
- **Early resolution in `InferPropType`.** It returns `V` directly when there is no default, or when the default has the same type, using an `IsSameType` identity trick. Generic props then resolve to a concrete `T | undefined` instead of a deferred conditional.
- **Safer constructor default.** It sets `TConstructor` to `Function` instead of `any`, a small safety step against confusion with `BooleanConstructor` now that `PropMethod` is always part of the union.

Patch B's `InferPropType` tweak (`unknown extends D ? V : D`) does not resolve the type. It leaves the type deferred and only makes every branch collapse to `V`, so it relies on TypeScript's assignability rules for deferred conditional types. That works for `expectType`, but it is a weaker fix. B also does not address `RequiredKeys` deferral when a default factory returns the generic type.

On tests, A's are broader. They cover all three cases from the issue, plus a generic default factory, union and function `PropType`s, mixed non-generic props, an unknown-prop error, and `ExtractPropTypes`, `ExtractPublicPropTypes` and `ExtractDefaultPropTypes` directly, with negative `@ts-expect-error` checks. B's tests cover the issue's cases plus `default: null` and an assignability check, but nothing for generic defaults.

A is more complex, but its comments explain why each piece exists. Overall it is the more robust and better-tested fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
