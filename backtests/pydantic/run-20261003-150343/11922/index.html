Some Field attributes lost in JSON schema when using RootModel

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the reported symptoms in `GenerateJsonSchema` for root models: `examples` and `deprecated` from the root `Field` now appear in the schema, and a root field `title` can replace the class name. The deciding differences are at the edges.

**Correctness**
- **Title source.** Patch A uses the root field title only when it is in `_attributes_set`, meaning the user set it explicitly. A comment explains this excludes titles produced by `field_title_generator`. Patch B reads `root_field.title` whenever it is truthy. Pydantic fills `FieldInfo.title` from `field_title_generator` while building the schema, so a config like `field_title_generator=lambda n, i: n.upper()` would wrongly turn the model title into 'ROOT' under Patch B. Patch A guards against this and tests it.
- **Title precedence.** Patch A puts an explicit field title ahead of `model_title_generator`. Patch B puts it behind. Either order is defensible.
- **Deprecated message.** Patch A also treats `deprecated=''` as deprecated. Patch B relies on truthiness, so an empty message is silently dropped.
- **Refactor.** Patch A computes `root_field` once via `__pydantic_root_model__` and reuses it, consolidating the existing checks.

**Tests**
Patch A's tests are broader. They cover:
- the Annotated form and the assigned-default form;
- non-JSON example values, with `date` serialized to '2020-01-01';
- a deprecated message string;
- the root model nested inside `$defs`;
- config title precedence;
- the `field_title_generator` regression;
- `deprecated=False`.

Patch B's tests cover only the basic cases plus config precedence.

**Scope and craft**
Both patches stay in scope. Patch A's consolidation is clean and fits the surrounding code. Overall, Patch A is more correct at the edges and better tested.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

When declaring a RootModel and adding a Field annotation to the root property that includes examples, those examples are not part of the generated JSON schema. This also applies to the deprecated attribute. The title attribute is also not applied or it is overwritten by the class name of the root model class.

Most other attributes, such as pattern or description are exposed as expected. Furthermore, placing examples in json_schema_extra also works as expected.

Example Code

from typing import Annotated
from pydantic import RootModel, Field

class Foo(RootModel):
    root: Annotated[str, Field(examples=["foo", "bar"], deprecated=True)]

print(Foo.model_json_schema())  # does not include examples or deprecated.
