v-model on <select multiple> uses stale collection type after switching between Array and Set

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches apply the same root-cause fix. They store the current model value on the element in `created` and refresh it in `beforeUpdate`, and the change listener calls `isSet(el._modelValue)` at event time instead of using the stale `isSetModel` captured at creation. Correctness is equivalent: both handle Array->Set and Set->Array switches and keep `el.multiple` semantics unchanged. Both tests would fail before the fix and pass after, since the first change event after a runtime switch would emit the old type. Patch A's test is slightly stronger. After each switch it also asserts that the DOM `selected` state was synced to the new model before the user interaction, and its interaction modifies only one option, which mirrors a real user action. Patch B forces both options' selected states manually and skips those checks. On craft, Patch A is clearly better. It adds `_modelValue?: any` to the `ModelDirective` element type, matching how `_assigning` is declared, and adds a short explanatory comment. Patch B uses repeated `(el as any)` casts with leading-semicolon statements, which is less consistent with the surrounding typed code. Scope is minimal and equal for both. Patch A wins on test thoroughness and type-safe consistency.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Steps to reproduce

  1. Bind a <select multiple v-model> to an Array.
  2. Switch the bound value to a Set at runtime.
  3. Interact with the select again.
  4. The emitted model becomes an Array again.
  5. Switching back from Set -> Array shows the same stale-type behavior in reverse.

What is expected?

The current collection type should be respected after the model switches at runtime.

What is actually happening?

The change handler keeps using the collection type captured when the directive was created, so the first user interaction after a runtime Array/Set switch emits the old type.
