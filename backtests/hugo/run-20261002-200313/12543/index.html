resources/images: Poor overlay quality when background image is an indexed (not true color) PNG

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches make the same core fix. In `doWithImageConfig` they skip re-applying the source palette when the action is a filter. That addresses the root cause: overlay and text output gets clamped back to the indexed PNG's palette. Both also update the paletted overlay and text golden images in the same way.

Patch A also changes how colors are handled across the board. Hex colors now parse to NRGBA instead of RGBA, `Color.init` normalizes to NRGBA, `ColorGoToHexString` un-premultiplies, and `AddColorToPalette` compares by color value. It also edits existing test expectations and changes the `padding-transparent-chained.png` golden file. These changes target a different issue (12536, premultiplied alpha) and are not needed to fix this one. They alter behavior visible to users, such as how hex strings are interpreted and how colors compare, which adds risk and makes the fix harder to see.

Patch B keeps to the issue. It also adds a focused integration test that checks three things: resize still keeps the palette, overlays (including on a resized image) reproduce the overlay's pixel colors exactly and are not paletted, and the text color survives. This test would fail before the fix and pass after it. Patch A adds no new test for the overlay behavior beyond the golden-file updates.

On correctness the two are equal. Patch B is better on tests and scope.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Before getting into the details, I have verified that this is not an upstream issue with disintegration/gift. I tested with this:

<details>
<summary>main.go</summary>

package main

import (
	"image"
	"image/png"
	"log"
	"os"

	_ "image/png"

	"github.com/disintegration/gift"
)

func main() {
	// Get the background image (24 bit: indexed not true color)
	f, err := os.Open("background.png")
	if err != nil {
		log.Fatal(err)
	}
	bgImage, _, err := image.Decode(f)
	if err != nil {
		log.Fatal(err)
	}

	// Get the foreground image (24 bit with 8 bit alpha channel)
	f, err = os.Open("foreground.png")
	if err != nil {
		log.Fatal(err)
	}
	fgImage, _, err := image.Decode(f)
	if err != nil {
		log.Fatal(err)
	}

	// Create a new image with dimensions of the bgImage.
	dstImage := image.NewRGBA(bgImage.Bounds())
	// Copy the bgImage to the dstImage.
	gift.New().Draw(dstImage, bgImage)
	// Draw the fgImage over the dstImage at the (20, 20) position.
	gift.New().DrawAt(dstImage, fgImage, image.Pt(20, 20), gift.OverOperator)

	// Create the composite file.
	f, err = os.Create("composite.png")
	if err != nil {
		log.Fatal(err)
	}
	defer f.Close()

	// Encode the composite image.
	err = png.Encode(f, dstImage)
	if err != nil {
		log.Fatal(err)
	}
}

</details>

Details:

  • Background image is a 24 bit indexed PNG file with 256 colors in its palette
  • Foreground image is a 24 bit true color PNG with an 8 bit alpha channel
  • The final (composite) image seems to be limited to the palette of the background image
