Both patches apply the same root-cause fix: after `_resolve_self_type` replaces `Self` with the resolved (possibly parametrized) class, they recompute `origin` from the new `obj` instead of using the stale origin computed on `Self`. The independent tests confirm both make all failing cases pass with no regressions, so correctness is equal. The differences are in craft and tests. Patch A keeps the original `origin = origin if ... else get_origin(obj)` line after unconditionally reassigning `origin`, leaving a redundant no-op for the Self branch; Patch B restructures into an if/elif so each path computes origin exactly once, which reads cleaner. On tests, A nicely reuses the `dataclass_decorators` helper and adds a NamedTuple case, while B adds an Annotated-wrapped `Self` case and, importantly, negative assertions (`ValidationError` on `'not an int'`) that verify the type argument actually propagates into the nested Self schema rather than falling back to an unparametrized/Any schema. Both sets would fail on base and pass after. The margin is small, but B's cleaner control flow and stronger behavioural assertions give it the edge.

Description

It looks like in 2.14.x a generic dataclass with a Self-annotated field cannot be used with type arguments. The example below shows a minimal example. This did work in 2.13.x, and I walked it back as far as 2.11.7, all of which seem to handle this fine. It's kinda of a weird use case, but I have code where we are building pydantic models that store graph-like information (hence my example) and the bump to 2.14.x broke everything.

I think the root cause originates in #13614. generate_schema() now calls get_origin() before _generate_schema_inner(), which is where Self gets replaced by the type being built via _resolve_self_type. That causes the origin to now be stale and not match the new obj which could be a generic, so its origin of None is wrong.

Pretty sure it's a one line fix to regenerate the origin after _resolve_self_type is called. Seemed to work for me

Example Code

from dataclasses import dataclass
from typing import Generic, Self, TypeVar

from dataclasses import dataclass
from typing import Generic, Self, TypeVar

import pydantic
from pydantic import TypeAdapter

T = TypeVar('T')


@dataclass
class StdNode(Generic[T]):
    value: T
    parent: Self | None = None


@pydantic.dataclasses.dataclass
class PydNode(Generic[T]):
    value: T
    parent: Self | None = None


print('pydantic', pydantic.VERSION)
for tp in (StdNode, PydNode, StdNode[int], PydNode[int]):
    try:
        ta = TypeAdapter(tp)
        print(f'  OK    {tp!r:28} ->', ta.validate_python({'value': 1, 'parent': {'value': 0}}))
    except pydantic.errors.PydanticSchemaGenerationError as e:
        print(f'  FAIL  {tp!r:28} -> PydanticSchemaGenerationError: {str(e).splitlines()[0][:70]}')
