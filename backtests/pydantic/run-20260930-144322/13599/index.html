PEP 695 type aliases don't work with callable discriminators

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause the same way. `_convert_schema` gains a `definitions` mapping, and `apply_discriminator` passes it along. That lets the deferred path used by `Field(discriminator=Discriminator(callable))` resolve `definition-ref` schemas produced by PEP 695 / `TypeAliasType` aliases, both for the top-level union and for individual choices. Without this, tags on those schemas are never found, which is the `Tag not provided` error in the issue. The two resolution helpers behave essentially the same: each tries the handler first, then the definitions dict, and raises `MissingDefinitionForUnionRef` when a top-level ref is missing. B always passes a dict (`definitions or {}`) and uses a single LookupError-raising helper, which keeps the existing try/except structure. A returns None from its helper and rewrites the control flow; this is fine but slightly more churn. A also swallows `LookupError` behind a `pragma: no cover`. The deciding factor is tests. A adds one test that covers the basic union alias case and only checks the happy path. B parametrizes the union alias case and a case where an individual member is an alias-wrapped tagged type. It checks both tags and asserts a `union_tag_invalid` error for a bad tag. It also adds a recursive type alias case, which exercises the ref-resolution path through definitions more thoroughly. Correctness is equivalent, so B's stronger and broader tests make it the better patch.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

What the agent reported

I fixed it: a PEP 695 type alias now works with Field(discriminator=Discriminator(fn)), and your M3 case validates. The full test suite passes apart from one failure that also happens without my change (explained below). Nothing is committed.

What was wrong

There are two ways to attach a callable Discriminator, and they took different code paths:

  • Annotated[Alias, Discriminator(fn)] already worked, because the schema handler resolves the alias's reference to its definition (support added in #11941).
  • Field(discriminator=Discriminator(fn)) goes through apply_discriminator(), which called Discriminator._convert_schema(schema) without a handler. The alias therefore stayed as an unresolved definition-ref, got treated as a one-member union with no Tag, and raised `Tag` not provided for choice {'type': 'definition-ref', ...}. The string-discriminator path (M1) worked because it resolves references from the definitions mapping it is given.

What I changed

  • pydantic/_internal/_discriminated_union.py: apply_discriminator now passes its definitions mapping to _convert_schema.
  • pydantic/types.py: _convert_schema takes an optional definitions argument. A small local resolve_ref_schema uses the handler when there is one and otherwise looks the reference up in definitions. That covers both the alias itself and alias members inside a union.
  • When no handler is passed and the alias's definition isn't built yet, it raises MissingDefinitionForUnionRef so building the schema is postponed, as the string-discriminator path already does.
  • Behaviour when a handler is passed is unchanged.

Tests

  • New tests in tests/types/unions/test_discriminated_union.py, all right after test_discriminated_union_type_alias_type_separate_callable_discriminator:
  • test_callable_discriminator_field_type_alias[union_type_alias]: your M3 scenario, using TypeAliasType (what a type statement creates).
  • test_callable_discriminator_field_type_alias[tagged_member_type_alias]: an alias of a single tagged model used as one member of a union.
  • test_callable_discriminator_field_recursive_type_alias: an alias that refers to itself, which exercises the postponed path.

Each checks that the right model or value comes back, and the first two also check that an unknown tag raises union_tag_invalid. All three fail with the reported error without the fix and pass with it.

  • Manual check: with real type statements on Python 3.13, the Field form and the Annotated form both validate. A self-referencing model with a callable discriminator still works.
  • Targeted ./bt-test on the union, type-alias, forward-ref, JSON-schema, generics, types, main and edge-case tests: 2402 passed, 0 failed.
  • Full ./bt-test: 12322 passed, 1 failed. The failure is tests/test_validators.py::test_v1_validator_deprecated, which expects a file under /work/ while this checkout is at /workspace/. It fails the same way with my change removed, so it comes from the environment, not this fix.
