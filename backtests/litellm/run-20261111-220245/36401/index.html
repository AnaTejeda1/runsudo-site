The Feature

Let callers turn off Gemini thought summaries while keeping thinking on.

In litellm/llms/vertex_ai/gemini/vertex_and_google_ai_studio_gemini.py, both reasoning-effort mappers hardcode includeThoughts:

# _map_reasoning_effort_to_thinking_budget (Gemini 2.5)
"low" | "medium" | "high"  -> {"thinkingBudget": N, "includeThoughts": True}
"disable" | "none"         -> {"thinkingBudget": 0, "includeThoughts": False}

# _map_reasoning_effort_to_thinking_level (Gemini 3+)
"low" | "medium" | "high"  -> {"thinkingLevel": ..., "includeThoughts": True}
"disable" | "none"         -> {"thinkingLevel": low|minimal, "includeThoughts": False}

includeThoughts is coupled 1:1 to whether the model thinks at all, so thinking ON + summaries OFF is unreachable — even though that is the default of Google's own SDK.

Any of these would work (preference order):

  1. Request param include_thoughts: bool that overrides the mapping.
  2. Module flag litellm.gemini_include_thoughts_default — same shape as the existing litellm.enable_gemini_default_thinking_level_low in that file.
  3. litellm_params / config knob for proxy operators.
  4. Minimum: stop dropping an explicitly supplied thinkingConfig under drop_params: true.

Keep True as the default — this is about reachability, not changing behavior.

Motivation, pitch

We run LiteLLM Proxy as a shared gateway in front of Vertex Gemini. It measured 2.4-3.2 s/request slower than a direct Vertex call on identical prompts. Cause:

direct  (google SDK) : thinkingConfig = {"thinking_level": "MEDIUM"}
gateway (LiteLLM)    : thinkingConfig = {"thinkingLevel": "medium", "includeThoughts": true}

Summaries are pure added latency for us: decoded token counts are byte-identical and reasoning_tokens stays at 700-900 either way — the model reasons the same, we just pay seconds to narrate it. Affects both thinkingBudget (2.5) and thinkingLevel (3.x) families.

No client-side fix exists — all verified against a live proxy:

AttemptResult
reasoning_effort: "none" / "disable"Also zeroes the budget — disables reasoning
reasoning_effort + thinking={...}UnsupportedParamsError
Explicit thinkingConfig in bodySilently dropped under drop_params: true

So we monkey-patch internals:

from litellm.llms.vertex_ai.gemini.vertex_and_google_ai_studio_gemini import VertexGeminiConfig

original = VertexGeminiConfig.map_openai_params

def patched(self, non_default_params, optional_params, model, drop_params):
    result = original(self, non_default_params=non_default_params,
                      optional_params=optional_params, model=model,
                      drop_params=drop_params)
    cfg = result.get("thinkingConfig")
    if isinstance(cfg, dict) and cfg.get("includeThoughts") and not client_opted_in():
        cfg["includeThoughts"] = False   # thinkingLevel/thinkingBudget untouched
    return result

VertexGeminiConfig.map_openai_params = patched

It works, but it pins us to a private import path and an exact signature, has to swallow every exception because it runs on every request, and needs manual re-verification on each upgrade.

Worth noting generally: since "thinking on, summaries off" is the Google SDK default, anyone benchmarking LiteLLM against direct Vertex is comparing unequal work and concluding LiteLLM is slower.

Happy to open a PR for option 1 or 2 — just say which shape you'd take.
