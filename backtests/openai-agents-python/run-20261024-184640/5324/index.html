Both patches add `kind="tool_exception"` with an `error` field, apply the run formatter only on the default failure path, preserve `failure_error_function=None` re-raising, fall back to the default on formatter crash or non-string return, and pass all independent tests. Describe the feature

Since 0.23.0 (#5112), default_tool_error_function returns a fixed "An error occurred while running the tool. Please try again.". That is a sensible secure default. The only way to send approved error detail back to the model is a failure_error_function on each tool.

Apps with many tools usually want one run-wide policy instead. For example, "expose messages from our own ToolInputError, redact everything else". Today that means decorating every @function_tool call site. Tools added later silently fall back to the generic message, so the model can no longer self-correct bad arguments.

RunConfig.tool_error_formatter already exists for this kind of per-run policy, but ToolErrorFormatterArgs.kind only covers "approval_rejected" and "tool_not_found".

Proposal: add a kind="tool_exception" to tool_error_formatter, with the exception on the args (e.g. error: Exception | None). It would apply only when a tool uses the default failure_error_function, and returning None keeps the redacted default. Precedence would be: an explicit per-tool failure_error_function wins, then the run-level formatter, then the SDK default. Secure by default is preserved, and nothing changes unless the formatter opts in.

class ToolInputError(Exception): ...

def formatter(args: ToolErrorFormatterArgs) -> str | None:
    if args.kind == "tool_exception" and isinstance(args.error, ToolInputError):
        return f"Invalid input: {args.error}"
    return None  # keep SDK default

Runner.run(agent, input, run_config=RunConfig(tool_error_formatter=formatter))

Repro of current behaviour (0.23.1 vs 0.22.3)

A tool that raises ValueError("order_id must start with 'ORD-', got '123'"), run with a fake model that captures the next turn's input:

On 0.23.1 the only fix is per tool (@function_tool(failure_error_function=...)). There is no run-wide equivalent.
