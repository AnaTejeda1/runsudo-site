Agent end hooks lose the structured purchase details of an agent-as-tool call

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The source changes are byte-identical: both patches pass `context_wrapper.tool_input` into the `AgentHookContext` built for `on_start` in `run_single_turn` and `run_single_turn_streamed`, and for `on_end` in `run_final_output_hooks`. That is the root cause (the hook context was constructed without the structured tool input even though the wrapper carried it), and the independent tests confirm both patches fix on_start and on_end across nested-streamed, non-streamed, and outer-streamed runs. So the decision rests on tests and craft. Patch A's test sits next to the existing `test_agent_as_tool_structured_input_sets_tool_input`, parametrizes nested streaming, and asserts the full hook sequence for both agents, including that the outer Buyer's hooks see `None` and that ordering is Buyer-start, Calculator-start, Calculator-end, Buyer-end. That extra assertion guards against the plausible regression of tool_input leaking into the parent agent's hook context, which neither B nor the independent tests check. Patch B parametrizes outer streaming as well, but the asserted hook context is created inside the nested run, so the outer-streaming axis adds little beyond what A covers. B also has small craft issues: an inline `from pydantic import BaseModel` inside the test body, and an inconsistent hook signature (`on_start` typed with `AgentHookContext` while `on_end` is typed with `RunContextWrapper`), plus a more verbose ScriptedModel setup. Both tests would fail before and pass after the fix; A's is tighter and checks a more complete invariant, so A edges out B.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. Describe the bug

<!-- Clearly and concisely describe the bug. -->

I was using a purchasing assistant that delegates invoice calculations to a calculator agent through Agent.as_tool(parameters=Purchase). I attached an end hook to the calculator to save the quantity, unit price and calculated total in a CSV. For two notebook boxes at $25 each, the assistant reported $50 and said the invoice was saved, but the saved row was ,,50. The structured input is available on the nested run result; it disappears specifically in the context passed to the lifecycle hook.

import asyncio
import csv
import os
from pathlib import Path
from openai import AsyncOpenAI
from pydantic import BaseModel
from agents import Agent, AgentHooks, ModelSettings, OpenAIChatCompletionsModel, Runner, set_tracing_disabled

set_tracing_disabled(True)
model = OpenAIChatCompletionsModel("deepseek-flash", AsyncOpenAI(api_key=os.environ["DEEPSEEK_API_KEY"], base_url="https://api.deepseek.com/v1"))
settings = ModelSettings(temperature=0, extra_body={"thinking": {"type": "disabled"}})
invoice = Path("/tmp/notebook-invoice.csv")


class Purchase(BaseModel):
    quantity: int
    unit_price: int


class SaveInvoice(AgentHooks):
    async def on_end(self, context, agent, output):
        purchase = context.tool_input or {}
        with invoice.open("w", newline="") as file:
            csv.writer(file).writerows([["quantity", "unit_price", "total"], [purchase.get("quantity", ""), purchase.get("unit_price", ""), output]])


async def main():
    calculator = Agent(name="Purchase calculator", instructions="Calculate quantity times unit_price. Reply with only the numeric total, without currency symbols or explanation.", model=model, model_settings=settings, hooks=SaveInvoice())
    buyer = Agent(name="Purchasing assistant", instructions="For a purchase, call calculate_purchase with its quantity and unit_price exactly once, then report the total.", model=model, model_settings=settings, tools=[calculator.as_tool(tool_name="calculate_purchase", tool_description="Calculate a purchase total and save its invoice.", parameters=Purchase)])
    answer = await Runner.run(buyer, "Please calculate and save the invoice for two notebook boxes at $25 each.")
    print(answer.final_output)
    print(invoice.read_text())
    assert "2,25,50" in invoice.read_text(), "The saved invoice lost the purchase details"


asyncio.run(main())

The invoice should contain 2,25,50.
