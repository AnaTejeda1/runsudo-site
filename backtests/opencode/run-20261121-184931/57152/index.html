DigitalOcean provider plugin rebuilds and republishes every location's provider/model catalog every five minutes, even without a connection

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Patch B implements the fix the issue asks for at the root cause: it snapshots the inventory (access token + router names) before `load()` and calls `ctx.provider.reload()` only when the snapshot differs afterward. The 5-minute poll is retained, so routers added/removed on DigitalOcean are still discovered, and the idle poll without a connection is silent because `load()` returns early with an unchanged empty inventory. It adds the two regression tests the issue describes (idle poll silent across two ticks; connected poll silent when unchanged, exactly one provider.updated/model.updated when the inventory changes, silent again afterward), using a bus subscriber to count events, which would fail on base and pass with the patch.

Patch A removes the periodic poll entirely (`Effect.repeat(Schedule.spaced("5 minutes"))` becomes a single `refresh()`). That silences the event spam only by deleting the feature: router inventory changes would no longer be picked up until a credential switch, which contradicts the issue's expectation that a changed inventory ("routers added/removed") still triggers a reload. It also deletes 51 lines of existing tests covering periodic refresh, retention of the last successful inventory through 503/invalid responses, empty-inventory handling, and token expiry, and adds no test for the issue's scenarios. The removed comment about retaining inventory through transient failures signals it is discarding designed behavior rather than fixing it.

The independent tests are MISSING on all three trees, so they provide no signal; the judgement rests on the diffs. On correctness, tests, scope, and craft, B is clearly better.

The issue

View on GitHub

Summary

packages/core/src/plugin/provider/digitalocean.ts polls the DigitalOcean router inventory every five minutes and follows every poll with ctx.provider.reload():

const refresh = () => loading.withPermit(load().pipe(Effect.andThen(ctx.provider.reload())))
...
yield* refresh().pipe(Effect.repeat(Schedule.spaced("5 minutes")), Effect.forkScoped)

ctx.provider.reload() rebuilds the location's provider catalog and republishes provider.updated, which makes the Model service rebuild and republish model.updated. This happens even when there is no DigitalOcean connection at all (load() returns early with an empty router list, then the reload runs anyway).

Every loaded location runs its own copy of the plugin, so a server with N loaded folders rebuilds N provider catalogs and N model catalogs every five minutes and pushes 2N catalog events to every connected client, forever, for a provider nobody configured.

Observed (opencode 2.0.32, Windows, OpenChamber desktop, up to 24 loaded folders)

  • 802 of the 1,028 provider.updated events in one day's opencode.log carry pluginID=opencode.provider.digitalocean; the rest come from config/models.dev plugins. There is no DigitalOcean credential on the machine.
  • Per folder the cadence is exact: e.g. 17:21:01, 17:26:01, 17:31:01, 17:36:01 for one folder; 17:24:36, 17:29:36, 17:34:36 for another. Each is followed ~16 ms later by model.updated for the same folder.
  • Clients subscribed to the event stream refetch the provider and model catalogs for that folder on every pair.

Expected

The idle poll should be silent when nothing changed. A reload is only needed when the access token or the router inventory actually changed (first sync after a connection, credential switch, routers added/removed).

Fix

PR follows: compare the inventory (access token + router names) before and after a sync and call ctx.provider.reload() only when it differs. Two regressions: the idle poll without a connection publishes no provider.updated/model.updated across two 5-minute ticks; with a connection, an unchanged poll publishes nothing and a changed inventory publishes exactly one of each.
