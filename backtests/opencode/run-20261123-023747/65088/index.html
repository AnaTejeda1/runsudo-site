Patch A replaces the colon heuristic with a bracket/quote-aware scanner for flow values (tracking state across lines so multi-line flow collections pass through intact) and uses a real parse (`isValidYaml`) for other colon-bearing values, so only genuinely unparseable lines are rewritten. The hand-rolled scanner is more surface area than B's helper, but it is exercised by a much broader test set: nested collections, quoted delimiters with `]`/`}` and doubled single quotes, inline comments, multi-line flows with repaired fields before and after, explicit CRLF (the reporter is on Windows), and failure cases. Description

Frontmatter recovery converts valid flow-style YAML collections into strings when another field needs the existing unquoted-colon repair. A Markdown agent with a structured model then fails decoding and is skipped. Changing only its description to plain text makes the same agent load.

Plugins

Built-in configuration agent plugin in an isolated Core fixture; no external plugins.

   ---
   Review carefully.
  1. Load it through the configuration agent plugin. Compare with an otherwise identical file whose description is Review changes.
  2. The control loads with example/chat#high; the first agent is missing. ConfigMarkdown.parse returns its model as the string "{ providerID: example, model: chat, variant: high }" instead of an object.

Expected: repairing the description preserves the valid model mapping. The same corruption affects a flow sequence of permission mappings.
