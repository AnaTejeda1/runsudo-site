Spurious comma in parametrize causes obfuscated crash

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the primary crash at the same spot by catching the TypeError from len(param.values) in ParameterSet._for_parametrize and raising a clean, nodeid-prefixed fail() message. The independent tests confirm both resolve the None/int/tuple-argnames crash scenarios. The difference is the issue's second ask: showing a string value as the character sequence it is unpacked into (['f', 'o', 'o']). Patch B implements this (converting str values to a list in the mismatch message) and the independent test for it passes only under B; Patch A ignores that part entirely and fails that test. On tests, B is stronger: it parametrizes over four argnames forms ('x,', ('x',), 'x, y', ('x','y')), adds an unsized-object case where __len__ itself raises TypeError, and a dedicated string-display test, all of which would fail on base. A adds a single test for the None case. On craft, both are comparable; B's error message reads naturally and its explanatory comments and changelog are accurate, while A's suggestion to use a one-element tuple is a nice touch but does not compensate for the missing string-display improvement. B's extra AUTHORS-less diff and A's AUTHORS edit are neutral. B is the more complete fix.
