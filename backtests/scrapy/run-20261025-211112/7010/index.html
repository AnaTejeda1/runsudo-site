scrapy settings --get does not account for add-ons

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the reported behaviour the same way at the core: in the settings command they call AddonManager.load_pre_crawler_settings, build a Crawler with the base Spider, and run crawler.addons.load_settings so both pre-crawler and update_settings changes are visible. All eight independent tests pass on both, so correctness on the issue's scenarios is equal.

Differences: Patch A copies the settings before mutating them, keeping the command's self.settings untouched, which is slightly cleaner than B mutating self.settings in place. A also applies the same pre-crawler loading to list/edit/genspider, which share the exact root cause (commands that never build a CrawlerProcess miss add-on changes such as SPIDER_MODULES); this is beyond the literal ask but low risk and directly tested, so it does not count against A. B instead adds a new --spider feature with docs; that is also out of scope and neutral on its own, but it is more product-surface than fix.

Tests tip the balance. A's new test class has a distinct name (TestSettingsCommandAddons) and covers get/getbool/getint/getfloat/getlist, pre-crawler settings, project and command-line priority. B names its new class TestSettingsCommand, which already exists earlier in tests/test_commands.py (visible in A's diff context, the base class ends right before TestCommandCrawlerProcess). Redefining it at module level shadows the original, so pytest would silently stop collecting the existing TestSettingsCommand tests, and ruff F811 would flag the redefinition. That is a concrete craft defect that quietly removes coverage. A's edit test has a win32 skip, which is a reasonable platform restriction and still runs on the POSIX hosts the issue's scenario would use (though I cannot verify its write_recording_editor helper exists, which slightly lowers confidence).

On balance A is the better patch: equivalent fix, cleaner handling of settings, tests that extend rather than clobber existing coverage.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours.
