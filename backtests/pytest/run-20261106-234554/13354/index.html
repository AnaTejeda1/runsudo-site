Node.get_closest_marker default kwarg deprecation

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The reported problem is that the only way to satisfy the `default: Mark` parameter is to build a `pytest.Mark`, which now warns. At runtime `next(iter, default)` already accepts anything, so the real restriction is the type signature. Patch B fixes that at the root: the overload becomes `default: _T -> Mark | _T`, so any sentinel (or `pytest.mark.x(...).mark`) is a valid, correctly typed fallback, matching the conventional `dict.get`-style contract. It adds `typing_checks.py` assertions that pin the new overload behaviour (the right place for a typing fix), a functional test covering sentinel/None/`.mark` defaults, and a `-W error::PytestDeprecationWarning` test showing the documented alternative is warning-free. The docstring explicitly tells users to use `pytest.mark.<name>(...).mark`, which is the missing 'alternative way' the issue asks for. Patch A instead adds a special case: it accepts a `MarkDecorator` and silently unwraps it. That is a reasonable convenience and its test does fail-before/pass-after, but it keeps the `default` type artificially restricted to Mark-like values (the independent sentinel test still fails with A), adds an isinstance branch to a hot accessor, and does not point users at the already-working `.mark` route. The independent tests split (A passes the decorator-default test, B passes the sentinel test); the issue only asks for an alternative way to pass a default, which B provides generally while A provides narrowly. Minor nit on B: the implementation signature widens to `object -> object`, but the public overloads carry the precise types. Overall B is the more complete and conventional fix with better type-level test coverage.

I think that overload of Node.get_closest_marker with default kwarg should be deprecated or we should have alternative way to pass default.

commit, where deprecation warning of pytest.Mark.__init__ was added: https://github.com/pytest-dev/pytest/commit/2ec372df8b987207efc4ad0f33c2f82df5c9e2e5
