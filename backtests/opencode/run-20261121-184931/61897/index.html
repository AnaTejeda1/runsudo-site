[FEATURE]: Make the active session ID easy to copy in Desktop

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The issue asks for a one-click way to copy the ID of the session currently being viewed, from the session header or its menu. Patch B does exactly that: it extracts the existing copy-session-ID logic into a reusable `useCopySessionID` hook and `SessionCopyIDMenuItem`, refactors the existing command to use it, and adds the menu item to the session header's location card, the timeline's session options menu, the tab context menu, the sidebar inbox, project session rows, and home session rows. The active session's ID is now reachable from the header and multiple menus with one click, with success/failure toasts, and the hook has unit tests covering desktop clipboard, browser fallback, and failure reporting. Scope is tight and consistent with surrounding menu conventions (sits next to Export / SessionReadMenuItem).

Patch A instead builds a right-click context menu on session *references* inside transcript markdown and composer mentions (Copy Session ID / Copy Session Title / Open Session), plus a session-ID cell in the debug bar plugin. Neither surfaces the active session's ID in the session header or its options menu: the reference menu only applies to IDs that happen to appear in message text or mentions, and the debug bar is an opt-in developer plugin, not the normal Desktop session view. The patch also carries substantial unrelated churn: it changes how session references render (prepending '@' to titles), rewrites their CSS, alters copy-to-clipboard behaviour for selections containing references, and adds a new lookup state machine for fetching titles of unloaded sessions. That is a broader redesign that adds risk and does not address the issue's core ask. Its tests are reasonable for what it builds, but they test the reference menu and lookup machine, not the requested header/menu action.

The independent tests are MISSING on all trees, so they provide no signal. On correctness relative to the issue, scope, and relevance of tests, Patch B is clearly the better fix.

Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours.
