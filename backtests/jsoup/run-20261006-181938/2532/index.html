Issue #2532 Merged fix PR # Run 6 Oct 2026 · run-20261006-181938 jhy/jsoup

Element.html(Appendable) violates the contract of Node.html(Appendable)

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the issue the same way: they make `Node#outerHtml(Appendable)` public so an element's outer HTML can be streamed. Both also document that `Element#html(Appendable)` writes inner HTML, consistent with `html()`. Both handle `Document` so it writes no wrapper tag.

Patch A does this with the smallest possible change. It widens the visibility from protected to public and keeps the `void` signature, which is binary- and source-compatible. It adds a `Document` override that delegates to `html(accum)`. Its tests check the result against `outerHtml()` and `html()`, cover non-element nodes and building a fragment from several elements, and run from outside the `org.jsoup.nodes` package to show the method is now public.

Patch B changes the signature to a generic `<T extends Appendable> T outerHtml(T)`. That breaks binary compatibility, so it has to add a japicmp exclusion in `pom.xml` and argue that no downstream code overrides the method. It also removes `Document#outerHtml()` (String) and instead overrides `outerHtml(QuietAppendable)`. That drops the old `super.html()` path, which trimmed output under pretty-print, so `Document.outerHtml()` may now behave differently. It also refactors `Element#html` into a package-private `QuietAppendable` overload. The return value for chaining is a nicer API, and its tests are also solid, including `assertSame` and prefix checks. But the extra signature changes, the build-config exclusion and the altered `Document.outerHtml()` path add risk without being needed to fix the issue.

On correctness and tests the two are about equal, and A's scope is tighter and lower-risk, so A wins.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

The contract of Node.html(Appendable) states: "Write this node and its children to the given Appendable", but if you call Element.html(Appendable) only the children of the Element are appended:

https://github.com/jhy/jsoup/blob/d8c49e5ec72a08ca1ac4e08740e70dc0f47ad911/src/main/java/org/jsoup/nodes/Element.java#L2047

On the other hand, Node.outerHtml(Appendable) is protected, and the class Printer is not visible too.

It would be very useful to have a method to write all the HTML of an element and its content, especially when one have to generate HTML fragments. The String outerHtml() method is public and does the job, but it's obvious that the version that accept an Appendable is more efficient if the caller has an Appendable ready to use.
