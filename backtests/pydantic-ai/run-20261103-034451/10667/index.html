Early exit from node.stream() leaves AgentStream's inner generators (_events_iter, _model_events) to the garbage collector

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

The core fix is identical in both patches: `_events_iter` closes `base_iter` in a `finally`, the usage-checking wrapper closes its source, and `dispatch_event_stream` closes its source. Both pass all independent tests, including the pending-task and GC-finalizer checks with and without token limits and the consumer-error case. The differences are at the margins. Patch A also closes the node stream inside `_with_event_stream_buffer`, so the remaining link between `dispatch_event_stream` and `CallToolsNode._run_stream` is torn down deterministically too. That is adjacent to the issue's stated ask but squarely in the spirit of 'teardown closes the whole chain deterministically', and it adds essentially no risk: closing an exhausted or already-failed generator is a no-op, and on early exit the `finally` runs before the GeneratorExit propagates. Patch A's tests check the exact observable the issue reports (no pending tasks after `agent.iter()` exits) plus the asyncgen finalizer hook, with a sanity assertion that the hook is recording, and add a second test for the consumer-raises path on the tool-call node. Patch B's test is well designed in its own way (it holds references to the layer generators and asserts `ag_frame is None`, so GC cannot mask a missing close), but it only covers the model-request node and does not assert the pending-task symptom. Patch A also documents each new `finally` with a comment stating why it exists, matching the explanatory style of the surrounding code, while Patch B's `finally` blocks are bare. On correctness they are equal; on tests and craft A is slightly ahead, and its extra coverage of the node-stream link is low-risk and aligned with the issue, so A wins narrowly.

Description

Suppose a consumer stops reading a model request node's stream early:

async with node.stream(ctx) as s:
    async for e in s:
        break

On teardown, AgentStream's internal generator chain is not closed:

  • aclose_events() closes only the head of the event chain.
  • _events_iter pulls from base_iter with anext() and never closes it.

The rest of the chain is therefore closed only when the garbage collector finalizes it through asyncio's asyncgen finalizer hook:

  • _events_iter;
  • the usage-checking wrapper, when token limits are set;
  • since #10003, _model_events.

Visible since 2.57.0. _model_events is finalized only when agent.iter() exits. The aclose() task that asyncio schedules for it is still pending when agent.iter() returns.

2.54.0 leaked too, but invisibly. The chain (_pull_shared, _events_iter) was also left to the GC there, but it was finalized before node.stream() exited, so nothing was pending afterwards.

Expected: teardown closes the whole chain deterministically, as #7095 did for wrap_run_event_stream wrappers (#7013). For example:

  • _events_iter closes base_iter (aclosing / aclose_if_supported);
  • aclose_events() reaches _model_events (and the usage-checking wrapper).

#8822 does not cover this. It closes the tool-execution chain and makes dispatch_event_stream close its source, but it does not touch result.py, so _model_events would still be left behind.

Consumer-side workaround does not help. Closing the consumer's own iterator (aclosing(aiter(s))) only closes _pull_shared. The leftover generators are internal to AgentStream.

How we hit it. Our runtime asserts that no tasks are left pending after a cancelled run. With 2.57.0 that check fails on every early exit, with FunctionModel, OpenAI Responses and Anthropic alike.

Minimal, Reproducible Example

import asyncio
import sys

from pydantic_ai import Agent
from pydantic_ai.models.function import FunctionModel


async def stream(messages, info):
    for piece in ('aa', 'bb', 'cc', 'dd'):
        yield piece


async def main():
    firstiter, finalizer = sys.get_asyncgen_hooks()

    def report(agen):  # asyncio's finalizer: called only for generators nobody closed
        print('  left for GC:', agen.ag_code.co_qualname)
        finalizer(agen)

    sys.set_asyncgen_hooks(firstiter, report)

    agent = Agent(FunctionModel(stream_function=stream))
    async with agent.iter('hi') as run:
        node = run.next_node
        while not Agent.is_end_node(node):
            if Agent.is_model_request_node(node):
                async with node.stream(run.ctx) as s:
                    async for _ in s:
                        break  # consumer walks away early
                print('node.stream exited')
                break
            node = await run.next(node)
    pending = [t for t in asyncio.all_tasks() if t is not asyncio.current_task()]
    print('agent.iter exited; pending:', [t.get_coro() for t in pending])


asyncio.run(main())
