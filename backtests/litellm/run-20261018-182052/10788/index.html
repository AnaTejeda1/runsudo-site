[Bug]: INFO logging of incoming requests to the LiteLLM proxy server can not be switched off.

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the core bug the same way: pass LITELLM_LOG through as uvicorn's log_level so uvicorn.access/uvicorn.error stop emitting INFO request lines, and the independent tests pass on both. B is the stronger fix. Its level parsing (_get_server_log_level) is tolerant of blank, whitespace-padded, lowercase, and invalid values and returns None instead of raising; A's resolve_log_level uses getattr(logging, ...) and will raise AttributeError on an invalid value, and its litellm_proxy_extras change calls logger.setLevel with a raw env string that raises ValueError at import time on a typo. A only applies the level in an elif branch, so with JSON_LOGS=true the fix silently does nothing, while B applies log_level alongside the JSON log_config (uvicorn applies log_level after dictConfig, so this works) and has a test for it. B also covers the hypercorn, granian, and gunicorn launch paths the same proxy CLI exposes, including disabling gunicorn's pinned-at-INFO access log, which is the same user-facing problem under a different server flag; this is adjacent work but low-risk and tested rather than churn. A's extras logger change is tangential to the issue (the request lines come from uvicorn, not litellm_proxy_extras) and adds import-time failure risk. B's tests are more comprehensive (parsing table, json mode, user log_config not overridden, each server path), and A's tests are solid but narrower. Minor nit against B: slightly larger diff and granian/hypercorn string conversions are untested for unusual levels, but nothing that outweighs A's json_logs gap and unsafe parsing.

What happened?

Hi, our LiteLLM proxy logs are full of INFO lines for each request. We'd like to switch that off. We expect LITELLM_LOG=ERROR to do the job, but it does not help.

Here is a minimal example to reproduce the problem:

litellm_config.yaml:

model_list:
  - model_name: gpt-4o-mini
    litellm_params:
      model: openai/gpt-4o-mini
      api_key: sk-[...]
general_settings: 
  master_key: sk-1234

run:

docker run \
    -v $(pwd)/litellm_config.yaml:/app/config.yaml \
    -p 4000:4000 \
    --env LITELLM_LOG=ERROR \
    ghcr.io/berriai/litellm:main-v1.69.0-stable \
    --config /app/config.yaml

When sending requests like this

curl -X POST 'http://0.0.0.0:4000/chat/completions' \
-H 'Content-Type: application/json' \
-H 'Authorization: Bearer sk-1234' \
-d '{
    "model": "gpt-4o-mini",
    "messages": [
      {
        "role": "user",
        "content": "Hi."
      }
    ]
}'

the LiteLLM proxy server logs lines as follows:
