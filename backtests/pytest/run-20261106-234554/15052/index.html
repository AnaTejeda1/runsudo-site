fixtures: --fixtures-per-test has an off-by-one on item's lineno

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Root cause: `getlocation` returns `co_firstlineno + 1`. `co_firstlineno` is already 1-based and points at the first decorator, so the `+1` only produced the `def` line by accident for single-decorator fixtures and is one too high for undecorated test items (the 357 vs 356 in the issue). Both patches fix the item header line, and the three independent header tests pass for both.

Patch B simply drops the `+1`. That fixes the item line but shifts every decorated fixture's reported location from its `def` line to the `@pytest.fixture` decorator line. The issue quotes `monkeypatch -- src/_pytest/monkeypatch.py:36` as the correct companion line and only objects to 357; the independent test that checks the fixture line stays at its def fails on B (it now prints 35). B's own test edits confirm the regression: `arg1 -- test_fixtures_in_module.py:6` becomes `:5`, and the 'Requested fixture ... defined in' and 'request is a reserved word' messages also move to the decorator line. That is a user-visible behaviour change beyond the ask, not justified by the issue. B does add a changelog entry, which is a plus for craft.

Patch A replaces the accidental `+1` with a real lookup of the `def` line via `inspect.getsourcelines` + `ast`, with fallbacks to `co_firstlineno` on OSError/TypeError/SyntaxError/TokenError, an `if True:` wrapper to cope with indented methods whose docstrings dedent, and name matching on `co_name`. This yields correct def-line locations for undecorated items, single-decorator fixtures (preserving existing output), stacked decorators, methods, async methods, and falls back sanely for lambdas. It adds targeted tests for each of those cases in test_compat.py, show_fixtures_per_test.py and fixtures.py, and the independent fixture-location test passes. The approach is heavier than a one-line change, and it lacks a changelog, but the extra code is directly needed to fix the item line without regressing fixture lines, and it is guarded at every edge. A is the better fix.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.
