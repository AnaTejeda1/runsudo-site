Allow arbitrary core schemas for serialization

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Patch B adds an explicit `SchemaSerSchema` (`{'type': 'schema', 'schema': ...}`) with a `schema_ser_schema()` constructor. In Rust it builds the inner schema with `Self::build`, so nested `serialization` keys and definition refs are still honored. Because the new type is a distinct tag, it never collides with existing ser schema types. B then removes the identity-wrap-serializer workaround everywhere it appeared: ValidateAs, PlainValidator, InstanceOf, SkipValidation and the non-dict mapping case in `_generate_schema`. It also updates JSON schema generation to handle the new type. Its tests cover pydantic-core (list, typed dict, dataclass, definition refs, overriding the outer type, nested serialization, error on a missing inner schema) and pydantic itself (ValidateAs, InstanceOf, SkipValidation, PlainValidator, OrderedDict serialization, and the serialization JSON schema). Those tests check the real end-to-end behavior the issue asks for.

Patch A takes a more invasive route: any core schema can be used directly as a serialization schema. This is inherently ambiguous because `function-plain` and `function-wrap` validator schemas share type tags with the function ser schemas. Patch A acknowledges this and works around it with a Python-side `as_ser_schema` helper. It also reshapes `SerSchema` into a string-literal type alias and touches `IncEx*` aliases and `json_schema.py` (rewritten as a `match`) for typing reasons, which is churn and adds risk. Most importantly, Patch A does not remove any of the workarounds the issue points at. It only rewrites the TODO in ValidateAs, so pydantic still uses identity wrap serializers. Its tests are mostly pydantic-core-level plus a unit test for a helper that nothing uses yet.

Patch B is the more correct, less risky and more complete resolution, with stronger tests.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

View on GitHub

As per the TODO in https://github.com/pydantic/pydantic/pull/13487:

There is currently no way to tell pydantic-core "serialize this value using this core schema". SerSchema is:

SerSchema = Union[
    SimpleSerSchema,
    PlainSerializerFunctionSerSchema,
    WrapSerializerFunctionSerSchema,
    FormatSerSchema,
    ToStringSerSchema,
    ModelSerSchema,
]

The only member that expresses "use this schema" is SimpleSerSchema, and it does not take a schema at all, only a name from a closed literal:

ExpectedSerializationTypes = Literal[
    'none', 'int', 'bool', 'float', 'str', 'bytes', 'bytearray', 'list', 'tuple',
    'set', 'frozenset', 'generator', 'dict', 'datetime', 'date', 'time', 'timedelta',
    'url', 'multi-host-url', 'json', 'uuid', 'any',
]

class SimpleSerSchema(TypedDict, total=False):
    type: Required[ExpectedSerializationTypes]

So an arbitrary schema (a model, a dataclass, list[int], a TypedDict, anything constructed by the schema generator) cannot be used directly. Every place in Pydantic that needs it works around the gap the same way: it wraps the schema in a wrap serializer whose function is the identity, purely so the schema can ride along in the schema argument.

From ValidateAs.__get_pydantic_core_schema__():

https://github.com/pydantic/pydantic/blob/27f95c789b20aa23306e5ce559327db0e9a10a6e/pydantic/functional_validators.py#L911-L917
