Clearing select's value in change handler behaviour changed since 3.4.15 via webdriver

Worse

The merged fix was judged better than our patch.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause the same way. The `_assigning` flag in the select's `updated` hook unconditionally skipped `setSelected` until nextTick, even when a `@change` handler changed the model again in the same tick. Each patch replaces that blanket skip with a comparison: the DOM resync is skipped only if the incoming model value still matches what was just assigned from the DOM. Each snapshots the Array value so a handler mutating it in place is still detected, and each resyncs for the issue's single-select-cleared-to-null scenario.

Patch A compares with `hasChanged` on `toRaw(value)` and clears the snapshot in nextTick. Its tests cover the issue directly: single select reset to null, multiple-select reassignment, and in-place mutation of an Array or Set.

Patch B compares with `looseEqual`, which matches how `setSelected` itself compares option values. It also handles more edge cases:
- It records whether the select was `multiple` at assign time and resyncs if that toggles.
- It clears the pending value in `updated`, guarded by identity so a stale nextTick cannot clobber a newer one.
- It uses try/finally around the assigner.

Patch B's tests are notably stronger. Beyond the issue's reset-in-change-handler case, they check:
- Set override.
- Duplicate option values keep the chosen index.
- Mutation of the emitted Array or Set.
- The multiple/single toggle.
- No `option.selected` writes when the model simply echoes the DOM, for primitive arrays and for Arrays and Sets of objects.

The no-write tests guard the performance optimization that introduced the regression. That optimization is the main risk of any fix here, and Patch A has no test for it.

Both are correct and in scope. Patch A is somewhat simpler. Patch B's more robust edge handling and much more thorough regression coverage give it the edge.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
