What the agent reported

The fix is complete and verified. Final summary:

What was wrong

Commit ec52e638c upgraded KaTeX from 0.16.21 to 0.18.4, which changes the rendered math output. But transform.ToMath caches renderings on disk keyed by a version segment, fileCacheEntryVersion, which stayed at "v1". As a result, sites with an existing cache (like the docs site's chem example) kept serving stale pre-upgrade output from tomath/v1/... instead of re-rendering with the new KaTeX.

What I changed

  1. tpl/transform/transform.go:296 — bumped const fileCacheEntryVersion = "v1" → "v2". This changes the cache key path to tomath/v2/..., so old v1 entries are no longer looked up and everything re-renders with the new KaTeX.
  2. tpl/transform/transform_integration_test.go — added TestToMathCacheVersionInvalidation (plus imports). It pre-seeds a stale tomath/v1/... misc-cache entry on the real filesystem containing a marker STALE_CACHED_MATH_DO_NOT_SERVE, builds a site rendering E=mc^2, and asserts the stale marker is not served while a fresh <span class="katex"><math render is.

Test evidence

  • Before the production change: the new test FAILED — Got: STALE_CACHED_MATH_DO_NOT_SERVE (the seeded v1 entry was served).
  • After bumping to "v2": ./bt-test ./tpl/transform/ → package PASS. TestToMathCacheVersionInvalidation passes; all pre-existing ToMath tests (TestToMath, TestToMathError + subtests, TestToMathBigAndManyExpressions, TestToMathRenderHookPosition, TestToMathMacros, TestToMathStrictMode) still pass. No failures in the package.
  • Reviewer confirmed the diff is minimal, matches the report, adds no scratch files, weakens no tests, and the test genuinely distinguishes v1 vs v2 code.

  • Bump fileCacheEntryVersion in transform.ToMath — ✅ Implemented ("v1"→"v2"), with a regression test that fails before and passes after.
