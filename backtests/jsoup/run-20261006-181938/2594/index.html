The issue's central example is a parsed attribute name like `data-x\u0001` being trimmed down to `data-x` and then treated as equal to it.

The issue

View on GitHub

Currently some parser paths use Normalizer.normalize(...) for names that require narrower rules.

The current implementation trims with String.trim() and lowercases with Unicode rules. That can remove control characters from accepted tag and attribute names, and can make non-ASCII names compare as equal to ASCII names. The HTML5 spec has tag and attribute names as ASCII case insensitive.

For example, these should not equal:

"data-x\u0001"
"data-x"

"K"
"k"

"ſ"
"s"

HTML name comparisons should use ASCII-only case folding. XML parsing should preserve exact names unless the configured parse settings request ASCII folding.

This affects tag and attribute identity, duplicate detection, selector matching, and contextual parser choices.
