Scoped slot transforms array argument if rendered conditionally

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches take the same core approach: stop merging the compiler-generated branch key into a single `v-bind` expression on a slot outlet and instead pass the key as a separate sixth `renderSlot()` argument, with `props.key || key` priority at runtime. The independent tests pass on both. The differences are at the edges.

Patch A is more correct. (1) It adds `if (props == null) props = {}` in `renderSlot`. This matters: before either patch, `<slot v-if="ok" v-bind="maybeNull" />` worked because `mergeProps({key:0}, null)` yields an object; after Patch B, the slot now receives `normalizeProps(guardReactiveProps(null))` = `null` and `props.key` (and `Object.keys(props)` in custom-element mode) throws. Patch B therefore regresses a previously working case; Patch A covers it and tests it. (2) Patch A fixes `guardReactiveProps` to `slice()` arrays instead of `extend({}, arr)`, so a reactive array (e.g. an auto-unwrapped `ref([])`) bound to the slot stays an array. Without this, Patch B still turns reactive arrays into index-keyed objects, which is exactly the symptom the issue reports, just via a different code path. (3) Patch A suppresses the `ref_for` marker merge for slot outlets inside `v-for`, so `<slot v-for ... v-bind="arr">` no longer gets `mergeProps({ref_for:true}, arr)`; this is the v-for counterpart of the same array-to-object conversion and is tested.

Scope and craft: Patch A's compiler change is narrow, adding one branch in `injectProp` only for the single-expression case and leaving existing object-props codegen and snapshots untouched. Patch B reroutes all slot key injection through the new argument, requiring snapshot churn, and includes a misplaced snapshot entry (a `compiler: v-for` snapshot added to `transformElement.spec.ts.snap`, apparently duplicated), which is sloppy. Patch B's unit tests for `renderSlot` are reasonable, but Patch A also adds end-to-end compiler+runtime tests covering v-if, v-else, template v-if, template v-for, v-for, objects, nullish, reactive arrays, custom-element mode, and branch toggling.

Patch B's uniform 'key is always a separate arg' design is cleaner conceptually, but the nullish regression and the unhandled reactive-array case outweigh that. Patch A is the better fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Steps to reproduce

  1. Create a component with a scoped slot that is rendered conditionally
  2. Pass an array as the sole argument to the slot

What is expected?

Array is rendered normally.
If you render items of that array in v-for loop, you only see items inside that array

What is actually happening?

Array is transformed into object. Items and their indexes are staying the same, key field is added
