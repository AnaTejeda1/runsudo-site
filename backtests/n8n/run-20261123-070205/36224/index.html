In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches apply the identical, correct pagination fix (advance limit_start by the full page length) and both stop the TypeError by guarding on filters?.customProperty?.length before mapping, so each resolves both root causes in the issue. The difference is in how the filters fix is shaped. Patch B moves the qs object inside the per-item loop, so every item starts with a clean query: no filters leak from item N to item N+1, and neither do fields. Bug Description

Two independent bugs in the ERPNext node's Document → Get Many operation with "Return All" enabled:

1. Duplicates one row per page boundary once a doctype has more than 1000 records.

The pagination loop advances limit_start by limit_page_length - 1 instead of limit_page_length:

https://github.com/n8n-io/n8n/blob/98f69ed52cca22b118b68ef88c7f2152c539d218/packages/nodes-base/nodes/ERPNext/GenericFunctions.ts#L79-L86

With the default page size of 1000, page 2 starts at limit_start = 999 instead of 1000, so it re-fetches record 999 — the last record of page 1 — as its own first record of page 2. This repeats at every page boundary. It's invisible on any doctype with fewer than 1000 rows, which is likely why it's gone unnoticed.

2. Touching the Options block without adding a filter throws before any request is made.

https://github.com/n8n-io/n8n/blob/98f69ed52cca22b118b68ef88c7f2152c539d218/packages/nodes-base/nodes/ERPNext/ERPNext.node.ts#L178-L184

The Filters fixedCollection's own field definition defaults to {}, not { customProperty: [] }:

https://github.com/n8n-io/n8n/blob/98f69ed52cca22b118b68ef88c7f2152c539d218/packages/nodes-base/nodes/ERPNext/DocumentDescription.ts#L128-L133

{} is truthy, so if (filters) passes, and filters.customProperty is undefined on that default shape — .map() throws a TypeError before any HTTP request happens. This is exactly what the // TODO: filters not working comment sitting directly above the code is flagging.

Both are separate from #19271 (double URL-encoding a doctype name with spaces, already claimed by #22338) and from #35796 / #17267 (System Manager role requirement on the Fields/Filters dropdowns) — this issue is only about the two bugs above.

To Reproduce

Bug 1: Add an ERPNext node, Document → Get Many, pick a DocType with more than 1000 records, enable Return All, execute. The result contains one duplicate record per 1000-record boundary crossed.

Bug 2: Add an ERPNext node, Document → Get Many, pick any DocType, open Options and add a Field (or otherwise cause the Options collection to be touched) without adding anything under Filters, execute.

Expected behavior

Bug 1: Return All returns exactly one row per record, no duplicates.
Bug 2: The node should not throw when Filters is left empty; the request should proceed without a filters query parameter.

Actual behavior

Bug 1: one duplicate row per page boundary.
Bug 2: unhandled TypeError: Cannot read properties of undefined (reading 'map') (or similar, depending on engine) before any request is sent.
