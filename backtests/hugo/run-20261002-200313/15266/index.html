Consider bumping mainImageVersionNumber

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Patch A is the better fix: it bumps the version number the issue names and fixes the reason a bump alone would not reach filtered images.

**Correctness.** The issue asks to bump `mainImageVersionNumber` so cached output from two filter-related fixes is invalidated. Before either patch, `Filter()` set `confMain.Key = hashing.HashString(gfilters)` with no version number in it. So bumping `mainImageVersionNumber` by itself would not invalidate filtered images, which are exactly the ones affected by those fixes.
- Patch A handles this cleanly. It moves the version-number assembly into a `versionOptions()` helper and adds an `ImageConfig.FilterKey` method that folds those numbers into the filter cache key. It then bumps `mainImageVersionNumber` to 2. Every cached image, filtered or processed, is invalidated, which is what the issue asks for.
- Patch B also folds the version numbers into the filter key, so filtered images get new hashes. However, it does not bump `mainImageVersionNumber`. Instead it adds a `PNG: 1` format version, which invalidates PNG resizes in a fairly arbitrary way. Its main-version invalidation of filters is only a side effect of changing the hash input.

**Tests.** Patch A adds `TestImageConfigMainVersionNumber`. It checks directly that bumping the main version changes both the processing key and the filter key, a meaningful regression test for the root cause. Patch A also updates all the affected golden hashes and golden image files consistently. Patch B only updates hash expectations and adds no targeted test.

**Scope and craft.** Patch B exports two package-level mutable variables (`MainImageVersionNumber`, `FormatVersionNumbers`), widening the public API, so the filter-key logic can be built inline in `image.go`. That duplicates logic already in `DecodeImageConfig`. Its diff also carries a lot of unrelated reformatting of `AssertFileContent(` calls across test files, which obscures the actual change. Patch A keeps the logic encapsulated in the `images` package, keeps one source for the version options, and stays focused.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
