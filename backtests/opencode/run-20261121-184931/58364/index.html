The issue

View on GitHub

Description

Archiving a session has no visible effect in the TUI: the session keeps showing up in the Ctrl+O session picker, indistinguishable from active ones, and selecting it opens it normally.

The API already has the filter — GET /api/session?archived=false returns no archived sessions — but the client lists them anyway, so "archive" cannot be used to keep the session list tidy. Today the only way to get an archived session out of the list is to delete it.

Plugins

Local CLI plugins (clear-session, git-status, sidebar-plugins) plus wsl-notify, opencode-roslyn, superpowers, btw-context, zen-failover.

The problem does not depend on them: it is visible from the API alone, and the stock Ctrl+O dialog renders the archived rows it receives.

OpenCode version

2.1.3

Steps to reproduce

  1. Create a session and send any prompt.
  2. Archive it: sh opencode api patch /api/session/<sessionID> --data '{"archived":true}'
  3. Confirm the flag is stored: sh opencode api get '/api/session?limit=50' | jq -r '.data[] | select(.time.archived) | "\(.id) \(.title) archived=\(.time.archived)"'
  4. Confirm the server-side filter works: sh opencode api get '/api/session?limit=50&archived=false' | jq '[.data[] | select(.time.archived)] | length' # 0
  5. Open the TUI and press Ctrl+O, then search for the session title: the archived session is listed and opens.

Expected Behavior

Archived sessions are hidden from the session picker by default (the same rows that ?archived=false removes), or at least marked as archived so they are distinguishable from active ones.

Actual Behavior

The archived session is listed like any active session and opens on select.
