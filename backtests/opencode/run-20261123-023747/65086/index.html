opencode-child-permission.patch

Web client drops subagent permission requests after reconnect

Summary

When a child session (subagent) asks for permission, the TUI shows the prompt but a reconnecting web client does not. The child stays blocked until someone answers in the TUI. The web client only syncs pending permissions for the session whose page is open; it never fetches pending permissions for child sessions in the same tree.

Environment

  • ubuntu, terminal Konsole
  • TUI connected to the same background service.
  • Network dropped while away; the phone web client reconnected later.

Root cause

createSessionRequestModel in packages/app/src/session/requests/model.ts only runs:

data.session.permission.sync(id)

for the current params.id. Forms already sync every running session in the tree through formSessions. Permissions do not.

permission.asked is an ephemeral event. The client event stream does not replay events missed while disconnected (the auto-approve sweep comments in auto-approve.ts say this explicitly). The regular permission path has no connect-time sweep. Therefore a request asked while the phone web client was offline stays out of the client store. sessionPermissionRequest walks the tree, but the child's permission list is empty because it was never fetched.

The TUI was connected the whole time, so it received the event and rendered the prompt.

Fix

Reuse the existing tree-wide session set for permissions, not only for forms:

  • rename formSessions to requestSessions;
  • sync forms for it, as before;
  • sync permissions for it as well;
  • keep the current session in the set (id === params.id), so the root is still synced.

Diff is attached as opencode-child-permission.patch against v2.3.2.

Regression test

Added to packages/app/e2e/regression/multi-server.spec.ts:

test("shows a child session's pending permission when the parent page opens", async ({ page }) => {
  const view = await setup(page, {
    tabs: [sessionA.id],
    a: {
      sessionPermissions: {
        [sessionA.id]: [],
        [childA.id]: [pending("permission-child-a", childA.id)],
      },
    },
  })

  await page.goto(sessionHref(sessionA.id))
  await expectSessionTitle(page, sessionA.title)

  const permission = page.locator('[data-component="dock-prompt"][data-kind="permission"]')
  await expect(permission).toBeVisible()
  await expect(permission.getByText("git status")).toBeVisible()
})

The mock serves the request only through the child's per-session permission list, never through an event or a location sweep. Before the fix the dock is absent; after the fix it is present.
