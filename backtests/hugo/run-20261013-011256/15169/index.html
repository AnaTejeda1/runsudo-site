resources/jsconfig: Address VS Code linting notice in jsconfig.json

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The lint fires because a `paths` target is not relative while `baseUrl` is unset. TypeScript wants targets to start with `./` or `../`.

Patch B fixes this at the root. Every target computed by `filepath.Rel` gets normalized to start with `./` or `../`. So `*` becomes `./*`, a subdirectory root becomes `./c/*`, and `../d/*` is left as is. The meaning of the mapping is kept: bare imports still resolve against the assets dir and the other source roots, so editor resolution keeps working.

Patch A just skips the source root equal to `dir`. That has three problems:
(1) It removes the self-mapping. In the common case (only the assets root) `Build` now returns nil and no jsconfig mapping is produced, so the editor can no longer resolve bare imports such as `imp1/index.js` from assets. That is a functional regression, not a fix.
(2) It does not handle source roots that are subdirectories of `dir`. Those still yield non-relative targets like `c/*`, which trigger the same lint.
(3) It hides the symptom by removing the mapping rather than correcting its format.

On tests, Patch B adds a unit test covering the parent (`../`), same (`./*`) and child (`./c/*`) cases. It also adds an integration test checking that the generated `assets/jsconfig.json` contains `./*` and that the JS build still resolves the bare import. Patch A's test only asserts a nil config, which encodes the regression.

The scope of both patches is comparable. Patch B's helper is small and clearly documented.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

When building a site that calls js.Build, the assets/jsconfig.json file looks like this:

{
 "compilerOptions": {
  "paths": {
   "*": [
    "*"
   ]
  }
 }
}

VS Code lints line 5 as follows:

Non-relative paths are not allowed when 'baseUrl' is not set. Did you forget a leading './'?
