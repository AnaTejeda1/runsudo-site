Mypy internal error when subclassing a generic model with a recursive type variable

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the crash the same way: they check `has_placeholder(field.type)` in the transform path, call `self._api.defer()` when this is not the final iteration, and return False. This stops `serialize()` from being called on unresolved placeholder types, which is the root cause in the traceback. Correctness on the reported scenario is therefore equivalent.

The differences are in scope and tests. Patch B folds the check into the existing `field.type is None` branch, so it now also defers in the None case, which previously returned False without deferring. That is a behavior change beyond the issue. It is probably harmless, but it adds risk. Patch A applies the defer only to the placeholder case, which is narrower and clearer.

On tests, Patch A reproduces the issue (`Child(ElementWithChildren['Child'])`). It also checks an `Optional[ElementT]` field and a forward reference to a class defined later (`EarlyElement` / `LateElement`), which exercises the deferral more broadly. Patch B tests only the basic self-reference case, and its test contains an odd `"""<link>"""` docstring that looks like leftover junk. Patch A wins on test coverage, tighter scope and craft.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

  • inherits from a generic model with a TypeVar bound to a BaseModel subclass,
  • has a self-referential type hint (e.g., Child referencing itself through Generic[_T]).

Example Code

from typing import Generic, TypeVar

from pydantic import BaseModel


class Element(BaseModel):
    pass


_T = TypeVar("_T", bound=Element)


class ElementWithChildren(Element, Generic[_T]):
    children: list[_T] = []


class Child(ElementWithChildren["Child"]):
    pass
