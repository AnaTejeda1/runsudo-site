Question tool accepts empty questions array

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches stop an empty questions array from registering a never-resolving pending request, and both cover the existing tool and the V2 core tool. The independent tests were MISSING on every tree, so they provide no separation.

Correctness: The issue explicitly frames the expected behaviour as 'failing input validation'. Patch B does exactly that: it adds a minLength(1) check to the tool parameter schema in both packages/opencode/src/tool/question.ts and packages/core/src/tool/question.ts, so the call is rejected by the tool runtime as invalid arguments (InvalidArgumentsError / 'Invalid tool input'), which is the normal path the model receives feedback on and can retry from. It also changes the JSON Schema advertised to the model (minItems: 1, verified via the updated snapshot), so the model is told up front not to send an empty array. Patch A instead pushes the check into the Question service and uses Effect.die, i.e. it raises a defect rather than a typed/validation failure. That prevents the hang but surfaces an empty array as an unrecoverable defect rather than a validation error, and it leaves the tool schema unchanged so the model can still emit the bad input. A's service-level guard does protect non-tool callers, but that is beyond what the issue asks and does not offset the weaker error semantics.

Tests: A tests the service directly with Effect.timeout + Exit; these would fail before and pass after, but they do not exercise the tool path the issue describes. B tests the actual tool execution path in both packages (settleTool/tool.execute with questions: []), asserts no pending question is registered, asserts the schema advertises minItems:1, and updates the wire-shape snapshot. B also had to change existing tests that used questions: [] as a convenience sample, which is a sensible and necessary consequence.

Scope and craft: B is a small, idiomatic change consistent with how the schemas are already defined. A's Effect.die for a predictable input error is less idiomatic in Effect and adds a reformatting of the whole ask body in core. Overall B resolves the issue at the layer the issue names, with better error semantics and more targeted tests.

Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. OpenCode version

1.18.16 / current dev

Steps to reproduce

  1. Invoke the question tool with { "questions": [] }.
  2. Observe that the call remains pending instead of failing input validation.

This affects both the existing question tool and the V2 core question tool.
