Panic when deleting a directory in static when server is running

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches stop the panic in processPartialFileEvents, but B is the more contained and better-tested fix.

Patch B filters static-component paths out of the resolved component paths before any per-path processing. Static files then never reach the switch or any later logic in the build-graph code. The comment states the right reason: static files are handled by the static syncer, not the site build. Because the filter works per component path, a file mounted into both static and assets still triggers an asset rebuild. B tests exactly that dual-mount case.

B's tests use the in-process TestRunning harness. They cover removing a directory (the issue's scenario), renaming a directory, removing a file, adding and editing a file, and the dual static/assets mount. Each would hit the panic before the fix and pass after. They also assert that nothing is rendered and that later edits still rebuild correctly.

Patch A adds a `case files.ComponentFolderStatic` no-op to the switch, which fixes the panic. It also rewrites `SourceFilesystem.Contains` to use `ReverseLookup`. That change goes beyond the issue: it alters how the static syncer decides whether a path belongs to a filesystem, now including file mounts that were previously skipped. It may be a legitimate improvement, but it adds behavioral risk in code shared by other callers and is not needed for the reported panic.

A's tests are server testscripts with sleeps and a check for empty stderr. They exercise the real server path but are timing-dependent. Both use custom mounts rather than the plain static-directory deletion described in the issue.

Overall, B fixes the root symptom precisely, guards the edge cases, and has stronger, deterministic tests with no unrelated churn.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
