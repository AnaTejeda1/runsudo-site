Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The two patches make the same core fix in `pydantic/mypy.py`. Both register `_RootModelMetaclass` in `get_metaclass_hook`, so the plugin (not `dataclass_transform`) handles `RootModel` classes. Both also skip the 'existing `__init__`' early return when the class is `RootModel` itself, so the plugin-generated `__init__` (untyped unless `init_typed`) replaces the hand-written typed one. This covers direct parametrizations like `RootModel[float]('1.0')` and subclasses. The only code difference is `self._cls.fullname` (A) versus `self._cls.info.fullname` (B), which are equivalent in mypy. Correctness is therefore essentially tied. The difference is in the tests. A covers only the positional form for an alias and a subclass. B also covers the keyword form `root='1.0'`, an inline `RootModel[float]('1.0')`, a nested coercion case (`RootModel[list[int]](['1'])`), and `assert_type` checks that the `.root` type is still inferred as `float`. B also adds a `mypy-plugin-strict.ini` run of `root_models.py`, which checks that `init_typed=True` still reports the arg-type errors, so the fix does not over-loosen strict mode. B's tests are more thorough and guard the setting-dependent behavior better, so B is the better patch.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

The below example code (named foo.py) passes when running python foo.py as the input "1.0"-string gets converted to float. However, running mypy foo.py (with or without --strict) gives the following error:

foo.py:11: error: Argument 1 to "RootModel" has incompatible type "str"; expected "float"  [arg-type]
Found 1 error in 1 file (checked 1 source file)

I would expect the BaseModel-fields and the RootModel-field to behave the same in this case. That is, if the value can be converted – either via a custom made validator or through the conversion table – then mypy should not raise an error.

Example Code

import pydantic


class Foo(pydantic.BaseModel):
    f: float


RFoo = pydantic.RootModel[float]

f = Foo(f="1.0")
rf = RFoo("1.0")

assert isinstance(f.f, float)
assert isinstance(rf.root, float)
assert f.f == rf.root
