Scoped slot transforms array argument if rendered conditionally

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause the same way: the compiler stops merging the branch key into a single `v-bind` value on `<slot>`, passes it as a new sixth `renderSlot()` argument, and the runtime uses that argument for the fragment key. Both also handle custom-element mode by copying props before applying the key.

Correctness edges:
- Patch A limits the new branch in `injectProp` to the single-`v-bind`-expression case, the only case where merging corrupts the slot props. Object-literal props and `mergeProps` keep their existing behavior and snapshots.
- Patch A also fixes the closely related `<slot v-for v-bind="item">` case. There, the `ref_for` marker was being merged into the `v-bind` value, which would turn an array into an object in the same way.
- Patch A adds a guard so a nullish `v-bind` value (e.g. `v-bind="null"`) does not crash. With the key no longer merged in by `mergeProps`, `props` could now be null where it previously was not.
- Patch B rewrites key injection for every `renderSlot` call, changing existing codegen for plain `<slot v-if>` (`{}` plus a positional key). That is broader churn with no extra benefit.
- Patch B does not handle the `v-for` `ref_for` case.
- Under Patch B, `<slot v-if v-bind="null">` would now reach `props.key` with null props and throw, a regression from the old `mergeProps` behavior.
- Patch B's user-key priority check and `RenderSlotCall` type updates are reasonable but secondary.

Tests:
- Patch A adds compiler tests for `v-if`, template `v-if`, keyed template `v-for`, and `v-for` on a slot. It also adds end-to-end compiler+runtime integration tests that reproduce the issue (array stays an array after toggling, `v-if`/`v-else`, keyed `v-for`, nullish binding) and a custom-element test.
- Patch B adds compiler tests and unit tests of `renderSlot`, but no end-to-end test of the reported scenario.

Overall, Patch A is more targeted, covers more of the related failure modes, and is better tested.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Steps to reproduce

  1. Create a component with a scoped slot that is rendered conditionally
  2. Pass an array as the sole argument to the slot

What is expected?

Array is rendered normally.
If you render items of that array in v-for loop, you only see items inside that array

What is actually happening?

Array is transformed into object. Items and their indexes are staying the same, key field is added
