W3CDom serializes plain XML with the reserved XML namespace

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause the same way. When the W3C element is created, they map jsoup's internal plain-XML sentinel namespace (Parser.NamespaceXml) to null. Explicit namespaces are kept, and xml:* attributes are left alone. The main difference is how they treat prefixed elements that sit in the sentinel namespace without a declaration (e.g. `<foo:bar>`).

- **Patch A** nulls the namespace unless the tag name starts with `xml:`. An undeclared `foo:bar` then goes through the existing imputed-empty-namespace path instead of being bound to the reserved XML namespace, and `xml:baz` correctly keeps the reserved namespace.
- **Patch B** only nulls when `tag().prefix()` is empty. An undeclared `foo:bar` therefore still asks for createElementNS(XML-namespace, "foo:bar"). That is invalid per the Namespaces spec, so it either throws and falls back or keeps the reserved namespace on the element. Patch B also depends on `Tag.prefix()`, which is not shown in the diff.

**Tests.** Patch A's tests are broader. They cover:
- the exact issue example, round-tripped through a namespace-aware parser;
- the static `convert` path;
- xml:lang preserved alongside explicit default and prefixed namespaces;
- undeclared prefixes and `xml:`-prefixed elements.

Patch B's tests are solid but narrower: plain XML with xml:lang, and explicit default namespaces including `xmlns=""`. They do not cover the undeclared-prefix edge.

**Other differences.** Patch B adds a CHANGES entry and a tidy helper method with @Nullable, which is nice craft but secondary. Overall, Patch A handles more of the edge cases correctly and verifies them more thoroughly.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

Plain XML parsed with Parser.xmlParser() should round-trip through the default namespace-aware W3CDom conversion as parseable XML. But for an ordinary no-namespace XML document, W3CDom currently serializes jsoup's internal XML parser namespace as the document's default namespace.

For example, converting <root><child>One</child></root> through new W3CDom().fromJsoup(doc) and W3CDom.asString(..., W3CDom.OutputXml()) emits <root xmlns="http://www.w3.org/XML/1998/namespace">.... That namespace is reserved for the xml prefix and cannot be bound as the default namespace, so a normal XML parser rejects the output.

Fix is to keep explicit source namespaces as W3C DOM namespaces, but map our internal plain-XML sentinel namespace to no namespace when creating unprefixed W3C elements. xml:* attributes such as xml:lang should continue to use the reserved XML namespace.
