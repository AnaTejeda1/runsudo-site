JSON model validation allocates an unused extras dict per model when extra isn't 'allow'

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches remove the unconditional `PyDict::new` in `validate_json_by_iteration` and both pass every independent allocation test, so they are equal on the core correctness of the reported JSON case. Patch A does it lazily via `get_or_insert_with` in the Allow branch and relies on the existing post-validation fix-up to materialize an empty dict for extra='allow' with no extra keys; that is correct and minimal. Patch B allocates eagerly only when extra='allow', which preserves the original semantics directly, and applies the same change to the Python-input path (`ValidateToModelExtra`), which had the identical wasted allocation; that extension is small, follows the same pattern, and adds no real risk. The decisive difference is tests: Patch A adds none, while Patch B adds parametrized tests across python/json modes and schema/runtime extra combinations asserting `model_extra` is a dict exactly when allow and `None` otherwise, plus a nested-model test checking each model gets its own dict. These guard the behavioral contract the refactor could break (e.g. allow with no extra keys must still yield an empty dict, separate dicts per nested model). Minor craft nit: B's `unreachable!` guards are slightly noisier than A's `get_or_insert_with`, but not enough to offset missing tests.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

Description

Optimization oportunity.

validate_json_by_iteration in pydantic-core/src/validators/model_fields.rs always creates the
__pydantic_extra__ dict, then throws it away unless extra='allow'. With the default extra='ignore', that's one
wasted dict per model instance, which adds up for JSON with many small nested models.

Proposed fix: only create the dict for 'allow'. In a microbenchmark it saved ~5% on model_validate_json for 100
small models. Performance improvement when extra=ignore and unchanged when 'allow'.

This overlaps with #13275, which also removes this allocation as part of a larger rewrite. If that's landing soon,
feel free to close this. Otherwise I have a small change with tests ready for just this small improvement and am happy to open a PR.
