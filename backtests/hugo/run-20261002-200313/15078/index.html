In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches make the same core fix: the placeholder file now sets `draft: false`. In Hugo, a page's own front matter overrides cascaded values. So the cascaded `draft: true` from `posts/drafts/_index.md` no longer drops the placeholder page from the build, and the 'no page found / target path conflicts' error goes away. The placeholder's explicit `build:` block already overrides the cascaded `build.render: link`, so draft was the root cause, and both patches fix it.

Correctness: the two are equivalent for the reported scenario. Patch B also sets `BuildExpired` in the `new content` command, next to the existing `BuildFuture`. This covers the parallel case where a cascaded past `expiryDate` would likewise remove the placeholder. It is a small, low-risk change that matches the existing BuildFuture handling, and the code comments explain why each case is handled where it is.

Tests: both add a Go unit test reproducing the issue's `_index.md` cascade, and both tests would fail before the fix. Patch A tests only the leaf-bundle path. Patch B's unit test covers both the leaf bundle and a regular page, and asserts the placeholder text is gone. B also adds an end-to-end testscript through the actual CLI that covers:
- bundles with a custom kind;
- expired-cascade and future-cascade sections;
- a regular `hugo` build still not publishing the drafts, which guards against the fix leaking drafts into output.
That is much stronger evidence.

Scope and craft: B's extra work is tightly related and well commented, and it adds little risk. A is minimal and clean but less thoroughly verified. Overall, B is the better patch.

I run my personal blog using Hugo for about two years ago, and it has been great!, but there have been issues with how I create pages.

I have section called posts/drafts/ where I create drafts for posts before I move them to a posts/YEAR/MONTH directory where I can post them. The bug happens when I create the page for a post, like this:

<pre>
hugo new content posts/drafts/trip-to-puebla/index.md
</pre>

Running this command with the debug flag returns the following:

What's funny is that a page _is_ created, but it's a placeholder page that looks like this:

---
title: "Content Placeholder"
build:
  render: never
  list: never
  publishResources: false
---

After consulting with ChatGPT (yes you can stone me now) and testing some things here's another stuff that cursed AI and I found:

  • The name of the page still causes some issues, doesn't matter if its trip-to-puebla/index.md or trip-to-puebla.
  • Renaming the drafts directory and rerunning the command with the new name still throws the error
  • This issue does not happen if I run it when creating something like hugo new content posts/2026/07/foo/index.md

One final thing, I have a branch bundle on posts/drafts/_index.md that has the following front matter:

title: Drafts
build:
    render: never

cascade:
    draft: true
    build:
        render: link

weight: 9999
draft: true

This is so any of the pages inside posts/drafts don't get published.
