XML serialization drops attributes whose names start with a digit or hyphen

Worse

The merged fix was judged better than our patch.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause the same way. Each changes `Attribute.getValidKey` so that an XML key with an invalid first character (digit, hyphen, dot) gets a leading `_` instead of returning null. That fixes the dropped attributes in the issue (`1a` → `_1a`, `-a` → `_-a`). Because element tag names go through the same helper, both also repair invalid element names, and both simplify the W3CDom fallback paths that this change makes redundant.

The difference is correctness at an edge the fix itself creates. Once invalid names are repaired by prefixing `_`, a repaired name can collide with an existing valid one. For example, `<root 1a='one' _1a='two'>` under Patch A serializes as `_1a="one" _1a="two"`. Duplicate attributes are not well-formed XML, so the output is still broken, just in a different way. Patch B addresses this directly in `Attributes.html`:
- The set of source keys is built lazily, only when a repair actually happens, so ordinary output does not allocate.
- Valid source names always keep their name, regardless of attribute order.
- A repaired name gets extra `_` prefixes until it is unique.
- The comparison is case-insensitive in HTML syntax and case-sensitive in XML.

Patch B also follows the issue's request to simplify and unify the normalization flow. `getValidKey` becomes non-null; the null checks in `Attribute.html`, `Element.safeTagName` and W3CDom go away; and `Normalizer.xmlSafeTagName` becomes a deprecated delegate. Patch A keeps the nullable contract (null for an empty key), so the null-handling branches stay.

On tests, both add tests that fail before the change and pass after: XML attribute repair and programmatic tag repair. Patch A also checks that HTML syntax output is unchanged and unit-tests `getValidKey`. Patch B tests the collision handling in both XML and HTML, plus element-name repair.

Patch B has some churn: a `StringUtil.concat` helper, a `keysEqual` refactor, and empty keys now serializing as `_` rather than being skipped. None of this adds meaningful risk. Overall, B's output stays well-formed in cases where A's does not, and B delivers the requested unification, so B is the better fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

When XML input contains an attribute whose name starts with a digit or hyphen, jsoup retains the attribute and its value in the DOM but silently drops it during serialization.

For example:

Document doc = Jsoup.parse("<root 1a='one' -a='two' />", Parser.xmlParser());
System.out.println(doc.html());

This currently outputs:

<root />

It will be better to repair the attribute names with a leading underscore, preserving the attribute name and values.

<root _1a="one" _-a="two" />

Also we can simplify and unify the HTML and XML normalization flow.
