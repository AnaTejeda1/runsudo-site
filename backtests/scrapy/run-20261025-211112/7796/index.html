get_func_args_dict doesn't support PEP649 lazy annotation loading

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the reported problem the same way: a `_signature` helper that passes `annotation_format=Format.FORWARDREF` on 3.14+, used in `get_func_args_dict` and in `_warn_spider_arg`. All five independent tests go from NameError on base to PASS on both, so correctness on the issue's scenarios is equal. The difference is in tests and scope. Patch A adds a small reusable helper (`tests/utils/pep649.py`) and exercises the fix at several levels: unit tests for `get_func_args_dict`/`get_func_args` with the issue's exact middleware shape, `_warn_spider_arg`, a real downloader-middleware run through the middleware manager (the user's actual use case), and a stats-collector regression. Patch B adds two narrower unit tests built around inline exec/compile. Both sets would fail before and pass after, and both are correctly skipped only below 3.14, where the bug cannot occur, so neither skip undermines the evidence. Patch A also rewrites `get_spec` on 3.14+ to avoid `getfullargspec`, which is beyond the issue's ask; it is carefully done (keeps bound `self`, ignores `__wrapped__`, filters to positional kinds, maps failures to TypeError like the stdlib) and gated to 3.14, so it adds modest risk but does not obscure the core fix. Patch B is tighter and has a nice touch documenting that `annotation` may now be a ForwardRef, but that craft edge does not outweigh A's materially stronger, scenario-level test coverage. Close call; A wins on tests, which rank above scope.

Description

Hi scrapy team, in 3.14 inspect.signature() on type-annotated functions isn't safe at runtime as types are lazy in 3.14.

Steps to Reproduce

from typing import TYPE_CHECKING

if TYPE_CHECKING:
    import scrapy


class SomeMiddleware:
    def process_exception(self, request: scrapy.Request, exception: Exception) -> None:
        pass

from scrapy.utils.python import get_func_args_dict

get_func_args_dict(SomeMiddleware().process_exception)  # crashes here

Expected behavior:
get_func_args_dict returns (dict of arguments)

Actual behavior:
Raises NameError: name 'scrapy' is not defined instead of returning.

Reproduces how often:
N/A / Always with Python 3.14
