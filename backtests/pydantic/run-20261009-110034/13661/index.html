Runtime by_name/by_alias arguments dropped by model_validator(mode="wrap")

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The production fixes are functionally identical. Both add `by_alias` and `by_name` fields to `InternalValidator`, populate them from `extra` in the constructor, and forward them in both code paths that previously hard-coded `None`. That fixes the root cause: a wrap handler or generator re-entering validation through `InternalValidator` lost the runtime alias settings. The only difference is where the struct fields sit, which does not matter. So the patches differ only in their tests.

Patch B's tests are more thorough and more closely tied to the issue:
- They reproduce the issue's scenario directly: `TypeAdapter` with an `alias_generator` and `validate_by_name=True`.
- They check a `Plain` model against a `Wrapped` model for equivalence.
- They cover all three entry points: `validate_python`, `validate_json` and `validate_strings`.
- They check both directions: by_alias without by_name, and by_name without by_alias.
- They cover `model_validate`, a wrap `field_validator` on a nested model, and the generator/`Iterable` path. The generator test exercises the second modified `InternalValidator` method, which Patch A leaves untested.

Patch A's first test covers `model_validate` in both directions plus a nested wrap field validator, which is adequate but narrower. Its second test checks `strict`, `extra`, `from_attributes` and `context`. Those settings were already forwarded before the change, so that test does not guard against this regression and adds little.

Neither patch adds risky scope; Patch B's import changes are minimal. Because Patch B's tests cover more of the changed code, B is better.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

The handler passed to a wrap-mode model validator appears to silently drop the passed-in by_name/by_alias arguments from the top-level validate_python methods.

Example Code

from typing import Self
from pydantic import BaseModel, TypeAdapter, ValidatorFunctionWrapHandler, model_validator

CFG = {"alias_generator": lambda s: s.replace("_", "-"), "validate_by_name": True}

class Plain(BaseModel):
    model_config = CFG
    build_depends: list[str] = []

class Wrapped(BaseModel):
    model_config = CFG
    build_depends: list[str] = []

    @model_validator(mode="wrap")
    @classmethod
    def _noop(cls, data, handler: ValidatorFunctionWrapHandler) -> Self:
        return handler(data)

data = {"build_depends": ["x"]}  # field name, not the alias
print(TypeAdapter(Plain).validate_python(data, by_alias=True, by_name=False))    # build_depends=[]    correct
print(TypeAdapter(Wrapped).validate_python(data, by_alias=True, by_name=False))  # build_depends=['x'] wrong
