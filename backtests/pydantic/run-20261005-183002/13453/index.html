RootModel.model_dump() typing signature rejects supported serialization arguments

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches make the same change to the `TYPE_CHECKING`-only `RootModel.model_dump()` declaration. Each one widens `context` to `Any | None`, tightens `include`/`exclude` to `IncEx | None`, and adds `fallback` and `polymorphic_serialization` in the same order as `BaseModel`. Correctness on the reported issue is therefore equivalent.

The difference is in the tests and the surrounding changes.

**Patch B** adds regression cases to `tests/typechecking/root_model.py`, as the issue proposes. Its `assert_type` calls cover `context='prefix'`, `fallback=...` and `polymorphic_serialization=True`. Mypy, Pyright and Pyrefly would reject these before the fix and accept them after. That directly tests the symptom the issue reports, which is static type-checker rejection. B also keeps the `Callable` import inside `TYPE_CHECKING`, which is tidy, and leaves the existing explanatory docstring alone.

**Patch A**'s test is a runtime hack. It sets the global `typing.TYPE_CHECKING = True` and re-executes `root_model.py` as a fresh module. That mutates global interpreter state during the test, and it could break if any `TYPE_CHECKING`-only code in the module, such as the metaclass and `dataclass_transform` tricks, does not run cleanly at runtime. It also never runs a type checker, so it does not confirm the calls actually type-check. The test does catch future signature drift, which has some value. But it also asserts exact docstring equality with `BaseModel.model_dump`, which is brittle.

To satisfy that assertion, Patch A replaces the useful explanatory docstring with a copy of the base docstring. The copied docstring wrongly says `Returns: A dictionary representation of the model` for `RootModel`, whose return value is generally not a dict. It moves the real explanation into a comment. That is churn that adds risk and an inaccuracy.

B is the cleaner, better-targeted fix with the more meaningful tests.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

Initial Checks

  • I confirm that I'm using Pydantic V2

Description

RootModel inherits the runtime implementation of BaseModel.model_dump(), but defines a separate declaration under TYPE_CHECKING to preserve its more precise return type.

That declaration has diverged from the base method:

  • context is restricted to dict[str, Any] | None instead of Any | None.
  • fallback is missing.
  • polymorphic_serialization is missing.

As a result, Mypy, Pyright, and Pyrefly reject valid calls that succeed at runtime.

All three calls in the example below succeed at runtime.

Mypy currently reports errors equivalent to:

Argument "context" to "model_dump" of "RootModel" has incompatible type "str"
Unexpected keyword argument "fallback" for "model_dump" of "RootModel"
Unexpected keyword argument "polymorphic_serialization" for "model_dump" of "RootModel"

Pyright and Pyrefly report the same signature incompatibilities.

Expected behavior

The type-checking-only RootModel.model_dump() declaration should accept the same parameters, annotations, defaults, and ordering as BaseModel.model_dump(), while preserving the more precise RootModel return annotation.

Cause

The declaration appears to have drifted as the base method evolved:

  • Serialization context originally updated both signatures.
  • BaseModel.context was later widened to Any.
  • fallback was subsequently added to BaseModel.model_dump().
  • polymorphic_serialization was later added to BaseModel.model_dump().

Those later changes were not propagated to the manually maintained RootModel declaration.

Proposed fix

Update only the static RootModel.model_dump() signature and add focused regression cases to tests/typechecking/root_model.py.

No runtime serialization behavior needs to change.

I have prepared and locally validated a focused two-file fix. The following checks pass:

  • Mypy type-checking suite
  • Pyright type-checking suite
  • Pyrefly type-checking suite
  • Focused RootModel serialization tests
  • Ruff lint and formatting checks
  • git diff --check

I would be happy to submit the PR after the issue is reviewed and assigned.

from typing import Any

from pydantic import BaseModel, RootModel, SerializationInfo, model_serializer


class ContextRoot(RootModel[str]):
    @model_serializer
    def serialize_root(self, info: SerializationInfo) -> str:
        return f'{info.context}:{self.root}'


class Unknown:
    pass


class Base(BaseModel):
    x: int


class Sub(Base):
    y: int


ContextRoot(root='value').model_dump(context='prefix')

RootModel[Any](root=Unknown()).model_dump(
    mode='json',
    fallback=lambda _: 'fallback',
)

RootModel[list[Base]](root=[Sub(x=1, y=2)]).model_dump(
    polymorphic_serialization=True,
)
