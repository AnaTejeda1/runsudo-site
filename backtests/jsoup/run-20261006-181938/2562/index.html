Pop foreign elements before processing HTML breakout tags

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches add the core fix the issue asks for. When a breakout start tag (or `</p>`/`</br>`) appears in foreign content, they pop elements until reaching an HTML-namespace element, a MathML text integration point, or an HTML integration point, then reprocess the token as HTML. Both handle the issue's example correctly and update the existing mixed-namespace test.

Patch A is more correct at an edge that the new popping behavior makes important. The existing `isHtmlIntegration` matched `foreignObject` case-sensitively on `tagName`. jsoup preserves foreign tag case, so input like `<svg><foreignobject><p>` would not be seen as an integration point. Once breakout pops elements, Patch B would pop that `foreignobject`/`DESC` and move the `<p>` out of the SVG. Browsers don't do this, because the tokenizer lowercases tags and the tree builder adjusts them to `foreignObject`. Patch A fixes this by matching on `normalName` against a lowercased list, and adds a test for it.

Patch A also:
- explicitly avoids popping the bottom element of the stack, which guards fragment and root edge cases;
- records a parse error, as the spec requires.

On tests, Patch A is much more thorough. It covers:
- nested SVG and MathML;
- `font` with and without color/face/size attributes;
- end-tag breakouts (`</p>`, `</br>`);
- stopping at `foreignObject`, `mi`, and `annotation-xml` integration points;
- lowercase integration points;
- fragment parsing with an SVG context.

Patch B tests the basic case, the `</p>` end tag, and a negative case for other end tags. Patch A is stronger on correctness, tests, and craft.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

The HTML parser reprocesses foreign-content breakout tags as HTML, but does not first pop the foreign elements from the stack of open elements as required by the HTML specification.

For example:

Document doc = Jsoup.parse("<svg><s><p>One</p></s></svg>");
System.out.println(doc.body().html());

jsoup currently leaves the HTML <s> inside <svg>:

<svg>
 <s>
  <p>One</p>
 </s>
</svg>

Browsers close the foreign content before processing <s>:

<svg></svg>
<s>
 <p>One</p>
</s>

Need to update the foreign-content breakout handling to pop elements until reaching a MathML text integration point, an HTML integration point, or an element in the HTML namespace before reprocessing the token.

Spec: https://html.spec.whatwg.org/multipage/parsing.html#parsing-main-inforeign
