SSR hydration warning: dynamic props on SVG elements are patched as properties instead of attributes

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause identically: they derive the element's namespace from `el.namespaceURI` and pass it to `patchProp` in the dynamic-props hydration branch, so runtime-dom's `shouldSetAsProp` routes SVG/MathML props to `setAttribute`. The independent tests confirm both resolve every scenario. The differences are in tests and craft. Patch A's tests emulate the browser's read-only IDL getters (viewBox, r, foreignObject width) and assert that no 'Failed setting prop' warning and no mismatch warning is emitted while the attribute value is preserved; this directly mirrors the issue's symptom and would fail on base. Patch B sets `__DEV__ = false` in both tests, which suppresses the very warning the issue is about and makes the tests rely on attribute values instead; its first test also does not define a read-only property, so on jsdom (where `width`/`viewBox` are not on the element) the key-in-el check already falls through to setAttribute and the test likely passes on base, making it weak evidence. Only B's second test (with the defined getter) reliably fails before the fix. On craft, A factors the namespace detection into a small documented helper that distinguishes element namespace from `getContainerType`'s foreignObject handling, and avoids B's non-null assertions on `namespaceURI`. A's additional use of the helper in the `onClick` branch is harmless (events ignore namespace) and neutral. Overall A is the better-tested, cleaner fix.

Steps to reproduce

  1. Open the reproduction.
  2. Open the browser devtools Console.
  3. Observe the [Vue warn]: Failed setting prop … error logged during hydration.

What is expected?

During hydration, dynamic props on SVG (and MathML) elements width, height, viewBox, etc. should be patched as attributes (via setAttribute) exactly as they are during normal client-side rendering. Hydration should be silent.

What is actually happening?

Since 3.5.39, dynamic props on SVG elements are patched as DOM properties during hydration, which throws for read-only SVG IDL properties:

[Vue warn]: Failed setting prop "viewBox" on <svg>: value 0 0 24 24 is invalid.
TypeError: Cannot set property viewBox of #<SVGSVGElement> which has only a getter
    at patchDOMProp
    at patchProp
    at hydrateElement
    at hydrateNode
    at hydrateSubTree
    at <App>

Nothing is visually broken but the console is flooded with warnings.

We ran across this issue in a Nuxt app but I believe the issue is coming from Vue core
