Test collection is 10x slower on 9.1.1 compared to 9.0.3

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches eliminate the quadratic visibility scan in `_register_fixture` and both pass all independent scaling tests. Patch A keeps the existing `_arg2fixturedefs` list and adds a per-name ancestor set so the common case (new fixturedef's node is not a strict ancestor of any existing one) appends in O(depth) without calling `is_visibility_more_specific`; the fallback to the old insertion scan when the node is an ancestor or when legacy nodeid-based defs are involved keeps the ordering semantics exactly as before. The logic is sound: if the new node is not an ancestor of any existing def's node, no existing def can be more specific, so appending preserves the partial order. A also adds a genuine regression test that counts calls to `is_visibility_more_specific` (would fail on base, roughly n^2/2 calls) plus an ordering test for the ancestor-registered-after-descendant path. Patch B goes further, re-indexing fixturedefs by node so both registration and lookup become O(depth), which is a nicer design, but it removes the `_arg2fixturedefs` attribute and `_matchfactories`, admittedly breaks pytest-bdd, and 'fixes' that by commenting out the plugin integration test in tox.ini. Knowingly breaking a widely used plugin and disabling the test that would catch it is real added risk, not neutral scope. B also changes the `getfixturedefs` return type from tuple to list and adds no test that exercises the performance regression itself (its new tests cover only the legacy nodeid fallbacks it had to re-plumb). On correctness both resolve the reported regression; on tests A is clearly stronger; on scope/risk B's redesign introduces a known compatibility break. A is the better fix.

Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. Hello!

On 9.1.1: 30406/30495 tests collected (89 deselected) in 303.61s (0:05:03)

The only thing that changed between the two runs was adding this to filterwarnings (as we have a lot of class based fixtures)

ignore:.*Class-scoped fixture defined as instance method.*:pytest.PytestRemovedIn10Warning

I did some profiling with pyinstrument, it seems that most of the time is now spent in is_visibility_more_specific from FixtureManager.parsefactories

The codebase has a lot of class-based tests, but I can't share the code unfortunately.

I do appreciate there is not a lot to go on here, please lmk what other info I could provide to make the debugging easier!
