Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches make the core layout change the issue proposes (`flex: 1 0 auto` with the existing `min-width` floor), which lets the card grow and the strip scroll instead of painting over the neighbour. Patch A stops there: it adds no `min-width: 0`/nowrap guards on `.valueRow`, `.value`, or the delta badge, does not touch the 6-decimal `formatMetricNumber` that the issue identifies as the reason both strings are wide, leaves the unscaled custom metric with no value tooltip, and includes an unrelated `as-child` change to the title tooltip. The issue

View on GitHub

Describe the bug

#40852 fixed the formatting half of #40844 — custom setMetrics values are no longer squashed into percentages, and that part works exactly as hoped. But raw values are much wider than the 73% strings the summary strip was laid out for, and the card cannot grow or clip, so the value and its delta badge paint on top of the neighbouring card.

<img width="1313" height="272" alt="Image" src="https://github.com/user-attachments/assets/d2277b3f-eed7-4605-873b-c14da349317d" />

In the screenshot (Run #39, 17 custom metrics): Jev Legible Confidence's value 0.7 and its -0.037 badge are drawn on top of Jev Legible Norm's +0.084333 badge, and the same happens between Jev Faithful and Judge Match Ok, whose value 1 is buried under the badge to its left.

Why it happens

MetricSummaryCard.vue gives each card a fixed track that cannot shrink and does not clip:

flex: 1 0 calc(var(--spacing--4xl) + var(--spacing--3xl));   /* 128px + 64px = 192px */
padding: var(--spacing--md) var(--spacing--lg);              /* 24px each side */

That leaves 144px of content box. .valueRow is display: flex with flex-wrap: nowrap, no min-width: 0 and no overflow, holding:

  • the value at --font-size--2xl (28px) — 0.728333 is roughly 120px of glyphs,
  • --spacing--sm (16px) of gap,
  • the TrendDeltaBadge, itself an icon plus +0.084333 at --font-size--sm, roughly another 100px.

So ~240px of content in a 144px box, with flex-shrink: 0 and overflow: visible — the surplus is painted over whatever sits to the right.

Both strings come from the same helper added in #40852, which is why the value and the delta are wide:

function formatMetricNumber(value: number): string {
	return value.toLocaleString(undefined, { maximumFractionDigits: 6 });
}

This only shows up for unscaled custom metrics, because formatMetricPercent keeps every other category to 3–4 characters.

To Reproduce

  1. On a workflow with evaluations, emit two or more custom metrics whose values are not round — e.g. 0.728333, 0.833333, 0.777778 (an average over 14 rows produces these naturally).
  2. Run the evaluation twice, so the cards also render a delta badge.
  3. Open the run detail. Adjacent cards overlap; the narrower the viewport and the more metrics, the more of them collide.

Expected behaviour

A metric card is at least as wide as the value and delta it renders, and never draws over the card next to it.

Suggested fix

Two small changes, in the spirit of #40852:

1. Let the card size to its content — MetricSummaryStrip.vue already wraps the row in an ElScrollbar, so a wider row scrolls instead of colliding:

-	flex: 1 0 calc(var(--spacing--4xl) + var(--spacing--3xl));
+	flex: 1 0 auto;
 	min-width: calc(var(--spacing--4xl) + var(--spacing--3xl));

min-width keeps today's floor for short values, flex-grow: 1 still fills the strip when there are only a few metrics.

2. Keep the tile readable — six decimals is more than a summary tile needs, and the delta needs it even less. Capping formatMetricNumber to about four significant digits (0.7283, 1, 0.8333) keeps the cards compact while the exact value stays available on hover. Note that unscaled custom metrics currently have no value tooltip at all: formattedSumScore is '' for them, so valueTooltip is empty — worth populating it with the full-precision value as part of this.

Optionally min-width: 0 on .valueRow as a guard, so no future change to either string can paint over a neighbour again.

Both are covered by the test files #40852 added (evaluation.utils.test.ts, MetricSummaryStrip.test.ts).

Happy to open a PR for this if that helps.

Environment

  • n8n version: 2.45.4 (self-hosted, Docker, SQLite)
  • First affected release: 2.45.0, where #40852 shipped
  • Browser: Chrome
