Clearing select's value in change handler behaviour changed since 3.4.15 via webdriver

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause the same way. The original code skipped `setSelected` while `_assigning` was true, which dropped any model change made synchronously in a change handler. Each patch now keeps a snapshot of the assigned value and resyncs the DOM when the model in `updated` no longer matches it. Both snapshot arrays with `.slice()`, so in-place mutations are caught, and both compare Set models by membership. Either one resolves the reported scenario (single select set to null in onChange).

Patch A is somewhat more robust:
- It records `el.multiple` with the pending value and resyncs if the select's multiple-ness changes before the update.
- It wraps the assigner in try/finally, so pending state is always cleaned up.
- It clears the pending marker after the first `updated`, so later updates in the same tick resync normally.
- It compares with `looseEqual`, matching the semantics `setSelected` already uses for option matching.

Patch B compares by `toRaw` identity. That works for the common cases, but it is a different equality notion from `setSelected`. B also leaves `_assigning`/`_assignedValue` set until nextTick even after the first update. Its ordering (assign before setting the flags) means a throwing assigner leaves no state, which is fine but not a deliberate choice.

Tests: both add tests that would fail before the change and pass after.
- A includes the issue's single-select-cleared case, plus array/Set mutation, duplicate values, the multiple-toggle edge, and no-rewrite performance checks.
- B's tests are tightly focused on the issue and its in-place mutation variants, and are clean.

B is slightly simpler and closer to the existing code, but A's extra hardening adds little risk and handles edge cases B does not. On balance A is modestly better.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
