PEP 695 type aliases don't work with callable discriminators

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the root cause the same basic way: they pass `definitions` from `apply_discriminator()` into `Discriminator._convert_schema()`, so `definition-ref` schemas built from PEP 695 aliases can be resolved when there is no handler. That covers the `Field(discriminator=callable)` case (M3).

Patch A handles the edge cases better:

1. **Unresolvable choices.** When a choice's ref cannot be resolved on the `definitions` path, A re-raises `MissingDefinitionForUnionRef`, so the discriminator application is deferred until definitions are available. B returns None instead and falls through to a `PydanticUserError` ('Tag not provided'). That is a spurious hard failure in deferred or recursive scenarios.

2. **What goes into the tagged union.** A reads the tag from the resolved definition's metadata but keeps the original `definition-ref` as the choice. B replaces `choice` with the resolved definition schema, which inlines it into the tagged union. This copies the old handler-path behaviour, but it is less safe for recursive or shared definitions.

3. **Tests.** A tests more scenarios:
   - a plain alias
   - a generic `TypeAliasType` with `type_params`
   - an alias as one member of a union
   - the error path (`union_tag_invalid`)
   - `TypeAdapter` with an `Annotated` `Field`
   - a self-referencing deferred case (`Tree`/`Node`) exercising the deferral path

   B adds only one minimal happy-path test, with a placeholder `<link>` docstring.

4. **Craft.** A also simplifies the control flow by moving the definition-ref tag lookup into a single block and documents the method. B's `# pragma: no cover` on a branch that now handles real cases is slightly misleading.

Overall, A is more robust and better tested.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

New type aliases prefixed with the type keyword are not supported as the type annotation for a callable discriminator.

M1, M2, M4 ok
M3

pydantic.errors.PydanticUserError: `Tag` not provided for choice {'type': 'definition-ref', 'schema_ref': '__main__.TaggedAnyA:2210408548368'} used with `Discriminator`

Example Code from #12843 also doesn’t work.

from sys import stderr
