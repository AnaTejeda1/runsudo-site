suspense.resolve() is called without a pending branch.

Tie

The judges split evenly between our patch and the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches identify the same root cause: when the parent Suspense patches its pending branch with the same root type, a nested suspensible Suspense that flips to synchronous content resolves itself during that patch and immediately decrements the parent's deps to 0, calling parentSuspense.resolve() mid-patch. The parent then falls through to its own post-patch deps check and calls resolve() again with pendingBranch already cleared, producing the reported warning. Both patches defer the parent's resolution until the patch completes, and both pass all five independent tests (base fails four of them with the exact warning). The difference is in mechanism and craft. Patch A temporarily increments and decrements suspense.deps around the patch call. This is minimal but overloads the deps counter, which is meant to count registered async dependencies, with a synthetic placeholder; any other code reading deps during the patch (nested boundary creation, devtools, future callers) sees a misleading count, and if patch throws the counter is permanently off by one so the boundary can never resolve. Patch B adds an explicit isPatchingPendingBranch flag on the boundary, initialized in createSuspenseBoundary and checked only in the nested-suspensible resolve path, which is the one path that can fire synchronously during the patch. This matches the existing isFallbackMountPending convention, states intent clearly, and leaves the deps semantics intact. On tests, Patch A's two tests are good (including a follow-up update that verifies activeBranch isn't corrupted), but Patch B adds three scenarios: the basic mid-patch resolve, a later sibling registering a new async dep during the same patch (verifying the parent keeps waiting), and a multi-root branch with a plain element mounted after the nested boundary. Both sets would fail before the fix. Scope is equivalent and tightly focused in both. Patch B wins on clarity of intent, consistency with surrounding conventions, and marginally broader test coverage, while A's deps hack is terse but less principled.
