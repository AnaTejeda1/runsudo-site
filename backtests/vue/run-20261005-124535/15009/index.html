v-model on <select multiple> uses stale collection type after switching between Array and Set

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the bug the same way. Each replaces the `isSetModel` flag captured once in `created` with per-element state that `beforeUpdate` refreshes from the current binding value. So the change listener sees the current Array/Set type after a runtime switch. Correctness is equivalent for the scenarios in the issue.

Tests: both add a regression test that would fail before the fix and covers both Array -> Set and Set -> Array. A's test is a bit more thorough. It first interacts while the model is still an Array, then checks that the DOM selection syncs after each switch, then interacts again. B's test switches to a Set before any interaction, which still exercises the stale closure, but it checks less along the way.

Craft: A stores a boolean `_isSetModel`, typed through the directive's element generic (`HTMLSelectElement & { _isSetModel?: boolean }`). It adds an explanatory comment and calls `isSet` once per update. B uses repeated `(el as any)` casts with leading-semicolon statements, and keeps a reference to the whole model value on the element just to check its type later. That is less type-safe and less idiomatic than A's typed flag. A therefore wins on craft and slightly on test thoroughness.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Steps to reproduce

  1. Bind a <select multiple v-model> to an Array.
  2. Switch the bound value to a Set at runtime.
  3. Interact with the select again.
  4. The emitted model becomes an Array again.
  5. Switching back from Set -> Array shows the same stale-type behavior in reverse.

What is expected?

The current collection type should be respected after the model switches at runtime.

What is actually happening?

The change handler keeps using the collection type captured when the directive was created, so the first user interaction after a runtime Array/Set switch emits the old type.
