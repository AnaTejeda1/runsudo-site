Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches make the same core fix: they add `draft: false` to the placeholder front matter in `CreateContentPlaceHolder`. Page front matter takes precedence over cascaded values, so this stops a cascaded `draft: true` from excluding the placeholder from the build. That exclusion is why the page lookup fails with the 'target path conflicts' error. Both therefore fix the reported root cause.

Patch A also sets `BuildExpired` alongside the existing `BuildFuture` in the `new content` command. This closes the same class of failure for a cascaded `expiryDate`, mirroring how `publishDate` is already handled. It is small, low-risk and consistent with the existing code. On its own it is neutral, but it makes the fix more robust in the issue's own spirit.

On tests, Patch A adds testscripts that drive the actual `hugo new content` CLI. They reproduce the user's exact `_index.md` front matter and both the bundle (`trip-to-puebla/index.md`) and single-file forms. They assert that the 'Content Placeholder' text is not left behind, and they add an archetype-directory multilingual bundle case under a draft cascade. Patch B adds one Go unit test that calls `create.NewContent` with the reporter's cascade. That test is valid and would fail before the fix, but it bypasses the command layer and covers fewer scenarios.

Patch A's tests are closer to the reported workflow and broader, and its extra change is coherent and low-risk. A is somewhat better.

I run my personal blog using Hugo for about two years ago, and it has been great!, but there have been issues with how I create pages.

I have section called posts/drafts/ where I create drafts for posts before I move them to a posts/YEAR/MONTH directory where I can post them. The bug happens when I create the page for a post, like this:

<pre>
hugo new content posts/drafts/trip-to-puebla/index.md
</pre>

What's funny is that a page _is_ created, but it's a placeholder page that looks like this:

---
title: "Content Placeholder"
build:
  render: never
  list: never
  publishResources: false
---

After consulting with ChatGPT (yes you can stone me now) and testing some things here's another stuff that cursed AI and I found:

  • The name of the page still causes some issues, doesn't matter if its trip-to-puebla/index.md or trip-to-puebla.
  • Renaming the drafts directory and rerunning the command with the new name still throws the error
  • This issue does not happen if I run it when creating something like hugo new content posts/2026/07/foo/index.md

One final thing, I have a branch bundle on posts/drafts/_index.md that has the following front matter:

title: Drafts
build:
    render: never

cascade:
    draft: true
    build:
        render: link

weight: 9999
draft: true

This is so any of the pages inside posts/drafts don't get published.
