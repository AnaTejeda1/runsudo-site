Unexpected serialization schema with ValidateAs

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the core issue the same way: they give the ValidateAs after-validator a serialization schema built from the annotated (source) type, wrapped in a pass-through wrap serializer. Neither keeps the from_type serializer.

Correctness: B is more careful. It builds the source schema with `handler.generate_schema(source)`, so annotations listed before ValidateAs are not applied a second time; its test checks that JSON-schema examples are not duplicated. It keeps an existing custom serializer such as a preceding PlainSerializer. It skips the wrapper when the source schema equals the inner schema, and it silences ArbitraryTypeWarning while probing. A calls `handler(source)`, which re-runs the earlier annotations and can apply them twice. A also always installs a wrap serializer, even when it is unnecessary.

Scope: B also applies the same fix to pipeline `transform`, which has the identical bug. That is extra scope, but it is coherent, low-risk and tested.

Tests: A's main test only checks `model_dump_json() == '{"x":2}'`. That likely passes even before the fix, because pydantic-core warns and then falls back to inference, so the test does not really catch the regression. B runs its assertions with warnings turned into errors, so its tests fail before the fix and pass after. B also covers the arbitrary-type fallback, a dataclass target, the PlainSerializer case, non-duplication of annotations, and the pipeline cases.

Overall B is the more robust fix with meaningfully better tests.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

From https://github.com/pydantic/pydantic/discussions/13232:

import pydantic as p
import typing as t

def first_even(nums: list[int]) -> int:
    for i in nums:
        if i%2 == 0:
            return i
    raise ValueError("Even not found.")

class Foo(p.BaseModel):
    x: t.Annotated[int, p.ValidateAs(list[int], first_even)]

d = Foo(x=[1, 3, 5, 8, 6, 7])
print(d)
# x=8
print(d.model_dump())
# PydanticSerializationUnexpectedValue(Expected `list[int]` - serialized value may not be as expected [field_name='x', input_value=8, input_type=int])
# {'x': 8}
