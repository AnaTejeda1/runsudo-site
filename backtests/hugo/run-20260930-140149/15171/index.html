Remove -embedded from the default exec.allow

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The issue asks only to remove '-embedded' from the default exec.allow sass pattern. Patch B does exactly that: it changes '^(dart-)?sass(-embedded)?$' to '^(dart-)?sass$', updates the TOML test, and adds assertions to TestDecodeConfigDefault. Those assertions check that 'sass' and 'dart-sass' are still allowed and 'dart-sass-embedded' is now rejected, which would fail before the change and pass after it. B also updates the docs (Babel.md and docs.yaml) to match. Patch A makes the same sass change but also removes '^tailwindcss$' from the default allow list. That was not requested, and it is a behavior-breaking regression: users running TailwindCSS with default config would suddenly be blocked. A papers over this by editing the tailwind integration tests to add tailwindcss to exec.allow explicitly, which shows the breakage rather than justifying it. A also adds no new behavioral assertions beyond the TOML string update. B is correct, well-tested, and properly scoped. A adds risk through unrelated removal of a default.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

What the agent reported

dart-sass-embedded is no longer allowed by default. The official test gate (./bt-test) couldn't run: the container has no network, so Go couldn't download modules. I ran the same tests directly against a local module cache at /bt/cache/go-mod instead. There they fail without the fix and pass with it.

What was wrong: The default security.exec.allow still had ^(dart-)?sass(-embedded)?$. Hugo stopped supporting the old dart-sass-embedded binary in 0.139.0, so the -embedded part only allowed a program Hugo already refuses to use.

What I changed:

  • config/security/securityConfig.go:42: the default entry is now ^(dart-)?sass$ (the comment reads "sass, dart-sass."). Only whitespace changed on the neighbouring comment lines.
  • docs/content/en/functions/js/Babel.md and docs/data/docs.yaml: the default allow list shown there now matches the new value.
  • config/security/securityConfig_test.go:
  • TestDecodeConfigDefault now checks that sass and dart-sass are allowed and dart-sass-embedded is not.
  • TestToTOML's expected string changed only in the allow entry, to match the new default. This updates the expected value; it doesn't loosen the test.

Test evidence:

  • Old default restored: TestToTOML and TestDecodeConfigDefault both fail, the second on the dart-sass-embedded check.
  • With the fix: ok github.com/gohugoio/hugo/config/security.
  • Nearby tests also pass: the TestSecurityPolicies tests in hugolib, the root TestCommands/config tests (which print the security config), and the tocss/dartsass package.

What else was affected: Users who still have dart-sass-embedded installed see the same message as before: "unsupported Dart Sass version detected, please upgrade…". That check in resources/resource_transformers/tocss/dartsass/client.go:55 runs before the allowlist check, so the removed pattern never came into play for them.

Requirements:

  1. Remove -embedded from the default exec.allow: done, with the test evidence above.
  2. Keep the docs consistent: done in both docs files; a repo-wide search finds no other default allow list still containing -embedded.

The existing test in hugolib/securitypolicies_test.go:210 matches the error with sass(-embedded)?. It still works with the new default, so I left it alone. Everything is left as uncommitted edits; AGENTS.md and CLAUDE.md were already deleted before I started and I didn't touch them.
