Issue #10505 Merged fix PR #15298 Run 1 Oct 2026 vuejs/core

Clearing select's value in change handler behaviour changed since 3.4.15 via webdriver

Worse

The merged fix was judged better than our patch.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches find the same root cause. The `_assigning` flag added for select performance makes `updated` skip `setSelected` for the whole tick. So when a @change handler changes the model again after v-model's assignment (e.g. sets it to null), the DOM is never resynced. Both patches fix the issue by remembering what was assigned and resyncing only when the model no longer matches.

Patch A compares by identity: `toRaw(value) !== el._assignedValue`. This fixes the reported single-select case, where 'foo' is assigned and then the handler sets null. Its test reproduces the bug and would fail before the change. But identity comparison misses in-place changes. If the handler mutates the emitted Array (pop/push) or Set (delete), the reference is unchanged, so A still skips the resync and the DOM stays stale. That is the same class of bug the issue describes. A also never clears `_assignedValue` in `updated`, so it relies only on the nextTick reset.

Patch B snapshots the assigned value, copying Arrays so later mutation can't hide a change. It compares with `looseEqual` or a Set-membership check, also resyncs if `multiple` changed, and clears the pending marker in `updated`. A nextTick guard in `finally` means a throwing assigner can't leave stale state. These extra cases all follow from the same root cause (the model diverging from the DOM within the pending tick), so they are not unrelated churn.

B's tests cover the reported scenario plus mutation, Set override, duplicate values, a multiple-to-single toggle, and assigner errors. Several tests also check that the optimization is kept, using zero option write counts. The added complexity is moderate and well contained.

Overall, B is more robustly correct on the root cause and much better tested, while A is simpler but leaves closely related stale-DOM cases unfixed.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

What the agent reported

I fixed the bug: a <select v-model> whose @change handler clears the model now actually clears on screen. The new regression test failed before the fix and passes after it.

What was wrong: The 3.4.15 speed-up (commit 2ffb956) works like this. When the select fires change, vModelSelect writes the picked value to the model and sets el._assigning = true until the next tick. While that flag is set, the updated hook skips setSelected, on the assumption that the page already shows the model's value. That assumption breaks when your @change handler runs in the same tick (v-model's listener runs first) and sets selection.value = null. The component re-renders with null, but setSelected is skipped, so the page keeps showing the option you picked. The nextTick workaround from the report only works because it runs after the flag has been reset.

What I changed (packages/runtime-dom/src/directives/vModel.ts):

  • The change listener now also stores the value it wrote, in el._assignedValue. It is cleared in the same nextTick that resets _assigning.
  • updated now skips setSelected only if the model still holds exactly that value (toRaw(value) === el._assignedValue). If anything changed the model again in the same tick, the select is updated to match it.
  • In the normal case (the model just takes the picked value), the update is still skipped, so the 3.4.15 speed-up is kept. toRaw makes the identity check work for reactive arrays and Sets.

Test evidence:

  • New test should reset single select value when cleared in change handler in packages/runtime-dom/__tests__/directives/vModel.spec.ts. It picks an option, fires change, has onChange set the model to null, and checks that the model is null, selectedIndex is -1 and the option is no longer selected.
  • Before the fix: it failed with expected +0 to be -1 on selectedIndex.
  • After the fix: it passes.
  • ./bt-test packages/runtime-dom: 16 test files, 242 passed, 1 skipped (that skip was already there). The vModel.spec.ts file on its own: 30/30 passed.
  • tsc --noEmit and the Prettier check are clean. Only those two files changed, and nothing is committed.
