Subclass of a @deprecated model is marked deprecated in its JSON Schema, and json_schema_extra can't opt out

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches make the same core change: check `'__deprecated__' in cls.__dict__` instead of `hasattr`, and let an explicit `deprecated` key from `json_schema_extra` take priority (Patch A via `'deprecated' not in json_schema`, Patch B via `setdefault`). Both pass all six independent tests. The meaningful difference is parametrized generic models. Pydantic creates `Old[int]` as a dynamically generated subclass of `Old` whose namespace does not include `__deprecated__`, so with Patch B's bare `cls.__dict__` check a deprecated generic model loses its `deprecated` flag whenever it is parametrized, a regression from base behaviour that users of deprecated generic models would hit silently. Patch A anticipates this by resolving to `__pydantic_generic_metadata__['origin']` when present, keeping `Old[int]` deprecated while still treating `class Child(Old[int])` as non-deprecated, and it tests exactly these cases. The fallback expression `(generic_metadata and generic_metadata['origin']) or cls` is slightly terse but correct for non-generic models (origin is None), dataclasses, and TypedDicts (no attribute). On tests, Patch A is also stronger: it covers inheritors across all deprecated class kinds including TypedDict, both directions of `json_schema_extra` override (opt-out on a deprecated class and on a subclass, opt-in on a non-deprecated class), and generics. Patch B's tests are sound and additionally assert the runtime DeprecationWarning on subclass definition, but skip TypedDict and omit the generic case. Patch B's comment that the runtime 'only warns on instantiation of the decorated class' is also slightly inaccurate since subclass definition warns too. Patch A is the better fix.

Description

GenerateJsonSchema._update_class_schema marks a model deprecated with hasattr(cls, '__deprecated__'). hasattr walks the MRO, so every subclass of a @deprecated model gets "deprecated": true too.

That doesn't match runtime behaviour. Under PEP 702 a subclass warns once, when it's defined; instantiating or validating it doesn't warn. Only the decorated class is treated as deprecated.

The flag is also set after json_schema_extra is applied, so a subclass can't clear it with json_schema_extra={"deprecated": False}.

We hit this in OvertureMaps/schema#757, where we now strip the inherited flag in a GenerateJsonSchema subclass. That workaround also erases a deprecated a subclass sets on purpose through json_schema_extra, so we'd rather it were fixed here.

Checking '__deprecated__' in cls.__dict__ and setting the key only if json_schema_extra hasn't already set it would fix both.

Example Code

import warnings

from pydantic import BaseModel, ConfigDict
from typing_extensions import deprecated


@deprecated("Use NewModel instead.")
class Old(BaseModel):
    x: int


with warnings.catch_warnings():
    warnings.simplefilter("ignore")

    class Child(Old):
        pass

    class ChildOptOut(Old):
        model_config = ConfigDict(json_schema_extra={"deprecated": False})


for m in (Old, Child, ChildOptOut):
    print(m.__name__, m.model_json_schema().get("deprecated"))

Output:

Old True
Child True
ChildOptOut True

Expected: Old True, Child None, ChildOptOut False.

For runtime: defining Child emits one DeprecationWarning, while Child(x=1) and Child.model_validate({"x": 1}) emit none. Old(x=1) emits one.
