Both patches make the same functional fix: they pass `typescriptVersion: ref('6.0.3')` to `useStore`, overriding @vue/repl's default of 'latest'. That addresses the reported problem directly; neither is more correct, and both still let users pick another version from the dropdown. Patch A is the more minimal change: it adds a local constant in App.vue, but with no comment explaining why TS is pinned. Patch B moves the constant into a small `typescriptVersion.ts` module with a comment saying Vue's language tools don't support TS 7 yet. For a pin that is explicitly temporary, recording the reason is useful, because it tells future maintainers when the pin can be lifted. Patch B also adds a spec asserting the default is an exact 6.x version and not 'latest'. The test is close to tautological, since it checks a constant, and it is unclear whether the repo's vitest config picks up tests under packages-private. It still acts as a small regression guard against someone reverting to 'latest' or bumping to 7 by accident. The extra file adds slight indirection but no real risk. With correctness equal, B wins narrowly on its documented rationale and its modest regression test.

What the agent reported

I fixed it: the playground now starts on TypeScript 6.0.3 instead of "latest" (which is now TS 7). The new test passes, but it only checks the pinned version number, not the running playground.

What was wrong: The playground creates its editor state with useStore from @vue/repl and didn't say which TypeScript version to use. @vue/repl then defaults to "latest", which now means TypeScript 7. Vue's language tools don't support TS 7 yet, so type support breaks unless the user changes the version by hand.

What I changed:

  • New file packages-private/sfc-playground/src/typescriptVersion.ts: exports DEFAULT_TYPESCRIPT_VERSION = '6.0.3', with a comment saying why. That's the version the repo's own package.json uses (~6.0.3), and it's installed in node_modules, so it is a published release.
  • packages-private/sfc-playground/src/App.vue: passes typescriptVersion: ref(DEFAULT_TYPESCRIPT_VERSION) to useStore. If a shared link names a TypeScript version, that version still wins. Old links that don't name one now open with 6.0.3.
  • Side effect: because the default is no longer "latest", every playground link created from now on records 6.0.3. Those links will stay on TS 6 even after Vue supports TS 7 and this default is changed.

Test evidence:

  • New test packages-private/sfc-playground/__tests__/typescriptVersion.spec.ts: checks that the default is an exact version with major version 6, not "latest".
  • Before the fix it failed (the module didn't exist).
  • With the value set to 'latest' it failed on the assertion, so it does catch the bug.
  • After the fix, ./bt-test packages-private/sfc-playground/__tests__/typescriptVersion.spec.ts passes (1 test).
  • Limit of the test: I wanted a stronger test that builds the store and checks it uses TS 6, but @vue/repl/core can't be loaded under this repo's vitest setup without changing the shared vitest.config.ts, so I left that out.
  • No type-check: there's no tsconfig for the playground, so vue-tsc couldn't be run on it.
  • Not run in a browser: I haven't confirmed the editor actually downloads TS 6.0.3 at runtime. The reviewer traced the version through @vue/repl's code and found no problems, and nothing else in the diff changed.
