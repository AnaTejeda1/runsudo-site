Initial Checks

  • I confirm that I'm using Pydantic V2

Description

Transient BaseModel classes are not collected when either:

  • A model field references an Enum whose class defines a Python method.
  • A model field uses Field(exclude_if=<Python callable>).

After the defining module is removed from sys.modules and every ordinary strong reference is dropped, weak references to the model and enum classes remain alive after repeated full gc.collect() calls. Repeating this construction in disposable module namespaces causes linear memory growth.

Controls using an enum without methods or a field without exclude_if are collected normally.

I encountered this in combination with a Temporal workflow sandbox. With a large interconnected model graph and high volume Temporal workflows this can result in multi-GiB process growth relatively quickly.

The likely cause is missing PyGcTraverse edges for Python objects held by pydantic-core:

  • SerField owns serialization_exclude_if, but traverses only serializer: https://github.com/pydantic/pydantic/blob/c67a1397327c6abc1a2e2e921af01aebbbeedf1c/pydantic-core/src/serializers/fields.rs#L26-L38
  • EnumSerializer owns class, but traverses only serializer: https://github.com/pydantic/pydantic/blob/c67a1397327c6abc1a2e2e921af01aebbbeedf1c/pydantic-core/src/serializers/type_serializers/enum_.rs
  • Each EnumValidator<T> owns lookup, but traverses only class and missing: https://github.com/pydantic/pydantic/blob/c67a1397327c6abc1a2e2e921af01aebbbeedf1c/pydantic-core/src/validators/enum_.rs

Traversing py_schema does not compensate for another unreported direct reference: CPython’s collector accounts for every actual strong edge individually.

I tested a temporary build from Pydantic main at c67a1397327c6abc1a2e2e921af01aebbbeedf1c. Adding only these traversal edges made all objects in the reproduction collectible:

  • Add serialization_exclude_if to SerField traversal.
  • Add class to EnumSerializer traversal.
  • Add lookup to every EnumValidator<T> traversal.

For the enum case, changing only the serializer or only the validator was insufficient; both missing edges were required.

This appears related to earlier missing-traversal fixes such as:

  • https://github.com/pydantic/pydantic/issues/5136
  • https://github.com/pydantic/pydantic-core/pull/787
  • https://github.com/pydantic/pydantic-core/pull/1100

I would be happy to submit a focused patch.

import gc
import sys
import types
import weakref

def transient_module(name, source, class_names):
    module = types.ModuleType(name)
    sys.modules[name] = module
    exec(compile(source, f"<{name}>", "exec"), module.__dict__)
    refs = tuple(
        weakref.ref(module.__dict__[class_name])
        for class_name in class_names
    )
    del sys.modules[name]
    del module
    return refs

enum_ref, enum_model_ref = transient_module(
    "_pydantic_enum_gc_repro",
    """
from enum import Enum
from pydantic import BaseModel

    FULL = "full"
    def label(self) -> str:
        return self.value

    membership: Membership
""",
    ("Membership", "Model"),
)

    "_pydantic_exclude_if_gc_repro",
    """
from pydantic import BaseModel, Field
class Model(BaseModel):
    value: int = Field(exclude_if=lambda value: False)
""",
    ("Model",),
)

for _ in range(5):
    gc.collect()

print("enum alive:", enum_ref() is not None)
print("enum model alive:", enum_model_ref() is not None)
print("exclude_if model alive:", exclude_if_model_ref() is not None)

What the agent reported

Done. The working tree contains exactly the fix and its regression tests, uncommitted.

What was wrong

pydantic-core omitted several PyGcTraverse edges, so CPython's cyclic collector could not see strong references that pydantic-core held to Python objects. Transient model/enum classes that formed reference cycles through those unreported edges therefore never got collected, leaking memory. Three owned-but-untraversed fields:

  • SerField.serialization_exclude_if (the Field(exclude_if=...) callable)
  • EnumSerializer.class (the enum class)
  • EnumValidator<T>.lookup (holds the enum members, which reference the class)

What I changed

Rust — added the missing fields to the existing impl_py_gc_traverse! invocations (GC-only, purely additive, no behavior change):

  • src/serializers/fields.rs:38 → SerField { serializer, serialization_exclude_if }
  • src/serializers/type_serializers/enum_.rs:51 → EnumSerializer { class, serializer }
  • src/validators/enum_.rs → added lookup to all four EnumValidator<T> monomorphizations (Plain/Int/Str/Float), now { class, missing, lookup }

Tests — tests/test_garbage_collection.py gained two regression tests following the file's existing idiom (transient class in a 10,000-iteration loop, WeakValueDictionary, assert_gc, same xfail/skip markers):

  • test_gc_enum — enum with a Python method, validator+serializer stored on the class (cycle through lookup/class)
  • test_gc_serialization_exclude_if — model field whose serialization_exclude_if callable captures the class (cycle through SerField.serialization_exclude_if)

Test evidence

  • Reproduced first: the report's exact script printed all three objects alive: True on the current build; after the fix all three print False.
  • Fails before / passes after, verified by rebuild: with the Rust fix stashed and rebuilt, both new tests fail (AssertionError: Timeout waiting for GC) for the right reason (the cycle stays uncollectable). With the fix restored and rebuilt, both pass.
  • Final gate (fixed build): tests/test_garbage_collection.py + validators/test_enums.py + serializers/test_enum.py → 32 passed, 1 skipped, including all 5 GC tests (3 pre-existing untouched + 2 new).
  • Reviewer confirmed the diff correctly and minimally implements the report's fix, with no existing test weakened and no unrelated changes.

Note: cargo fmt/clippy aren't installed in this environment, but the edits are single-line macro additions matching surrounding formatting.

Requirements disposition

  • Add serialization_exclude_if to SerField traversal — Implemented; covered by test_gc_serialization_exclude_if (fails before, passes after).
  • Add class to EnumSerializer traversal — Implemented; part of the enum fix.
  • Add lookup to every EnumValidator<T> traversal — Implemented on all four monomorphizations. The report noted both the enum serializer and validator edges are required together; test_gc_enum exercises the combined cycle (fails before, passes after).
  • Enum case requires both serializer and validator edges — Satisfied: all three enum-related edges added; the single combined enum regression test verifies collection.
  • Report's control cases (enum without methods / field without exclude_if collected normally) — Confirmed still collected; the pre-existing GC tests and the diagnostic variants (plain enum, no-store) all collect normally and remain passing.
