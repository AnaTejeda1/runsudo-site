Parametrized generic models no longer resolvable by __module__/__qualname__ (pickle fails) since 2.14.0

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches make `__module__` + `__qualname__` resolvable again, so in-process and cross-process pickle work under both (independent tests confirm). They differ in how. Patch A keeps `__module__` as the origin's module (the 2.13.5 behavior the issue explicitly expects and reproduces in its output) and registers the class on both the origin module and the parametrizing module, so pickling works and the 2.14 registration is preserved. It also handles the origin module not being in `sys.modules`, and deliberately skips the origin registration when parametrizing in `__main__` so cloudpickle still pickles by value. Its tests cover the issue scenario in-process, the unimported-origin edge, and a real two-process round trip. Patch B instead rewrites `__module__` of every module-scope parametrization to the caller's module. That is a broader behavioral change: the independent fresh-process test fails on B because the qualified name is now `app.Response[Page[Item]]` instead of `models.Response[Page[Item]]`, and B's own new xfail test admits a regression it introduces: a generic whose fields hold forward refs to names in the origin module (`f: 'A'`) now gets those refs evaluated in the parametrizing module on rebuild, resolving to the wrong object. Changing the module identity of parametrized classes also affects any existing pickles, docs, and tooling that keyed on the origin module. B is cleaner conceptually but trades the reported regression for a new one and departs from the expected output; A fixes the root cause of the issue as stated with lower risk and stronger tests.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

Since 2.14.0, instances of a parametrized generic model can no longer be pickled, or otherwise looked up by qualified name, when the model is parametrized at module scope in a module other than the one defining the generic. This includes nested parametrizations like Response[Page[Item]]. It worked in 2.13.5.

create_generic_submodel registers a module-scope parametrization in module globals "and therefore allow[s] pickling". #13243 (a __slots__ fix) also changed which module receives that registration:

- reference_module_globals = sys.modules[created_model.__module__].__dict__
+ reference_module_globals = sys.modules[model_module or created_model.__module__].__dict__

created_model.__module__ is still the origin's module, but the class is now registered on the module where the subscript was written. __module__ + __qualname__ no longer resolves, so pickle can't find the class. Neither can other tools that save a class by its qualified name and import it back later, such as Prefect's to_qualified_name / from_qualified_name, which some result serializers use. The change isn't mentioned in the 2.14 changelog, so I assume it wasn't intended.

Expected: as in 2.13.5, a module-scope parametrization is resolvable at f"{cls.__module__}.{cls.__qualname__}", so pickle round-trips the instance (including nested generic type arguments) and the restored object validates as the exact parametrized class. Registering on created_model.__module__ (as before) would restore this. Registering on both modules would also keep whatever 2.14 behavior the change was meant to add.

Example Code

# models.py
from typing import Generic, TypeVar

from pydantic import BaseModel

T = TypeVar('T')


class Page(BaseModel, Generic[T]):
    items: list[T]


class Response(BaseModel, Generic[T]):
    result: T


# app.py
from pydantic import BaseModel

from models import Page, Response


class Item(BaseModel):
    name: str


# Parametrized at module scope, in a module other than the one defining the generics.
ItemResponse = Response[Page[Item]]


# main.py
import pickle

import models
from app import Item, ItemResponse

print(f'{ItemResponse.__module__}.{ItemResponse.__qualname__}')
print('resolvable:', getattr(models, ItemResponse.__qualname__, None) is ItemResponse)

resp = ItemResponse(result={'items': [{'name': 'a'}]})
restored = pickle.loads(pickle.dumps(resp))
assert type(restored) is ItemResponse
assert isinstance(restored.result.items[0], Item)
print('round trip OK')

Output with 2.13.5:

models.Response[Page[Item]]
resolvable: True
round trip OK

Output with 2.14.1 (also reproduces on main):

models.Response[Page[Item]]
resolvable: False
_pickle.PicklingError: Can't pickle <class 'models.Response[Page[Item]]'>: attribute lookup Response[Page[Item]] on models failed
