Scrapy capitalizes headers for request

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The issue is that lowercase request header names arrive at the server Title-Cased when using Scrapy's default (HTTP11, Twisted-based) download handler, including through an HTTP proxy. Patch B fixes exactly that path: it records each header's original spelling in Headers (keeping the stored keys Title-Case for backward compatibility), exposes original_case_items(), and wraps Twisted's Headers in a _CasePreservingTxHeaders whose getAllRawHeaders() emits the original names, with copy() and removeHeader() overridden so the Agent's internal header copy and the tunneling agent's Proxy-Authorization removal keep working. It also propagates original case to to_dict/request_from_dict, request_to_curl, to_tuple_list/to_unicode_dict, copy and pickling. The independent tests confirm it: all five pass, including the default-handler and proxy on-the-wire checks that fail on base. Patch B's own tests use a raw socket server to assert the actual bytes sent, both direct and via proxy; the skip for secure/http2 is a test-infrastructure limitation and the same TxHeaders code path serves HTTPS, so the fix covers the issue's https URL. Patch A changes Headers.normkey to preserve the first-seen spelling, which fixes to_tuple_list and the aiohttp/httpx handlers, but it never touches the HTTP11 handler, which still builds a plain TxHeaders that Twisted canonicalizes to Title-Case. The three default-handler independent tests still FAIL-ASSERT on Patch A, and Patch A's own docs table admits HTTP11 remains 'Capitalized', so the reported scenario stays broken. Patch A also makes normkey O(n) on every lookup and changes the observable keys() of both request and response Headers (e.g. httpx response headers now in raw server case), a wider behavioral change than the ask with no benefit for the default handler. B resolves the root cause at the wire for the handler the issue describes and has stronger tests; A masks only the in-memory representation.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.

The issue

View on GitHub

I'm setting the headers following way

headers = {
    'accept': 'text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8',
    'cache-control': 'no-cache',
    ...
}

And calling request like that:

yield scrapy.Request(url='https:/myurl.com/', callback=self.parse, headers=headers, cookies=cookies, meta={'proxy': 'http://localhost:8888'})

And it makes that scrapy capitalizes all these headers and it looks like that (I'm using Charles proxy for debugging):

Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8
Cache-Control: no-cache

And this is not working correctly for my case.

If I'm using curl and set headers lowercase

accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8
cache-control: no-cache

everything works like a charm.

Is there any way how I can disable this capitalizing behavior in Scrapy?
Thanks for any help!
