What the agent reported

The fix is complete and verified. Here is my final report.

What was wrong

TypeAdapter.json_schema() ignored the adapter's own config. GenerateJsonSchema reads config from self._config_wrapper_stack.tail, and that stack is only populated when the generator traverses into a model/dataclass/TypedDict node (each pushes its config). For a bare top-level type like bytes, nothing was ever pushed, so TypeAdapter(bytes, config={'ser_json_bytes': 'base64'}).json_schema() fell back to the default config and produced format: 'binary' instead of 'base64url' — unlike a BaseModel, whose config is pushed during traversal.

What I changed

pydantic/type_adapter.py — in TypeAdapter.json_schema(), wrapped the final generate call to push the adapter's config onto the generator's stack, mirroring what the model/dataclass/TypedDict handlers do during traversal:

with schema_generator_instance._config_wrapper_stack.push(self._config):
    return schema_generator_instance.generate(self.core_schema, mode=mode)

ConfigWrapperStack.push accepts ConfigDict | None and is a no-op for None, so config-less adapters are unaffected. It sits at the bottom of the stack, so any inner type's own config still correctly overrides it.

tests/test_json_schema.py — added test_type_adapter_default_bytes, parametrized over ser_json_bytes ('base64' → base64url, 'utf8' → binary), asserting on the report's exact call TypeAdapter(bytes, config=ConfigDict(...)).json_schema().

Test evidence

  • Before fix: the new test FAILED on the base64 case ({'format': 'binary'} != {'format': 'base64url'}) — confirming the reported bug.
  • After fix: full run of tests/test_json_schema.py + tests/test_type_adapter.py → 776 passed, 3 skipped, 2 xfailed, including the new regression test. No previously passing tests regressed.
  • Reviewer confirmed the fix is correct, minimal, and free of blast-radius issues (configured types can't take a config arg, so their behavior is unchanged; inner config still overrides).
