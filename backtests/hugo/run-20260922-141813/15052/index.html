The issue

View on GitHub

Currently, when you invoke .Page.Render and pass it the name of a non-existent template, the method returns an empty string without warning or error. This isn't anything new; Hugo has behaved this way since 0.54.0, and probably earlier.

There may be a good reason for the existing behavior, but it was surprising to me.

Summary

What was wrong
Page.Render "name" silently returned an empty string with no error when the named template/view did not exist. In hugolib/page__per_output.go, the Render method's if !found { return "", nil } branch swallowed the "layout not found" signal from resolveTemplate, so typos in view names failed silently (issue 15052).

What I changed

  • hugolib/page__per_output.go (production fix): the !found branch now returns a wrapped error naming the missing layout, mirroring the method's existing idiom: go return "", pco.po.p.wrapError(fmt.Errorf("layout %q not found", layout[0])) This path is only reached when a layout argument was supplied (the no-argument case already errors earlier), so layout[0] is safe.
  • hugolib/page_test.go (regression test): added TestRenderViewNotFound — the exact scenario from the report (.Render "view_bar" with no view_bar.html), asserting a build error via TestE + qt.IsNotNil.
  • tpl/page/page_integration_test.go (blast-radius repair): fixed a pre-existing malformed txtar marker (-- layouts/myview.html → -- layouts/myview.html --). The missing trailing -- meant myview.html was never created as a fixture; the old silent-empty behavior masked this, but the intended {{ .Render "myview" }} in TestThatPageIsAvailableEverywhere would now error. Repairing the marker creates the fixture the test always intended, so .Render "myview" outputs "Render OK." directly — strengthening the test, not weakening it.

Test evidence

  • Before the fix: TestRenderViewNotFound FAILED (got nil value but want non-nil), proving the bug.
  • After the fix (gate run via ./bt-test ./hugolib/ -run TestRenderViewNotFound|TestRenderWithoutArgument|TestErrorNestedRender): all three PASS — the regression test passes and the adjacent Render/error tests still pass.
  • TestThatPageIsAvailableEverywhere (./bt-test ./tpl/page/ -run ...): PASS after the marker repair.

Requirements checklist

  1. Throw an error when .Render is given a non-existent template — Implemented, verified by TestRenderViewNotFound (fails before, passes after) and the production diff.
  2. The provided integration test (TestRenderViewNotFound) should now produce a non-nil error — Implemented; added verbatim and confirmed passing.
  3. Preserve existing behavior for the no-layout case and legitimate views — Verified: TestRenderWithoutArgument and TestErrorNestedRender still pass; blast-radius scan found and repaired the only affected test.
