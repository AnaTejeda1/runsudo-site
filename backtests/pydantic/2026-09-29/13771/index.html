The issue

View on GitHub

Initial Checks

  • I confirm that I'm using Pydantic V2

Description

ValidateCallWrapper.__call__ is declared as def __call__(self, *args, **kwargs), so the instance is bound to the name self. A decorated function with a keyword parameter literally named self can then never be called with it: f(self=1) raises TypeError: ValidateCallWrapper.__call__() got multiple values for argument 'self' before validation runs. The wrapped function itself is fine with that name; it is only the wrapper's signature that collides. Same in 2.12.5, 2.13.5 and pydantic/_internal/_validate_call.py on main.

Making self positional-only in __call__ (def __call__(self, /, *args, **kwargs)) removes the collision without changing anything else. Can send the PR.

Example Code

import pydantic.version
from pydantic import validate_call


@validate_call
def f(*, self: int) -> int:
    return self


try:
    print("f(self=1) ->", f(self=1))
except TypeError as e:
    print("f(self=1) -> TypeError:", e)
print(pydantic.version.version_info())

What the agent reported

The fix is complete and verified.

Summary

What was wrong: ValidateCallWrapper.__call__ in pydantic/_internal/_validate_call.py was declared def __call__(self, *args, **kwargs). Because self is an ordinary positional-or-keyword parameter, a @validate_call-decorated function with a parameter literally named self could never be called by keyword — f(self=1) forwarded self=1 through the wrapper's **kwargs into the already-bound self, raising TypeError: ValidateCallWrapper.__call__() got multiple values for argument 'self' before validation ran.

What I changed (minimal, exactly as the report proposed):

  • pydantic/_internal/_validate_call.py:133 — made self positional-only: def __call__(self, /, *args, **kwargs). This is the only method with the collision; the internal wrapper_function/__init__ forwarders don't take a named self from user kwargs.
  • tests/test_validate_call.py — added test_self_name (modeled on the adjacent test_args_name) covering both a keyword-only self param and a positional-or-keyword self param, asserting the returned value, that coercion still runs (self='2' → 2), and that a bad value still raises ValidationError naming self.

Test evidence:

  • Before the fix: test_self_name failed on the first assertion with the exact reported TypeError.
  • After the fix: ./bt-test tests/test_validate_call.py → 65 passed (64 pre-existing + the new regression), exit 0.

Requirements checklist:

  1. Fix so a function with a keyword param named self can be called with self= — Implemented (positional-only self); regression test passes.
  2. Use the specific def __call__(self, /, *args, **kwargs) approach offered in the report — Implemented verbatim.
  3. Preserve validation behavior (not bypass it) — Verified via coercion and ValidationError assertions in the test; all existing tests still pass.

All changes are left uncommitted in the working tree.
