Webhook lifecycle lint rule rejects function references

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the reported behaviour: shorthand `checkExists`, `create`, and `delete: deleteWebhook` are accepted, and `delete: undefined` is still reported. Patch B does this with a three-line change inside `isMethodProperty` that adds Identifier values (excluding `undefined`) to the accepted forms, keeps the existing function/arrow branch, updates the docstring, docs, and adds focused tests that mirror the issue's reproduction (shorthand and renamed identifiers, mixed inline/identifier, identifier with one method absent, `undefined` placeholder). Those tests would fail before and pass after, and the change stays consistent with the surrounding code's style. Patch A also satisfies the issue but rewrites the rule's model: it inverts the check to 'anything not explicitly null/undefined/void is an implementation', adds type-annotation unwrapping for description/webhookMethods/groups/methods, and introduces new spread semantics (only properties after the last spread are conclusive, so `{ ...sharedLifecycle }` now passes and keys before a spread are ignored). None of that is requested, and the spread rework is a real behaviour change to the rule that extends well beyond the issue, which itself explicitly signals that scoped fixes are expected ('separate from the static property-key fix'). The extra breadth is defensible but adds review surface and risk without being needed for the issue's scenarios, and the resulting `findMissingMethods` with a tuple-returning `conclusiveProperties` helper is harder to follow than the original. Correctness on the issue is a wash; tests are comparable (A's are broader, B's are precisely targeted); scope and craft favour B.

The issue

Description

The webhook-lifecycle-complete rule accepts inline functions. It rejects lifecycle methods that reference a function by identifier.

The n8n type allows a function reference. The runtime also supports it. It reads the function from webhookMethods and calls it with the hook context.

Reproduction

async function checkExists(this: IHookFunctions): Promise<boolean> {
	return true;
}

async function create(this: IHookFunctions): Promise<boolean> {
	return true;
}

async function deleteWebhook(this: IHookFunctions): Promise<boolean> {
	return true;
}

webhookMethods = {
	default: {
		checkExists,
		create,
		delete: deleteWebhook,
	},
};

The rule reports all three methods as missing. The runtime can call all three methods.

Expected behavior

The rule must accept an identifier value as an implemented lifecycle method.

This issue is separate from the static property-key fix in #34972.
