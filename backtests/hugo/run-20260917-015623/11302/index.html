What the agent reported

Summary

What was reported: Markdown with an outer shortcode whose .Inner contains nested shortcodes — e.g. {{< figure >}}{{< img … >}}{{% figcaption %}}…{{% /figcaption %}}{{< /figure >}} — failed in Hugo v0.111.x with failed to extract shortcode: unclosed shortcode "figure", even though the outer figure was properly closed. The "is closed" detector was matching against the wrong (outer) shortcode.

What I found: The root cause is already fixed in this checkout. The page lexer (parser/pageparser/pagelexer_shortcode.go) previously validated a closing tag against a single currShortcodeName field, which got overwritten each time a nested shortcode was opened (img, figcaption), so the later {{< /figure >}} no longer matched the "current" name and was flagged as unclosed. That single-value check was replaced by a set-based openShortcodes map (field at line 26; matching logic in lexIdentifierInShortcode, lines 260–270). The fix landed via the shortcode-nesting rework (commit 1e91e4652, an ancestor of HEAD).

I confirmed this by reproducing the exact reported scenario two ways with throwaway tests (both passed, then removed):

  • Lexer-level: the reported delimiter string lexes with no error item.
  • Full end-to-end site build (hugolib.Test) with figure/img/figcaption shortcodes and the verbatim reported markdown — the site built and rendered correctly.

What I changed: Since no production defect remains, no production code was modified (a needless change would violate minimality). I added one regression test to lock in the fixed behavior:

  • parser/pageparser/pageparser_shortcode_test.go — new TestShortcodeLexer table case "nested, outer closed after inner (issue 11302)", asserting the reported input lexes to a clean token stream with no tError (no spurious "unclosed shortcode").

No existing test was modified, weakened, or removed. (The AGENTS.md/CLAUDE.md deletions in git status pre-existed this session and are unrelated.)

Test evidence:

  • Gate ./bt-test -run 'TestShortcodeLexer|TestShortcodeParser|TestPage' ./parser/pageparser/: package PASS, 67 subtests passed, 0 failed.
  • New case TestShortcodeLexer/nested,_outer_closed_after_inner_(issue_11302): PASS.
  • Reviewer confirmed the diff is scoped to only the added test, the token sequence is correct, and nothing unrelated changed.

Note: The reviewer correctly observed the regression test is at the lexer level (the true root cause), not an added end-to-end render test. I separately verified the end-to-end render path passes during investigation; if you'd like, I can also add a permanent integration test (e.g. in tpl/tplimpl/shortcodes_integration_test.go or hugolib) for defense in depth.
