Description

When declaring a RootModel and adding a Field annotation to the root property that includes examples, those examples are not part of the generated JSON schema. This also applies to the deprecated attribute. The title attribute is also not applied or it is overwritten by the class name of the root model class.

Most other attributes, such as pattern or description are exposed as expected. Furthermore, placing examples in json_schema_extra also works as expected.

Example Code

from typing import Annotated
from pydantic import RootModel, Field

class Foo(RootModel):
    root: Annotated[str, Field(examples=["foo", "bar"], deprecated=True)]

print(Foo.model_json_schema())  # does not include examples or deprecated.

What the agent reported

All green. Here's the summary.

What was wrong

For a RootModel, the JSON schema generator discarded field-level metadata (examples, deprecated, title) from the root field. Normal model fields carry this metadata on a model-field core schema wrapper where generate_inner merges pydantic_js_updates into the schema, but a RootModel's inner schema is the bare root type with no such wrapper (_generate_schema.py:842-844 explicitly drops the field metadata — there's even a FIXME there). The maintainers already worked around this for description via a dedicated fallback in _update_class_schema; examples/deprecated/title simply had no equivalent, and title was additionally always overwritten by the class name. pattern survived because it's a str constraint baked into the inner schema itself.

What I changed

In pydantic/json_schema.py, _update_class_schema — mirroring the existing description special-case, all guarded to only affect root models:

  • title: when no config/generator title is set, use the root field's title before falling back to cls.__name__ (config title still takes precedence).
  • examples: setdefault('examples', to_jsonable_python(root_examples)) when the root field has examples.
  • deprecated: set deprecated: True when the root field is deprecated, using the same truthy/empty-string test as the field-level path (_extract_json_schema_info_from_field_info) for consistency.

Test added in tests/test_root_model.py: test_root_model_field_json_schema_attributes, asserting the full schema for the exact reported scenario.

Test evidence

  • ./bt-test tests/test_root_model.py tests/test_json_schema.py → 609 passed, 3 skipped, 1 xfailed.

  • Non-root models unaffected (all branches guarded); plain RootModel[int] still gets title == 'Bar'/class name.

Requirements disposition

  1. examples on root Field appear in JSON schema — Implemented; covered by regression test (asserts 'examples': ['foo', 'bar']).
  2. deprecated on root Field appears in JSON schema — Implemented; covered by regression test (asserts 'deprecated': True), aligned with field-level empty-string semantics.
  3. title applied / not overwritten by class name — Implemented; regression test asserts 'title': 'My Title'; existing tests confirm class-name fallback and config-title precedence are preserved.
  4. pattern/description continue to work — Verified unchanged; both asserted in the regression test and existing suites pass.
