Align parser scope classification with HTML spec

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches make the same changes to the scope lists: they add `select` to TagsSearchInScope and `template` to TagSearchTableScope, keeping both arrays sorted. The difference is in the SVG special-element fix.

Patch B checks the normalized name against TagSearchInScopeSvg, the existing lowercase list (`desc`, `foreignobject`, `title`). This removes the case mismatch at its root and works however the element was built or which ParseSettings were used.

Patch A instead compares the case-preserved `tagName()` against TagSvgHtmlIntegration using an unsorted linear `in`. That works when the parser has case-adjusted the name to `foreignObject`. It fails for an SVG element whose tagName is lowercase `foreignobject`, which can happen through programmatic construction or other settings. Patch A also switches away from the `inSorted` normalized-name convention the rest of `isSpecial` uses.

On tests, Patch A adds only two membership assertions, which are close to tautological, and one `isSpecial` check on a parsed foreignObject. It also deletes three imports with no explanation. Patch B adds behavioral tests that would fail before the fix and pass after it:
- `li` and `dd` inside foreignObject stay contained.
- A stray `</x-a>` stops at foreignObject.
- A stray `</tr>` inside a template in a cell does not escape the template.
- Direct `inScope` and `inTableScope` checks on a constructed stack confirm the boundary semantics, including that `select` does not affect table scope.

Patch B's changelog entry is also more informative. Overall, B is more robust and much better tested.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

I saw that jsoup's HTML tree-builder classification lists are missing a few entries from the current WHATWG HTML parsing spec: select is not included as an ordinary in-scope boundary, template is not included as a table-scope boundary, and SVG foreignObject is not treated as a special element (because the special element check compares the normalized name (foreignobject) with the case-preserved integration-point name (foreignObject))

Spec references:

  • Has an element in scope: https://html.spec.whatwg.org/multipage/parsing.html#has-an-element-in-scope
  • Has an element in table scope: https://html.spec.whatwg.org/multipage/parsing.html#has-an-element-in-table-scope
  • Special elements: https://html.spec.whatwg.org/multipage/parsing.html#special
