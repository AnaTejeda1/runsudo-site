Initial Checks

Description

The handler passed to a wrap-mode model validator appears to silently drop the passed-in by_name/by_alias arguments from the top-level validate_python methods.

Example Code

from typing import Self
from pydantic import BaseModel, TypeAdapter, ValidatorFunctionWrapHandler, model_validator

CFG = {"alias_generator": lambda s: s.replace("_", "-"), "validate_by_name": True}

class Plain(BaseModel):
    model_config = CFG
    build_depends: list[str] = []

class Wrapped(BaseModel):
    model_config = CFG
    build_depends: list[str] = []

    @model_validator(mode="wrap")
    @classmethod
    def _noop(cls, data, handler: ValidatorFunctionWrapHandler) -> Self:
        return handler(data)

data = {"build_depends": ["x"]}  # field name, not the alias
print(TypeAdapter(Plain).validate_python(data, by_alias=True, by_name=False))    # build_depends=[]    correct
print(TypeAdapter(Wrapped).validate_python(data, by_alias=True, by_name=False))  # build_depends=['x'] wrong

What the agent reported

Review confirms the fix is correct, minimal, and complete. Done.

Summary

What was wrong: In the vendored Rust pydantic-core, InternalValidator — the struct backing the handler object passed to a model_validator(mode="wrap") — did not carry the by_alias/by_name validation settings. When a wrap validator called handler(data), the nested validation was reconstructed with by_alias: None, by_name: None hardcoded, so those values fell back to defaults (by_alias=True, by_name=False) and silently discarded whatever was passed to the top-level validate_python(..., by_alias=..., by_name=...).

What I changed (pydantic-core/src/validators/generator.rs):

  • Added by_alias: Option<bool> and by_name: Option<bool> fields to InternalValidator.
  • Captured them from the incoming Extra in InternalValidator::new (mirroring strict, from_attributes, etc.).
  • Propagated self.by_alias/self.by_name (instead of None) in both validate and validate_assignment.

Then rebuilt the extension with maturin develop --uv --release.

Test evidence:

  • Added regression test tests/test_aliases.py::test_by_name_and_by_alias_honored_with_wrap_model_validator, using the public API from the report. It failed before the fix (assert ['x'] == []) and passes after.
  • Direct reproduction now returns the correct build_depends=[] for the wrapped model, while positive cases (match by alias, or by_name=True) still populate the field.
  • Gate: ./bt-test tests/test_aliases.py tests/test_validators.py → 301 passed, 32 skipped, 2 xfailed, 1 failed. The single failure, test_v1_validator_deprecated, is unrelated to this change: it asserts a deprecation warning's filename == __file__ and fails only on the /work→/workspace symlink path mismatch in the bt-test environment (/work/tests/... vs /workspace/tests/...). It does not exercise pydantic_core validation behavior at all and fails independently of this fix.
  • Reviewer confirmed the fix is correct, minimal, consistent with sibling fields, and the validate_assignment propagation is a symmetric correct improvement with no regression risk.

Requirements disposition:

  • Honor by_name/by_alias passed to validate_python when a mode="wrap" model validator is present — implemented, with a regression test that fails before and passes after, and a live reproduction confirming the reported example now yields the correct result.

Changes are left uncommitted in the working tree (pydantic-core/src/validators/generator.rs, tests/test_aliases.py); the rebuilt .so is gitignored. No scratch files.
