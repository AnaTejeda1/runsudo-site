Scoped slot transforms array argument if rendered conditionally

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches find the same root cause: the compiler injects the v-if/v-for branch `key` into slot props via `mergeProps`, which turns an array `v-bind` value into an object. Both fix it the same way, by passing the key as a new 6th argument to `renderSlot`, so the slot receives the props unchanged. Both fix the reported v-if case.

**Why A is better on correctness:** A also handles a closely related path that B misses. When a slot outlet with `v-bind` sits inside v-for, `buildProps` calls `pushRefVForMarker`. That merges `{ref_for: true}` into the slot props and reshapes an array the same way. A skips the marker for `ElementTypes.SLOT` and adds a test confirming that `ref="foo"` on a slot still keeps `ref_for`. Under B, `<slot v-for="list in lists" v-bind="list"/>` still passes an object instead of the array.

**Scope:** A is narrow. It only reroutes the key when the slot props are a single v-bind expression, which is the case that breaks. Plain-object props keep the existing `{ key: 0 }` output, so existing snapshots are unchanged. B reroutes every injected slot key, including slots with no props. That changes existing codegen to `{}, undefined, undefined, 0` and rewrites existing tests and snapshots. B also adds a snapshot to `transformElement.spec.ts.snap` for a vFor test, which looks like misplaced churn.

**Where B is slightly better:** B keeps the old precedence where a user-provided `props.key` wins over the branch key, both at runtime and in the compiler via `hasProp`. A lets the compiler key override a `key` inside the v-bind object, a minor behavior change.

**Tests:** A adds end-to-end runtime tests in `packages/vue` covering v-if toggling, keyed template v-for with element reuse after reordering, and slot v-for, all checking `Array.isArray(props)`. B adds only compiler and unit-level tests.

Overall, A fixes more of the actual bug class with less churn and has stronger tests.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Steps to reproduce

  1. Create a component with a scoped slot that is rendered conditionally
  2. Pass an array as the sole argument to the slot

What is expected?

Array is rendered normally.
If you render items of that array in v-for loop, you only see items inside that array

What is actually happening?

Array is transformed into object. Items and their indexes are staying the same, key field is added
