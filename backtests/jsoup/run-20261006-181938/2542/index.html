Parse CDATA as a bogus comment in HTML content

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches correctly make `<![CDATA[` in HTML-namespace content a bogus comment that ends at the next `>`. Both keep CDATA in SVG, MathML and the XML parser.

The difference is in fragment parsing, where the spec's 'adjusted current node' is the context element.

Patch A keeps the real context tag, including its namespace, when it builds the fragment context element. Fragments parsed inside `<svg>` or `<math>` therefore behave as foreign content all the way down: nested children get the SVG/MathML namespace, and CDATA inside those nested children is still recognized. It also fixes the knock-on effects of keeping the namespace:
- tokeniser start state only switches to script, plaintext or template mode for HTML contexts;
- noscript handling only applies to HTML contexts;
- `resetInsertionMode` treats non-HTML nodes without `continue`, which also removes a latent null dereference.
These changes are broader, but each follows from honouring the context namespace and is covered by tests (SVG and MathML fragments, HTML integration points, foreign script/plaintext/noscript contexts, custom foreign data tags).

Patch B adds a side field, `contextNamespace`, and consults it only while the context element is the sole item on the stack. The context copy itself stays in the HTML namespace. As a result, `svg.html("<g><![CDATA[x]]></g>")` would create an HTML-namespace `<g>`, and the CDATA inside it would wrongly become a bogus comment. Its fix is partial for fragments.

Patch B's tokenizer change (`matches && allowsCdata && matchConsume`, falling through to the existing bogus-comment branch) and its virtual `allowsCdata` in `TreeBuilder` are tidy.

On tests, both update the existing CDATA tests and add HTML-vs-foreign cases. Patch A's tests are more thorough: integration points, nested SVG, XML with the HTML namespace, error position, and fragment namespaces.

Patch A wins on correctness and test depth.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

The HTML parser currently recognizes <![CDATA[...]]> in all contexts and creates a CDataNode.

Per the HTML specification, CDATA sections are recognized only in foreign content such as SVG and MathML.

In the HTML namespace, <![CDATA[ is a parse error and should start a bogus comment, which ends at the next >.

Update the tokenizer to consider the adjusted current node’s namespace so that HTML parsing aligns with browser behavior.

CDATA handling should remain unchanged for SVG, MathML, and XML parsing.
