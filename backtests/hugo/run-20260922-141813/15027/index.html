The issue

View on GitHub

The --templateMetrics output table prints duration values (sum/avg/max) using time.Duration.String(), which varies both units and decimal places depending on the magnitude. This makes the table hard to scan when rows have durations of different magnitudes.

Proposed fix: Use a fixed-decimal formatter (two decimal places, unit suffix padded to consistent width) so decimal points align across all rows in the table.

What the agent reported

The fix is complete and verified. Here is my final report.

What was wrong

metrics/metrics.go's (*Store).WriteMetrics printed the cumulative/average/maximum duration columns by passing time.Duration values directly to fmt.Fprintf with %s, which invokes time.Duration.String(). That method varies both unit and decimal-place count by magnitude ("2s", "1.5ms", "500µs"), so decimal points never lined up down a column and the --templateMetrics table was hard to scan.

What I changed

  • metrics/metrics.go — Added an unexported formatDuration(d time.Duration) string helper that formats each duration with exactly two decimal places (%.2f) and a unit suffix (ns/µs/ms/s) right-padded to a consistent width of 2 runes (%-2s). This makes the text after the decimal point a constant 4 runes for every magnitude, so within each right-justified %15s/%12s column the decimal points align. Both branches of the row-printing loop now wrap v.sum, v.avg, v.max in formatDuration(...). Headers, sorting, and all other columns are untouched.
  • metrics/metrics_test.go — Added TestWriteMetricsDurationFormatting (regression test).

Test evidence

  • Red before fix: the new test failed on qt.Contains "2.00s" — old output was 2s / 1.5ms / 500µs.
  • Green after fix: ./bt-test ./metrics/ → TestWriteMetricsDurationFormatting pass, plus existing TestSimilarPercentage and TestSimilarPercentageNonString still pass; package pass.
  • Blast radius: two integration tests inspect WriteMetrics output. hugolib/pagesfromdata only asserts on the template key (unaffected). tpl/partials's TestIncludeCacheHints normalizes durations away with a regex and trims the leading columns — I ran it: pass. The reviewer confirmed the fix is correct/complete and nothing unrelated changed.

Requirements checklist

  1. Duration columns (sum/avg/max) use a fixed-decimal formatter, two decimal places — Implemented (%.2f), covered by the regression test asserting 2.00s / 1.50ms / 500.00µs.
  2. Unit suffix padded to consistent width — Implemented (%-2s, so s → "s "), covered implicitly by the alignment assertion.
  3. Decimal points align across all rows — Implemented; the test asserts the first-. index is equal across all three mixed-magnitude rows.
