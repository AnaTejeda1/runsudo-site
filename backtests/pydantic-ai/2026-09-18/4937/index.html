The issue

View on GitHub

Description

GoogleProvider currently doesn't expose the google-genai SDK's built-in HttpRetryOptions, which means users who want retry behavior for transient HTTP errors (429, 500, 502, 503, 504) must construct their own GenAIClient and pass it via GoogleProvider(client=...), bypassing the provider's normal setup.

The google-genai SDK supports this natively via HttpOptions.retry_options:

from google.genai.types import HttpOptions, HttpRetryOptions

HttpOptions(
    retry_options=HttpRetryOptions(
        initial_delay=1.0,
        attempts=4,
        exp_base=2,
        max_delay=60,
        jitter=1,
        http_status_codes=[408, 429, 500, 502, 503, 504],
    ),
)

Reference: https://docs.cloud.google.com/vertex-ai/generative-ai/docs/retry-strategy

Proposal

Add a retry_options parameter to GoogleProvider.__init__ (or accept HttpRetryOptions as part of an existing config) so users can configure retries without having to manually construct the underlying Client.

Something like:

from google.genai.types import HttpRetryOptions

provider = GoogleProvider(
    project="my-project",
    location="us-central1",
    retry_options=HttpRetryOptions(
        initial_delay=1.0,
        attempts=4,
        http_status_codes=[408, 429, 500, 502, 503, 504],
    ),
)

Current Workaround

Construct a GenAIClient manually with retry options and pass it to GoogleProvider(client=...). This works but requires duplicating the provider's setup logic (User-Agent header, timeout, vertexai flag, etc.).
