Description

pydantic_evals.evaluators.llm_as_a_judge.judge_output() currently returns a freeform reason: str. In practice, with reasoning-capable models, that reason can become very long, include visible self-correction / re-checking, and even contradict itself mid-response.

This is especially problematic when judge_output() is used inside an agent output_validator and the reason is fed back into ModelRetry(...), because the retry message becomes noisy and unstable instead of being a concise repair instruction.

Example pattern:

@agent.output_validator
async def llm_judge_validator(ctx: RunContext[AgentDeps], data: _ModelT) -> _ModelT:
    grading = await judge_output(
        output=data,
        rubric=response_model.rubric(),
        model=self.model_obj,
        model_settings={"temperature": 0.0},
    )
    if not grading.pass_:
        raise ModelRetry(grading.reason)
    return data

In my case, the judge reason did things like:

  • state a violation
  • re-check the same rule
  • partially retract the earlier claim
  • continue with more analysis
  • still return pass=false

So the issue is not just verbosity. The reason can become self-contradictory and unsuitable for retry feedback loops.

I realize some of this is model behavior, but the current built-in prompt/output shape seems to allow the model to "think out loud" inside reason rather than returning a short, stable failure summary.

One workaround is to disable thinking in judge_model_settings, but that is not what I want. I want the judge model to retain the benefits of internal reasoning; I just do not want reasoning/thinking output to leak into the public reason field. Ideally, the judge should be able to think internally while still returning a concise, stable, retry-safe explanation.

Minimal, Reproducible Example

import asyncio

from pydantic_evals.evaluators.llm_as_a_judge import judge_output

OUTPUT = {
    "title": "The Blue Light of Silence",
    "pages": [
        {"phase": "setup"},
        {"phase": "escalation"},
        {"phase": "climax"},
    ],
}

RUBRIC = """
Judge whether this structured output is acceptable.
Check each rule independently. Fail the output if ANY single rule is violated.

Episode:
- Fail if pages do not form a complete dramatic arc with forward-progressing phases
  (e.g. setup -> escalation -> turning point -> climax -> aftermath);
  repeating or skipping phases is not acceptable.
"""

async def main():
    result = await judge_output(
        output=OUTPUT,
        rubric=RUBRIC,
        model="gemma4:31b-cloud",
        model_settings={"temperature": 0.0},
    )
    print(result.model_dump())

asyncio.run(main())

Observed behavior: the returned reason can be a long, self-reflective paragraph rather than a concise explanation of the failed rule(s).

Expected behavior: reason should be short, stable, and directly usable as validation feedback, especially in retry loops.

What the agent reported

The change is complete and verified. Final report below.

What was wrong

pydantic_evals.evaluators.llm_as_a_judge.GradingOutput.reason was a bare reason: str with no guidance, and the four judge agents' system prompts only said "respond with {reason, pass, score}". Nothing told the model to keep reason short or final, so reasoning-capable judge models would dump long, self-correcting, sometimes self-contradictory "think out loud" text into reason — making it unusable as concise, stable retry feedback (e.g. fed into ModelRetry). The reporter wanted the judge to keep reasoning internally but return a concise, stable reason, without disabling thinking.

What I changed

Two production edits in pydantic_evals/pydantic_evals/evaluators/llm_as_a_judge.py — purely prompt/schema guidance, no model_settings/thinking disabled, no signatures touched:

  1. GradingOutput.reason now has a Field(description=...) telling the model to keep the reason concise, self-consistent, and final (at most a few sentences), to state only the final conclusion, and to exclude step-by-step reasoning, re-checking, or self-corrections. Because output_type=GradingOutput, this description is emitted in the structured-output JSON schema the judge model receives — the direct lever on the reason field.
  2. All four judge agents' system prompts (_judge_output_agent, _judge_input_output_agent, _judge_input_output_expected_agent, _judge_output_expected_agent) got an identical appended paragraph reinforcing the same "keep reason concise, don't think out loud in it" instruction.

One test edit in tests/evals/test_llm_as_a_judge.py: added test_grading_output_reason_description, asserting via the public GradingOutput.model_json_schema() that reason carries a description mentioning conciseness and discouraging verbose reasoning/self-correction.

Test evidence

  • Regression test failed before the fix (assert None is not None — reason had no description).
  • After the fix: ./bt-test tests/evals/test_llm_as_a_judge.py → 14 passed (the new test plus all 13 pre-existing tests). No existing test was weakened, skipped, or altered; system-prompt additions don't touch any snapshot because those assert only the user prompt, never the system prompt.
  • Reviewer confirmed the diff is limited to the two intended files, pass_/score/signatures unchanged, thinking not disabled, and no scratch/temp files.

Requirements disposition

  • reason should be concise/stable and not polluted by think-out-loud/self-correction text → Implemented via the reason field description (schema-level) + system-prompt guidance across all four judges. Tested by test_grading_output_reason_description (red→green).
  • Judge must retain internal reasoning (do NOT disable thinking) → Honored: no model_settings/thinking changes; the fix only shapes what goes into the public reason field. Verified by reviewer (no settings changed).
  • Applies to the judge_output() path shown in the report → Covered: judge_output uses _judge_output_agent + GradingOutput, both updated; the sibling judges (judge_input_output, judge_input_output_expected, judge_output_expected) share GradingOutput and were updated consistently.
