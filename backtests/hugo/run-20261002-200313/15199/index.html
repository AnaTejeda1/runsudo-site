related: Add option to tokenize headings

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Patch A is the better fix, mainly on correctness and scope.

**Correctness**
- **ID matching.** A keeps exact-identifier matching and adds heading-title tokens on top of it. B replaces a heading's identifier with its tokens when `tokenize` is on. Under B, heading IDs are no longer indexed, so explicit `fragments` queries by heading ID (e.g. `Related (dict "fragments" ...)`) stop matching.
- **ApplyFilter.** B puts every tokenized-index FragmentKeyword, including query IDs, into `ff.words`. It then compares those only against title words, so ID-based heading filtering breaks for tokenized indices.
- **Query tokens.** A also tokenizes `opts.Fragments` query strings and deduplicates keywords, so a shared word counts once per document. Its ApplyFilter path still checks IDs first and then title tokens, honouring ToLower.
- **HTML in titles.** A's tokenizer strips HTML tags (heading titles can contain `<code>`) and decodes entities. B's `splitWords` decodes entities but leaves tags in place, so tag fragments can leak into tokens.

**Scope**
- B extends tokenization to basic indices via `ToKeywords`. The issue explicitly limits it to heading titles in fragments indices, and this change also alters keyword query behaviour.
- B adds an unrequested `MinTokenLength` option and makes whitespace churn in existing tests.
- A sticks to the issue's specification and adds the requested documentation text verbatim.

**Tests**
- Both add meaningful tests.
- A's integration test covers default vs. tokenize vs. toLower, applyFilter output, definition terms staying exact, inline code in titles, and query strings.
- A also has unit tests for the tokenizer, keyword generation, config decoding and duplicate-weight avoidance.
- B's tests are reasonable, but several target behaviour outside the issue's scope (basic-index tokenization, minTokenLength).

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
