The issue

View on GitHub

On Pyodide (sys.platform == 'emscripten'), import pydantic_ai.models fails with ModuleNotFoundError: No module named 'httpcore2' whenever httpx2>=2.10 is installed.

Why

pydantic_ai_slim/pydantic_ai/_http.py imports httpcore2 eagerly, so the first client construction doesn't do blocking I/O inside the event loop:

# Import httpcore2 eagerly: httpx2 defers it to first client construction, which performs blocking
# I/O if that happens inside the event loop.
import httpcore2  # noqa: F401  # pyright: ignore[reportUnusedImport]

Since 2.10.0, httpx2 doesn't install httpcore2 on emscripten. It uses httpx2-jsfetch instead, which sends requests through the browser's fetch():

httpcore2==2.13.0; sys_platform != 'emscripten'
httpx2-jsfetch; sys_platform == 'emscripten' and python_version >= '3.12'

httpx2 itself only imports its transports for the current platform (httpx2/_transports/__init__.py), so it imports fine without httpcore2. Our eager import is the only thing that requires it:

import pydantic_ai.models            (models/__init__.py)
  └─ from .._http import ...
       └─ _http.py:  import httpcore2   ← not installed on emscripten with httpx2 >= 2.10

pydantic-ai-slim requires httpx2>=2.7 with no upper bound, so a fresh Pyodide install resolves a current httpx2 and hits this. Since #8655, the openai extra requires openai>=3.19.0, which requires httpx2>=2.12.0. So Pyodide users on that extra can no longer work around it by pinning httpx2<2.10.

Reproduction

Pyodide isn't in CI, and this wasn't run under Pyodide. It was reproduced on CPython by making httpcore2 unimportable, which is the state httpx2>=2.10 leaves on emscripten:

import sys
sys.modules['httpcore2'] = None

import httpx2              # OK: httpx2 doesn't need httpcore2 at import time
import pydantic_ai.models  # ModuleNotFoundError: import of httpcore2 halted; None in sys.modules

Suggested fix

Skip the eager import on emscripten, where httpcore2 isn't used:

if sys.platform != 'emscripten':
    import httpcore2  # noqa: F401  # pyright: ignore[reportUnusedImport]

Pydantic AI already has emscripten-specific behavior, e.g. _disable_threads in _utils.py (#6086), so the platform is meant to work.

Found during an adversarial review of #8655.
