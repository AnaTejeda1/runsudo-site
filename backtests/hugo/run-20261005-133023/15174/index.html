Panic when deleting a directory in static when server is running

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches find the same root cause. `SourceFilesystem.Contains` walks `d.mounts()`, which stats each mount. Once a static directory (or the mount root itself) is deleted, that mount is skipped. The removal event then isn't classified as static and falls through to `processPartialFileEvents`, which panics on the unknown component. Both make `Contains` stat-free and also add a guard in `processPartialFileEvents`.

Patch A reuses the existing `ReverseLookup(filename, false)` API, which is the stat-free reverse mapping the filesystem already provides. The fix is a two-line change. Because it goes through the general reverse lookup, it also covers single-file mounts into static. Its new testscript for deleting a file mounted at `static/robots.txt` exercises exactly that, so the static syncer still sees the removal. The added `case files.ComponentFolderStatic` is a minimal, clearly commented guard placed exactly where the panic occurred.

Patch B adds a new `RootMappingFs.MountDirs` method and walks the filesystems by hand to rebuild the prefix check. This is more new surface area for the same result. It deliberately skips single-file mounts (`fiSingleFile != nil`), so a deleted file mounted into static is still not recognized as static by `Contains`. The early `continue` in `processPartialFileEvents` avoids the panic for that case, but the event is silently dropped rather than routed to the static syncer. It also rewrites the `pss` slice construction, adding churn to a hot loop.

On tests, B's Go integration tests are good and directly assert `IsStatic`/`IsContent` on removed roots. A's testscripts run the real server and check for no stderr output, so they reproduce the reported scenario end-to-end, including mounted dirs and files.

Overall A is the smaller, more idiomatic fix with broader coverage, so A is preferred.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
