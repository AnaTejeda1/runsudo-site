resources/jsconfig: Address VS Code linting notice in jsconfig.json

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Patch A fixes the root cause: every mapping emitted into compilerOptions.paths is made relative (prefixed with './' unless it already starts with '..'), which is exactly what the VS Code/TypeScript rule demands when baseUrl is unset. It covers the project's own assets ('./*'), themes/modules ('../...'), and nested mounts inside assets ('./sub/*'). Patch B instead sidesteps the symptom by dropping the mapping for the current directory, so in the single-root case no jsconfig.json is written at all. That avoids the lint notice for the simplest site but leaves any other root that resolves to a non-'..' relative path (e.g. a mount whose source lies inside assets, yielding 'sub/*') still non-relative and still flagged. The independent tests confirm this: both patches pass the project-only and theme scenarios, but only A passes the nested-mount scenario while B fails it. B also silently changes behaviour (no file emitted) rather than fixing the content. Tests: A adds a dedicated test asserting the relative forms for mixed roots plus the JSON shape, which would fail on base; B's added assertion only checks the nil case. Scope and craft: A's helper is small, documented, and uses filepath.Separator consistently with the existing filepath.Rel usage; the docs/assets/jsconfig.json tweak is a trivial, consistent companion change. A is clearly the better fix.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The issue

View on GitHub

When building a site that calls js.Build, the assets/jsconfig.json file looks like this:

{
 "compilerOptions": {
  "paths": {
   "*": [
    "*"
   ]
  }
 }
}

VS Code lints line 5 as follows:

Non-relative paths are not allowed when 'baseUrl' is not set. Did you forget a leading './'?
