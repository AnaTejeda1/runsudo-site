What the agent reported

The fix is complete and verified. Here is my final report.

What was wrong

Hugo panicked with unknown component: "static" when a directory inside static/ was deleted while hugo server was running.

Root cause: in hugolib/hugo_sites_build.go, the handleChange closure inside processPartialFileEvents switches on pathInfo.Component() with cases for content, layouts, assets, data, i18n, and archetypes, then a default: that panics. There was no case for files.ComponentFolderStatic. When a static directory is deleted, fileEventsApplyInfo marks the event removed=true (Stat fails), the extension-less directory path is resolved to the static component, and it fell through to the default panic (hugo_sites_build.go:1084). Static files are published by an entirely separate pipeline (the server's staticSyncer/copyStatic), so the partial-rebuild path should never have tried to act on them.

What I changed

  • hugolib/hugo_sites_build.go — added a case files.ComponentFolderStatic: with an empty body (ignoring the event, exactly like the adjacent archetypes case) and a comment explaining static files are handled by the server's static syncer. The default: panic remains for genuinely unknown components. Cache-buster compilation and deletedDirs accumulation happen earlier in the loop (before handleChange), so they still run for static paths — no behavior was dropped.
  • hugolib/rebuild_test.go — added regression test TestRebuildRemoveStaticDirIssue15174 reproducing the exact scenario (delete a directory under static/ in a running server) and asserting the build completes without panicking.

Test evidence

  • Before the fix: TestRebuildRemoveStaticDirIssue15174 panicked with panic: unknown component: "static" at hugo_sites_build.go:1084 — the exact reported failure.
  • After the fix: the test passes (--- PASS, ./bt-test ./hugolib/ -run TestRebuildRemoveStaticDirIssue15174 exit 0).
  • Regression gate: ./bt-test ./hugolib/ -run TestRebuild (all rebuild/partial-rebuild tests) exit 0 — nothing previously passing broke.
  • Reviewer confirmed the fix is correct, minimal, and additive; no unrelated changes, no weakened/removed tests, no scratch files.
