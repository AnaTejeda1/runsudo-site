Steps to reproduce

originally reported in https://github.com/nuxt/nuxt/issues/30782

  1. create an options API component with an async setup(), a computed property that reads shared module-level state, and a watch on that
  2. render it on the server and then mutate the shared state after the render is done
  3. see that the watcher is still active on the server

Reproduction

test('options-api watchers should not be created for async setup components', async () => {
  const open = ref(true)
  const spy = vi.fn()

  const App = defineComponent({
    setup: () => Promise.resolve({}),
    computed: {
      isOpen() {
        return open.value
      },
    },
    watch: {
      isOpen: spy,
    },
    render() {
      return h('div', String(this.isOpen))
    },
  })

  const html = await renderToString(createSSRApp(App))
  expect(html).toBe('<div>true</div>')

  // mutating the state after the request is done should not trigger the watcher
  open.value = false
  await nextTick()
  expect(spy).not.toHaveBeenCalled()
})

What is expected?

the same behavior as with a synchronous setup: regular watchers declared via the watch option don't run during SSR and don't survive the render

mutating the shared state after renderToString resolves should not trigger anything

What is actually happening?

when setup() returns a Promise, the watch option creates a live watcher on the server that is never stopped

if this subscribes to state that outlives the request, it keeps the entire component instance (and app) reachable forever

What the agent reported

When a component had an async setup(), watchers from its watch option stayed live on the server after renderToString finished. That's fixed now, and the regression test from the report failed before the change and passes after it.

What was wrong: setupComponent turns off the "inside SSR setup" flag as soon as setup() returns. With an async setup(), the options API (computed, watch, lifecycle hooks) is only applied later, after the promise resolves, and by then the flag is already off. So the guard in apiWatch.ts that skips non-immediate watchers during SSR never kicked in. A live watcher was created, never stopped, and kept the component instance and app reachable through any shared state it read.

What I changed:

  • The fix (packages/runtime-core/src/component.ts, setupStatefulComponent): in the server-side async-setup branch, the flag is turned back on around handleSetupResult(...) and turned off again in a finally. The options API is now applied in the same SSR mode as with a synchronous setup().
  • Side effects: the same as the sync path. Options-API computed properties don't cache on the server, mounted-style hooks are dropped during SSR, and serverPrefetch still registers. Watchers with flush: 'sync' are still collected and stopped after the render.
  • The test (packages/server-renderer/__tests__/ssrWatch.spec.ts): the test from the report, added to the ssr: watch block unchanged.

Test evidence:

  • Before the fix: the new test failed with "expected vi.fn() to not be called at all, but actually been called 1 times", with arguments (false, true, cleanup).
  • After the fix: ./bt-test on all of packages/server-renderer, plus runtime-core's apiOptions, apiWatch, Suspense and hydration specs, passed 611 of 611 in 21 files. No existing test was changed.
  • Review: the reviewer found no blocking issues. It suggested also testing a flush: 'sync' option watcher, which I didn't add.

Requirements:

  1. Watchers from the watch option are not live after rendering a component with an async setup(): done; the regression test covers it.
  2. Same behaviour as a synchronous setup() (non-immediate watchers don't run during SSR and don't outlast the render): done. The async path now goes through the same SSR guard as the sync path, and the existing SSR watch, computed and suspense tests still pass.
  3. Changing the shared state after renderToString resolves triggers nothing: done; the test asserts the spy is never called after open.value = false and nextTick().

All changes are uncommitted in the working tree.
