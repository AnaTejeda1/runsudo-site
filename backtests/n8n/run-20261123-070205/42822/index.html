Both patches make the identical source change: they add an `evaluation.listRuns.runAt` key to en.json and replace the hardcoded `'Run at'` label in RunsSection.vue with `locale.baseText('evaluation.listRuns.runAt')`. That fully resolves the issue at its root (the label was never routed through i18n) and matches the convention of the neighbouring `runNumber` and `status` columns. The only difference in the en.json placement (A after `runDate`, B before it) is cosmetic. The independent tests crashed on every tree, so they provide no signal either way, and I judged the fix from the diffs. The deciding factor is tests: Patch A adds a RunsSection unit test that mocks `useI18n` to return a `translated:<key>` marker, stubs TestRunsTable to render each column label as text, and asserts the `runAt` header is `translated:evaluation.listRuns.runAt` and not the English `Run at`. That test would fail on the base commit (where the label is the literal string) and pass after the change, so it is a genuine regression guard rather than a tautology, and it also checks the neighbouring columns for consistency. Patch B adds no test. Scope and craft are otherwise equal, so A wins on criterion 2.

Bug Description

On the Evaluations tab of a workflow, the table of past runs has a "Run at" column. Its header is written in English straight into the code, so it does not get translated.

https://github.com/n8n-io/n8n/blob/fa52841130f3576b50da09a55a9d1e61ae9ad5f8/packages/frontend/editor-ui/src/features/ai/evaluation.ee/components/ListRuns/RunsSection.vue#L83

The other columns next to it are already translated. They use evaluation.listRuns.runNumber and evaluation.listRuns.status.

To Reproduce

  1. Set the UI to a language other than English.
  2. Open a workflow that has an evaluation set up, and go to the Evaluations tab.
  3. Run the evaluation at least once.
  4. In the table of past runs, the "Run at" header is still in English.

Expected behavior

The column header shows in the selected language.

Debug Info

I found this while reading the code on master (2.46.0). The text is written into the code, so it happens on every setup.

Environment

  • Operating System: macOS (platform independent)
  • n8n Version: 2.46.0 (master)
  • Node.js Version: 24.x
  • Database: n/a
  • Execution mode: n/a
