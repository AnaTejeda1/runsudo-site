Preserve input values entered during hydration

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches use the same approach. In `created`, they detect that the element is already in the DOM (meaning hydration is underway) and compare its live state to its server-rendered default. In `mounted`, they sync the user's value back to the model instead of overwriting the DOM.

Patch B only does this for `vModelText`, and only when `el.type` is 'text' or 'textarea'. Values typed during hydration are still lost for other input types (email, number, password, search, tel, url), and for checkbox, radio, and select. The issue covers forms with v-model inputs in general, so B fixes only the narrowest case. Its newline normalization is hand-rolled per type, and it passes only the `number` modifier to `castValue`. That is harmless here because `type=number` is excluded, but it shows how limited the coverage is.

Patch A covers text inputs of every type, textarea, checkbox (boolean, array and Set models, including several checkboxes sharing one stale model during a single mount pass), radio, single and multiple select, and `vModelDynamic`. It avoids false positives from browser value sanitization (range, color, newlines) by comparing against a pristine input built from the same attributes. It also reproduces the browser's default-selection rules for select (disabled options and optgroups, listbox size). It casts with both trim and number, and handles `type=number` correctly.

The `pendingModelValues` WeakMap and the select heuristics add some complexity and risk. However, they are justified by real cases, and the tests exercise them directly. The refactoring into `assignCheckboxValue` and `assignSelectValue` reuses the existing change-handler logic without changing its behavior.

On tests, A adds a thorough suite. It covers each directive, modifiers, untouched elements still receiving the client model value, browser-sanitized values, and a non-hydration client mount that must not sync. B adds one text-input test.

A is clearly the more complete and robust fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
