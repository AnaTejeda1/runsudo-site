Issue #9546 Merged fix PR #15523 Run 13 Oct 2026 · run-20261013-093701 vuejs/core

defineProps options object loses properties when using generics

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Patch A fixes the root cause directly. `PropMethod<T>` was a conditional type on `T`. When `T` is a generic type parameter, `PropType<T>` becomes deferred, which in turn defers `RequiredKeys`/`OptionalKeys` and drops non-required props. A makes `PropMethod` a plain function-like constructor type, so the conditional disappears and the key computations resolve again. It adds one small, targeted adjustment to `InferPropType`: fall back to `V` when `D` is unknown, so a deferred generic stays assignable to `T`. Removing the conditional looks low-risk. Mismatched constructors still fail because the `(): T` call signature must match, and the existing inference branches for Object/Boolean/Date/array come before the `Prop<infer V, infer D>` branch. A's dts tests cover the shorthand `Object as PropType<T>`, the required case, a default-null case, a plain String prop, the key set, and assignability to `{ bar: T }`. They do not exercise the exact `{ type: Object as PropType<T> }` without `required`, but the root-cause change covers that path as well.

Patch B leaves the deferred conditional in place and works around it everywhere. It rewrites `RequiredKeys`, `OptionalKeys`, `DefaultKeys`, `InferPropType`, `ExtractPropTypes`, `PublicRequiredKeys` and `PublicOptionalKeys` using `{ v: X } extends { v: Y }` wrappers. It also adds an `IsSameType` identity trick and a complex `IsUndefinedDefault` with factory-return inference, and it changes `InferPropType`'s default-fallback logic. This large redesign of core prop typing carries significant regression risk for existing non-generic users, through subtle changes in distributivity and inference and in how the `OptionalKeys` per-key `Pick` behaves. It also obscures the actual cause. B's tests are more thorough: they mirror the issue's a/b/c cases and also cover public props and defaults. But that thoroughness does not outweigh how much more invasive and fragile B's implementation is compared with A's minimal fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
