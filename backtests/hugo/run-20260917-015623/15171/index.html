What was wrong
The default exec.allow whitelist in the security config still allowed the dart-sass-embedded binary via the pattern ^(dart-)?sass(-embedded)?$. That embedded variant is no longer relevant, so it needed to be removed from the default.

What I changed (uncommitted, working tree only)

  1. config/security/securityConfig.go:42 — changed the default allow pattern from "^(dart-)?sass(-embedded)?$" to "^(dart-)?sass$" and updated the trailing comment from // sass, dart-sass, dart-sass-embedded. to // sass, dart-sass.. Ran gofmt so the comment-alignment block (lines 42–45) is canonical.
  2. config/security/securityConfig_test.go:138 — updated the TestToTOML golden string so the first exec.allow element matches the new default ('^(dart-)?sass$'). This is a required update to a golden expected value, not a weakening of the test.

What I deliberately left alone

  • hugolib/securitypolicies_test.go:210 uses an optional sass(-embedded)? matcher and explicitly sets allow="none", so it's independent of the default — verified unaffected.
  • References in common/hugo/hugo.go (binary-name/version detection) and resources/.../dartsass/* (comments) are unrelated to the allow-list default.
  • Docs (docs/data/docs.yaml, docs/content/.../Babel.md) still show the old pattern. They're documentation reflections outside the code test-gate and outside the narrow scope of this fix — flagging them in case you want a follow-up doc update.
