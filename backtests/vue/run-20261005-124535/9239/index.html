Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches target the same root cause. A dynamic `:key` forces the element into a block in `buildProps`, which skips the `NEED_PATCH` flag. vFor's stable-fragment path then converts it back to a plain vnode, so the fragment no longer tracks it. On unmount the ref, directive and vnode-hook cleanup is lost, and the ref array keeps growing.

Patch A fixes this at the exact point where the information is lost. When vFor switches a child from block to vnode and the child has no meaningful patch flag, it re-adds `NEED_PATCH` if the child has directives, a `ref` prop, or a reserved vnode-hook prop. The change is small, localized and easy to verify. Its integration test reproduces the issue scenario directly: a keyed v-for over a constant source, with a `ref` array on both divs and components, toggled by `v-if` several times. That test would fail before the change. A also covers custom-directive and vnode-hook unmount, and adds compiler-level codegen assertions. One minor gap: props built via `mergeProps` (from `v-bind="obj"`) are not inspected, which is an edge case.

Patch B also fixes the issue, by threading `needsPatch` and `isBlockRequired` flags from `buildProps` through new `VNodeCall` AST fields into vFor. It goes beyond the ask in two ways:
- It moves `hasRef` detection ahead of the constant-value early return. This changes codegen for non-v-for elements with setup-const function refs.
- It keeps stable v-for children as blocks when they have before-update hooks.

Both changes are defensible, and B's tests are thorough. However, B touches the AST interface, the `buildProps` return shape, and the patch-flag analysis for all elements. That broadens the risk surface and makes the core fix harder to see.

On correctness for the reported issue the two are roughly equal. A is the tighter, lower-risk fix with a direct regression test, so it wins on scope and craft.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
