Cannot use model_dump(include=...) with @model_serializer (raises PydanticOmit)

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Patch A fixes the root cause. It addresses the common pattern `handler(value, info)`, which the repo's own `WrapSerializer` docstring currently demonstrates. When a forwarded `SerializationInfo` was passed as the positional `index_key`, it reached `key_filter` under include/exclude, failed to match any key, and caused `PydanticOmit`. Patch A filters out `SerializationInfo` instances before index/key filtering, so the issue's exact example now returns `{'bar': 123}`. It also widens the `SerializerFunctionWrapHandler` protocol type so this usage type-checks. Its tests would fail before the change and pass after it. They cover the core-level wrap serializer, the issue's `model_serializer` scenario (include, exclude, python, json), and nested `WrapSerializer`/`field_serializer` cases. Patch B does not make the issue's code work. Passing `info` would now raise a `TypeError` ('index_key is expected to be an integer or a string') instead of `PydanticOmit`. That is a clearer error, but the user's example still fails. Patch B also rewrites the docstring example to stop forwarding `info`, which implicitly declares the pattern unsupported, even though the codebase previously documented it and users rely on it. Its single test only checks the new error with a bytes key and never exercises the reported scenario. On correctness, which is the top criterion, A resolves the issue and B only improves the failure message. A also has stronger tests and a minimal, well-commented change.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Description

Attempting to use the include parameter to model_dump when the model has a @model_serializer method causes a PydanticOmit exception to be returned.

Example Code

from pydantic import BaseModel, model_serializer

class Foo(BaseModel):
    bar:int
    baz:int

    @model_serializer(mode='wrap')
    def _serialize(self, next_serializer, info):
        return next_serializer(self, info)

f = Foo(bar=123, baz=456)

print(f.model_dump(include={'bar'}))
