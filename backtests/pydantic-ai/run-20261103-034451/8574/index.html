VercelAIAdapter.dump_messages emits providerMetadata: null instead of omitting it — breaks AI SDK validateUIMessages

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches make the FastAPI and JSON-mode paths omit `providerMetadata` (all independent tests pass for both), so the decision rests on root-cause coverage, robustness, and tests.

Patch B adds one wrap serializer on `CamelBaseModel` that drops a field only when its value is None *and* its declared default is None. That rule is derived from the model definitions, so required fields that legitimately hold None (e.g. `data`, `output`) round-trip automatically, and new fields added later are handled without touching the serializer. It applies in Python mode too, so the issue's literal reproduction (`model_dump(by_alias=True)` then JSON) is fixed, and it matches the stream path's existing `exclude_none=True` behaviour. It also removes the now-redundant per-field `exclude_if` on `ReasoningUIPart.id`. The 139 lines of snapshot deletions are the expected consequence of the behaviour change, not churn. Its tests cover the issue repro through both `model_dump` and `TypeAdapter.dump_json`, a full-history no-null sweep across SDK versions 5/6/7 with an equality round-trip, retention of real provider metadata, retention of required-None fields, and a regression check that the serialization JSON schema still lists the fields.

Patch A reaches the same JSON-mode result but with more moving parts: three separate serializers (parts, `ToolApprovalResponded`, `UIMessage`), a hard-coded allowlist `('input', 'output', 'data')` that will silently drop any future required-but-nullable field, and an adapter rewrite so `metadata` stays out of `model_fields_set`. Restricting the fix to JSON mode means the issue's own repro still prints `providerMetadata: None`, which A papers over with a docs sentence rather than a fix. Its handling of an explicit client `metadata: null` is a thoughtful edge case, but a niche one. A's tests are decent (null-key sweep, round-trip, Python-mode preservation) but narrower than B's and encode the brittle allowlist as expected behaviour.

B is the simpler, more principled, better-tested fix; A is correct for the FastAPI path but more brittle and incomplete for the issue's stated reproduction.

The issue

Initial Checks

  • I'm using the latest version of Pydantic AI
  • I've searched for my issue in the issue tracker before opening this issue

Description

VercelAIAdapter.dump_messages() produces UIMessageParts with provider_metadata=None. When serialized with default Pydantic settings (model_dump(by_alias=True) / FastAPI response), this becomes explicit "providerMetadata": null on the wire. The JS AI SDK (validateUIMessages, safeValidateTypes) rejects it:

expected record, code: invalid_type, path: ["providerMetadata"]
message: Invalid input: expected record, received null

The SDK type is providerMetadata?: Record — absent is valid, null is not. The resulting invalid_union error tries every UIMessagePart variant and obscures the real cause.

Streaming is unaffected because chunk encode() uses exclude_none=True. Only the dump_messages history path hits this.

Where

  • pydantic_ai/ui/vercel_ai/request_types.py: TextUIPart.provider_metadata: ProviderMetadata | None = None (same for Reasoning/File/Source* parts)
  • pydantic_ai/ui/vercel_ai/_adapter.py:_convert_user_prompt_part() (~L1082): TextUIPart(text=..., state='done') — always None
  • pydantic_ai/ui/vercel_ai/_adapter.py:_dump_response_message() (~L710): dump_provider_metadata() returns None when empty (_utils.py:114-116), still stored
  • pydantic_ai/ui/vercel_ai/_models.py:CamelBaseModel: no exclude_none, so None → null
  • Contrast response_types.py:BaseChunk.encode(): model_dump_json(..., exclude_none=True) — correct

Expected

dump_messages output should serialize without providerMetadata key when there is no metadata (matching what the AI SDK accepts and what the stream path already does), e.g. either:

  • set exclude_none on dump serialization, or
  • document that callers must use model_dump(by_alias=True, exclude_none=True, mode="json").

Currently a naive return VercelAIAdapter.dump_messages(...) from FastAPI (the documented pattern) produces invalid output for plain text history.

Minimal, Reproducible Example

from pydantic_ai.messages import ModelRequest, UserPromptPart
from pydantic_ai.ui.vercel_ai import VercelAIAdapter

msgs = [ModelRequest(parts=[UserPromptPart(content="Hello")])]
dumped = VercelAIAdapter.dump_messages(msgs)
print([m.model_dump(by_alias=True) for m in dumped])
# actual: [{'id': ..., 'role': 'user', 'metadata': ..., 'parts': [{'type': 'text', 'text': 'Hello', 'state': 'done', 'providerMetadata': None}]}]
# serialized to JSON -> "providerMetadata": null -> frontend throws
