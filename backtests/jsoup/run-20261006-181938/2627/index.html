Script text closes early after a nested script marker

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the reported body case. The root cause is that the InBody default branch took `tag.textState()` for `script` (a raw-text style state) before reaching the InBodyStartToHead dispatch, so the ScriptData escape and double-escape states never ran.

Patch B reorders the branch so InBodyStartToHead tags go through InHead first. This is spec-aligned and fixes the body case. However, it leaves another path that uses `tagFor(start).textState()` untouched: `insertNoscriptStartTag` in HtmlTreeBuilder. A script inside a noscript island would therefore still close at the first `</script>`.

Patch A adds a single `textStateFor` helper that maps HTML-namespace `script` to ScriptData. It applies the helper both in the InBody default branch and in the noscript-island insertion, so it fixes the issue wherever an HTML script is tokenised. Its parameterized test covers body, head, div, table, and noscript in both head and body.

Both patches also make double-escape matching ASCII case-insensitive. A does it with one `equalsIgnoreAsciiCase` in the shared handler. B lowercases the buffer at two append sites. Both are correct.

B's reorder also routes title, style, and noframes in body through InHead. That is likely equivalent behaviour but adds some unrelated surface. B's CHANGES entry is fine but neutral.

Tests: both add regression tests that would fail before the change. A's are broader and include the noscript contexts that B's fix misses. A is therefore more complete on correctness and better tested.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

The issue

View on GitHub

A script in the body can close too early after <!-- and a nested <script> marker:

FOO<script><!--<script>-></script>--></script>QUX

Under the HTML spec's script data double-escape rules, the first </script> is text. The following --> should return the tokenizer to ordinary script data, and the final </script> closes the element. jsoup instead closes at the first </script>, leaving -->QUX outside.
