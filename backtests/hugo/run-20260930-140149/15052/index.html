In this judgment, Patch A = our agent, Patch B = the merged fix.

The two patches are nearly identical. Both replace the silent `return "", nil` in `pageContentOutput.Render` with an error naming the missing layout, which fixes the root cause. Both add essentially the issue's integration test, and both carry the same small fix to the malformed txtar header in `tpl/page/page_integration_test.go`. The only substantive difference is error construction. Patch A wraps the error with `pco.po.p.wrapError(...)`, which attaches the page's content-file context. The error is really a template/layout problem, and it already surfaces through template execution. Go's text/template reports it as an 'error calling Render' at the calling template's file, line and column. So the page wrapping is at best redundant. At worst it could point the reported error location at the content file rather than the template that made the bad call. Patch B returns a plain `fmt.Errorf`, which lets the template engine supply accurate location context and matches how other template-function errors propagate. On tests, B's `qt.ErrorMatches` on `template "view_bar" not found` is slightly more precise than A's `IsNotNil` plus a check that the message contains `"view_bar"`. Both tests would fail before the change and pass after it. Scope is equivalent. The difference is small, but B is the cleaner, lower-risk fix.

The issue

View on GitHub

Currently, when you invoke .Page.Render and pass it the name of a non-existent template, the method returns an empty string without warning or error. This isn't anything new; Hugo has behaved this way since 0.54.0, and probably earlier.

There may be a good reason for the existing behavior, but it was surprising to me.

What the agent reported

I've made .Render return an error when it can't find the named template, but none of it has been compiled or tested. Each ./bt-test run failed at [setup failed] because Go couldn't download the module dependencies (DNS lookup failed and proxy.golang.org returned Forbidden). No test ran, including the new one.

What was wrong: In pageContentOutput.Render (hugolib/page__per_output.go:116), when no template matched the requested layout, the code returned "", nil, so a misspelled or missing view rendered as an empty string with no error.

What I changed:

  1. The fix (hugolib/page__per_output.go:116-118): that path now returns template "view_bar" not found, wrapped with the page's path like the other errors in that function. Only the first layout name is used, because that is the only one the lookup reads.
  2. New test (hugolib/hugo_sites_build_errors_test.go): TestRenderViewNotFound is the test from the report. It checks that the build fails and that the error names "view_bar". By reading the code it should fail before the fix and pass after, but I haven't seen it do either.
  3. Existing test fixed (tpl/page/page_integration_test.go:80): one file header read -- layouts/myview.html, missing its closing --. So myview.html was never created, and its text was added to the end of render-link.html. The test's Render OK. check only passed because that text came from the link render hook while .Render "myview" returned "". With the fix, this test would fail, so I corrected the header. No assertion was removed or loosened; Render OK. now actually comes from .Render. It's the one existing test I changed.

Other code affected: Any site that relied on a missing view rendering as nothing will now fail to build, which is the point of the fix and probably worth a release note. In this repo, the only .Render "<name>" calls in tests are the two above and the new test; the one in TestErrorNestedRender points to a template that exists. No built-in templates or testscripts call .Render, and the call with no argument already returned an error. The reviewer checked all of this by reading the code and found no blocking issues.

Test evidence: None. I ran ./bt-test ./hugolib/ ./tpl/page/ -run 'TestRenderViewNotFound|TestErrorNestedRender|TestThatPageIsAvailableEverywhere' twice, and both times it exited 1 at setup. gofmt reports nothing. On a machine with network access, run that same command to confirm.

Requirements:

  • Throw an error when .Render can't find the named template: done in hugolib/page__per_output.go; not yet compiled or tested.
  • The report's test (view_foo exists, view_bar doesn't, expect an error): added exactly as TestRenderViewNotFound, but I haven't seen it fail before the fix or pass after.
  • "There may be a good reason for the existing behavior": I found none. Only the broken header in tpl/page/page_integration_test.go depended on the silent empty result.

Everything is left as uncommitted changes. The AGENTS.md and CLAUDE.md deletions were already there and I left them alone.
