In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches fix the exact scenarios in the issue (bedrock/claude_platform/claude-opus-5-5 and the bare claude_platform/ form), and the independent tests confirm that. The difference is in how. Patch A addresses the root cause the issue names: it adds claude_platform/ to strip_bedrock_routing_prefix and overrides BedrockModelInfo.get_model_cost_key to map a Claude API id onto the existing Bedrock key (anthropic.<id>, with -v1:0 / -v1 fallbacks, verified against the cost map before use). Patch B instead adds ~600 lines of per-model JSON entries (duplicated in two files) under bedrock/claude_platform/<id>, which works only for models explicitly listed and leaves the silent-zero path intact for anything else (the dated claude-sonnet-4-5-20250929 id still returns (0.0, 0.0) under B, exactly the failure mode reported). B also changes bedrock cost_per_token for every Bedrock model to apply a geo multiplier, a behavior change beyond the issue's ask that adds risk, and it has to whitelist claude_platform entries in an unrelated test. B's test is reasonable but data-driven over its own entries rather than over the issue's scenarios. A is the smaller, root-cause fix with stronger targeted tests; B masks the symptom with data and carries extra scope.

The issue

Description

Every request routed through Claude Platform on AWS (bedrock/claude_platform/<model>, or claude_platform/<model> with
provider bedrock) gets spend = 0 in LiteLLM_SpendLogs. The proxy returns no x-litellm-response-cost header and
logs no cost-calculation error, so budgets and spend reports silently under-count Claude usage.

Other Bedrock routes for the same models are priced correctly. Examples: bedrock/converse/anthropic.claude-opus-5-5,
bedrock/us.anthropic.claude-opus-5-5.

Cause

Claude Platform on AWS takes Claude API model IDs (claude-opus-5-5). The cost map stores Bedrock pricing under
Bedrock model IDs (anthropic.claude-opus-5-5), and no entry exists for claude_platform/....

  • strip_bedrock_routing_prefix does not remove claude_platform/, so get_model_info searches for claude_platform/claude-opus-5-5.
  • BedrockModelInfo does not override get_model_cost_key, so nothing maps the Claude API ID to the Bedrock key.
  • The lookup then falls back to a capability-only entry with zero costs instead of raising, so the miss is silent.

Adding claude_platform/ to strip_bedrock_routing_prefix alone is not enough. The lookup then searches for
claude-opus-5-5 under provider bedrock. That key belongs to provider anthropic, so it is rejected and the cost is still 0.
