[compiler-sfc] Typo 'exit' instead of 'leave' in estree-walker causes missing ASI guard and runtime error with consecutive awaits

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The source change is identical in both patches: `exit` becomes `leave` in the estree-walker options in compileScript.ts. This fixes the root cause. `scope.pop()` now runs when a BlockStatement is left, so `needsSemi` is computed against the correct enclosing block, and consecutive awaits after a nested block get their `;` guard. Correctness is therefore equal, and the decision rests on tests and craft.

Patch A adds one test. It compiles a nested-block case, strips the import line with a regex, evaluates the output through `new Function` with a mocked `_withAsyncContext`, and checks that `setup` resolves. This would fail before the fix, because the missing semicolon makes `(...)(...)` call `undefined` and throw a TypeError. It directly reproduces the runtime symptom from the issue. However, it depends on the exact output shape: the import line format, the `genDefaultAs` binding, and the setup context. It also breaks from how the surrounding async/await tests are written.

Patch B adds two tests inside the existing `async/await detection` block using the established `assertAwaitDetection` helper and snapshots. One covers a nested `if` and the other a `for` inside a `while`. Each asserts that a `;(` precedes the second `_withAsyncContext` and that no bare `)(` juxtaposition appears. Both would fail before the fix, because the regex requiring `;` would not match. They cover two block-nesting shapes, not one. They also follow the file's conventions, and the snapshots make the expected output easy to read.

Both test suites are meaningful regression tests. Patch B fits the codebase better and covers more scenarios, without Patch A's ad-hoc evaluation approach, so it is the somewhat better patch overall.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

### Any additional comments?

**Root Cause:**
The bug is caused by a typo in the AST walker configuration inside `compiler-sfc`. The compiler uses `estree-walker` which expects the hooks `{ enter, leave }`. However, the code currently passes `{ enter, exit }`.

Since `exit` is not a valid hook in `estree-walker`, it is never called. Consequently, `scope.pop()` is never executed when leaving a `BlockStatement` (like the `if` block in the reproduction). This corrupts the `scope` stack, causing the `needsSemi` calculation to fail for all subsequent `AwaitExpression` nodes.

**Proposed Fix:**
Simply change `exit` to `leave` in the walker options:
  • exit(node2) {
  • leave(node2) { if (node2.type === "BlockStatement") scope.pop(); }
