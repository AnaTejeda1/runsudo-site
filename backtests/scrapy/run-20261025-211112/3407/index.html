Patch A's change to scrapy/core/downloader/handlers/http11.py adds `if not isinstance(result, Failure)` without importing `Failure`, so every timeout on the default HTTP/1.1 handler now raises NameError. The independent tests confirm this: on Patch A, not only do the partial-response tests still fail, but the default-behaviour test (data loss not allowed, timeout should raise DownloadTimeoutError) regresses from PASS on base to FAIL with NameError. That is a hard breakage of the most common code path. Patch A also skips its own new HTTP test for handlers that don't opt in and only works for aiohttp. Patch B passes all independent tests across http11 (HTTP and HTTPS), aiohttp, the crawl-level scenarios, and the default-behaviour test. Its design is sound: it keeps the reader reference in _ScrapyAgent and returns the buffered body flagged as dataloss from _cb_timeout only when headers were received and data loss is allowed; otherwise it still raises DownloadTimeoutError. It also extends the behaviour to the HTTP/2 stream, uses the broader httpx.TimeoutException and aioftp's timeout exception set, adds tests for both meta and setting paths plus the no-headers case and FTP, and documents the behaviour in settings.rst. B is strictly better on correctness, tests, and craft.

The issue

View on GitHub

I'm working on scraping some pages that hold the HTTP connection open indefinitely, trickling data to the client little by little. I had hoped to use a short timeout to grab the page up to a certain point, but after the timeout is triggered, I can't get at the data that was received. I thought that setting DOWNLOAD_FAIL_ON_DATALOSS=False would allow partial responses to be processed, but I still get twisted.internet.error.TimeoutError: User timeout caused connection failure. If I use errback= on the request, the errback just gets the TimeoutError object and not the response.

Should setting DOWNLOAD_FAIL_ON_DATALOSS=True allow timed out responses to be processed? Or is there another way to deal with partial responses after a timeout?
