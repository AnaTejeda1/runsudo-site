What happened?

Anthropic's preserved-thinking controls for Claude Fable 5.1 (thinking.block_binding.prefix_mismatch_behavior, https://platform.claude.com/docs/en/build-with-claude/preserved-thinking) are only accepted alongside the beta header thinking-binding-controls-2026-08-01.

When a client sends both through the proxy to a bedrock/ or vertex_ai/ Claude deployment on /v1/messages, the proxy forwards the block_binding body field untouched but strips the beta header, because the header has no entry in anthropic_beta_headers_config.json (bundled at v1.101.0-rc.1, and not on main as of 03a4c806c4 either). The provider then rejects the request with:

thinking.adaptive.block_binding: Extra inputs are not permitted

Consequences:

  • Nobody behind a LiteLLM gateway can opt into preserved-thinking enforcement on Bedrock/Vertex, which Anthropic's docs tell integrators to do now to test their append-only behaviour before later models enforce it for everyone.
  • Accounts created on or after 2026-08-31 are enforced by default on Fable 5.1; the SDKs send block_binding for them, so this is a hard 400 for those users rather than an opt-in inconvenience.

The same request sent directly to the provider (header + block_binding) succeeds and returns input_transformations: [].

User Flow

Before a (hypothetical) fix: a developer testing their integration against preserved thinking gets a 400 from every Claude Fable 5.1 deployment behind the gateway.

  1. They send POST https://litellm-domain/v1/messages with header anthropic-beta: thinking-binding-controls-2026-08-01 and body "model": "claude-fable-5-1", "thinking": {"type": "adaptive", "block_binding": {"prefix_mismatch_behavior": "drop_block"}}, "messages": [{"role": "user", "content": "..."}]
  2. They get HTTP 400 invalid_request_error: Vertex_aiException BadRequestError - thinking.adaptive.block_binding: Extra inputs are not permitted, followed by the configured Bedrock fallback failing the same way (BedrockException - {"message":"thinking.adaptive.block_binding: Extra inputs are not permitted"})
  3. They remove the block_binding field: the request succeeds, but now they cannot see input_transformations or make the API enforce the prefix check, so they cannot tell whether their integration is affected

After a (hypothetical) fix: the same request goes through and the API reports what it dropped.

  1. They send the same POST https://litellm-domain/v1/messages with the same header and body
  2. They get HTTP 200 with the usual content array plus a top-level input_transformations: []
  3. On a later turn where they edited an earlier message, input_transformations lists the dropped thinking blocks with reason: "prefix_binding_mismatch" (or, with "error", the 400 Anthropic documents naming what changed)

{"type":"error","error":{"type":"invalid_request_error","message":"litellm.BadRequestError: Vertex_aiException BadRequestError - {\"type\":\"error\",\"error\":{\"type\":\"invalid_request_error\",\"message\":\"thinking.adaptive.block_binding: Extra inputs are not permitted\"},\"request_id\":\"req_vrtx_011Cf4R9GhDLYQ5oqHS46VnE\"}. Same request against bedrock-claude-fable-5-1 directly (x-litellm-call-id: e0ddc96d-a555-4c57-84db-9266ab6adf15): HTTP 400, BedrockException - {"message":"thinking.adaptive.block_binding: Extra inputs are not permitted"}.

Same request body without the beta header and without block_binding: HTTP 200 on all three turns, each response carries a thinking block with a signature and no input_transformations field (expected for an account created before 2026-08-31 with no opt-in).

After registering the header (branch fix/anthropic-thinking-binding-beta-header), the identical request to the same two deployments returns HTTP 200 and the response carries input_transformations: [] — the field only exists when the header reached the provider — on both bedrock/us.anthropic.claude-fable-5-1 and vertex_ai/claude-fable-5-1.

Where the header goes: filter_and_transform_beta_headers drops any value not present in the provider's mapping in anthropic_beta_headers_config.json; thinking-binding-controls-2026-08-01 has no entry for any provider. Confirmed on a local litellm --config proxy against a recording upstream: the outgoing Bedrock invoke body has block_binding but no anthropic_beta, and the outgoing first-party request has no anthropic-beta header.
