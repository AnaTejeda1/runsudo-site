What happened?

https://github.com/BerriAI/litellm/blob/v1.102.0-rc.1/model_prices_and_context_window.json#L48398-L48416

This entry has cache_read_input_token_cost (5e-07) and cache_read_input_token_cost_above_200k_tokens (1e-06) but no supports_prompt_caching, so supports_prompt_caching() returns false and GET /v1/model/info reports "supports_prompt_caching": false for a Vertex Grok 4.6 deployment.

The same model on the other providers does set it:

  • xai/grok-4.6 → supports_prompt_caching: true (L49979)
  • azure_ai/grok-4.6 → supports_prompt_caching: true

xAI prompt caching is provider-managed (automatic on a stable prefix), and the Vertex route does return usage.prompt_tokens_details.cached_tokens > 0 on follow-up turns, which is what the cache-read rate on this entry bills. Callers that gate on /model/info before reusing a prefix therefore skip caching on the Vertex route only.

The whole vertex_ai/xai/grok-* family looks the same — each has a cache-read price and none sets the flag:

Before a (hypothetical) fix

The flow fails when I ask the gateway whether Vertex Grok 4.6 supports prompt caching: the catalog says no, even though a follow-up completion on that same model returns cached tokens.

  1. I start the proxy with a config that exposes grok-4.6-vertex (vertex_ai/xai/grok-4.6) and grok-4.6-direct (xai/grok-4.6) and see it listening on http://localhost:4000.
  2. I send GET http://localhost:4000/v1/models with Authorization: Bearer sk-[REDACTED]. I get HTTP 200 and both model names in data.
  3. I send GET http://localhost:4000/v1/model/info with the same header. I get HTTP 200. For grok-4.6-vertex, model_info.supports_prompt_caching is false (or absent) while cache_read_input_token_cost is 5e-07. For grok-4.6-direct, supports_prompt_caching is true.
  4. I send POST http://localhost:4000/v1/chat/completions for grok-4.6-vertex with a long stable system prefix, a first user turn, and header x-grok-conv-id: conv_repro_1. I get HTTP 200 and usage.prompt_tokens_details.cached_tokens of 0.
  5. I send the same URL again with the same x-grok-conv-id, appending the assistant reply and a follow-up user turn. I get HTTP 200 and usage.prompt_tokens_details.cached_tokens greater than 0.
  6. I send POST http://localhost:4000/v1/responses for grok-4.6-vertex with the same prefix and "prompt_cache_key": "conv_repro_1". I get HTTP 200 and usage.input_tokens_details.cached_tokens of 0.
  7. I send the same URL again with the same prompt_cache_key and the follow-up turn. I get HTTP 200 and usage.input_tokens_details.cached_tokens greater than 0.
