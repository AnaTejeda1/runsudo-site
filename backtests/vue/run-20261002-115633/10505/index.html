Clearing select's value in change handler behaviour changed since 3.4.15 via webdriver

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause the same way. They replace the blanket `_assigning` flag, which skipped `setSelected` for the whole tick, with a snapshot of the value just assigned from the DOM. `updated` then re-syncs the DOM whenever the model differs from that snapshot. So a `@change` handler that sets the model to null now clears the select in both patches, and both add tests that fail before the change and pass after it.

The difference is in the edge cases, where Patch A holds up better:

1. **Snapshot timing.** Patch B snapshots `selectedVal.slice()` after calling the assigner. For Array models the user's `onUpdate:modelValue` receives `selectedVal` itself and may mutate it synchronously. Patch B's snapshot then records the mutated array, matches the (same) mutated model, and skips the re-sync, leaving the DOM stale. Patch A computes and snapshots before calling the assigner, and has a test for exactly this case.
2. **Multiple flag changes.** Patch A records `el.multiple` at assign time and re-syncs if it changed before `updated`. Patch B compares using the current `el.multiple` against a snapshot taken under the old mode.
3. **Throwing assigner.** Patch A wraps the assigner in try/finally so the pending marker is still cleared if the assigner throws.
4. **Repeated updates.** Patch A consumes the pending value in `updated`, so a second update in the same tick always re-syncs. Patch B keeps reusing the stale snapshot until nextTick.

On tests, Patch B's are more directly focused on the issue's variants: null reset, setting another value, Array reset and mutation, and Set reset. Patch A includes the core issue test plus many edge-case tests; a few (counting writes to `selected`) are more about performance and are somewhat tangential.

The code footprint is similar in both. Patch A is the more robust fix overall.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
