Bug Description

After upgrading our n8n Cloud instance from the stable channel to 2.37.0 this morning, every Code node in every workflow on the tenant fails with:

Your Code node task was not matched to a runner within the timeout period.

A full instance restart from the Cloud admin panel does not resolve it. At least three other reports were filed today with the identical symptom on 2.37.x: #37062, #37037, #36989. I understand individual cloud instances are handled via help@n8n.io (we are contacting support as well) — this issue is to document what looks like a release-line regression in 2.37.x, with the code-level comparison below, since it is affecting multiple tenants on the beta channel today.

Why this does not look like broker/matching logic: the only recent behavioral change to the task broker, #36530 ("Avoid restarting task runners that are only slow"), was backported to 2.36.x via #36609 — so the working stable line (2.36.7) and the broken beta line (2.37.x) run essentially the same matching/registration code.

What is exclusive to 2.37.x is a rebuild of the runner runtime (runners Dockerfile diff: 2.36.7 vs 2.37.1):

  • Node 24.18.1 → 26.5.1 in the n8n and runners images (#36291) — matches the nodeJsVersion: 26.5.1 in the debug info attached to #37062
  • corepack removed; pnpm 10.32.1 → 11.22.0, now installed from npm (#36702, #36424)
  • task-runner-launcher still pinned at 1.4.7 (released June 10) — predating the Node 26 runtime it now supervises

This is consistent with the JS runner sidecar failing to start or complete registration with the broker on 2.37.x, so every Code node task times out unmatched — and with why an instance restart doesn't help (it respawns the same pairing). Related prior fragility in this area: #35685 (launcher health-check breakage from an environment-level change).

Happy to provide the full debug information or instance details privately to support.

To Reproduce

  1. n8n Cloud instance on 2.37.0 or 2.37.1
  2. Create a new, blank workflow containing only a Manual Trigger and a Code node with return [{ json: { test: "hello" } }];
  3. Execute the workflow
  4. Fails after ~60s with "Your Code node task was not matched to a runner within the timeout period" — same result in every workflow on the tenant; a restart of the instance does not change the behavior

The same instance's Code nodes worked on the stable channel immediately before the upgrade.

Expected behavior

The task runner registers with the broker and Code node tasks execute, as on 2.36.7.
