Issue #12569 Merged fix PR # Run 5 Oct 2026 · run-20261005-124535 vuejs/core

Custom directive's unmounted event is not triggered on v-for element

Worse

The merged fix was judged better than our patch.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Root cause: in `buildProps`, an element is forced into a block when it has a dynamic `:key`, or a custom directive or before-update hook plus children. Because `shouldUseBlock` is set, NEED_PATCH is skipped. The stable-fragment branch of the v-for transform then demotes the block to a plain vnode. The result is an untracked vnode whose directive unmounted hooks, refs and vnode hooks never run, which is the reported bug.

Patch A fixes the symptom inside vFor. When demoting, it re-derives a NEED_PATCH condition with a separate `needsPatch` helper that duplicates `buildProps` logic (refs, runtime directives, onVnode* props and `@vue:` handlers). This fixes unmount and update for the issue's case. However, it still demotes elements that were forced into blocks *because* of directives or before-update hooks with children. Those blocks exist so that `beforeUpdate` runs before the children update. Once demoted, the children are tracked in the parent block and patched first, so hook ordering stays broken. Patch A's own test `custom directive with children` asserts `isBlock: false`, which locks in that behaviour. The duplicated detection logic can also drift from `buildProps`.

Patch B computes `needsPatch` and `isBlockRequired` at the source in `buildProps` / `transformElement` and records them on the VNodeCall. vFor then adds NEED_PATCH on demotion and keeps the block when it is truly required, for directives or before-update hooks with children. That fixes the unmount bug and also preserves `beforeUpdate` ordering. It also normalizes the before-update arg check via camelize and tracks setup-const function refs, which were previously skipped by the early return.

Tests: both add compiler and runtime tests that fail before the fix. Patch B's runtime tests are broader. They cover static ref array cleanup, function ref null calls, directive and vnode unmounted hooks, and `beforeUpdate` ordering relative to children.

Patch B touches more code, but the changes are coherent and keep a single source of truth. Patch B is the more correct root-cause fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
