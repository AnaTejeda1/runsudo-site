Description

The below example code (named foo.py) passes when running python foo.py as the input "1.0"-string gets converted to float. However, running mypy foo.py (with or without --strict) gives the following error:

foo.py:11: error: Argument 1 to "RootModel" has incompatible type "str"; expected "float"  [arg-type]
Found 1 error in 1 file (checked 1 source file)

I would expect the BaseModel-fields and the RootModel-field to behave the same in this case. That is, if the value can be converted – either via a custom made validator or through the conversion table – then mypy should not raise an error.

Example Code

import pydantic


class Foo(pydantic.BaseModel):
    f: float


RFoo = pydantic.RootModel[float]

f = Foo(f="1.0")
rf = RFoo("1.0")

assert isinstance(f.f, float)
assert isinstance(rf.root, float)
assert f.f == rf.root

Summary

What was wrong
pydantic.RootModel[float]("1.0") raised a mypy [arg-type] error, while the analogous BaseModel field construction (Foo(f="1.0")) did not. The cause is in pydantic/root_model.py:60: the hand-written RootModel.__init__ typed its positional root parameter as the class TypeVar RootModelRootType, which binds to float for RootModel[float], rejecting a str. Because the pydantic mypy plugin does not regenerate __init__ for a parametrized generic alias, this strict source signature is what type checkers use — with or without the plugin. BaseModel.__init__, by contrast, is def __init__(self, /, **data: Any), so its field inputs are never rejected at the type level.

What I changed

  • pydantic/root_model.py:60 — changed only the root parameter annotation from RootModelRootType to Any, giving parity with BaseModel. The class-level field root: RootModelRootType (governs the .root attribute type) and model_construct's signature were left untouched.
  • Added a regression scenario to tests/mypy/modules/root_models.py (FloatRootModel = RootModel[float]; float_root = FloatRootModel('1.0'); assert_type(float_root, RootModel[float])) and recorded the desired no-error post-fix state in the three fixtures (mypy-default_ini, pyproject-default_toml, mypy-plugin_ini).

Test evidence (mypy is not in the standard ./bt-test container, so I ran the mypy suite in the same Docker image with the repo's typechecking dependency group):

  • Before fix: mypy emitted Argument 1 to "RootModel" has incompatible type "str"; expected "float" [arg-type] on the new line under all three configs (error counts 9/9/4).
  • After fix: that error is gone with no new errors (counts 8/8/3). The actual test_mypy.py comparison against the fixtures passes: 3 passed for -k root_models, and the full mypy suite: 53 passed.
  • Runtime gate ./bt-test tests/test_root_model.py: 78 passed (change is type-only).
