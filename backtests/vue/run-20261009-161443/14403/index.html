Preserve input values entered during hydration

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

Both patches use the same root-cause approach: during hydration the element is already attached in `created`, so each compares the live DOM value against the server-rendered default and, if they differ, writes the DOM value into the model instead of overwriting it in `mounted`. They differ in coverage. Patch B only handles `type === 'text'` inputs and textareas. Password, email, search, tel, url and number inputs still get reset, as do checkboxes, radios and selects. The issue is about forms in general, so many common fields stay broken. Patch A handles text-like inputs of every type, including a sanitization-aware comparison for range and color inputs and support for the .trim and .number modifiers. It also handles textarea, checkbox (including true-value/false-value and array/Set models, with a pending-model map so several boxes sharing a collection combine correctly), radio, and select (single and multiple, including correct default-index logic for selects with no `selected` attribute). It deliberately skips custom elements. Patch A's tests are thorough: each element type, the modifiers, the unchanged-by-user case, and false-positive guards for browser-sanitized values and selects with no matching option. Patch B adds a single text-input test. Patch A is more complex, notably the `pendingCheckboxModels` mechanism, but the complexity is targeted and tested, and the refactors (`assignChecked`, `assignSelected`) keep existing behavior. On correctness breadth and tests, Patch A is clearly better.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Steps to reproduce

user loads a page with a slow internet connection
starts entering some values ​​into the input with v-model
after all browser resources loaded - input v-model reset to default value

What is expected?

entered input value is preserved once hydration completes

What is actually happening?

input value is reset to its default value

System Info

Any additional comments?

This is affecting UX when interacting with inputs/forms in slowly loading apps, where values entered during hydration phase are erased and the progress is lost. I have been blocking all forms myself until mounted hook fires to workaround this issue - it would be great to not have to!
