The issue

Description

opencode run --format json usually exits without printing the final step_finish event, even though the session completed and stored that step. Scripts that read tokens and cost from step_finish lose usage for the final step.

With OpenCode Go, 9 of 9 completed runs ended like this:

step_start tool_use step_finish step_start text

The final step_finish is missing. opencode session export shows the final assistant message with finish: "stop" and the expected text. The same thing happens with no tool call (step_start text, no step_finish).

In packages/cli/src/run/noninteractive.ts, session.wait resolves when the session goes idle. The client then sets finalizing = true, which drops every queued event except session.execution.*. reconcile() fills in missing text, reasoning and tool parts from the saved messages, but never emits step_start or step_finish. If idle arrives before the final session.step.ended is processed, that event is lost. The existing test uses session.wait then reconciles projected output without a terminal event expects only text in this case.

Older reports of this symptom (#31435, #38661, #26855) were for the v1 run.ts and were closed. This is the v2 client.
