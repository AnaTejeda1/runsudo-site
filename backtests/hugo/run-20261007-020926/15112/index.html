In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches move the chromastyles generation logic out of commands/gen.go into a shared markup/highlight package, so the CLI and the new template function use the same code. Both add a css.ChromaStyles template function that returns a Resource.

Patch B follows the issue's explicit guidance that creating the Resource "should be delegated to `create.Client.FromString`". Patch A instead calls ResourceSpec.NewResource directly with a hand-rolled LazyPublish/Anonymous descriptor and its own small LRU cache. This duplicates what create.Client already does and adds risk around identity and dependency tracking and publishing semantics.

Patch B also handles the edges better:
- It copies the input map rather than decoding it in place, so site params used as options are not mutated, and a test asserts this.
- It normalizes targetPath with paths.ToSlashTrimLeading.
- It rejects unknown option keys, such as the typo `styel`, with a clear error.
- It prefixes errors with `css.ChromaStyles:`.

Patch A has one nice touch: it defaults the style to the markup.highlight.style config value, which arguably fits the "configured in hugo.toml" wish. Patch B defaults to `friendly`, but its documentation shows config-driven options via site.Params, which also meets that wish.

On tests, Patch B adds both unit tests for the shared package (decoding, mode selector, highlight style, error cases) and integration tests (params-sourced options, map immutability, error cases including a non-map argument). Patch A has integration and error tests plus a benchmark but no unit coverage of the shared code. Patch B also adds documentation.

Overall, Patch B is more faithful to the issue's design direction, more robust, and better tested.

We have a CLI command for this, with Chroma's recent addition of dark/light modes, it would be convenient to generate these on-the-fly. This would allow this to be configured in hugo.toml and also allow the user an easier way to find the correct settings.

E.g.

{{ $dark := css.ChromaStyles dict 
  "targetPath" "css/croma_dark.css"
   "style" "monokai"
   "modeSelector" "dark"
    "mode" "dark"
}}
<link rel="stylesheet" href="{{ $dark.RelPermalink }}">

This would be even more useful if we fix #15103.

  • The options would be targetPath + the options in https://gohugo.io/commands/hugo_gen_chromastyles/#hugo-gen-chromastyles
  • Some sharing of code between the gen command in the commands package would be sensible.
  • Creating the Resource should be delegated to create.Client.FromString.
