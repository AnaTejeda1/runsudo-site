get_project_settings of doesn't reflect per-spider settings

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The issue is a user misunderstanding with two components: get_project_settings() is documented nowhere and does not include spider settings, and custom_settings assigned in __init__ is silently ignored because spider settings are read from the class before instantiation. Patch A only adds a docstring and a brief docs mention of get_project_settings; it does nothing about the silent-ignore half, which is what actually confused the reporter, and adds no tests. Patch B documents both points explicitly (a note in settings.rst stating custom_settings must be a class attribute and that get_project_settings excludes spider settings, plus a fuller docstring), and adds a targeted runtime UserWarning in Crawler._create_spider when custom_settings is found on the instance and differs from the class attribute. The check is narrow and low-risk (vars() membership plus identity comparison), covers both the __init__ case and the spider-argument case, and points users at the correct alternatives (class attribute, update_settings, from_crawler with priority='spider'). It is backed by four tests that would fail before the change and pass after, including a full crawl_async run. The independent evidence confirms this: only Patch B passes the 'not silently ignored' test, while the 'override in __init__' test fails on both since neither (correctly) changes the settings model. The warning is a modest behavior addition beyond pure docs, but it directly targets the reported confusion rather than being unrelated churn. B is the more complete and better-verified fix.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. It's possible I'm using this wrong. But I'm doing the following:

class MySpider (Spider)
  def __init__(self):
		custom_settings = {
			'AUTOTHROTTLE_ENABLED': False
		}

  a = scrapy.utils.project.get_project_settings()
  print(a.copy_to_dict())

My settings.py has AUTOTHROTTLE_ENABLED: True.

Based on my reading of https://doc.scrapy.org/en/latest/topics/settings.html#populating-the-settings - the custom_settings value should override the value of settings.py. But the result of the above is:

....
AUTOTHROTTLE_ENABLED: True
...

It's using the value from settings.py - am I misunderstanding this or is it a bug? I was hoping to load and alter settings dynamically during the init.
