Extend self deprecation to module/package/session scoped fixtures inside classes

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches extend the warning to module/package/session scopes and both pass the independent tests for the issue's core scenarios (warn on `self` fixtures in test classes, no warn on `@staticmethod`). The decisive difference is a regression in Patch A: it changes the condition to `fixturedef._scope >= Scope.Class` and warns whenever the fixture function is bound to a non-type instance, without checking that the fixture lives on a test class. Session/module-scoped fixtures defined as instance methods on plugin objects registered via `pluginmanager.register(Plugin())` are a legitimate, long-supported pattern where `self` works correctly because the plugin instance is long-lived. Patch A emits the deprecation for them, and the independent test `test_session_fixture_on_plugin_object_does_not_warn` fails under A (errors=1 instead of passed=1). Patch B guards with `isinstance(fixturedef.node, _pytest.python.Class)`, so only fixtures collected from test classes warn, and it adds a regression test for the plugin case. Patch B also ships a dedicated, scope-aware warning message ("once per module/session" rather than A's now-inaccurate "once per class" text for session scope, and A's message still says "Use a @classmethod" even though the issue asks for `@staticmethod`), a documented deprecation section with before/after examples, and tests that assert the full message text. Patch A's test diff is broader (parametrizes over all scopes including `Scope.Class` and `@staticmethod`), but that does not offset the false-positive warning on plugin fixtures. Minor nit for B: the local `import _pytest.python` inside the function is slightly awkward, but it is a common circular-import workaround in pytest and does not affect correctness.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Each saw the issue and the two patches, labelled A and B in random order (two of them saw ours as A), with issue links and version numbers removed. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours. The reasoning above is one judge's, shown verbatim.

#14071 added a deprecation warning for:

import pytest

class TestFixture:

    @pytest.fixture(scope="class")
    # without @classmethod
    def fixt(self):
        self.x = 23

    def test_fixt(self, fixt):
        print(self.x)

because that doesn't work which might be surprising to people.

However, the same issue exists with scopes module, package and session as well. We should extend the deprecation to those, and require that those are @staticmethod.
