TypeAdapter config not used for JSON Schema generation

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches apply the same core fix for the single-adapter case: pushing the TypeAdapter's config onto the JSON schema generator's config wrapper stack before `generate()`. That resolves the exact snippet in the issue, and the independent tests confirm both pass the direct bytes/list[bytes] scenarios. Patch B goes further on the same root cause in ways that matter: (1) `TypeAdapter.json_schemas()` is left untouched by Patch A, so multiple adapters passed together still ignore their configs, which is the very bug reported, just via the sibling API; B threads per-input configs through `generate_definitions()` with a length check. (2) B makes config-less TypedDicts and stdlib dataclasses nested inside the adapter inherit the adapter config during JSON schema generation, mirroring core schema generation. This is justified rather than speculative: B's test shows `dump_json` already serializes such nested bytes as base64 under the adapter config, so on Patch A the JSON schema would contradict actual serialization output. The independent tests show exactly this split: A fails the nested TypedDict, nested dataclass, and `json_schemas` cases, B passes all six. B's change of `_get_typed_dict_config` to return `None` is safe because `ConfigWrapperStack.push(None)` is a no-op, and the `config or {}` fallback preserves `_update_class_schema`'s contract. B's tests are also more thorough (several config keys, both modes, nested classes, `json_schemas`), all of which fail before and pass after. A's single test is adequate but narrow. B's extra surface (`_definitions_input_configs` attribute set externally on the generator) is slightly awkward design, but it is small, commented, and validated, and does not outweigh A leaving real instances of the reported behaviour broken.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
