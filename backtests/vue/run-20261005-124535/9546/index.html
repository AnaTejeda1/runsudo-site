defineProps options object loses properties when using generics

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches target the root cause: when a prop option references a generic `T`, the key-classification conditionals are deferred, so optional props get dropped. They fix it in different places.

Patch B changes only the key-classification helpers. It wraps the check as `{ v: T[K] } extends { v: ... }`, which keeps TypeScript from deferring the conditional on a generic check type. It also computes `OptionalKeys` and `PublicOptionalKeys` per key instead of via `Exclude<keyof T, RequiredKeys<T>>`, which stays deferred when any key is unresolved. The same treatment goes to `DefaultKeys` and `PublicRequiredKeys`. This is local and does not change what `PropType<X>` means for any existing user code. The comments explain the trick clearly.

Patch A takes a wider path:
- It removes the conditional from `PropMethod`, so every `PropType<X>` now includes a function-like constructor member, not just function types. That conditional existed on purpose for function props, and removing it alters the shape of a central public type.
- It also adds a new `unknown extends D ? V : D` branch in `InferPropType`.

These changes are probably mostly harmless, but their effect reaches beyond the bug and is harder to reason about.

On tests, Patch A has the stronger value assertions: `T | null`, `T`, `T | undefined`, plus a usability check. Patch B's `expectType<unknown>` value checks are nearly tautological. However, Patch B checks what the issue is actually about: the full key set, which keys are required or optional (with `@ts-expect-error` negatives), and correct handling of `ExtractPublicPropTypes` and `ExtractDefaultPropTypes` under generics. Patch A does not cover those. Patch B also includes non-generic props alongside generic ones, confirming that `Boolean`/`default`/`String` behavior is preserved.

Weighing correctness and risk first, Patch B's fix is narrower and safer and addresses the dropped-keys problem directly across all the extract helpers. Patch A's better value-type assertions do not outweigh its riskier change to `PropType`.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
