Scoped slot transforms array argument if rendered conditionally

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The bug is that `<slot v-if v-bind="items">` compiles to `mergeProps({key:0}, items)`, which turns an array into an object. Both patches fix this by passing the branch key to `renderSlot` as a separate 6th argument, and both keep user-provided `props.key` higher in priority at runtime.

**Patch B is narrower and therefore lower risk.**
- It only reroutes the key in the one case that causes the bug: a slot outlet whose props are a single bare `v-bind` expression (the final `else` branch of `injectProp`).
- Every other path keeps today's codegen. A plain `<slot v-if>` still compiles to `{ key: 0 }`, so no existing snapshots change.
- It also stops the `ref_for` marker from being merged into slot-outlet props. That marker causes the same array-to-object conversion for `<slot v-for v-bind="item">`. This closely related fix carries little risk, because slot outlets do not use refs.

**Patch B's tests are stronger.**
- Its compiler tests cover `v-if`/`v-else`, the fallback-plus-`scopeId` argument padding, and `template v-for` with `:key`.
- Its runtime tests cover props identity and key priority.
- Crucially, it adds end-to-end tests in the `vue` package. These render the issue's exact scenario and check that `Array.isArray(props)` is true after toggling the branch. These tests would fail before the fix.

**Patch A changes much more than the bug requires.**
- It reroutes every key injection on slot outlets, including slots with no props.
- As a result it rewrites existing snapshots and test expectations (`{key:0}` becomes `{}, undefined, undefined, 0`).
- Its snapshot diff for `transformElement.spec.ts.snap` looks wrong: it adds a v-for test snapshot to the transformElement snapshot file, with the same index hashes as the vFor snap file. This looks like stray churn.
- Its AST type changes are broader than needed.
- It does not address the `ref_for` merge path.

Both patches are correct for the reported case, but B is more targeted, better tested end to end, and avoids A's churn.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.

Steps to reproduce

  1. Create a component with a scoped slot that is rendered conditionally
  2. Pass an array as the sole argument to the slot

What is expected?

Array is rendered normally.
If you render items of that array in v-for loop, you only see items inside that array

What is actually happening?

Array is transformed into object. Items and their indexes are staying the same, key field is added
