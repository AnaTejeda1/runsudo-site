In this judgment, Patch A = our agent, Patch B = the merged fix.

Patch A fixes the root cause. The lint fires because path entries in `paths` lack a `./` or `../` prefix when `baseUrl` is unset. Patch A normalizes every generated entry so it is explicitly relative. That turns `"*"` into `"./*"`, keeps the self-mapping that lets bare imports resolve to the assets dir in the editor, and also covers source roots nested under `dir` (e.g. `sub/*`). Those nested roots would trigger the same lint, and Patch B leaves them unfixed. Its test checks a sibling root (`../c/*`), the self root (`./*`) and a nested root (`./sub/*`). That test would fail before the change and pass after. Patch B instead drops the mapping for the current dir entirely. In the issue's exact scenario this makes `Build` return nil, so the self-mapping functionality is removed rather than corrected. It also still emits non-relative paths for nested source roots, and its `root == dir` string equality is brittle against path-form differences. Its test only asserts nil for the single-root case and does not check that the remaining paths are valid relative paths. One minor nit on A: on Windows it uses the OS separator (`.\`), but this matches the existing `filepath.Rel`-based behavior. Overall A is more correct, preserves functionality, and has a stronger test.

The issue

View on GitHub

When building a site that calls js.Build, the assets/jsconfig.json file looks like this:

{
 "compilerOptions": {
  "paths": {
   "*": [
    "*"
   ]
  }
 }
}

VS Code lints line 5 as follows:

Non-relative paths are not allowed when 'baseUrl' is not set. Did you forget a leading './'?
