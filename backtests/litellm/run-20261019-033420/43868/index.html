The issue

View on GitHub

Custom-priced OpenAI deployments can return service_tier="ultrafast" while recording the standard-tier cost if the deployment only overrides the standard input/output rates. In our reproduction, 1,000 input + 100 output tokens record $0.015 instead of $0.09 (6x undercount).

This is distinct from the above-272K metadata problem fixed in #43764, which we have backported. The short-context missing-override behavior below still reproduces with that backport applied to LiteLLM 1.100.0. Initial ultrafast support was tracked in #37326.

Minimal reproduction (no credentials or inference needed)

Install litellm[proxy]==1.100.0, save the following as repro.py, then run LITELLM_LOCAL_MODEL_COST_MAP=true python repro.py. The published price entry is injected to make the reproduction independent of catalog refreshes.

import litellm
from litellm import Router
from litellm.types.utils import ModelResponse, Usage

model = "openai/gpt-6-astra"
published = {
    "litellm_provider": "openai", "mode": "chat",
    "input_cost_per_token": 10e-6, "output_cost_per_token": 50e-6,
    "input_cost_per_token_ultrafast": 60e-6,
    "output_cost_per_token_ultrafast": 300e-6,
}
litellm.model_cost[model] = published
router = Router(model_list=[{
    "model_name": "astra",
    "litellm_params": {"model": model, "api_key": "unused"},
    "model_info": {
        "input_cost_per_token": 10e-6,
        "output_cost_per_token": 50e-6,
    },
}])
response = ModelResponse(model="gpt-6-astra", service_tier="ultrafast")
response.usage = Usage(prompt_tokens=1000, completion_tokens=100, total_tokens=1100)
result = router.completion(
    model="astra", messages=[{"role": "user", "content": "OK"}],
    service_tier="ultrafast", mock_response=response,
)
print("returned tier:", result.service_tier)
print("recorded cost:", result._hidden_params["response_cost"])
print("published ultrafast cost:", 1000 * 60e-6 + 100 * 300e-6)

Output:

returned tier: ultrafast
recorded cost: 0.015
published ultrafast cost: 0.09

Expected behavior

Missing custom tier overrides should be made explicit. Either preserve the published tier rate when appropriate, or clearly warn/document that declaring standard custom prices requires independently declaring every supported tier/threshold/cache rate. Silently recording a standard price for an ultrafast response makes spend attribution misleading.

For a proxy deployment, /model/info can also merge published tier prices into the displayed model metadata even though the custom deployment's billing record does not use those prices. Ideally the API should distinguish published prices from effective billing overrides, so it can be used to verify pricing.

Root cause and workaround

The router registers custom model pricing for the deployment. The cost calculation uses that custom entry; an omitted tier key falls back to the standard rate instead of the provider catalog's tier rate. Adding input_cost_per_token_ultrafast=60e-6 and output_cost_per_token_ultrafast=300e-6 to model_info changes this reproduction to $0.09.

For Astra, the complete workaround declares input, output, cache-read and cache-write ultrafast rates for both context bands (eight fields). On 1.100.0, the above-272K fields also need #43764. Other models/tier configurations with partial custom overrides may have the same observability gap; this reproduction specifically verifies Astra ultrafast.

Pricing reference: https://developers.openai.com/api/docs/pricing

This report compares token usage against configured/published rates, not a vendor invoice. No provider keys or real inference are needed to reproduce it.
