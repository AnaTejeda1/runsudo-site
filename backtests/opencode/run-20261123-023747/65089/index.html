Description

V2 Markdown commands discard a separate legacy variant field. Executing the command switches to the configured model without its reasoning variant. Legacy JSON configuration and Markdown agents already preserve this selection. This is a remaining compatibility case after #51234, whose maintainer response requested a new V2 report if it persisted.

Plugins

Built-in configuration command plugin in an isolated Core fixture; no external plugins.

OpenCode version

Source version 2.3.0, upstream dev f898eae; Bun 1.4.4.

Steps to reproduce

  1. Define a Markdown command in .opencode/commands/variant-probe.md:
   ---
   model: example/chat
   variant: high
   ---
   Reply PROBE_OK.
  1. Load and execute it through ConfigCommandPlugin.Plugin and Command.Service.execute. In the existing test host, capture the session.switchModel argument.
  2. It receives { providerID: "example", id: "chat" }. Expected: { providerID: "example", id: "chat", variant: "high" }.

The regression uses real temporary Markdown files and the production command registry, without live inference. Using model: example/chat#high works. Embedded and structured native variants should retain precedence over a separate legacy field.
