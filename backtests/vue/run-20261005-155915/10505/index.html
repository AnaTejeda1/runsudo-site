Clearing select's value in change handler behaviour changed since 3.4.15 via webdriver

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the bug at its root cause. The 3.4.15 `_assigning` flag made `updated` skip `setSelected` for the entire tick after a change event. Any model change made in the same tick, such as resetting to null in an `@change` handler, therefore never reached the DOM. Each patch records the value just assigned and calls `setSelected` in `updated` whenever the current model differs from that value. Each snapshots the array, so in-place mutation is detected, and each treats a toggle of `multiple` as a mismatch. Both resolve the issue's scenario of a single select cleared to null.

Patch A replaces `_assigning` with a `[multiple, value]` tuple and compares with `looseEqual`. It also adds hardening that does not affect the reported bug: try/finally around the assigner, an identity check in the nextTick clear, and clearing the pending value inside `updated`. This works, but the extra machinery makes the fix harder to see. Its tests are numerous but drift from the issue. Several check counts of `selected`-setter writes via property-descriptor hooks, check that an error is thrown from the assigner, or check duplicate option values. Only one test directly covers the reported scenario.

Patch B keeps the existing `_assigning` structure and adds a single `_assignedValue` snapshot. It compares with strict equality after `toRaw`, which handles reactive proxies of option values. This is minimal and easy to follow. Its tests target the issue directly and would fail before the change:
- single select reset in `@change`, run twice
- model changed back in the same tick as the change event
- multiple-array reset
- multiple-array spliced in the handler
- Set model replaced in the handler

Correctness is roughly equal. B wins on test relevance, scope and clarity.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
