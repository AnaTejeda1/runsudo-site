XML parser does not support DOCTYPE with <!ENTITY> declarations

Better

Our patch was judged better than the merged fix.

In this judgment, Patch A = our agent, Patch B = the merged fix.

The issue is about `Jsoup.clean()`. `clean()` parses its input with the HTML body-fragment parser, not the XML parser. Patch A changes the doctype tokeniser states for every syntax and adds a `DoctypeInternalSubset` state. That state skips quoted strings, comments, PIs and markup declarations, then hands the trailing `]...>` to BogusDoctype. As a result, the `]>` and the entity declarations no longer leak as text in the HTML or the XML parser. Patch A's CleanerTest reproduces the issue's exact `Jsoup.clean` scenario, and HtmlParserTest checks `parseBodyFragment`. It also covers many doctype variants (`svg[`, `SYSTEM[`, `PUBLIC`, quoted `]>`), protects against a stray `[` swallowing the document, and handles EOF. Patch B gates every new transition on `t.syntax == xml`. The HTML tokeniser path used by `Jsoup.clean()` is therefore unchanged, and the reported `]&gt;` artifact would most likely still appear. B's own test shows that HTML output simply drops the subset after the doctype; it never exercises `clean()`. B adds a reasonable XML round-trip feature (keeping the subset in `DocumentType`), but that does not address the reported scenario. B also lacks A's guard: an unterminated subset consumes the whole rest of the document, a behaviour B's test asserts as intended. A's change to HTML tokenisation departs slightly from the spec's bogus-doctype handling, but it is well contained and tested. Patch A fixes the actual bug; Patch B likely does not.

The issue

View on GitHub

When Jsoup.clean() processes XML/SVG input that contains a DOCTYPE declaration with an internal DTD subset (i.e., entity declarations enclosed in [...]), jsoup correctly removes the DOCTYPE tag itself but leaves the closing ]> of the subset in the output string.

This was discovered while sanitizing SVG files that follow the Adobe Illustrator export format.

jsoup version: 1.22.1
Java version: 25

Steps to Reproduce

Call Jsoup.clean() with the following input SVG that contains a DOCTYPE with multiple <!ENTITY> declarations inside an internal DTD subset:

import org.jsoup.Jsoup;
import org.jsoup.nodes.Document;
import org.jsoup.safety.Safelist;
import org.junit.jupiter.api.Test;

    Safelist safelist = Safelist.none()
            .addTags("svg", "circle")
            .addAttributes("svg", "viewBox")
            .addAttributes("circle", "cx", "cy", "r", "fill");

                <?xml version="1.0" encoding="utf-8"?>
                <!DOCTYPE svg PUBLIC "-//W3C//DTD SVG 1.1//EN" "http://www.w3.org/Graphics/SVG/1.1/DTD/svg11.dtd" [
                	<!ENTITY ns_extend "http://ns.adobe.com/Extensibility/1.0/">
                	<!ENTITY ns_ai "http://ns.adobe.com/AdobeIllustrator/10.0/">
                	<!ENTITY ns_graphs "http://ns.adobe.com/Graphs/1.0/">
                	<!ENTITY ns_vars "http://ns.adobe.com/Variables/1.0/">
                	<!ENTITY ns_imrep "http://ns.adobe.com/ImageReplacement/1.0/">
                	<!ENTITY ns_sfw "http://ns.adobe.com/SaveForWeb/1.0/">
                	<!ENTITY ns_custom "http://ns.adobe.com/GenericCustomNamespace/1.0/">
                	<!ENTITY ns_adobe_xpath "http://ns.adobe.com/XPath/1.0/">
                ]>
                <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100">
                  <circle cx="50" cy="50" r="40" fill="red"/>
                </svg>
                """;
        String expectedSvg = """
                <svg viewBox="0 0 100 100">
                      <circle cx="50" cy="50" r="40" fill="red" />
                  </svg>
                """;

        Document.OutputSettings outputSettings = new Document.OutputSettings()
                .syntax(Document.OutputSettings.Syntax.xml)
                .prettyPrint(false);

        var cleanedSvg = Jsoup.clean(dirtySvg, "", safelist, outputSettings);

        assertThat(cleanedSvg).isEqualToNormalizingWhitespace(expectedSvg);
    }

}

Expected Behaviour

The entire DOCTYPE block (including its internal subset [...]>) is removed. Output:

<svg viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40" fill="red" />
</svg>

Actual Behaviour

The DOCTYPE declaration is removed but the closing ]> of the internal DTD subset is left behind in the output:

]&gt;
<svg viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40" fill="red" />
</svg>

Impact

Any application using Jsoup.clean() to sanitize SVG (or XML) produced by tools like Adobe Illustrator will silently receive malformed output containing the ]> artifact, which can break downstream XML parsers and SVG renderers.
