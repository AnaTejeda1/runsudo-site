TestModel generates values that violate falsy JSON Schema const constraints

Initial Checks

  • I reproduced this against the current main checkout at 5976ebf1038368ad16ca3507a334b06c8fb6f2ea in a tokenless Python 3.12 container.
  • I also reproduced it against released pydantic-ai v2.29.0 (f748e81ec64aff78c4d41593ed51803d8b15b9ee).
  • I searched open and closed issues and pull requests for TestModel/const, _JsonSchemaTestData, and falsy JSON Schema const; I found no report of this TestModel generator behavior. I also checked #3610, which concerns GoogleJsonSchemaTransformer, not _JsonSchemaTestData.

Description

TestModel's JSON Schema data generator checks const by truthiness:

if const := schema.get('const'):
    return const

Valid JSON Schema constants such as "", False, and 0 therefore fall through to ordinary type generation. This can make TestModel generate tool arguments or structured-output values that violate the schema it was given, producing misleading test behavior or validation retries.

Minimal, Reproducible Example

This uses the internal generator directly to keep the reproducer small:

from pydantic_ai.models.test import _JsonSchemaTestData

cases = {
    'empty_string': {'type': 'string', 'const': ''},
    'false': {'type': 'boolean', 'const': False},
    'zero': {'type': 'integer', 'const': 0},
}

for name, schema in cases.items():
    value = _JsonSchemaTestData(
        {
            'type': 'object',
            'required': ['value'],
            'properties': {'value': schema},
        },
        seed=1,
    ).generate()['value']
    print(name, repr(value))

Observed with released pydantic-ai v2.29.0:

empty_string 'b'
false True
zero 1

Expected output is '', False, and 0, respectively.

Suggested Direction

Distinguish an absent const from a present falsy value (for example, test for the key rather than the value's truthiness), then add focused coverage for these constants.

  • Pydantic AI: released v2.29.0 (f748e81ec64aff78c4d41593ed51803d8b15b9ee)

Summary

What was wrong: TestModel's JSON Schema data generator _JsonSchemaTestData._gen_any (pydantic_ai_slim/pydantic_ai/models/test.py:463) checked const by truthiness:

if const := schema.get('const'):
    return const

Valid falsy constants ('', False, 0) failed this check and fell through to ordinary type generation, so TestModel produced values that violated the schema's const — e.g. 'b', True, 1 instead of '', False, 0.

What I changed:

  • pydantic_ai_slim/pydantic_ai/models/test.py (production, 2 lines) — replaced the truthiness check with a key-presence check so a present falsy const is returned verbatim: python if 'const' in schema: return schema['const'] Only the const branch changed; enum/examples/anyOf were left as-is (out of scope for this report).
  • tests/models/test_model_test.py (regression test) — added test_json_schema_test_data_falsy_const, mirroring the established raw-dict-schema convention (test_prefix_unique, test_max_items) and the report's reproducer. It generates for a schema with const: '', const: False, const: 0 and asserts {'empty_string': '', 'false': False, 'zero': 0}.

  • Before the fix (isolated run): test_json_schema_test_data_falsy_const FAILED — generator returned {'empty_string': 'b', 'false': True, 'zero': 1}, matching the report.
