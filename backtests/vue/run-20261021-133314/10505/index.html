Clearing select's value in change handler behaviour changed since 3.4.15 via webdriver

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix the root cause the same way: instead of blindly skipping `setSelected` while `_assigning` is set, `updated` now compares the model value against what the change listener assigned and re-syncs the DOM when they differ. Both pass all six independent tests, including the single-select-cleared-to-null case from the issue, the fixed-value reset, and the multiple-select reset/in-place mutation cases.

Patch A is the more robust implementation. It compares with `looseEqual`/Set membership, which is the same equality `setSelected` itself uses, so a handler that replaces the model with an equal-but-new array still takes the fast path; Patch B uses `toRaw` identity, which forces a full option rewrite in that case, undermining the perf optimization the original commit introduced. A also clears the pending marker as soon as `updated` consumes it (so any further update in the same tick always syncs), detects `el.multiple` flipping during the pending update, snapshots the Array it hands to user code, and uses try/finally so a throwing assigner cannot leave stale state. B's snapshot/`_assigning` combination is correct for the scenarios in the issue but keeps three parallel fields and leaves `_assigning` semantics overloaded.

On tests, A adds a broader suite (single clear, Set override, duplicate values, multiple→single, Array/Set mutation in handler, no-rewrite guards, assigner throw), all of which exercise real behaviour rather than tautologies. B's five tests are well targeted at the issue (including the 0/1 values from the report) and include a no-re-sync regression guard, but cover fewer edges.

On craft, B is simpler and closer to the surrounding code, and its comment is clearer; A's tuple with `pending[0]`/`pending[1]` indexing is less readable. That readability cost is real but smaller than A's correctness and consistency advantages, so A wins by a moderate margin.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
