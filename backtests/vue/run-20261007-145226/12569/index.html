Issue #12569 Merged fix PR # Run 7 Oct 2026 · run-20261007-145226 vuejs/core

Custom directive's unmounted event is not triggered on v-for element

Worse

The merged fix was judged better than our patch.

In this judgment, Patch B = our agent, Patch A = the merged fix.

The bug: buildProps forces an element with a custom directive and children (or a dynamic key) into a block, which skips NEED_PATCH. A stable v-for then turns that block back into a plain vnode with no patch flag. The vnode is no longer tracked in the parent's dynamicChildren, so its directive unmounted and updated hooks, its ref and its vnode hooks are all skipped. Both patches fix the reported unmounted symptom.

Patch B adds NEED_PATCH in vFor whenever the converted vnode needs it. It detects this with `needsPatchAsVNode`, a helper that re-scans the element's props to duplicate buildProps' logic. That duplication is fragile. B also always demotes these elements to plain vnodes, which loses the reason they were forced into blocks: a directive's or vnode hook's beforeUpdate must run before the children update. As a plain vnode in the fragment, the element's children are created and tracked before the parent, so they update before its beforeUpdate. B's own test 'custom directive with children' locks in that non-block behavior.

Patch A carries information from buildProps on the VNodeCall instead:
- `needsPatch` adds NEED_PATCH when vFor demotes a key-forced block.
- `isBlockRequired` keeps the element a block when it has a custom directive or a vnode before-update hook with children.

This fixes the issue's case (directive plus children), because the element stays a tracked block and unmount and update hooks run. It also preserves beforeUpdate ordering, which A verifies with runtime tests. A also fixes a minor issue: the camelized `@vue:beforeUpdate` spelling was not recognized. Its compiler and runtime tests cover refs, function refs, directives, vnode hooks and ordering.

A touches more code (the AST interface and buildProps), but the changes are coherent and avoid B's duplicated prop-scanning. Overall A is the more correct root-cause fix.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
