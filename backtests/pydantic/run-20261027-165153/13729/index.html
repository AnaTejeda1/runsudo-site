Initial Checks

  • I confirm that I'm using Pydantic V2

Description

Adding a no-op mode='before' model validator makes smart-union validation select a model with fewer matching fields for JSON input. The equivalent Python input selects the model with more matching fields.

The example below prints:

Larger
Smaller

I expect Larger in both cases: it has three supplied valid fields, while Smaller has two. This follows the documented number-of-valid-fields-set ranking.

Reproduced on main at 965c23dd93bd5ca7b86224ba39ccbe79399f117b. In model_fields.rs, the Python-input helper adds its known-field count, then the outer validator adds fields_set.len() again. The before validator sends the smaller model through that Python-input path, while the larger model uses the plain JSON path and receives only the outer count.

I can send a focused fix with regression tests. Could you assign this to me?

Example Code

from typing import Any

from pydantic import BaseModel, TypeAdapter, model_validator


class Smaller(BaseModel):
    a: int
    b: int

    @model_validator(mode='before')
    @classmethod
    def keep_input(cls, value: Any) -> Any:
        return value


class Larger(BaseModel):
    a: int
    b: int
    c: int


adapter = TypeAdapter(Smaller | Larger)
print(type(adapter.validate_python({'a': 1, 'b': 2, 'c': 3})).__name__)
print(type(adapter.validate_json('{"a": 1, "b": 2, "c": 3}')).__name__)
