TypeAdapter config not used for JSON Schema generation

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches fix `TypeAdapter.json_schema()` the same way: they push `self._config` onto the generator's `_config_wrapper_stack` around `generate()`. That resolves the reported example, since `ser_json_bytes='base64'` now yields `format: base64url`.

The issue is titled generally: TypeAdapter config is not used for JSON Schema generation. `TypeAdapter.json_schemas()` is the other public entry point that generates JSON schema from adapters, and it has the same defect. Patch A leaves it broken: adapters passed to `json_schemas` still ignore their config.

Patch B fixes that path too:
- It threads per-input configs through `generate_definitions` and pushes each config for both passes (definition collection and final generation). This keeps per-adapter configs isolated, which its test with a base64 adapter next to a default adapter confirms.
- The new `configs` parameter is keyword-only, defaults to None, and checks that its length matches `inputs`.
- To stay compatible with subclasses that override `generate_definitions()`, it only passes the new keyword when some config is non-None.

This extends the public signature of `generate_definitions`, which adds some surface area. The change is backward-compatible and justified by the root cause, so the risk is low.

Tests: Patch A adds one test, for `list[bytes]` via `json_schema()`. Patch B adds tests for:
- the exact issue example
- a timedelta serialization config
- the `list[bytes]` case
- the multi-adapter `json_schemas` case
- the length-mismatch error

All of B's behavioral tests would fail before the fix. Patch A's test also contains a placeholder docstring (`"""<link>"""`).

Overall, Patch B fixes the root cause more completely and tests it more thoroughly.

The judge saw only the two patches, labelled A and B in random order, with issue links and version numbers removed. The reasoning above is shown verbatim.
