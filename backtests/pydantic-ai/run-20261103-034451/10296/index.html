MistralModel fails to import with mistralai>=3: No module named 'httpx'

Better

Our patch was judged better than the merged fix.

In this judgment, Patch B = our agent, Patch A = the merged fix.

Both patches remove the root cause, the module-level `from httpx import Timeout` in `pydantic_ai/models/mistral.py`, and both pass the independent httpx-free import and agent-run tests that fail on base. The difference is scope and risk.

Patch B is a targeted fix: it swaps the annotation source to the `Timeout` type already exported by `pydantic_ai.settings` (the same type that `model_settings['timeout']` carries, so arguably the more accurate annotation), keeps the function body untouched, and adds a subprocess test that would fail on base. The test is deliberately version-agnostic: it pre-imports `mistralai` so older SDK releases that still pull legacy httpx can load, then purges and blocks `httpx` before importing pydantic_ai, which checks exactly the issue's claim (pydantic_ai itself must not need httpx) across the full supported mistralai range. One minor risk: it uses a `@pytest.mark.subprocess(reason=...)` marker I cannot confirm is registered; if the suite runs with strict markers that would error, but this does not affect the production fix.

Patch A also fixes the import (via `.._http.HTTPTimeout`) but bundles unrequested changes: it raises the `mistral` extra floor from `>=2.9.2` to `>=3.1.0`, and it adds imports of `ResourceChunk`/`ResourceLinkChunk` into `_map_content`, which is what forces that floor. Dropping support for mistralai 2.9.2 through 3.0.x is a dependency-breaking change the issue did not ask for and that users pinned to those versions would hit as resolver conflicts on upgrade. The remaining churn (httpx -> httpx2 swaps across five test files, a reworded provider comment, removed pyright ignores) is consistent with that bump but is not needed to resolve the report. A's httpx-free stage test is fine, but it only holds because of the floor bump, whereas B's test holds regardless.

On correctness the two are equivalent for the reported scenario; on tests both add a real failing-before/passing-after check; on scope B covers the ask with no added risk while A couples the fix to an unrelated SDK-floor change. B is the better fix.

Four judges ruled on this ticket in parallel, and the verdict comes from counting their votes. Where tests could check the fix, they also saw the results of tests a separate agent wrote for the issue, run on both patches. None was told which patch was ours.
